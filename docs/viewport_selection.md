# 视口选择方式（工具条下拉 + Tab 径向菜单）

> 2026-11-04。用户原话（第一轮）：
> 「模式类型中的选择这项移除掉，然后当鼠标在视口范围中时，鼠标按下 tab 键
>   不动时可以打开一个圆盘选项，分别有普通选择，框选，套索选择，刷选，然后
>   鼠标移动到哪个区域对应的选项就直接切换到对应的选择方式。」
>
> 2026-11-04 第二轮：
> 「1.引擎编辑器中左侧的选择方式列表不需要移除掉吧，这个选择方式列表可以
>   放在视口顶部左侧的选择图标那里，点击箭头选择图标的时候展开这个方式列表。
>   2.所有的选择类型只能对场景中天空地面云层星空之外的物体对象操作生效」
>
> 结论：列表**搬家**（左栏 → 视口工具条左上那颗箭头），不是删掉；同时把
> "什么算物体"钉成一条所有方式共用的判据（见§六）。

## 一、为什么把"选择"从模式列表里摘掉

左栏 `Modes` 列表那一套是 **EditMode**（地形 / 植被 / 建模 / 动画…），
每一项都对应"一整套编辑工具 + 一块参数面板"。而"点选 / 框选 / 套索 / 刷选"
是同一套工具里的四个**手感**，混进单选列表有两个具体后果：

1. 每换一次手感要多点两次（离开选择模式 → 进另一个模式 → 再回来）；
2. 列表里那一行与视口工具条的 Q 键是同一件事的重复表达。

所以 `EditMode::Select` 退化成**默认状态**：枚举值保留（落盘的 `mode` id、
`clampEditMode` 的范围、所有 `switch` 的语义都不动），只是**列表不再画它**
（`ModeRail.cpp` 的 `kModeRailRows = kEditModeCount - 1`）。

⚠ 不删枚举值是有意的：删了要连带改落盘 id、`clampEditMode`、十来个
`switch`，而收益为零 —— 用户要的是"列表里看不见它"。

## 二、Tab 径向菜单

```
         ┌── Select ──┐         内圈 38px = 死区（不做切换）
    Brush│     ●      │Box      外圈 112px
         └── Lasso ───┘         角度：0 = 上，顺时针 90° 一块
```

| 行为 | 实现 | 为什么 |
|---|---|---|
| 视口里**按住 Tab** 打开 | `IsKeyPressed(Tab)` + `hovered` + `!io.WantTextInput` | 输入框里按 Tab 是"跳下一个字段"，不能弹饼 |
| 鼠标在哪个扇区就切到哪个 | 角度 → 索引，`hover` 变化时 `setSelectionMode` | 用户原话"移动到哪个区域就直接切换" |
| 内圈 38px 不切换 | `dist > kInner` 才判定 | 按 Tab 时鼠标原地抖两下会在四块间跳；死区不**重置**已切过的值 |
| 松手关闭 | `!IsKeyDown(Tab)` | — |
| 切方式时顺带退出专属工具 | `if (editMode != Select) setEditMode(Select)` | 在植被模式下换"框选"而不退出，左键仍被 FoliageEditor 吃掉，换了寂寞 |

**画法**：环形扇区用逐段四边形拼（`PathFillConvex` 对环形不成立——那是凹多边形；
先用中心扇形再盖背景也不行，底下是 3D 画面）。

## 三、四种方式的判定语义（彼此**故意**不同）

| 方式 | 起点 | 判据 | 语义 |
|---|---|---|---|
| Pick | 任意 | 射线拾取；点空白 → 清空（若拖动 >4px 仍可拉框） | "点"
| Box | **任意**（点中物体也起框） | 实体屏幕矩形的**投影 AABB 与框相交** | 扫一片 |
| Lasso | 任意 | 实体屏幕矩形的**中心落在多边形内** | 圈住 |
| Brush | 任意 | 圆形笔刷（26px）**扫过**实体屏幕矩形 | 涂 |

- 框选"碰到就选"（不是整框住）：整框住会让"框住半个地面"选不中地面。
- 套索"中心在内"（不是相交）：那是 8 条边 × N 条轨迹边的相交测试，代价两百倍，
  而收益只是"圈住一角也选中" —— 用户在套索上期待的就是"圈住"。
- 三者共用 `entityScreenRect()`（世界 AABB 八角投影）。各写一份必然漂移，
  症状是"框选能选到、套索选不到同一个物体"。

## 四、踩到的三个坑

### 1. ⚠⚠ 结算时"跳过已选中的"会毁掉整次选择

`selectMany` 的语义是**替换**，所以"先滤掉已选中的再加"看着像去重，
实际上会让 `found` 变成空集：

```
连框同一片区域两次 → 第二次全员命中却全员被跳过 → found 空
                  → else 分支 clearSelection() → 用户看到"再框一次，选中全没了"
```

套索更明显：先框选 96 个，再套同一片 → `LASSO-SELECT n=0`（判据抓到的就是这个）。

**修法**：`found` 只回答"这次命中了谁"，去重交给 `selectMany`。
（`selectMany` 内部先 `clear()` 再重建，`isSelected` 去重那一行在清空后恒假，
所以它本来就不承担去重。）

### 2. 短名会和词表撞车

径向菜单第一版直接写 `TR("Box")` / `TR("Brush")` —— 词表里这两个键是
"盒"（碰撞体形状）和"笔刷"（笔刷体），于是菜单上显示"盒 / 笔刷"。
**没有新增短名**，改成把长名按 `0.82` 倍字号画（`AddText(font, size, ...)`）：
扇区水平可用宽度约 106px，"Lasso Select" 默认字号 110px，缩一档正好。

### 3. 扇区间缝在亮背景上会消失

单条深色分隔线在天空/雪地上会和阴影糊在一起（四块看着连成一片）。
现在画两条：深色 2.6px + 内侧浅色 1.0px。

## 六、入口为什么搬去工具条（第二轮）

用户说得对：左栏那块 **不需要删**。它删掉之后，"我现在是框选还是套索"
就只剩"点开圆盘才知道"——圆盘一松手就消失，等于没有常显。

搬到工具条的理由是**位置语义**，不是省地方：

- 那颗箭头本来就是"我要用什么工具"，选择方式是同一句问话的答案；
- 它的图标现在**跟着变**（Select 态下画当前方式的字形：箭头 / 虚线框 /
  套索 / 刷子）。以前是一枚固定的箭头，用户点了才知道自己处在哪种方式；
- 弹层里在 Transform tools **上面**（先选择方式、再变换工具）。放下面等于
  藏进折页——用户点箭头时想找的第一件事就是"换成框选"。

⚠ 左栏那块现在只剩一张说明卡（`mode_rail_hint`），把两个入口写清楚。
**不要**再把单选列表加回左栏：两处各一份单选，用户改了这边那边的圆点不亮，
就会被当成"没切过去"。

⚠ 弹层里的选择方式**不受搜索框过滤**。搜索框是给 Transform tools 那张表用
的（会被打字逐行过滤）；四行固定项跟着过滤会出现"打了 rot，选择方式整段消失"，
那不像过滤，像坏了。

## 七、"只对物体生效"（第二轮）

用户要求：天空 / 地面 / 云层 / 星空之外的才算物体。逐条落到代码上：

| 东西 | 它是什么 | 为什么选不中 |
|---|---|---|
| 天空 / 云层 / 星空 | `render::SkyParams` 驱动的**程序化绘制**，不是实体 | 没有实体就没有句柄，`each<TransformComponent>` 扫不到；点选打到那片像素时射线只命中远平面 |
| 地面 / 地形 | 实体，`LockedComponent` 标成编辑器参照物 | `isSelectableObject()` 直接返回 false |
| 纯逻辑节点 | 没有 `TransformComponent` | 没有屏幕位置，任何"按屏幕选"都无从判定 |

判据只有一份：`editor::isSelectableObject(world, entity)`（`SelectionModes.h`），
点选（走 `PickingSystem`）、框选、套索、刷选四条路径都过它。各写一份的症状是
"框选能选中地面，套索不能"——那种不一致极难归因。

⚠⚠ **模板里的 Ground 一度漏了 `locked`**。`EditorScene::resetToEmptyScene()`
建的空场景地面是加了的，但从 JSON 载入的模板没有 —— 于是框选一次就把整块
地面带进选择集（这正是这条需求报上来的现象）。已修：
`templates/{third_person,first_person,isometric}/.../main.json` 与
`assets/scenes/{anime_town,water_bowl}.json` 的 Ground/Terrain 都补了
`"locked": true`。

⚠ 这条修的是**数据**，不是代码：老工程（在自己目录里存过盘的）不会自动被改。
如果哪个旧工程的地面还能被框选中，在层级里给它点一下 🔒 即可。
