# Venn 引擎「二次元 3D 游戏」全方位差距审视（2026-10-26）

> 性质：**面向开发者视角的现状总览**。逐文件的证据级审计在
> `docs/anime_gap_audit.md`（2026-10-25，2509 行，每条带代码位置）；
> 本文把审计之后又落地的部分算进来，按"做一款二次元 3D 游戏需要什么"重新组织。
> 判断截至 2026-10-26 上午，基于全仓源码核对，不是凭印象。

---

## 0 · 一句话结论

**这台引擎已经从"通用写实引擎"走到了"二次元渲染的门槛上"：底座（GPU-driven、
bindless、TAA、后处理链、资产管线、验收体系）是超配的；10-25 一天落地的八刀
（Toon/排序/弹簧骨/LookAt/L0 状态机/描边/材质页/morph 全链/两骨 IK）把"零行 NPR"
的历史清掉了大半。但离"能做出一款二次元游戏"，还差三块：**

1. **脸**——二次元 90% 的观感在脸上，脸部专用着色体系（A1~A6 已落地 5/9）
   还剩表情与打磨；
2. **表演**——层/遮罩（B1）、事件（B2）已落地，"边走边做动作 + 踩点触发"
   通了；仍缺 Root Motion 提取、重定向、蒙太奇；
3. **内容生产**——没有过场时间轴、对话、存档、Prefab，能"演示"不能"做游戏"。

## 2 · 还欠缺的体系（按对二次元游戏的"致命度"排序）

### A. 脸与头发的专用着色 —— 二次元观感的核心，当前几乎全空

这是**最大的一块空白**。通用 PBR/Toon 参数调不出二次元脸，因为二次元脸的明暗
不是"光照算出来的"，是"约定好的"：

| # | 缺什么 | 现状 | 为什么非做不可 |
|---|---|---|---|
| A1 | **面部 SDF 阴影贴图** | ✅ **已落地**（2026-10-26）：`sdfShadowMap` + `sdfShadowStrength` + `sdfFaceShift`（材质页 `params.z` / `spare.y`） | 脸上的阴影必须是"规范的几何形状"（腮红影、鼻影、下巴影），法线算出来的是噪点。原神/崩铁全套都是 SDF face map |
| A2 | **面部法线平面化** | 0 | 把头部法线向鼻梁中线插值，脸才不会出现斑驳阴影。这是二次元脸比写实脸"干净"的根本原因，和 A1 二选一也要做 |
| A3 | **眼睛专用着色** | ✅ **已落地**（2026-10-26）：`eyeStrength` / `eyeIrisDepth` / `eyeCatchlight`（材质页 `spare2.xyz`，页表 96→112 B）；Unlit 底 + 虹膜视差 + 程序化眼神光 | MatCap 高光片、视差虹膜、眼神光；二次元眼睛基本是"Unlit 底 + 高光贴片"，不吃场景光照 |
| A4 | **头发各向异性高光** | ✅ **已落地**（2026-10-26）：Kajiya-Kay 双环，材质 `anisoStrength`/`anisoShift`（材质页 `spare.z/w`），切线走顶点 location 9 | Kajiya-Kay 沿发流的环形高光（angel ring）。原来的阈值高光是各向同性的，头发只会"一片亮" |
| A5 | **角色光解耦（Character Light 通道）** | ✅ **已落地**（2026-10-26）：`useCharacterLight`（材质）+ `FrameUBO.charLightDir/charLightColor`（800 B），5 个 `charlight.*` 参数 | 二次元角色必须"独立打光"：不受环境色污染、单独的补光/轮廓光强度。这是角色特写镜头能看的前提 |
| A6 | **Toon ramp 的美术可控性** | ✅ **已落地**（2026-10-26）：`.vramp` 资产（2/3/4 档预设）+ 6 个材质字段 + Inspector「Toon/NPR」段 + `--selftest ramp` 29 条 | ramp 贴图语义已进材质页（§12），但**没有 ramp 资产、没有编辑 UI、没有 3~4 档与交界宽度参数**——美术现在改不了明暗交界 |
| A7 | **描边的逐物体开关与遮罩** | 全局开关 | 内眼角、鼻翼处线要断；头发内侧不该有线。需要顶点色/材质参数遮罩 + 逐物体强度 |
| A8 | **NPR × 阴影贴图的 PCF 台阶**（已知问题，审计 P1-13） | 未修 | Toon 把明暗二值化后，CSM 的 PCF 台阶直接画在角色脸上（实测 ~8 px 锯齿）。需要 NPR 专用的阴影滤波或分辨率对齐 |
| A9 | **Posterize / 色调分离后处理** | 0 | 可选，但它是"整体赛璐璐感"的廉价杠杆 |

> **判据提示**：A1/A2/A5 三项做完，同一角色在"逆光/侧光/强环境光"下截图
> 应该保持"二次元脸"，现在这套是 PBR 逻辑，光线一歪脸就崩。

#### A1/A5/A6 落地记录（2026-10-26）

做了什么（每条都有像素级验收，见 `tools/verify_toon_shading.py` 第 ④⑤⑥ 组）：

- **A1**：按光照方向在脸的切平面（`right = up × N`、`faceUp = N × right`）
  上偏移 UV 去采 SDF 图，再用遮罩值把半兰伯特坐标 `u` **连续**推向 0
  （乘法，不用 min/max，否则会在脸上造出第二条硬边）。依赖"脸皮 UV 是
  正脸展开"这条**角色管线约定** —— 资产不满足时 SDF 会出现在任意位置。
- **A5**：主光换成固定的角色光方向、环境项换成常量色（**不吃** IBL/AO/SSAO
  —— 二次元角色不做环境光遮蔽，脸上一块灰是 bug），并跳过 CSM。
  两个闸门都要开（全局 `charLightDir.w` + 材质 `spare.x`），
  默认全关 → 0 px 差异。
- **A6**：色带的三个通道**就是**该档的乘子色（不再是"乘在程序化两档上的
  亮度乘子"）。`.vramp` 是 JSON（bands[pos,color] + edge + softness），
  烘成 256×1 `R8G8B8A8_SRGB`；改色带时旧纹理会挪进"退役区"多留几帧，
  并把所有引用它的材质的 `rampMap` 重新指过去。

三条只有做了才知道的：

1. ⚠⚠ **色带是"图像"，不是"颜色数组"——采样坐标会被 REPEAT 采样器回绕。**
   `rampMap` 走共享的 `textures[]`（那把采样器必须是 REPEAT，法线/贴花要
   平铺），于是 `u=0` 的纹理坐标是 **-0.5 纹素 → 回绕到 255.5**，线性过滤
   把首末两档各取一半，"最暗档"变成整条色带的平均色。
   缺省色带首末都接近白 → **逐像素完全看不出来**；只有"整片被钉到 u=0"
   （面部 SDF 全遮）时才暴露，而那时人会先怀疑 SDF。
   修法：把采样点夹到首末纹素中心（`0.5/textureSize(rampMap,0).x`，
   不写死宽度）。验收用一张**纯红→纯蓝**探针色带（`toon_probe_rb.vramp`）
   钉死：黑 SDF 必须回纯红 `B/R<0.2`（实测 0.000），白 SDF 是混合（0.963）。
2. ⚠ **"白 ramp = 恒等"这个前提在 A6 之后失效了**，`verify_material_page`
   的 `ramp_white_is_identity` 因此改为两条因果判据（变亮 / 变平）。
   "关 = 基线"的落点变成 `params.x = -1`（**没挂**色带时连采样都不做）。
   这条要写下来：语义一变，"哪条恒等律还成立"必须重新指认，否则下一个人
   会拿旧判据去改实现。
3. ⚠ **赛璐璐上"暗档 ≠ 更暗"**：Toon 的阴影是**有颜色的颜料**。用"亮度
   是否下降"当判据会得到相反结论（实测暗档中间调 199 比被 CSM 压过的受光面
   156 还亮）。判据要用**分布塌缩**（std）+ **方向性主色**（换一张探针色带）。

#### A4 落地记录（2026-10-26）

**做了什么**（验收 `tools/verify_hair_aniso.py`，5 组全 PASS）：

- 切线通道打通：`Vertex::tangent`（112 B 布局里早就有，§13 落盘后一直没人读）
  → `Mesh::attributeDescriptions()` 加 location 9 → `pbr.vert` 的 `inTangent`
  → 世界空间 `vTangent`（与法线同样过 skinMat/modelMat）→ `pbr.frag`。
  程序化球/立方体/平面都生成了切线（球的 = 纬线方向 `(-sinθ,-cosθ,0)`）。
- `hairAnisoSpec()`：`pow(sin(T,H), n) × 背向衰减`，主环 128 / 副环 40×0.2。
  `shiftTangent(T,N,s) = normalize(T + N*s)` 控制环的位置。
- 材质 `anisoStrength`（0 = 关）/ `anisoShift`（位置）→ 页表 `spare.z/w`
  → 序列化 → Inspector「Toon/NPR」段的 `Hair Aniso` / `Ring Shift` 两行。

**五条只有做了才知道的：**

1. ⚠⚠ **`shiftTangent` 不能"先投影再沿法线推"**。第一版写
   `normalize(T - N*dot(N,T)*shift)` —— 但 `anisoTangent()` 返回的 T **已经**
   在切平面里（`dot(N,T)==0`），推的量恒为 0，**shift 成了死参数**。
   症状极容易误判：三档 shift 渲出来的画面**逐像素完全相同**，看着像
   "UI 没接线"，实际是数学退化。正确写法是标准公式 `normalize(T + N*shift)`。
   → 验收为此专门写了一条判据："strength=0 时改 shift 必须 0 px 变化"
   （证明 strength 是**硬闸门**，不是"算了再乘 0"——后者会让 normalize 的
   NaN 从乘法里逃出来）。
2. ⚠⚠ **判据不能拿"最亮的那 2%"当高光**。Toon 的底色本来就有明暗两档和
   一条硬交界，"最亮 2%"量到的是**底色最亮处的形状**，与环无关；关掉各向
   异性时它照样存在，于是"关 vs 开"的差异被完全掩盖（实测 sx 5.8 vs 5.3）。
   要用 **diff 区域**（on − off）——那才是"这个特性画出来的东西"。
3. ⚠⚠ **取景错了，判据全废**。第一版沿用 `verify_toon_shading` 的侧光
   `LIGHT_DIR=(-0.85,-0.28,-0.22)`：环落在 `T·H=0` 的经线上，而侧光把那
   条经线推到了球的**右缘**（质心 x=184，采样区宽 188）—— 环被裁成 10×24 px
   的一角。判据要的是形状，所以**必须让环完整落在采样区里**：光待在 YZ 平面
   内（x 分量为 0）时 `T·H = -H_y·cosθ`，环正对相机、竖直贯穿球心。
   顺带把采样区从视口中心 42% 改成**整个视口**（环宽约占球宽 1/3，42% 那块
   把它切成方块，高/宽恒为 0.7）。
4. ⚠⚠ **测形状要关 CSM 和 TAA**（`MYVK_SHADOW=0` / `MYVK_TAA=0`）。
   各向异性高光乘 `shadow` 是对的（阴影里没有高光），但球在 CSM 下自带一条
   自遮挡边界，diff 里会混进"中间一条横线 + 球底一排竖条纹"（PCF 台阶），
   把环的包围盒撑到 238×204；TAA 的历史缓冲则让"跑两次 0 px"这条判据
   变成"TAA 收敛了"的同义词。
5. ⚠ **阈值要按"问的问题"分开**：A4 是"锐主环 + 宽而淡副环"的两层结构
   （二次元头发的通行画法）。副环亮度增量只有 ~+30，但铺满整个可见面 ——
   用 `diff>8` 量形状得到 343×378（高/宽 1.10，"竖直"永远测不出来），
   抬到 `diff>45` 只剩主环核心：**120×377，高/宽 3.14**。
   所以"有没有环"用 8、"什么形状"用 45。
6. **底色必须留余量**：albedo 0.45 + 太阳 0.72（受光面 sRGB≈155）。用
   `verify_toon_shading` 的 0.78×1.2 时受光面已经 249，各向异性高光加
   上去只差 6 格 < 阈值 8 —— 「加了一整条环」在像素上变成 0 变化。

#### A3 落地记录（2026-10-26）

**做了什么**（验收 `tools/verify_eye_shading.py`，5 组全 PASS）：

- 材质页 **96 B → 112 B**（第 7 块 `spare2`）：`x=eyeStrength`（Unlit 混合权重，
  0 = 硬关）/ `y=eyeIrisDepth` / `z=eyeCatchlight` / `w` 预留。
  `w` 之所以不塞 `spare`：那里四个角各有主人（角色光 / SDF 偏移 / 各向异性
  强度与位置），硬塞只会让下一次读端改动变成解谜。
- **Unlit 底**：整段**替换** `ambient + direct + localLights + emissive`，不是
  往里加项 —— 加法救不了"暗部眼睛被压黑"，压暗是乘出来的，只有替换能覆盖。
  留 `0.96 + 0.04·vsN.z` 的朝向差，否则圆眼珠会退化成一张纯色贴纸。
- **虹膜视差**：在**所有材质采样之前**偏移 `matUV`（虹膜/瞳孔/巩膜是同一张
  图上的三层，错开就会"瞳孔掉出虹膜"）。偏移量 = 视线在切平面的横向分量
  × `eyeIrisDepth`，不需要高度图（与 POM 的逐层测深是两件事）。
- **眼神光**：视图空间法线上两个高斯光斑（左上大 / 右下小），锁在**头的朝向**
  上而不是光源上 —— 与 MatCap 同理，但不用美术再出一张图。
- 接线：`Material.h` 三字段（位 24/25/26，`kOvScalarMask` → `0x7FFFFFF`）→
  `Bindless.cpp` 填 `spare2` → `pbr.frag` → 序列化（非 0 才写，老场景逐字节
  不变）→ Inspector 三行（放在**Toon 禁用区之外**：Unlit 替换与着色模型无关）
  → `FeatureRegistry`（`eye` / `verify_eye_shading`）。

**四条只有做了才知道的：**

1. ⚠⚠ **"眼睛不吃光"必须用对照材质自证**。判据是"翻太阳方向，眼睛 0 px" ——
   但这句话单独成立不了：整个场景对光不敏感时它照样是 0 px。所以同一场景
   再跑一个 `eyeStrength=0` 的对照（实测翻光后 **46576 px / 19.58%**）。
   有了这个数，"眼睛 0 px"才证明是**这条特性**干的。这是"新断言必须带对照区"
   在"响应度"这个维度上的版本（A4 的对照区是空间维度的）。
2. ⚠⚠ **相机 yaw 的符号约定是 `yaw = 180° − φ`，不是 φ**。第一版把两个侧向
   机位写反，结果**根本没拍到球**（画面全是天空：mean 174、零暗像素），
   "视差 0 px 变化"看起来像实现没接线 —— 实际是取景错，与 A4 那轮"环被推出
   画面"同一个坑。根因在 `Camera::angleDir()`：`forward = -angleDir()`，
   水平分量是 `(-cos yaw, +sin yaw)`。
   → 判据的诊断顺序应该是"先确认被测物在画面里"，再谈它动没动。
3. ⚠⚠ **"位移方向"这个判据在程序化棋盘上量不出来**，别硬凑。第一版判
   "两侧机位的暗区质心位移方向相反"，实测右 −14.8 px / 左 −3.9 px **同号**。
   不是实现错，是代理量不成立：①质心把"接缝移动"和"可见暗格面积变化"混成
   一个数；②棋盘是**周期**图案，位移一接近半格，变化像素数就**饱和**，位移
   量不再能从像素数反推。要判方向得用非周期的虹膜圆盘贴图 + 亚像素相位相关
   （= 需要美术资产）。**所以本组只判"会动"与"随深度单调"**，把这个限制
   写进脚本注释，免得下次有人以为是漏了一条。
4. ⚠ **眼神光的判据落点是"质心在中心线以上"+ "中位增亮 > +8"**，实测
   y=227 vs 中心行 266、中位增亮 **+96**。两条一起才能排除"随便点亮一片"
   —— 只判"变亮了"时，下半部亮一片也能过。

**六条只有做了才知道的（前三条是设计决定，后三条是踩坑）：**

1. ⚠⚠ **遮罩用「根骨 + 父链子树」，不用骨名单。** 名单换资产就静默失效
   （人形资产的骨名从 `mixamorig:LeftUpLeg` 到 `thigh.L` 什么都有），而且
   美术改不了 OBJ/glTF 里的骨名，却能在 Inspector 里写 `spine`。
   代价是子树必须**包含全部命中**：`hand` 会同时命中 `hand.L/hand.R`，
   所以不能用 `Skeleton::findJoint`（那是"精确优先、命中即返回"，只会进去
   一根）。匹配必须**不分大小写 + 子串 + 全收**。
2. ⚠⚠ **匹配 0 根 = 该层不生效**，绝不是"全部"。写反的后果不是"层没生效"，
   而是"配错一个名字 → 整具身体被覆盖"—— 后者在屏幕上看着像"层工作得很好"。
3. ⚠⚠ **层的顺序是硬约束**：底座采样 → **附加层** → `applyPerformance`
   （LookAt/IK/弹簧骨）→ `poseToJoints`。表演层必须吃**最终**姿势，
   否则"挥手时头发跟着底座的头动、手不动"这种一半对一半错的样子。
4. ⚠⚠ **三条端点语义，逐位而不是"差不多"**：`w<=0` → 逐位等于 base；
   `w>=1` → 逐位等于 layer（`slerp(q,layer,1)` **不是**恒等：它会把两个
   四元数归一化一遍，长跑慢慢转歪）；`out` 可以与 `base` 同址，**不能**与
   `layer` 同址。像素侧的证据：Mask=All + 权重 1 与"直接播那段"**0 px**。
5. ⚠⚠ **`dt == 0`（编辑器非 Play）时层必须视为"已淡完"**。否则刚配好一层、
   在视口里什么都看不到，与"层没生效"完全一样 —— 而编辑器里 90% 的时间
   就是非 Play 态。
6. ⚠ **权重 0 不清 `playingClip`**。清掉的话把滑块拉回来会重新触发淡入，
   用户的感受是"动作从第一帧重来"。

**四条只有做了才知道的：**

1. ⚠⚠ **区间必须是 `[prev, new)`（左闭右开），三种写法都不行**：
   - 闭区间 → 播放头**停在**事件上（dt=0 / 暂停）时每帧发一次；
   - `(prev, new]` → `t=0` 的事件**永远发不出来**（`0 > 0` 为假），而"开场
     音效"是最常见的需求；
   - 半开还顺带解决精度：**正好落在 `new` 上不丢，只是推到下一帧**（那一帧的
     prev 就是它）。步长整除事件时刻时闭区间会重复发。
   否定测试：改成 `(a,b]` → 11 条断言立刻红（`ev_first_frame_t0`、
   `ev_half_open_*`、`ev_t_at_duration_never_fires`、`ev_scene_seq` …）。
2. ⚠⚠ **`t == duration` 永远不会触发**（`wrapTime` 之后播放头到不了那里，
   半开区间又把右端排除）→ 想让它发就写 `0`。这条在面板上给了提示
   （`t >= clip duration: never fires`），否则症状只是"加了个事件但从来没响"。
3. ⚠⚠ **换 clip 时 `eventPrev` 必须归零**。真实来路是状态机：
   `AnimController::switchClip` 会把 `time` 归零或按相位换算成另一个值，而
   `eventPrev` 还停在旧片段的 0.5 s → `[0.5, 1.0)` 被当成"这一帧跨过的区间"
   → 新片段里 0.8 的事件**立刻发一次**。
   ⚠ 造这条否证必须**同时改 clipName 与 time**：只改 clipName 的话
   `time` 还是 0.5，`[0.5, 0.5166)` 本来就不含 0.8 —— 第一版这么写，把修复
   去掉之后照样全绿（假通过）。
4. ⚠ **事件日志里的 `t=` 必须是事件自身的时间，不是播放头时间**。这是
   "序列不随帧率变"能被逐条比对的原因：播放头在不同 dt 下落在不同位置，而
   事件时间是作者填的那个数。端到端脚本 ① 专门有一条守它。

**判据的口径**：只用 **kind + t** 的序列，**不用"个数"** —— 个数与"这段 clip

种整数只是**自检**里的夹具设计，端到端那边一律比序列。

**三个必须自己发现的坑**（每个都做了否定测试）：

1. ⚠⚠ **剥离不能"减这一帧的增量"，要"钳回基准"。**
   每帧 `samplePose` 是**重新采样**的，根骨本来就在"动画当前时刻的位置"。
   减掉本帧增量只让它**滞后一帧**，并没有回到原点 → 实体走 0.98 m、
   模型也走 0.96 m = **双倍位移**。否证实测：把 base 改成跟着走，
   `rm_in_place` 立刻报 `p1=0.0167 p60=0.9666`。
   这个 bug 最阴的地方是**每帧日志都对**，只有拿模型世界位置去比才看得见。

2. ⚠⚠ **跨圈那一帧的增量必须丢。** 走路循环接回首帧时根骨从"前方 1 m"
   瞬回原点，增量是 -1 m。不丢的话两圈跑完停在 0.983（一圈的量），
   表现为"每走一步被拉回原地"。否证：去掉 `wrapped` 判断 →
   `rm_wrap_discard` 报 `x=0.983333`（应 ≈ 1.97）。

3. ⚠⚠ **glTF 与 FBX 给出的骨架不在同一个坐标系。**
   `parseSkeleton` 用的是**文件原始空间**（Y-up，`invMeshNode` 里带着
   `rootXform`，两着相乘才约掉）；`FbxLoader` 用 `ufbx` 的
   `target_axes = right_handed_z_up` 在加载时就转成了 Z-up。
   平时渲染完全正常，但位移要写进 `TransformComponent`（引擎 Z-up）——
   不转的话 glTF 角色走路**朝天上飘**。否证：`toEngine` 换成单位阵 →
   `rm_yup_to_zup` 报 `z=0.0, y=1.0`。
   修法不是"在提取处写死一个旋转"，而是给 `Skeleton` 加
   `skeletonToEngine` 字段、**由各 loader 自己填**。

**另外两条设计取舍**：

- **yaw 用 swing-twist 分解，不用 `atan2(right.y, right.x)`**：世界矩阵的
  X 轴在某些骨上会指向近乎垂直的方向，`atan2` 会在那一瞬间跳 ±π
  （"走着走着突然转身 180° 又转回来"）。`rm_twist_swing_is_zero` 钉住
  "绕 X 转 90°（纯 swing）的扭转角必须是 0" —— 否则每跳一下都会连带转朝向。
- **`n`（真的走了几个实体）不能用逐位比较**：原地动画的 `dist` 在 1e-6
  量级抖动，于是 `n` 在 0/1 之间跳，日志出现
  `n=1 dist=0.0000 yaw=0.00deg` 这种自相矛盾的行。加 0.1 mm / 0.01° 的
  物理阈值。

**端到端（`tools/verify_root_motion.py`）** —— 只验**接线**，位移语义交给数值侧：

#### C1 落地记录（2026-10-26）

**做了什么**：`sequence/SequenceAsset.{h,cpp}`（`parseSequence` 解析 + `sampleCamera`
采样 + `collectEvents` 半开区间收集 —— 三个**纯函数**，喂字符串就能自检）+
`sequence/SequencerSystem.{h,cpp}`（播放器：推进 `t`、产出 `pose()`、按区间派发）
+ `ecs::SequencerComponent` + `SceneSerializer` 读写 + Inspector 第 12 个页签
`sequence` + `assets/sequences/opening.seq.json` + `tools/make_sequencer_demo.py`
（生成 `cutscene_demo.json`）+ 48 条数值断言 + 8 组端到端。

**五条必须自己发现的坑**：

1. ⚠⚠ **播放器不能持有 `CameraSystem*`。** 第一版把 `CameraSystem*` 当参数传进
   `tick`，运行时正常、**编辑器里完全不能用** —— 编辑器视口是自由相机，压根不
   经过 `CameraSystem`。改成"只产出 `pose()`，调用方决定怎么应用"：运行时
   `setDesiredPose`（这样爆炸震动能叠在运镜上）、编辑器直接写 `scene.camera()`。
2. ⚠⚠ **`yaw` 插值必须走最短弧。** 170° → −170° 是 +20°，不是 −340°。
   直接 `a + (b−a)·u` 会让镜头原地抡一大圈，而日志里"转了多少度"看不出来，
   **只有画面能暴露**。
3. ⚠⚠ **`Ease::Step` 是"选择"不是"插值"。** 段内任意时刻都保持**前帧**，
   真的到达下一帧才切。写成 `lerp(a, b, u > 0.5 ? 1 : 0)` 会在段中间就跳过去
   （位置错了，而且"看着也有硬切"—— 最难查的一类）。
4. ⚠⚠ **事件跨圈要扫两段** `[prev, dur)` + `[0, next)`。只用 `[prev, next)`
   在回绕时 `from > to` → **一条都不发**。症状：循环运镜里每圈少一个音效，
   且**只在跨越那一刻少**，看着像"偶尔丢帧"。
5. ⚠⚠ **播完必须丢掉 `pose()`**（`hasPose() == false`）。留着的话相机冻在结尾
   机位，玩家再也拿不回镜头 —— 症状是"过场结束后人物在动、画面不动"。

**顺带三条接线事实**（写进代码注释了）：

- `loop` 是"组件 || 资产"的**或**关系，不是覆盖。覆盖会让"作者在资产里写了
  循环、却因为组件默认 false 而关掉"；
- 每帧推进夹到 **0.10 s**（`kMaxStep`）：窗口拖动/断点恢复会有几百毫秒到几秒的
  间隔，直接乘进播放头会让 5 秒过场"一下跳过去"；
- **编辑态（`dt == 0`）应用姿态但不推进、不发事件**（拖滑条预览运镜）。
  这与 B3「`dt == 0` 不提取根运动」**正好相反**：那里的跳帧是噪声，
  这里的跳帧正是用户想看的东西。

**验收（两条互补，别只跑一条）**：

| 层 | 命令 | 结果 |
|---|---|---|
| 数值（48 条：解析 / 采样 / 短弧 / step / 半开 / 跨圈 / 首帧 / 夹步长 / 循环 / 编辑态 / 优先级） | `Game.exe --selftest sequence` | `SEQ-TOTAL pass=48 fail=0` |
| 端到端（8 组：加载 / 资产 / 事件顺序 / 首帧机位 / 硬切倍率 / 走到底 / UI 四件套 / 存档往返） | `python tools/verify_sequencer.py` | 8/8 PASS |

⚠ 端到端 ⑤ 的判据是**倍率**（`max_jump / max_other ≥ 4`），不是绝对米数 ——
单帧位移 = 速度 × dt，dt 在真实运行时浮动（实测平滑段 0.32 m/帧、硬切 2.10 m/帧）。
第一版写的"< 0.15 m"会稳定误报。
⚠ 端到端 **验不了"播完撒手"**：`CAM-POSE` 只在姿态**变化**时打印，"停住" =
没有日志行。那条归数值侧的 `tick_finished_no_pose`。

**使用者文档**：`docs/cutscene_sequencer.md`（点哪里 / 资产怎么写 / 出错查哪条日志 /
现在还做不到什么）。

### E. 工程健康 —— 不挡路，但拖慢一切（审计 P3，全部未动）

按"对当前改造的影响"挑关键的说：

1. **`Renderer` 6812 行/212 成员、`EditorApp` 7733 行**——每加一个 NPR 参数都在
   两个上帝类里同时动刀，改动成本持续指数上涨；
2. **崩溃即丢档**：异常路径不调 `onShutdown()`，未保存场景全丢（10-23 就真实
   发生过一次——为重链接杀了正在运行的编辑器）；
3. **无 device-lost 恢复**（0 处处理 `VK_ERROR_DEVICE_LOST`）；
4. **Play = 整场景 JSON 往返**：新增组件忘写序列化分支会**静默消失**，无守卫；
5. **两套 FBX 管线行为不一致**（运行时权重截断 vs 离线归一化）——同一资产两条
   路两种结果，换装/表情这类"逐顶点敏感"的功能会被它咬；
6. **资产永不淘汰**（4 张表只增不减）——长时间编辑显存单调涨；
7. **零单元测试**：130 个验收全是 GUI 端到端（30 分钟+），重构安全网太重；
8. **打包/发布链缺失**：没有"出包"概念（资源打包、版本清单、热更新位）——
   商业化管线最后 1 公里。

### F. 平台与部署（远期）

- 仅 Windows/D3D 式假设（Vulkan 已抽象，但无 macOS/移动端验证）；
- 二次元手游常见目标（iOS/Android）需要：ES 级特性回退、触控输入体系、
  资源分级（现在已有 quality preset 的雏形）；
- 无崩溃收集/遥测。
