# 可上手性诊断（2026-11-03）—— 功能都在，为什么用不起来

> 本文只回答一个问题：**这台引擎的可上手性 / 可操作性为什么低，症结在哪。**
>
> 与既有文档的分工（别混着读）：
>
> | 文档 | 视角 | 回答什么 |
> |---|---|---|
> | `developer_workflow_gaps.md`（10-27） | **流程** | 八段流水线哪一段断 |
> | `panel_gap_review_2026-11-02.md` | **面板** | 哪个面板缺、哪个链路不成立 |
> | **本文（11-03）** | **认知** | 人怎么知道该按哪个按钮、按了之后怎么知道对不对 |
>
> 前两份问"有没有"，本文问"**有了，人用得起来吗**"。这三件事的修法完全不同：
> 缺功能要写代码，缺入口要加面板，而**认知断裂要改组织方式** —— 加更多面板只会更糟。
>
> 所有数字都是 2026-11-03 在本机源码上量的，不是估算。

---

## 0 · 一句话结论

**这台引擎最顺手的接口不是界面，是环境变量。**

把四个"人机接口"按**能力完整度**排（都能驱动引擎，都能改任何东西）：

| 接口 | 数量 | 谁在用 | 上手成本 |
|---|---|---|---|
| **环境变量** | **374** 个（`MYVK_*`） | 205 个验收脚本 | 读源码才知道有 |
| **控制台命令** | **137** 条 | 作者 + 验收脚本 | 得先知道命令名 |
| **命令面板**（Ctrl+Shift+P） | 从上面两者**派生** | 作者 | 得先知道**搜什么词** |
| **GUI 控件** | **47** 个面板，默认开 **3** 个 | 人 | 得先知道**去哪个面板** |

而"人"能用的顺序恰好是**反的**：人类最短的那一端（GUI）能力最弱、可见性最低。

> 所以准确的说法不是"这台引擎功能少"，而是：
> **它的第一用户是它自己的验收脚本，人是第二用户。**
> 20.3 万行验收代码 / 49.5 万行引擎代码 = **41%** —— 这个比例就是证据。

## 2 · 六个症结（从表层到根因）

### 症结 1 · 坐标系不对：一切按"实现批次"组织，不按"开发者的任务"组织

这是最根本的一条，其余五条都是它的表现。

**面板的分组是 `General / Authoring / Debug`** —— 这三个词描述的是**代码归属**（通用/作者向/调试向），
不是**任务**。结果是 47 个面板里 **35 个挤在 `Authoring` 一个组**，
`View ▸ Panel` 下拉是一个 35 项的平铺长菜单。

**文档按批次组织**：`A1/A3/A4/A5/A6`（着色）、`B1/B2/B3`（动画）、`C1/C2`（过场/对话）、
`G16/G17`（存档）、`E28/G29`（出包）、`J5`（关节）…… 这些编号对**写它的人**是索引，
对**读它的人**是噪声 —— 因为新人脑子里没有"J5"这个抽屉。

而真正的任务坐标（"我想让角色走路""我想加一句台词""我想让门打开"）在文档里**一张索引都没有**。

**证据**：

| 检查 | 结果 |
|---|---|
| `ls docs/ \| grep -i "start\|tutorial\|quick\|manual\|faq\|index"` | **0 份**（只有 `character_animation_guide.md` 一份"指南"） |
| 编辑器内有没有"首次运行引导" | `grep onboard\|FirstRun\|Welcome` → **0 命中** |
| `Help` 菜单里有什么 | 一屏**不可点**的快捷键文本（`MenuItem(..., false, false)`）+ 一行 `API docs: docs/editor_architecture.md` |

> **不是文档不够多**（195 万字符 ≈ 三本长篇），**是文档的坐标系不是使用者的坐标系**。
> 新人需要的是一条 15 分钟的路，不是 31,688 行可查的百科。

---

### 症结 2 · 入口密度与默认可见性严重错配：47 : 3

打开编辑器，默认看见 **3 个面板**（Hierarchy / Inspector / Viewport）。
另外 **44 个**在：
- 10 个有 `Alt+N` 快捷键（只到 `Alt+9` + `Alt+0`，**满了**，第 11 个再也塞不进去）；
- 37 个**没有快捷键**，只能从 `View ▸ Panel` 或 `Window ▸ Panels` 里用**名字**找。

而那 37 个的名字是：`PCG` / `NLA` / `Dope sheet` / `Bone curves` / `Fracture` / `Brush Editing` /
`Mesh Paint` / `GPU Timeline` / `Cinematography` / `State machine` / `Character Studio`……

**这套词汇是行业黑话，不是任务描述。** 一个想"让角色跑起来"的人，需要先在脑子里完成
"跑起来 → Animator → State machine → 但我的 clip 在 Model 里 → 得先去 Character Studio 绑骨架"
这条翻译链，才能知道要开哪三个面板。**引擎没有替他做这条翻译。**

命令面板（Ctrl+Shift+P）本来是最优解，它确实搜得到全部 47 个面板 + 137 条命令。
但它有一个前提：**你得知道要搜什么词**。搜"动画"会出来 12 条（Animation / Animator 相关 /
Dope sheet / Bone curves / NLA / State machine / Curve editor…），**没有一条告诉你该点哪个**。

> **可发现性的真度量不是"能不能搜到"，而是"知不知道该搜什么"。**

---

### 症结 3 · 同一件事有五条路，没有一条被标为"正道"

同一个意图，引擎里往往有三到五种实现，**语义各不相同，但界面上没有任何一处告诉你该走哪条**：

| 意图 | 几条路 |
|---|---|
| **导入一个角色** | ① Content 拖进视口 ② `MYVK_EDITOR_IMPORT=路径` ③ `tools/blender_import_*.py` 离线烘焙 ④ `Character` 面板 ⑤ `Character Studio` 面板 |
| **让角色播一段动画** | ① `Animator` 组件 ② `State machine` 面板（AnimatorGraph） ③ `Dope sheet` / `NLA` ④ `anim.clip` 控制台命令 ⑤ 脚本动词 |
| **跑起来看看** | ① **Play**（整场景 JSON → 副本） ② **Run** ③ **Anim play**（直接在编辑场景上跑，Stop 用快照恢复） ④ `Game.exe --scene` ⑤ `--package` 出包后跑 |

"跑起来"那三条尤其伤人 —— **同一个词 `Play` 在引擎里有三个语义**：

- `EditorContext::play()` —— `sceneToJson` 整份快照 → `sceneFromJson` 进 `m_runtimeScene`（副本）；
- `EditorContext::animPlay()` —— **就在编辑场景上跑**，Stop 时用 JSON 快照回滚；
- 工具栏上的「Play」按钮 —— 用户以为只有一个。

后果非常具体：**新人在 Anim 里改了东西，按 Stop 以为自己"没保存"，其实是设计如此；
而在 Play 里改的东西按 Stop 会消失，他会以为"引擎把我的编辑吃了"。**

> 多条路对专家是自由，**对新人是一道必须做、却没有判据的选择题**。

---

### 症结 4 · 参数即接口：界面是"寄存器面板"，不是"编辑器"

46 个渲染特性、上百个参数，全部以**参数 id** 的形式暴露：`ssao.radius`、`csm.splitLambda`、
`ramp.u`、`matcap.strength`、`aniso.shift`…… Inspecter 的 `All` 页签把它们堆在一列。

引擎对可读性做过努力：**351 处 tooltip**（对 1123 个可交互控件，覆盖率 ~31%）。
但 tooltip 解释的是「**这个数是什么**」，不是「**什么时候该动它、动了会怎样**」。

最典型的一处是二次元材质的 10+ 个旋钮（ramp / matcap / SDF / detail / aniso / eye）。
文档里明明白白写着"**"暗档 ≠ 更暗"**""**色带 `u=0` 会被 REPEAT 回绕 → 夹首末纹素**" ——
这些是**必须知道否则一定做错**的知识，它们活在 3 万行文档的角落里，
而旋钮旁边只写着 `Ramp U`。

同一个旋钮还常常同时存在于四个平面：**Inspector 控件 / `set` 命令 / `MYVK_*` 环境变量 / `FeatureRegistry` 参数**。
四者优先级没有任何一处写清楚（而这恰恰会咬人：`MYVK_BINDLESS` 默认关 → A 类材质槽**静默全失效**）。

> **界面把"引擎的内部状态"直接暴露成 UI，中间缺一层"意图"。**

---

### 症结 5 · 反馈回路太长，而且失败是无声的

**Play 的代价是整场景 JSON 往返。** `play()` 里 `sceneToJson(m_editorScene)` → `sceneFromJson(m_runtimeScene)`：

- 实体越多，按一次 Play 越慢（越不像"按一下");
- **没写序列化分支的组件在 Play 里会静默消失** —— 这不是理论风险，是这个仓库反复复发的 bug 类型
  （`nav` 组件第一次就是"Play 里代理一动不动"，查到最后是 `hasNonMeshContent` 少了两处）；
- 你改的东西如果忘了序列化，**Play 里看不到效果**，而日志一片正常 —— 于是你开始怀疑自己。

**Undo 的覆盖是漏的。** Inspector 里有 **207 个拖拽类控件**，只有 **28 处**显式处理了
`IsItemDeactivatedAfterEdit`（= 松手即入栈）。其余靠外层 `structuralEdit` 兜，
而 `structuralEdit` 是**整场景 JSON 前后快照** —— 大场景每拖一下滑条存两份全量 JSON。

加上**没有对齐/分布工具**（`alignSelection` / `distribute` 全仓 0 命中，E22 残留：
多选了 20 个箱子也没法让它们排整齐）。

> 用户体验里最贵的不是慢，是**不确定性**：改一下 → 等一次往返 → 看不出来 →
> **不知道是"没生效"还是"生效了但我没看见"还是"被 Undo 吃了"**。

---

### 症结 6 · 示例被夹具埋了：62 个场景文件里 51 个是测试垃圾

这是最不该出现、但**修复最便宜**的一条。

```
build/bin/assets/scenes/    62 个文件
  ├─ 51 个 "_" 前缀的验收夹具（_am_bus.json / _dlg_voice_fixture.json / _clip_fixture_off.json …）
  ├─ 27 个 ".trash-201620" 之类的残留
  └─ 11 个真场景（anime_demo / anime_town / cutscene_demo / sandbox / water_bowl …）
```

仓库里的 `assets/scenes/` 也有 **12 个里 5 个**是夹具。

新人打开 Content Browser → Scenes，看到的是一个**测试目录**。
而"读一个能跑的工程"是学引擎最有效的路径 —— 比读 3 万行文档有效十倍。
**这条路径现在被 CI 的中间产物堵死了。**

## 3 · 根因：为什么会长成这样（不是能力问题）

三条机制性原因，都**不是错误决策**，是**目标函数的遗留**：

**① 验收驱动开发。** 每个特性的验收方式都是"跑脚本 → 断言日志锚点"。
于是"**能被脚本驱动**"成了设计目标，"能被鼠标点到"是顺带。
374 个环境变量、137 条命令、`GP-*` / `NAV-*` / `DLG-*` 日志锚点，全是这条路径的产物。
**这套体系极强** —— 它让一个人在半年里做出了别人一个团队的工程量 ——
但它长出来的接口形状，是"机器可断言"，不是"人可理解"。

**② 一人项目的时间预算。** 加一条命令 8 分钟，加一个环境变量 8 秒，做一个面板 8 小时。
在只有作者一个用户时，"命令优先"是**完全正确**的选择。
问题只在**用户变了**（从"作者"变成"开发者"）之后，这个选择没有被重新做一遍。

**③ 文档是写给"下一个自己"的。** 所以全是变更记录 + 踩坑清单 + 判据口径。
这种文档对**继任者**是无价之宝（它保住了 4111 条断言的意图），
对**新人**是一堵墙 —— 因为它的每一段都假设读者知道上一段。

> **一句话：症结不在渲染、不在架构、不在功能数量，
> 在于"谁被当成用户"这件事从来没有被重新定义。**

## 4 · 修的顺序（按"解开多少下游"排，不按难度）

前三条是**坐标系补丁**（改组织方式，几乎不写引擎代码），后三条是**机制补丁**。

| 序 | 做什么 | 成本 | 解开 | 属于 |
|---|---|---|---|---|
| **1** | **《15 分钟：让一个角色走起来》** —— 一份任务向导 + 配套示例工程（开箱能跑，反例：现在 4 套模板都不是"角色走在场景里"） | 1~2 天 | 症结 1、2、3 | 文档 + 模板 |
| **2** | **首次运行向导**（Welcome 窗口 4 张卡：导入角色 / 摆场景 / 挂玩法 / 出包），点卡片直接落到**对应面板 + 对应文档页** | 1 天 | 症结 1、2 | GUI |
| **3** | **面板目录改按任务分组**（`General/Authoring/Debug` → `摆放/角色动画/演出/UI/渲染/音频/构建`），并把 37 个无快捷键面板纳入 Ctrl+Shift+P 的**同义词**（"动画"能命中 State machine） | 1 天 | 症结 2 | GUI + i18n |
| **4** | **夹具与示例分居**：`Content Browser` 默认隐藏 `_*` 与 `*.trash-*`（`assets/` 里同理），并加一个"显示测试资产"开关 | 半天 | 症结 6 | GUI |
| **5** | **给"三条 Play"改名并标注**：`Anim play` → `预览动画（不进游戏）`、`Play` → `运行（副本，Stop 丢弃改动）`、`Run` → `运行打包版本` | 半天 | 症结 3、5 | i18n |
| **6** | **失败要出声**：序列化漏组件时 `sceneFromJson` 报 `SCENE-LOST component=<name> entity=<id>` 并在 Play 时弹一条通知（现在静默） | 1 天 | 症结 5 | 引擎 |
| **7** | **撤销补齐**：Inspector 207 个拖拽控件补 `IsItemDeactivatedAfterEdit`（28 → 207） | 2~3 天 | 症结 5 | GUI |
| **8** | **对齐 / 分布**（E22 残留） | 2 天 | 可操作性 | GUI |

**不建议现在做的**（写在这里是为了不反复讨论）：

- **不要再加面板**。48 个找不到入口的面板比 47 个更糟。
- **不要做可视化脚本 / 行为树**。在坐标系修好之前，它只是第 48 个找不到入口的面板。
- **不要重写 UI 框架**。`ui2` + ImGui 没问题，问题在**分组与命名**，不在框架。
- **不要给每个参数补文档**。351 条 tooltip 已经证明"逐条解释"的边际收益很低；
  应该给**每一组**参数写一句"什么时候动它"。

## 5 · 判据：怎么知道修好了

不看"文档写了多少"，看**三条可量的**：

1. **新人从双击 exe 到"角色在我自己的场景里走起来" ≤ 15 分钟，且全程不吃任何环境变量。**
   （现在：不可能，没有这条路。）
2. **Content Browser 打开 Scenes，看到的第一屏全是示例，没有一个 `_` 或 `.trash-`。**
3. **从任意面板能一跳跳到它那一节文档**（Help 菜单现在是死文本，改成可点 → 文档锚点）。
   验收口径：`verify_usability.py` 断言 47 个面板各自有 `doc=` 链接且文件存在。

> 试金石：让一个没用过这台引擎的人（或你自己隔一个月）做一件具体的事，
> **只允许鼠标**，不许开控制台、不许设环境变量、不许 grep 源码。
> 卡住的第一个地方，就是下一条要修的。

## 7 · 收尾

这台引擎现在的状态，准确说是：

> **一个"作者向"的顶级研发平台，还没有变成"开发者向"的工具。**
> 差别不在能力 —— 在**入口的组织方式**。

好消息是：**要修的东西几乎都不在底层**。
上面 8 条里只有 2 条（#6 序列化报警、#7 撤销补齐）动引擎，其余 6 条动的是
**文档结构 / 菜单分组 / 命名 / 目录过滤** —— 没有一条碰渲染管线、没有一条碰 ECS。

而且这 6 条恰好是**收益最高、风险最低**的那一半。
