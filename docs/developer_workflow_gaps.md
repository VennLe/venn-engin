# 开发者工作流差距分析 —— 一个普通开发者现在能走到哪一步

> **判定口径**：本文不看"引擎有多少特性"，只看**开发者在做某个具体动作时，
> 面板上有没有那个按钮 / 那个控件 / 那条链路**。
>
> 与既有文档的分工：
> - `anime_gap_review_2026-10-26.md` = **能力视角**（渲染/动画/内容体系缺什么）
> - `editor_roadmap.md` = **任务视角**（E01~E29 逐条状态）
> - **本文 = 流程视角**（照着"做一个二次元 3D 游戏"的真实顺序走一遍，在哪一步卡住）
>
> 核对基准：2026-10-27 全仓源码 + 实跑。所有数字都来自代码，不是估算。

---

## 0 · 一句话结论

**这台引擎的"看"是专业级的，"做"是空白的。**

渲染（GPU-driven / Toon / 描边 / 面部 SDF / 眼睛 / 头发各向异性 / 角色光）、
动画（状态机 / 层遮罩 / 事件 / Root Motion / IK / 弹簧骨 / morph）这些
**最难做的部分已经做完了**，而且是带 130+ 验收脚本那种做完。

但是一个普通开发者打开它，会卡在一条很具体的分界线上：

> **凡是"在视口里摆东西、调参数"的事，都能做；
> 凡是"把东西串成游戏"的事，都要写 C++ 或手改 JSON。**

分界线在三处最硬：

| # | 断点 | 硬证据 |
|---|---|---|
| 1 | **脚本够不着演出系统** | `.vks` 内建表 **60 个函数，零个** `playSequence` / `showDialogue` / `playAnim` / `loadScene` |
| 2 | **UI 只能改 6 个数字** | `runtime/ui/UiConfig.h` 全部可配项：血条宽/高/边距、准星开关/长度/间隙。对话框、菜单、卡池要写 C++ |
| 3 | **出了工程就出不了包** | `File ▸ Package` 不存在（E28 未开始），没有资源裁剪、没有 Shipping 档、没有版本清单 |

## 1 · 八段流水线：逐段看能走到哪

先给总览。**绿 = 面板上能做**，**黄 = 能做但要手改文件/命令行**，**红 = 面板上根本没有入口**。

| # | 环节 | 状态 | 一句话 |
|---|---|---|---|
| 1 | 进工程（建项目/选模板） | 🟢 通 | Launcher 有向导，2 套模板 |
| 2 | 导资产（模型/贴图/音频） | 🟡 半通 | 能导入，但没有"导入向导"；角色要走命令行或专用窗口 |
| 3 | 搭场景（摆/父子/变换） | 🟢 通 | 23 面板 + 12 页签 Inspector，地形/植被/水体笔刷都有 |
| 4 | 装玩法（组件/脚本） | 🟡 半通 | 39 个组件里 10 个能从面板加；脚本能改属性不能导演出 |
| 5 | 做演出（过场/对话/动画） | 🔴 断 | 运行时全通了，**编辑器里够不着** |
| 6 | 做 UI（HUD/菜单/对话界面） | 🔴 断 | 无 UI 编辑器，6 个可配参数 |
| 7 | 存进度（存档/配表/旗标） | 🔴 断 | 全无 |
| 8 | 出包（打包/裁剪/发布） | 🔴 断 | 全无 |

下面逐段展开，每段给"✅ 能做什么 / ⚠️ 别扭在哪 / ❌ 做不了什么"。

---

### 1 · 进工程 🟢

**✅ 有**：`Launcher.exe` 独立启动器（M0~M6 全部完成），新建向导三步
（模板 → 目录 → 确认），`venn.project.json` 单源配置，最近列表。

**⚠️ 别扭**：

- **模板只有 FPS / TPS 两套**（`templates/first_person`、`templates/third_person`）。
  这两套是"能通关的小游戏"（收 5 个球进传送门），写得很好 —— 但它们示范的是
  **通用动作游戏**的写法，与"二次元 3D"这个定位毫无关系。
  一个想做剧情向二次元游戏的开发者，建完工程看到的是"胶囊体 + 5 个球"。
- **第三人称模板"看不到角色"**（`launcher_roadmap.md` §4.1 已明确记录）：
  程序化小人已删，模型要走角色详情窗口绑定。**这是新用户的第一印象**。

**❌ 没有**：

- **没有"二次元模板"**。以这个引擎的定位，至少该有一套
  「剧情向样板」：一个场景 + 一个角色 + 一段过场 + 一段对话 + 一个对话框 UI +
  一个存档点。现在这些东西**分散在 4 个演示场景里**（`anime_demo.json`、
  `cutscene_demo.json`、`ch01_open_01.dlg.json`…），没有一个把它们串成一个"游戏"。
- **没有示例工程市场/样例集**：学引擎只能读 `docs/` 的 30 份文档。

---

### 2 · 导资产 🟡

**✅ 有**：Content Browser 的 `Import...`（系统文件对话框，多选），支持
`png/jpg/jpeg/bmp/tga/gltf/glb/obj/fbx/wav/mp3/ogg/json/vks`；
从 Content 拖进视口即实例化；`Show in Explorer` / `Show References` / `Duplicate` / `Rename`。

**⚠️ 别扭**：

- **导入是"复制文件"，不是"导入资产"**。`ContentBrowser::importFiles()` 只做
  `m_importRequest = true` + 拷文件；轴朝向、单位、缩放、动画段选择、
  材质映射**一个参数都没有**。
- **角色/模型这条链要靠专门窗口或命令行**：
  - `editor/CharacterWindow` —— 骨架绑定、Animator、相机装配都在这里，
    是一个"角色详情"窗口，不是"导入向导"。
  - `MYVK_EDITOR_IMPORT=路径` —— 环境变量导入（等价于拖拽）。
  - 离线烘焙：`tools/blender_import_*.py`、`fbx→.vmesh` 转换。
  → **同一件事有三条路，面板上没有指明该走哪条。**
- **两条 FBX 管线行为不一致**（`anime_gap_review` §2.E.5）：运行时权重截断 vs
  离线归一化。普通开发者不会知道自己的模型走了哪条。

**❌ 没有**：

- **导入向导**：选骨架 → 选根骨 → 选动画段 → 预览 → 生成 `.vmat`/`.vmesh`。
  这是 UE/Unity 里最标准的一屏，这里没有。
- **缩略图/预览播放**：有 `ThumbnailCache`（静态图），没有"点一下预览模型转一圈"。
- **资产类型过滤视图**（只看模型/只看材质/只看音频）。

---

### 3 · 搭场景 🟢

这一段是全引擎**最成熟**的部分，不要重做。

**✅ 有**：

- **23 个面板**（`EditorApp::buildPanelTable()` 逐条可数）：
  Hierarchy / Inspector / Content / Viewport / Stats / Scripts / Engine / Console /
  GPU Timeline / Character / Physics / Particles / Quality / Landscape / Foliage /
  Mesh Paint / Modeling / Fracture / Brush Editing / Animation / PCG / Water / Material library
- **Hierarchy**：New Cube/Sphere/Point Light/Empty/Folder、Rename、Duplicate、
  Delete、Focus(F)、Unparent、父子拖拽
- **Viewport**：Gizmo（移动/旋转/缩放 + 世界/局部）、网格、多视口（部分）、
  拾取、拖放、Blender 式视图方向键
- **Inspector 12 页签**：object / tool / render / output / scene / world /
  particles / physics / material / animation / sequence / all
- **专业笔刷**：地形（笔刷 + 光标）、植被、水体、Mesh Paint、Fracture、PCG

**⚠️ 别扭**：

- **单选**：`EditorContext::selection()` 返回**一个** `ecs::Entity`。
  没有多选，就没有"批量移动 20 个箱子""批量改 20 个灯的强度"。
  关卡搭建的效率直接差一个数量级。
- **Undo 是整场景 JSON 快照**（`EditorContext::structuralEdit`：`snapshot()` →
  `fn()` → `snapshot()` → 入栈）。后果两条：
  - 大场景每一步撤销都存一份**完整**场景 JSON（内存 + 耗时随实体数线性涨）；
  - 属性面板里拖滑条**默认不进历史**（只有显式包了 `structuralEdit` 的
    79 处才进），于是"我改坏了想撤回"经常撤不回来。
- **没有 Prefab**（全仓 `prefab` **0 命中**）。摆 100 个木箱只能
  `Duplicate` 100 次；改一处**不能**全更新。二次元游戏的教室/走廊/街道
  全是重复件，这一条直接决定关卡能不能做。

**❌ 没有**：

- **Prefab / 嵌套预制 / 实例覆盖**（`ship_roadmap` G18 已登记，未做）
- **场景流送 / 关卡切换面板**（G19）
- **多选 + 批量编辑 + 对齐/分布工具**
- **资产依赖图**（改一张贴图会影响哪些场景）

### 4 · 装玩法 🟡

**✅ 有**：

- `Add Component` 菜单 **10 项**：Point Light / Spot Light / Script / Animator /
  Cutscene Sequence / Decal / Reflection Probe / Particle Emitter / Audio Source / Audio Listener
- 脚本引擎 `.vks`：协程 + 热重载 + 参数区/状态区 + `on start`/`on update`
- 输入映射（Action/Axis/上下文栈）、角色控制器（胶囊 Sweep/台阶/坡度）、
  物理（碰撞/刚体/触发器/物理材质）、相机（SpringArm/混合栈/震动）

**⚠️ 别扭**：

- **39 个 ECS 组件，面板上能加的只有 10 个**。其余要么藏在专用窗口
  （Collision/RigidBody 在 Physics 面板、SpringBone/LookAt/IK 在
  CharacterWindow、AnimKeyMap 在 Animation 编辑模式），要么**完全没有入口**。
  开发者要"给这个物体加个碰撞体"，得先知道"去 Physics 面板"这件事 ——
  面板之间没有交叉引用。
- **脚本能改状态，不能导演出**。`kBuiltins[]` 全部 60 项逐条看：
  - 数学 17 项、集合/查询 8 项、变换 8 项、世界访问 10 项、输入 4 项、
    协程 3 项、音频 3 项、视觉/光照 6 项
  - **零项**：`playSequence` / `showDialogue` / `playAnim` / `crossFade` /
    `loadScene` / `spawn` / `openUI`
  → 一段剧情脚本只能 `print` 和 `wait`，**没法"播过场、弹对话、切动画"**。
    这是"能不能做游戏"和"能不能做演示"的分界线。
- **Play 模式 = 整场景 JSON 往返**：每次进 Play 都是
  序列化 → 反序列化。新增组件忘了写序列化分支会**静默消失**；
  改一行脚本想验证，要等一次完整往返。

**❌ 没有**：

- **导演 API**（C6）：上面那 7 个函数
- **代码调试**：无断点 / 无单步 / 无变量监视。只有 `print` 进 Console 面板
- **可视化脚本 / 行为树 / 状态图**：纯文本 `.vks`
- **组件交叉引用**（从 Inspector 跳到"这个组件归哪个面板管"）

### 5 · 做演出 🔴 ← **二次元引擎的核心，这里是断的**

这一段最能说明"能力有了、流程没有"。

**✅ 运行时全通**（都是这两天刚落地的，质量很高）：

- **C1 过场时间轴**：`SequenceAsset`（相机关键帧 + 事件，能读能写）+
  `SequencerSystem` + `SequencerComponent` + Inspector `sequence` 页签 +
  **时间轴轨道编辑器**（#311）+ 67 条断言 + 8 组端到端 + 6 组编辑器端到端
- **C2 对话**：`DialogueAsset`（id 寻址 + 加载时校验）+ `DialogueRunner` +
  `DialoguePlayer` + `DialogueSystem` + `DialogueComponent` +
  `SubtitleBox`（SDF 字体、打字机、选项、几何按 1920 等比缩放）+ 97 条断言 + 11 组端到端
- **动画表演**：层/遮罩、事件、Root Motion、IK、弹簧骨、LookAt、morph

**❌ 但编辑器里够不着 —— 三条各自独立的硬缺口：**

| 缺口 | 证据 | 后果 |
|---|---|---|
| ~~**`DialogueComponent` 零面板入口**~~ | ✅ **2026-10-26 已补**（`INS-DLG-*` 锚点 + Add Component 菜单） | 曾经：引擎能播对话，但**开发者没法给一个物体挂对话组件**。现在 Tool 页签第 13 页就是它 |
| ~~**对话剧本没有编辑器**~~ | ✅ **2026-10-27 已补**（`editor/DialogueEditorWindow`，见 `dialogue.md` §10） | 曾经：写剧情 = 手写 JSON（节点 id、`goto`、`choices`）。现在窗口里有节点列表 / 逐句编辑 / 选项表 / 实时校验 / 存盘 |
| ~~**时间轴没有轨道编辑器**~~ | ✅ **2026-10-27 已补**（`editor/TimelineEditorWindow`，见 `cutscene_sequencer.md` §9） | 曾经：`sequence` 页签只有 4 个锚点（`INS-SEQ-HEADER/PATH/TIME/PREVIEW`），填表 + 拖滑条预览，**没有轨道、没有关键帧点、不能拖时间**。现在两条轨道（相机 / 事件）、菱形关键帧可拖、播放头可 scrub、`step` 段画虚线 |

**再往下的内容层缺口**：

- **没有立绘系统**：二次元 AVG 的骨架是"背景 + 立绘（左右位置/淡入淡出/表情切换）
  + 名字条 + 逐字文本 + 选项"。现在只有最后两项（`SubtitleBox`）。
  立绘要当"带贴图的 UI 元素"用，但 UI 层没有编辑器（见第 6 段）。
- **没有表情预设**（B6）：morph 数据链通了 GPU，但没有"一个表情 = 一组
  target 权重"的资产，没有组合权重 UI，没有眨眼/口型驱动。
- **没有语音这一层**（D1）：一次性声部没有"播完了"回调 →
  "语音播完再进下一句"做不到。`AudioSourceComponent` 在，但对话和它没接。
- **没有剧情旗标 / 任务系统**（C7）：对话选项改变不了任何持久状态。

> **一句话**：现在的引擎能**演**给我看（`cutscene_demo` + `ch01_open_01` 跑得很好），
> 但一个开发者想**改一句台词**，得先用文本编辑器打开 JSON，再用 grep 找
> 哪个实体该挂组件，然后手改场景文件。

### 6 · 做 UI 🔴 ← **对二次元游戏最致命**

**✅ 有**：`ui2` 底层（SDF 字体 1 draw call、`UiCanvas`、`UiNav` 键盘导航），
以及三块**硬编码**的界面：`Hud`（血条/准星/伤害数字）、`PauseMenu`、`Subtitle`。

**❌ 没有 UI 编辑器**（全仓 `UIEditor`/`WidgetEditor`/`canvasEdit` **0 命中**）。

可配的东西只有这些 —— `runtime/ui/UiConfig.h` **全部字段**：

```cpp
float barWidth   = 360.0f;   // 血条宽
float barHeight  = 18.0f;    // 血条高
float barMargin  = 24.0f;    // 边距
bool  crosshair  = true;     // 准星开关
float crosshairLen = 10.0f;
float crosshairGap = 4.0f;
```

**六个数字。** 而且是"血条"和"准星"这两样 —— **FPS 的 HUD**。

一个二次元游戏需要的 UI，一样都做不了：

| 需要 | 现在 |
|---|---|
| 对话框（立绘 + 名字 + 正文 + 继续箭头） | 只有 `SubtitleBox` 一个，几何写死在 `kBoxW=1240 / kBoxBottom=96` |
| 主菜单 / 暂停菜单 | `PauseMenu` 写死 |
| 背包 / 编队 / 角色详情 / 卡池 / 商店 | **零** —— 要写 C++ |
| 血条之外的战斗 UI（技能图标/CD/连击数） | 零 |
| UI 动画（弹出、滑动、淡入） | 零 |
| 多分辨率适配 | 有等比缩放（字幕框那套），但没有锚点/九宫格系统对外暴露 |
| UI 与数据绑定 | 零（`HudModel` 是 C++ 结构体） |

**这块的严重性**：二次元游戏的工作量分布里，**UI 常常比 3D 还多**。
现在的状态是"每个界面一个新 `.cpp` 文件 + 重新编译"，这对"普通游戏开发者"
等于"做不了"。

### 7 · 存进度 🔴

**✅ 有**：场景可以 `scene.save`（JSON），有 `version` 字段。

**❌ 没有**：

- **存档系统**（C3 / G17）：没有玩家状态快照、没有多槽位、没有版本迁移。
  场景 JSON 的 `version` **只写不读**。→ 一切"游戏性"都是一次性的。
- **稳定 GUID**（G16）：实体没有持久标识，读档时只能按名字/下标对齐，
  改一次场景就错位。
- **配表 / 数据表**：全仓无 CSV / DataTable。二次元游戏的数值（角色属性、
  技能、掉落、对话文本表）**没有地方放**，只能塞进脚本常量或 JSON 手读。
- **剧情旗标 / 全局变量**：`worldAttr` 有（脚本世界黑板），但不持久、无编辑器。
- **i18n 的落地**：`TR()` 体系完整（60 项待译），但**对话文本不在 i18n 体系里**
  —— `.dlg.json` 的台词是硬文本。多语言二次元游戏要重做这一层。

---

### 8 · 出包 🔴

**✅ 有**：CMake 三目标（引擎库 / Editor / Runtime），`Game.exe` 能带
`--scene` 参数跑起来。

**❌ 没有**（E28 未开始）：

- **没有 `File ▸ Package`**：没有目标平台、没有 Debug/Development/Shipping 档、
  没有输出目录、没有进度条
- **没有 Shipping 剔除**：Console / GPU Timeline / Stats 这些调试面板会
  原样进发行包；没有 `VENN_SHIPPING` 宏
- **没有资源裁剪**：只打包被引用的资产（依赖 `Show References` 那套扫描）
- **没有版本清单 / 热更新位**
- **没有平台导出**：仅 Windows（Vulkan 抽象在，但无 macOS/移动端验证）

**后果**：开发者做到最后一步，**发不出去**。只能把整个工程目录拷给别人 +
让对方装 VS。这是"商业化最后 1 公里"，也是"给普通开发者用"的闭环缺口。

## 2 · 面板层面的横向欠账（跨所有环节）

上面是纵向流程，这五条是横向的、每时每刻都在拖慢开发者：

| # | 欠账 | 现状 | 为什么重要 |
|---|---|---|---|
| 1 | **单选** | `selection()` 返回单个 `Entity` | 批量移动/批量改参数/批量复制全部做不了。关卡效率差一个量级 |
| 2 | **Undo = 整场景快照** | `structuralEdit` 抓前后两份完整 JSON | 大场景每步一份全量；属性拖拽默认不进历史 → "改坏了撤不回" |
| 3 | **无资产编辑器框架**（E24） | 材质只有参数面板 + `matlib` 货架；无节点图、无曲线编辑器 | 二次元材质（ramp、SDF、各向异性）参数已经有 10+ 个，调参靠猜数字 |
| 4 | **无断点调试** | 只有 `print` → Console | 脚本写错只能靠日志；协程里的状态看不见 |
| 5 | **面板之间无交叉引用** | 加碰撞体要去 Physics 面板、加 IK 要去 Character 窗口 | 新用户学不到"什么东西归哪儿管" |

## 3 · 如果只做五件（按"解开几段"排序）

不是按"实现难度"，是按**每做一件能解开多少下游**：

| 顺序 | 做什么 | 解开 | 理由 |
|---|---|---|---|

## 5 · 一句话收尾

**这台引擎现在的状态，准确说是"一台非常好的渲染与动画研发平台"，
还不是"一款二次元游戏引擎"。**

差别不在渲染质量 —— 而在**"内容怎么进去、怎么串起来、怎么发出去"**这三步
全部落在代码和 JSON 上。而"普通游戏开发者"这个目标用户，恰恰最不能接受这三步。

好消息是：**要补的都不是底层**。七个脚本函数、两个编辑器面板、一个 Prefab、
一个打包对话框 —— 没有一项需要动渲染管线。地基已经在那儿了。
