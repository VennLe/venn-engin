## 一、这张表为什么不能照着摆

需求是一份 Rigify 人形「24fps · 24 帧行走循环」的逐帧 K 帧表。表本身没问题，
问题在**手工 K 帧这个工作流**与三条要求在物理上冲突：

| 表里的要求 | 手工 K 帧为什么做不到 |
|---|---|
| 承重期脚掌 X/Z 完全不动（§6 硬规则） | 你只能控制**关键帧**，帧与帧之间由插值决定。0.62 秒的承重期里插值给出的是弧线，脚一定滑。 |
| 换角色还能用 | 表里写的是 `thigh.L` / `foot_ik.L`。项目里的角色是 `mixamorig:LeftUpLeg` 这一套，名字换了整张表作废。 |
| 步幅 / 步频 / 摆幅可调 | 表是**结果**，不是参数。想改步幅得重摆 24 帧。 |

生成器把这三件事反过来做：

```
定脚的世界轨迹  →  用两骨 IK 回填大腿/小腿  →  逐帧烘焙成普通关键帧
   （约束在这）        （几何由骨架自己量）        （脚不滑是构造保证）
```

产物是普通的 `animation::EditClip` —— 落盘之后照样能在摄影表 / 曲线编辑器里手改。
**生成器不制造第二套数据。**

## 二、表 → 相位的映射

一个**完整周期 = 两步**（左一步 + 右一步）。`cycleFrames = 48`、`fps = 24`
时，表里那五帧正好落在 1/8 的整数倍上：

| 相位 φ | 帧（48 帧周期） | 表里的名字 | 姿态 |
|---|---|---|---|
| 0 | 1 | Contact L | 步幅最大，左脚跟触地 |
| 1/8 | 7 | Down L | 重心沉底（最低） |
| 1/4 | 13 | Passing | 左腿单撑，右腿掠过体侧 |
| 3/8 | 19 | Up L | 重心顶到最高，脚跟离地 |
| 1/2 | 25 | Contact R | **帧 1 的左右镜像** |
| … | … | … | 后半个周期是前半个的镜像 |
| 1 | 49 | = 帧 1 | 闭合帧 |

- `blocking = true` 时只在 9 个位置打帧（`1/7/13/19/25` + 镜像那四个 + 闭合），
  类型标 `Extreme`；`false`（默认）逐帧烘焙，每帧一个键。
- ⚠ 表里 §9 又写了"单步 12 帧"（日常步速）。两个都要能出 → 周期长度是**参数**，
  不是常量：`cycleFrames = 24` 就是单步 12 帧。
- ⚠ **帧 49 用的是相位 0，不是相位 1**（`frac(1) == 0`，同一条公式）。所以
  "闭合帧与首帧逐位相同"是构造保证，不靠浮点巧合。

## 三、参数（`GaitParams`）

| 参数 | 默认 | 含义 / 坑 |
|---|---|---|
| `stepLength` | 0.60 m | **一步**走过的距离。会被腿长夹一次（见下），夹了会报 `strideLimited`。 |
| `cycleFrames` | 48 | 一个完整两步周期。48 = 表里的帧号；24 = 日常步速 |
| `stanceFrac` | 0.62 | 一条腿承重占周期的比例。0.62 走 / 0.8 慢走 / 0.42 跑（会有腾空） |
| `bob` | 0.030 | 重心上下**半振幅**（表 §9 的 ±0.02~0.04）。⚠ 峰峰是**两倍** |
| `sway` | 0.030 | 重心左右半振幅（表 §9 的 ±0.03） |
| `footLift` | 0.100 | 摆动相脚尖离地峰值。低于 2 cm 就是蹭着地走 |
| `hipYawDeg` | 4.0 | 骨盆随步幅左右拧（表 §5：3~5°） |
| `chestYawDeg` | 5.0 | 胸与骨盆**反拧**，腰椎拿 0.4、胸拿 0.6 |
| `torsoLeanDeg` | 3.0 | 躯干前倾 |
| `hipRollDeg` | 3.0 | 骨盆侧倾（承重侧髋略高） |
| `armSwingDeg` | 22.0 | 摆臂幅值（相对静止姿势，绕侧向轴） |
| `armLagFrames` | 2.0 | 手臂比腿晚几帧（表 §7 的 overlap） |
| `elbowDeg` | 12.0 | 肘永远微曲 |
| `heelStrikeDeg` | 10.0 | 触地时脚尖上抬 |
| `toeOffDeg` | 22.0 | 蹬离时脚跟起来 |
| `toeRise` | 0.050 | 蹬离时踝抬高多少。⚠ 给 0 = 脚插进地里，给太多 = 踮着脚走 |
| `maxCrouch` | 0.09 | 为了够得着最多允许下蹲多少 |
| `blocking` | false | 只打关键姿态（调起来快，但**中间帧会滑**） |

## 四、读数怎么读（`GaitReport`）

面板上和控制台里都会给这些数。**判据全在这里，"看起来像在走"不是判据。**

| 字段 | 单位 | 期望 | 说人话 |
|---|---|---|---|
| `stanceSlideMm` | mm | ≈ 0 | 承重期脚掌**侧向**漂移 |
| `stanceVerticalMm` | mm | ≈ 0 | 承重期脚掌**竖直**漂移 |
| `stanceLineErrMm` | mm | ≈ 0 | 承重期前向偏离**匀速直线**多少（不是"走了多远"，是"走得直不直"） |
| `stanceSpeed` | m/s | == `nominalSpeed` | 承重脚相对身体**后退**的速率（最小二乘斜率） |
| `nominalSpeed` | m/s | — | **把角色移动速度设成它就不滑步** |
| `fwdDriftMm` | mm | ≈ 0 | 髋在**前向**的位移峰峰 = 原地走（treadmill） |
| `bobRange` / `swayRange` | m | 2×`bob` / 2×`sway` | 重心上下 / 左右**峰峰** |
| `footLiftPeak` | m | == `footLift` | 摆动相抬脚峰值 |
| `loopErrMm` | mm | ≈ 0 | 闭合帧与首帧（无缝循环） |
| `mirrorErrMm` | mm | 对称骨架 ≈ 0 | 半周期镜像（帧 25 = 帧 1 镜像），⚠ 见 §五 |
| `restMirrorMm` | mm | — | **资产自带**的左右不对称（镜像判据的地板） |
| `legSwingM` | m | > 0 | 触地帧左脚在**前** |
| `armCounterM` | m | > 0 | 同时左臂在**后**（反相）。⚠ 两条符号一起看才是判据 |
| `reachMargin` | 1 | < 1 | `max|踝−髋| / 腿长`。**> 1 = IK 够不着 → 腿拉直 → 看起来就在滑** |
| `armDownDeg` | ° | 0 | 把手臂从导入姿势放到自然下垂转了多少度（T-pose 资产会是 70~90） |

实测（`anime_girl.fbx`，默认参数）：`slide/vert/line = 0.00 mm`、`fwd = 0.000 mm`、
`bob = sway = 0.060`、`lift = 0.100`、`reach = 0.951`、`arm = 0.260`。

## 五、五个坑（每一条都是实测踩出来的）

### 1. ⚠ 镜像判据只在**对称**骨架上成立

"帧 25 = 帧 1 的左右镜像"是**逐点**的说法。手搭的对称夹具上实测
`mirrorErrMm = 0.000007`，而 `anime_girl.fbx` 上是 **711 mm** —— 它的**静止姿势
本身就自带 580 mm 的左右不对称**（一只脚在前、两条手臂朝向差很多）。
那不是生成器的错，任何动画都不可能把它抹平。

所以判据拆成两条：`mirrorErrMm` 小（对称骨架）**或者** `mirrorErrMm` 与
`restMirrorMm` 同一量级（不对称骨架）。`verify_gait_cycle.py` 里这一项
**只记录不判红**，真正的判据留在对称夹具的 `gait_mirror_mm` ——
写成 `mirror < 0.05` 就是一条永远红的断言，而"红着不管"比没有更糟。

### 2. ⚠⚠ 关节下标 ≠ 角色下标

`FrameData::pos[]` 是按**角色**下标排的，`rig.joint[角色]` 给的是**关节**下标。
两套下标在 19 骨的骨架上**都不越界**，于是错着也能算出像模像样的数：
`pos[13]` 是左上臂而不是左脚 → `reachMargin` 报 1.586（"IK 够不着"）、
`armCounterM` 报 −0.361（"同手同脚"），两条判据同时红，而动作完全正确。

### 3. ⚠⚠ 脚掌的基准必须是**静止**的世界旋转

写完 IK 之后 `world[foot]` 里带着小腿的动画旋转。拿它当"脚掌平放"的基准
→ 脚跟着小腿一起转 → 触地那一帧脚尖扎进地里。必须用 `rest.world[foot]`。

### 4. ⚠ 手臂要"先中和导入姿势，再摆"

导入姿势分三种情况，只有第三种能直接摆：

| 导入姿势 | 直接摆的后果 | 处理 |
|---|---|---|
| 自然下垂（A-pose） | 正常 | 无需处理 |
| T-pose（手臂横着） | 绕侧向轴 = 绕手臂**自己的轴**转，手原地打转 | `armDown`：绕 fwd 把手放下（从静止姿势量，不写死） |
| 肘折着（`anime_girl` 肩到腕只有 24 cm） | 摆幅只有 4.5 cm | 前臂指向对齐到上臂（伸直），再叠 `elbowDeg` 的微屈 |

伸直之后摆幅从 4.5 cm 回到 26 cm（臂长 43 cm × sin 21° × 2）。
`armDownDeg` 报的就是第 2 步转了多少度。

### 5. ⚠ blocking 模式**一定**会滑（这是对照组）

只打 9 个关键姿态时，承重期竖直漂移实测 **8.8 mm**（逐帧烘焙是 0.00 mm）。
这不是 bug，是"为什么默认走逐帧烘焙"的证据，也是"那三个毫米数不是盲的"
的反向证明 —— 一条永远报 0 的断言等于没测。

## 六、怎么用

1. 选中带骨架的角色 → 角色窗口 → 打开 **Pose Mode** → 切到 **Pose** 页
2. 滚到 **WALK CYCLE** 段，调步长 / 周期帧数 / 承重占比 / 上下左右 / 抬脚 / 摆臂
3. 按 **生成行走循环** —— 面板上立刻出现读数（速度、脚掌漂移、闭合、镜像、腿长余量）
4. 满意就按上面的 **保存**（写进 `.anim.json`，导入的片段永远只读）

命令行 / 自动化：`MYVK_EDITOR_POSE_SCRIPT="mode:on;gait:0.6:48:0;save:x.anim.json"`

- `gait` 命令与按钮共用 `CharacterWindow::generateWalk()`，不是两份实现。
- 第三个参数 `0/1` = 逐帧烘焙 / blocking。

`Mixamo`（`mixamorig:*`）与 `Rigify`（`thigh.L` / `shin.L`）两套命名都由
`resolveHumanoidRig()` 的候选名表 + **结构回退**（最长子骨）覆盖；
缺 Neck / Toe 的骨架照样能生成，只是少那一段动作，缺腿才拒绝。

# 步幅匹配（StrideMatch，A4，2026-10-30）

上面那套解决的是"**这段动画自己多少速度**"（`GaitReport::nominalSpeed`）。
可是走路滑不滑，还差一半：**播它的时候按几倍速**。

`Locomotion` 原来只按速度**选** clip（idle / walk / run / jump），从来没
告诉骨架"该播多快"。于是 0.6 m/s 的走路动画配上 3 m/s 的移动速度 ——
腿在动、位置在变、脚在地上滑冰，而日志里一行异常都没有。这条
`docs/character_locomotion.md` §8 的未完成表里记着它（"根运动 / 滑步"）。

## 一、三个数

| 量 | 含义 | 谁是权威 |
|---|---|---|
| `StrideInfo::nominalSpeed` | 这段 clip 的**地面速度**（承重期脚相对身体后退的速率，取中位数） | 从 clip 里量，不靠人填 |
| `StrideRate::rate` | 播放速率 = `moveSpeed ÷ nominalSpeed`，夹在 `[minRate, maxRate]` | `Locomotion` 每帧写进 `sk.speed` |
| `StrideRate::residual` | 夹住之后**还剩多少滑步**（0 = 一点都不滑） | 日志 `STRIDE-CLAMPED` |

真机上的一个实测（Alicia，`verify_char_locomotion` 的那次 Play）：

```
EDIT-STRIDE-MEASURE clip=Walk nominal=1.787 cycle=1.03s duty=0.52
EDIT-STRIDE clip=Walk nominal=1.787 speed=3.000 rate=1.679 residual=+0.0% clamped=0
```

移动速度 3.0 m/s、clip 自然步速 1.787 m/s → 播 1.679 倍 → 残差 0.0%。
接这条线之前是 1.0 倍，也就是**每一步都滑掉 68%**。

## 二、自然步速为什么"量"而不是"填"

填的话有三个逃不掉的坑：换来源（本引擎生成 / Mixamo / Rigify）每段都要人
填；改一个步幅参数就得同步改一个配置数字；换角色（腿长不同 → 步幅被夹）
之后那个数就过期了。而"地面速度"本来就写在 clip 里 —— 承重期脚以恒定速率
往后走，那个速率就是它。

量的入口是 `animation::measureClipStride()`（运行时 `AnimationClip`）与
`measureEditClipStride()`（编辑器 `EditClip`），两者共用**同一个**内核
`measureStride()`。⚠ 这不是洁癖：两份实现在"承重期判定"上差一点，症状就是
"编辑器里不滑、Game.exe 里滑"，而两边各自看都正常。

自检里钉这条的断言是 `stride_edit_speed` 与 `stride_clip_speed`：同一个生成
产物，一条路经 `resolveEditTracks + overlayEditPose`，一条路经 `samplePose`，
**两条独立采样路径**量出 0.598421 vs 0.598398（差 2e-5 m/s）。

## 三、三个坑（都是自检/验收抓出来的）

### 1. ⚠⚠ 脚的高度必须用**世界绝对量**，前向必须**相对髋**

第一版写成"脚相对髋的高度"，夹具上 `duty` 量出 **0.233**，而生成参数是
承重 0.62。根因：骨盆自己在上下起伏（bob ±3 cm），承重期脚钉在地面上不动，
于是"脚相对髋的高度"在整个承重期里扫过 6 cm —— 而承重带宽只有 12 mm，只有
骨盆恰好在极值那几帧被算成承重。

反过来**前向必须相对髋**：要的就是"脚相对身体走了多远"，用绝对量会把角色
整体前进（有根运动时）当成脚步。

### 2. ⚠⚠ 承重判据最后落在**两个定性事实**上，一个阈值都不用调

承重 = `dFwd < 0 && H <= 最低点 + 0.12 m`。两条各管一件事：

- `dFwd < 0`（脚**相对身体**在向后走）= 原地走的定义本身。身体前进 + 脚在地上
  不动 ⇒ 脚相对身体恒定向后；脚要迈到身体前面 ⇒ 摆动期相对向前。**0 是自然
  边界，不是某个资产上量出来的数。**
- `H <= 最低点 + 12 cm`（`kContactLiftMax`）只负责排掉"抬到半空、并且停在高处"
  的脚 —— 光看方向的话，脚在空中划过的后半段也可能还是向后的。12 cm 是**人脚
  掌滚动**的几何上限（脚跟→脚尖），所以它是绝对量、按"该脚自己的最低点"起算，
  不按行程比例。

为什么不是"行程的 25% / 50%"（这一版文档之前写的就是它，已经作废）：那种带宽
挂着**行程比例**，会被根运动的竖直漂移带跑。`animate_girl` 的 Walk 髋上下走
**0.805 m**、脚抬 **0.48 m**，任何比例带都会跟着一起放大，于是"承重期"变成了
"脚在半空也算"。八轮改动（踝高 25% → 50% → 加方向 → 脚底 → 绝对 3 cm → 自适应
参考系 → 封顶 70 mm → 脚底不动）每次只是把另一个阈值挪一挪，`duty` 在
0.13~0.61 之间乱跳。教训：**能用定性事实表达的判据，别用阈值去逼近它。**

两块资产的读数（2026-10-30 实测，`CHAR-STRIDE`）：

| clip | nominal | duty | air | 抬脚行程 | 髋起伏 | 说明 |
|---|---|---|---|---|---|---|
| 自研生成器 Walk | 0.598 | **0.633** | **0.000** | — | — | 教科书走路（双支撑 37%） |
| `animate_girl` Walk | 1.425 | 0.28 | 0.43 | 0.481/0.513 | 0.805 | 高抬腿风格，脚大部分时间在空中 |
| `animate_girl` Run | 3.943 | 0.22 | 0.56 | 0.655/0.572 | 0.059 | 真跑 |

⚠ 所以**别拿这一个数判"这段是走还是跑"**：`animate_girl` 的 Walk 量出
`duty=0.28` 不是算法错，是那段动画本身就这样（同一份数据里"只按方向"会给出
0.64 —— 那才是把摆动期一起算进去的错读数）。跨资产唯一稳的是**相对关系**，
见 §五。

### 3. ⚠ 夹住 ≠ 救回来了

只靠变速，一段 0.6 m/s 的走路在 4.5 m/s 下要播 7.5 倍速 —— 那不是跑，是
发抖。所以 `rate` 夹在 `[0.6, 1.7]`，**夹住时残差不为零是正常的**，但必须
被报出来（`STRIDE-CLAMPED` 一行 WARN，一次夹持只喊一次）。真正的解在调用方
手里：降移动速度，或换一段更快的 clip（walk → run），或调大生成器的步幅。

## 四、怎么用

- **运行时（Game.exe）**：`game.json` 的 `player` 块里有五个键 ——
  `strideMatch`（默认 `true`）、`strideMinRate` / `strideMaxRate`、
  `walkStrideSpeed` / `runStrideSpeed`（后两个 > 0 时**覆盖**量出来的值，
  等于"我知道这段是多少，别量"）。
- **编辑器 Play**：角色窗口 → Pose 页 → **STRIDE MATCH** 段：开关、
  速率范围、以及「测量片段的步速」按钮（量的是**模型里**那段 Walk ——
  Play 播的就是它，和上面那个还没落盘的编辑片段是两个对象）。
- **自动化**：`MYVK_EDITOR_POSE_SCRIPT="...;stride:Walk"`，日志锚点
  `CHAR-STRIDE clip=… ok=… nominal=… duty=… err='…'`（失败也打同一行 ——
  "命令没跑"和"跑了但拒绝"必须能分开）。
- **关掉它**：`strideMatch=false` 就退回 1 倍速播放，也就是**会滑**的那一
  版。留着这个位不是保守，它是"滑 / 不滑"唯一干净的 A/B（自检里
  `stride_loco_off_rate` 就是这条对照）。
- **相位速率曲线**：`game.json` 的 `strideCurve`（默认 `true`），编辑器
  Pose 页的 **`Phase rate curve (foot lock)`** 复选框，脚本命令
  `stridecurve:0|1` —— 三处同一个开关，见 §六。
  ⚠ 编辑器（`EditorContext::m_strideCurve`）与出包（`PlayerVisual::strideCurve`）
  的**默认值必须一致**，否则症状是"编辑器里脚钉得住、出包之后滑"，而两边各自
  看都正常。

## 五、走 / 跑怎么分开（A4b，2026-10-30）

`duty < 0.5` 是**教科书的代理量**，在真实资产上不成立（`animate_girl` 的
Walk 自己就 `duty=0.28`）。跨资产唯一稳的是三条**相对关系**：

```
nominal(Run) > nominal(Walk)    更快
duty(Run)    < duty(Walk)       承重更少
air(Run)     > air(Walk)        腾空更多
```

任一条单独都不够：只比速度的话"同一段动画按 2 倍速播"也能满足；只比 `duty`
的话一段几乎不落地的待机也能满足。三条一起，才把"跑"钉住。

`air`（`airborneFraction`）= 两只脚**同时**不承重的帧占比。判据是
`air > 0`，不是某个阈值 —— **0 与非 0 是两种步态，不是程度差别**。

实测（`animate_girl`，`verify_gait_cycle` G 组）：

```
[PASS] G1 跑步更快        — walk=1.43 run=3.94
[PASS] G2 跑步承重更少    — walk=0.28 run=0.22
[PASS] G3 跑步腾空更多    — walk=0.43 run=0.56
```

### ⚠ 交叉校验：`strideSpan` / `spanSpeed`

`spanSpeed = 2 × 摆幅 ÷ 周期`，来自"脚相对身体的**前向峰峰摆幅**"，是一条
**独立的**量法（承重期法看的是脚的速率，它看的是几何行程）。两者应当同量级；
差得远就说明承重样本被污染（中位数被离群速度带跑）—— 而那种错在 `duty` /
`air` 上都看不出来。实测比值 `Walk 1.16 / Run 0.99`（容差 `0.4~2.5`，给得宽
是因为摆幅法对跑步天然偏小：脚在空中划弧，前向投影被吃掉一部分）。

## 六、相位速率曲线（A4b，2026-10-30）

常量倍率只收掉**平均**滑步。承重期脚速在 clip 内部本身有 5~15% 起伏
（"迈出去快、落地慢"），所以还要按相位变速：

```
gain(φ) = clamp(nominal / v(φ), 0.5, 2.0)     摆动 bin 恒 1
```

`StridePhaseCurve`：32 个 bin，只在承重样本上填（摆动 bin 留 1）。

### ⚠⚠ 推进必须**积分**，不能逐帧查表

```
next = pc->advance(phase, dt * speed / dur)
```

`advance()` 把 `Δφ` 切成 `clamp(ceil(|Δφ|·bins), 4, 32)` 个子步，每个子步用
**它自己所在相位**的 gain。逐帧查表会把曲线量化到帧率上 —— 表现是
"60 fps 不滑、30 fps 滑"，而且只在慢机器上复现。

推进走的是 `AnimatorSystem` 的播放头（`time = next * dur`），回绕判定用的是
"跨没跨过 `phase`"（`speed >= 0` 时 `next < phase`），所以曲线对
`ANIM-WRAP` 的次数没有影响 —— 自检 `stride_curve_loop` 钉这条。

### ⚠ 只管**循环** clip

非循环 clip（Jump）套曲线会让末帧永远到不了：`advance` 回来永远差一点点。
所以 `if (loop)` 才推进曲线。

### ⚠⚠ 缓存键必须带**时长**

`strideCurveFor()` 的键 = 骨架地址 + clip 名 + **毫秒时长**。少了时长这一项，
clip 重新烤过之后旧曲线还在缓存里 —— 症状是"改了动画，滑步忽然回来了"，而且
清一次进程就"自己好了"。

### 自检怎么证明它**真的**抹平了起伏

夹具上的步态是构造出来的匀速步态，拿它当基准等于测了个寂寞。所以自检用**人造
对照**：给承重期叠一条 ±30% 的正弦，再看承重期速度的**离散度**：

```
stride_curve_spread_off  spreadOff=0.200367     关掉曲线：承重期速度差 20%
stride_curve_flattens    on=0.017544            开曲线：1.75%（差 11 倍）
stride_curve_mean        mean=1.000774          平均倍率没被改（容差 5%）
stride_curve_swing_gain  0.000000               摆动 bin 的 gain 恒 1
```

真机（`verify_char_locomotion` 的 Play）：

```
ANIM-STRIDE-CURVE clip=Walk nominal=1.929 bins=32 gain=[0.831, 1.989] mean=1.192
ANIM-STRIDE-CURVE-TICK on=1 curved=1 curves=2
```

`gain` 从 0.83 到 1.99（2.4 倍跨度）说明这段 clip 内部的脚速确实不平，
`mean=1.19` 是它相对中位数的整体偏移。

## 七、斜坡 / 上台阶（2026-10-30）

约定：`rate` 的分子是**水平投影速度**，`slopeDeg` **不参与** `rate`。

```
rate = moveSpeed / nominal            ← 永远这么算
verticalResidual = moveSpeed · |tan θ| / nominal     ← 只报，不进 rate
```

为什么不在 `rate` 里乘 `1/cos θ`：`nominal` 是在**水平面**上量出来的（前向投影），
`moveSpeed` 也是水平的，两者已经是同一个平面。再乘一次等于**二次投影** ——
20° 坡上会少播 6.4%，而且这个错在小坡上看起来"挺合理"，只有上到 30° 以上才
显形。

竖直方向确实会落后（脚在坡上要"爬"），所以它被单独报出来：

- `StrideRate::verticalResidual`，日志 `STRIDE … vert=%.2f slope=%.1fdeg`
- `> 0.10` 且**刚切进这段 clip** 时打一条 `STRIDE-SLOPE` WARN（一次一次，
  不刷屏）。它说的是"竖直方向落后身体 12%"，不是"速率算错了"。

`slopeDeg` 夹在 ±75°（`kMaxSlopeDeg`）：再陡 `tan` 就发散，而且那种地形该走
攀爬动画而不是变速。

自检四条：`stride_slope_rate_ratio`（20° 坡 rate 不变）、`stride_slope_rate_same`
（0° 与 20° 的 rate 逐位相同）、`stride_slope_zero`（0° 时残差为 0）、
`stride_slope_cap`（89° 被夹到 75°，不返回 inf）。

## 八、还没做

- **曲线只在承重 bin 上有效**：摆动 bin 恒 1，所以"脚在空中飞得快/慢"这件事
  没被补偿 —— 它对滑步没影响，但对"腿摆得像不像"有影响。
- **没有按角色身高归一化 12 cm**：低位门是**人**的脚掌滚动量，换成四足 / 大
  体型角色要么偏紧要么偏松。目前只在人形骨架上验过。
- **`duty` / `air` 目前只进日志**，没有下游消费者。真要拿它做"这段是走还是跑"
  的自动判定，必须用 §五 那三条**相对关系**，不能单看一个数。
