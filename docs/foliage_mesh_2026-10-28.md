# 植被：网格精细化 + 自定义模型绑定 + 随机区间（2026-10-28）

用户两句话：

> 「Foliage 模式中生成的 grass、tree、flower、bush、rock 都看起来太粗糙了，可不可以精细一些。」
> 「除了默认模型，这几个应该也允许用户自己从本地项目资源目录中拖入相关的模型进行绑定，
> 然后按算法去随机放置，而且偏移量区间和旋转量区间、缩放尺寸区间，也可以自己去设置。」

对应两处改动：**几何重写**（`engine/assets/FoliageMesh.cpp`）与**类型参数**
（`editor/FoliageEditor.*`）。

---

## 1 · 五种内置网格重写

旧版一律压到"能认出来就行"，理由是"撒几百株也无所谓"。但植被是**成片**看的：
几百个同样的粗糙轮廓叠在一起，粗糙会被放大成"一撮绿毛 / 一排圣诞树 / 一地塑料蛋"。

| 形状 | 旧结构 | 旧 tri | 新结构 | 新 tri |
|---|---|---|---|---|
| 草 grass | 3 张平面交叉卡 | **6** | 9 片**弯曲 + 锥度 + 4 段细分**的叶片，黄金角螺旋摊开 | **72** |
| 花 flower | 2 片杆 + 3 片冠 | **10** | 2 株：3 段弯曲茎 + 6 瓣菱形花冠 + 六边形花心 | **72** |
| 灌木 bush | 8×5 压扁球 | **~80** | 4 团噪声位移叶簇 + 8 张朝外叶卡 | **512** |
| 树 tree | 6 边柱 + 2 个 8 边锥 | **~32** | 5 环锥度**弯曲**树干 + 3 根树枝 + 6 团噪声树冠 | **830** |
| 石头 rock | 9×6 位移球 | **108** | 14×9 四倍频位移 + 平面着色 | **252** |

三条贯穿全文件的约定：

1. **Z-up**，`size` = 世界高度（米），XY 由形状按比例算；
2. 薄片（草叶/花/叶卡）法线**统一朝上** —— 逆光时面法线会全黑，朝上法线拿的是
   天光，观感稳定。材质必须 `doubleSided`；
3. 全部**确定性**（不用 `rand`）：同一份 `size`/`seed` 每次生成的顶点逐字节相同
   → 截图能回归、测试能断言三角数。

⚠ **API 也改了**：`makeXxxVertices()` + `makeXxxIndices()` 两半分法 → 
`buildXxxMesh(size, verts, idx)` 一次出。旧写法要求两份代码里的形状参数逐字相同
（树的旧注释专门警告过），而草/花的索引表是硬编码"每片 4 个顶点"的 —— 改叶片数
就整块错位：顶点够、索引指到别的叶片上，画出来是一团乱线。合成一个函数后这类
错位在结构上不可能发生。

## 2 · 自定义模型绑定（每个植被类型一份）

`TypeSettings::meshPath`（相对 `assets/` 的路径，空 = 用内置）。

- **入口**：Foliage 面板里的 `Mesh` 槽（`FO-MESH`）是一个 ImGui drag-drop target，
  从内容浏览器拖 `.obj / .fbx / .gltf / .glb` 上去即可；右侧 `x` 按钮换回内置。
- **只取第一个子网格**：一个 Foliage Type 在 UE 里也只对应一个 Static Mesh。多材质
  的植被应该开成多个类型，而不是把一堆子网格塞进同一个实例（日志会写
  `subs=N used=0 (只取第一个子网格)`）。
- **加载失败不回退**：拖进来的路径打不开时保持"没有网格"，槽上显示
  `…(load failed)`，并打一条 `FOLIAGE-MESH-FAIL`。**悄悄退回内置草**会让用户以为
  拖拽没生效 —— 这是最难查的一类"假成功"。
- **归属判定**：`matchesKind(k, mesh)` = 指针精确匹配（内置按 key 缓存、自定义按
  路径缓存）→ 失败再按 shape 名兜底（读档后内置网格会重新生成，指针会变）。
  统计 / 擦除 / 可见性 / Reapply 全部走它，不再各自比形状字符串。
- **贴地**：`-mesh.boundsMin().z * scaleZ` —— 外部模型的原点常在**几何中心**
  （Blender 导出默认），不补这一下会有一半埋进地里。内置网格原点在脚底（≈0），
  所以对这一条不敏感。

## 3 · 随机区间（缩放 / 偏移 / 旋转）

`TypeSettings` 新增：

```cpp
glm::vec3 offsetMin, offsetMax;   // 米：在落点上叠加的随机偏移（X/Y/Z）
glm::vec3 rotMinDeg, rotMaxDeg;   // 度：X=Pitch, Y=Roll, Z=额外的 Yaw 抖动
// 缩放沿用已有的 minScale / maxScale
```

UI 在 `Foliage type` 段的 `Random ranges` 折叠区里：`DragFloatRange2`（缩放）+
两行 `DragFloat3`（min/max）。用 min/max 两行而不是 6 个 `Range2`，是因为面板
只有 300~460 px 宽，`DragFloat3` 能让六个数字在两行里点得准。

**Yaw 的语义**：基础随机 0~360° **始终生效**（撒点本来就该朝向各异），`rot.z`
是在它**之上**再加的抖动 —— 与 UE 的 `Random Yaw Angle` 同义。把 rot.z 设成
-180..180 也不会"抹掉随机朝向"。

⚠ **偏移必须在坡度/高度过滤之前叠加**：偏移后的落点可能落在陡坡上，过滤必须按
"植株真正站的那一格"判断。顺序反了会出现"偏移量一大，就有一批树挂到悬崖上"。

## 4 · 三条路共用一份采样

`samplePlacement(k, wx, wy, out, reject)` 是唯一的落点规则：偏移 → 取地形 →
坡度/高度过滤 → 缩放 → 贴地（-boundsMin.z - sink）→ 旋转（贴坡 + 倾斜 + 用户区间
+ 岩石随机躺）→ 颜色变体。

撒点（`stamp`）、单株（`placeOne`）、`Reapply` 三个入口都调它。
为什么非要合并：项目里已经有过"Play 手写同一条抛物线 → 改一处改两处"的教训。
三条路各写一遍的话，"改完参数点 Reapply"得到的东西会和"重新撒一遍"不一样，
用户会认为 Reapply 是坏的。

## 5 · 判据 → `tools/verify_foliage_mesh.py`

三件事都属于**不会崩、也不报错**的那类（粗细只是观感、绑定没生效只是"还是程序化草"、
区间没生效只是范围不对），所以判据全落在数字上：

| 组 | 断言 | 实测 |
|---|---|---|
| A | 五种内置网格的 `FOLIAGE-TYPE-MESH … tris=` ≥ 下限（草 60 / 花 60 / 灌木 400 / 树 700 / 石头 200） | 72 / 72 / 512 / 830 / 252 |
| B | 自定义网格：`FOLIAGE-ENV mesh=…` + `TYPE-MESH src=… tris>0` + 撒点日志 `mesh=…` 三处一致 | `models/box01.glb tris=12` |
| C | 区间：`SCALE=2,2` → 实测 `scale=2.00..2.00`；`OFFSET=6,6,0` → `maxOff=11.99 > 11`（笔刷本身只有 10 m） | 精确命中 |
| D | **对照**（默认区间）：`scale=0.54..1.47` 有跨度、`maxOff≤10` | 见日志 |

D 组不是可有可无：没有它，C 组那两条分不清"设置生效"还是"本来就那样"。

自动化怎么设参数：`MYVK_FOLIAGE_KIND / SCALE / OFFSET / ROT / MESH` 五个环境变量
（`applyEnvOverrides()`，启动后跑一次，打一行 `FOLIAGE-ENV`）。**拖 DragFloat 的
数值在 GUI 用例里不可靠**（1 px 差 0.02），所以参数走钩子、拖拽手势走
`verify_asset_drag` 那套 CB→视口 的间接覆盖。

不验旋转区间：日志里没有单株欧拉角。它和缩放/偏移是**同一个 `rnd()` 调用序列**里的
相邻两步，缩放与偏移各自都有精确判据，旋转按同一函数顺带保证。

## 6 · 这轮踩到的坑

1. ⚠ **内部抖动会打破"区间承诺"**。缩放里原来有一层 `lateral`（±12%，为防
   "同网格同缩放像复制粘贴"）。加了用户区间之后它是错的：设 2.0..2.0，实测
   1.76..2.24 —— C2 当场抓到。变化量本来就该由区间提供，直接删掉那一层。
2. ⚠ `FOLIAGE-ENV` 由 `sync()` 触发，而 `sync()` 挂在**植被面板绘制**上：
   没进 Foliage 模式就看不到这行。测试第一版在进模式之前断言，白红一次。
3. ⚠ `Mesh` 没有三角数访问器（只有私有 `m_indexCount`）→ 补了
   `indexCount()/triangleCount()`。不然"精细化到底精细了多少"只能靠肉眼。
4. ⚠ 内置网格的类型归属在**读档后**会失效，如果只按 `Mesh*` 指针比：读档时网格
   是从 `MeshSource` 重建的，key 可能不同。所以 `matchesKind` 保留 shape 兜底，
   并且老场景里形状名还是 `sphere` 的灌木也一并认。
