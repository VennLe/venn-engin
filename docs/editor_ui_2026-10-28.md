# 编辑器 UI 三处改进（2026-10-28）

用户报的三条，逐条给出**根因**与**判据**。三条都不是"美术问题"，前两条是
真 bug（一条让用户完全无法调整布局，一条让整条分隔条失效却看不出来）。

---

## 1 · 视口往左拖扩不开、左边 Modes 一动不动

**用户原话**：*「Viewport 视口往左边拖拽扩大区域的时候，无法继续扩大，并且
在此过程中左边的 Modes 区域似乎是保持不动的。」*

### 根因 A：拖动下限**恒等于**默认宽度

`SplitLayout::buildDefault()` 里 `root.minA = kMinModeRail = 460`，而首帧算出来
的默认宽度也正好是 460（`clamp(bodyW * 0.175, 460, …)` 把 276 顶到了 460）。
于是拖动时 `clamp(pixel, 460, …)` —— 往左一格都夹不动。

**修法**：下限变成**按当前编辑模式问**（`editModeRailMinWidth`）：

| 模式 | 下限 | 理由 |
|---|---|---|
| Landscape / Foliage / Select | 300 | 面板是响应式的（按钮按可用宽度换列），300 时退成 1~2 列仍然点得到 |
| 其余六项 | 460 | 一条 `SameLine` 硬排到底（建模面板那排合计 400 出头），窄了会被裁 |

⚠ 默认宽度**没动**（仍是 460）：`verify_viewport` 的 `CONVERGED_VP =
(463,139,1241,778)` 与像素基线都钉着它。改"默认"和改"下限"是两件事，这里只
动后者 —— 用户能拖窄，但打开时的布局逐像素不变。

### 根因 B：遮挡裁切把"贴边"当成"穿过"，整条线被裁光

`SplitLayout::processSplitters` 里，分隔线要减去所有浮层矩形在它轴向的投影。
判据原本是 `lineC < c0 || lineC > c1 → 跳过`，也就是**碰到边界不算越界**。

而布局里的面板是**紧贴着**分隔条摆的：左栏那几个窗口（`###mode_rail`、
当前模式的参数面板）右边界正好 `== lineC`。它们又不在 `LayoutRects` 里（矩形
尺寸不一致 → `isLayoutPanel` 匹配不上）→ 被当成浮层塞进遮挡列表 → 每个都
"盖住整条线" → `spans` 为空 → **不画、不悬停、不能拖**。

实测：`SPLIT-0` 锚点还在（首帧遮挡列表为空时打过一次），但之后每帧
`spans=0`，按锚点去拖毫无反应。这也是"看起来像分隔条坏了"的直接原因。

**修法**（两处一起，缺一不可）：

1. 判据改成**严格穿过**：`lineC <= c0 + 0.5f || lineC >= c1 - 0.5f → 跳过`。
   真正的浮层（Content 抽屉、菜单、浮动面板）总是明显地横跨这条线，不会被
   这 0.5px 余量误放行。
2. `EditorApp::collectSplitOccluders` 的 `layoutRects[]` 里补上
   `modeRailListRect(L)` / `modeRailBodyRect(L)` —— 左栏那两块本来就是
   **布局的一部分**，不该被当成浮层。

顺带修好的：视口 | Inspector 那条线（`viewport.x + w == insp.x`，同样是贴边）
以前也是死的。

### 判据 → `tools/verify_layout_drag.py` **E 组**

真鼠标拖 `SPLIT-0`，断言四件事：

| 断言 | 说明 | 修复前 |
|---|---|---|
| E1 | 往左拖 120px → Modes 变窄 > 90px | 0 变化 |
| E2 | 同时视口变宽（> 左栏让出的一半；其余被按比例的右栏分走） | 0 变化 |
| E3 | 继续拖到底 → 停在 **300** 左右 | 停在 460 |
| E4 | 左栏没被拖没（≥280，下限不是 0） | —— |
| E5 | 再往右拖 200px 能变宽 | —— |

⚠ E5 是整组最容易打空的一下（上一步刚把光标甩到客户区外，而合成鼠标的
`IsMouseClicked` 要求"按下那一帧正好在热区里"）→ 先把指针停在线上让它热一帧，
仍打空就重试一次，并在输出里注明"第二次才命中"。

## 2 · Landscape 面板按钮太拥挤

原来：工具按钮 **2 列 × 188px、行高 20、行距 2**；整块操作"三按钮 + 振幅框"
挤一行（`avail*0.32 / 0.30`）；Undo/Redo 写死 184+184；层按钮 4 × 96 一行。

**改法**：新增 `editor/PanelLayout.h`，三个纯函数：

```cpp
panelGridColumns(avail, minW, gap)   // 一行能放几列（1..4）
panelGridWidth(avail, cols, gap)     // 每列宽度（均分剩余像素）
panelGridButton(label, idx, cols, w, h)   // idx 不是行首时自动 SameLine
constexpr float kBtnRowH = 26.0f;    // 行高唯一一份
constexpr float kBtnGap  = 6.0f;     // 横纵间距唯一一份
```

- 工具网格：行高 20 → **26**、间距 2 → **6**、列数按可用宽度算
  （460 宽 → 3 列 3 行 = 90px，与原来 4 行 88px 几乎一样高，**不会把下面的
  控件顶出面板**；被拖到 300 宽 → 2 列 4 行，按钮仍然全在窗口里）。
- 整块操作：两个按钮一行 + 振幅框单独一行（带标签）+ Reset 整宽。
- Undo / Redo：按可用宽度对半分（原来 368px 固定，300 宽时 Redo 出窗口）。
- Focus / Focus player / Save now：响应式网格（够宽 3 列、窄了 2 列换行）。
- 层按钮 4 × 96 → 响应式网格（`minW=104`）。

⚠ **加了行高之后要补回纵向空间**（实测踩到）：网格从 20px 行高、行距 2 换成
26 + 6 之后，8 个按钮整体下移 —— `LS-TOOL-6/7` 的 y 到 **897**，而面板底边只有
**842**。它们"有矩形却点不到"，点了砸到底栏上（`verify_world_tools` 的
A5a/A6a/A8* 整片 FAIL，症状是"按钮齐全、笔划全无"）。补回来的三处：

| 位置 | 改法 | 省 |
|---|---|---|
| 地形统计段 | "源文件 + 尺寸"合成一行（`%s · %d x %d samples · %d x %d m`） | 20px |
| 统计段按钮 | `auto-saves while you paint` 从单独一行改成 Save 按钮的 tooltip | 20px |
| 整块操作 | 去掉单独的 "Noise amplitude" 标题行（拖动框自己就显示 `amp 0.120`） | 20px |

一共 60px，网格末行落到 837 < 842（与改造前同级的余量）。

**额外给的两个纵向空间**：左栏模式列表可以**折叠**（表头那个小三角，
`MODE-RAIL-FOLD`）。9 行列表吃掉 ~310px，1600×900 下参数面板只剩 ~290px ——
Landscape 那 8 个工具 + 4 条滑条一屏放不下，"拥挤"有一半是这里来的。
折叠后参数面板直接多拿 310px。默认展开（`LAYOUT-RECTS` / `MODE-RAIL-<i>`
这些锚点与既有用例都不受影响）。

## 3 · Foliage 面板按 UE5 重做

对照表（UE5 → 本工程）：

| UE5 | 本工程 | 锚点 / 日志 |
|---|---|---|
| 顶部工具条 Select / Paint / Erase / Single | `Tool` 四态（Lasso 框选没做，换成 Single——撒树时"点一株"比框选常用） | `FO-TOOL-<i>` / `FOLIAGE-TOOL <id>` |
| Foliage 类型树（眼睛 + 名字 + 数量） | 5 行，点行=选中类型，眼睛=可见性 | `FO-KIND-<i>` / `FO-VIS-<i>` / `FOLIAGE-KIND` / `FOLIAGE-VIS` |
| Brush（Size / Falloff / Density） | Size（半径）/ Falloff / Per stamp | 滚轮与 Shift+滚轮也改这两个 |
| Details（选中类型的参数） | 缩放范围 / 随机倾斜 / 坡度上限 / 高度带 / 贴坡 / 颜色变体 | —— |
| Reapply | `Reapply to existing`：按当前设置重算**已有**实例，违反坡度规则的删掉 | `FO-REAPPLY` / `FOLIAGE-REAPPLY kind=… n=…` |

三处"照 UE 抄下来才知道为什么"的设计：

1. **参数是"每类型"的**。过去切类型会把密度/缩放**覆盖**成该类默认值 ——
   给树调好的参数，切到草再切回来就没了。现在 `TypeSettings m_types[5]`，
   切类型只换"当前编辑对象"。
2. **眼睛 = 可见性，不是删除**。写 `VisibilityComponent.visible`（渲染层认它），
   实例仍在场景里、仍随场景存盘。⚠ 因此"隐藏"是**会存进场景文件**的（和 UE
   一致：隐藏是关卡状态，不是视图状态）；眼睛状态在 `recount()` 里**从场景
   反推**，避免"眼睛睁着但画面里一棵都没有"。
3. **Reapply 才是改参数的闭环**。没有它，改完密度/倾斜只能清空重撒。

`Single` 与 `Paint` 共用同一套过滤规则（坡度/高度），所以"石头上撒不出草"在
单击时也成立 —— 用户对"规则"的预期不该因为换了工具而变。

`Select` 工具**什么都不吃**，直接让视口的正常点选干活（选中之后在 Inspector
里改/删）—— 在这里再写一套拾取只会得到两套略微不同的语义。

### ⚠ 一个不是"功能"但是"致命"的坑

`eyeButton` 里那个手画的眼睛用了 `ImVec2 pts[13]`，下半弧却写了 7 个点
（`pts[7..13]`）—— **栈越界**。MSVC 的 `/RTC1`（Debug 默认开）当场弹出
"Run-Time Check Failure #2 - Stack around the variable 'pts' was corrupted"
的**断言对话框**：进程还活着、日志停在上一行、面板一片空白，**连 ERROR 都没有**。
第一次跑用例时表现为"切到 Foliage 之后 FO-KIND 锚点全没了"。

排查手法（值得记住）：枚举该进程的顶层窗口，找类名 `#32770` 的那个，读它的
静态文本就是断言原文：

```
windows of editor pid: [('Microsoft Visual C++ Runtime Library', '#32770'), ...]
dialog texts: [... "Stack around the variable 'pts' was corrupted" ...]
```

### 判据 → `tools/verify_world_tools.py` B6~B10

B6 四格工具齐全 → B7 Single 单击只放 1 株（`placed=1`）→ B8 Erase 真的删掉
（`removed>0`）→ B9 眼睛：`FOLIAGE-VIS flower=0` 且**实例数不变**（隐藏 ≠ 删除）→
B10 Reapply 写了 `FOLIAGE-REAPPLY kind=…`。

⚠ B10 的按钮在面板下方，必须先 `reveal()` 滚进可视区再点 —— 被裁掉的控件
"有矩形却点不到"（这条坑 `verify_world_tools` 里已经踩过一次）。
