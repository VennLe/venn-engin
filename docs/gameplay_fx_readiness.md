# 玩法与特效：准备度评估 + 做法方案

> 2026-11-02。回答两个问题：
> ① 引擎对"玩法设计"够不够用（大世界探险 / 回合制 RPG / 回合制卡牌）；
> ② 特效（角色动作 + 打击特效）该怎么建。
>
> **本文的证据全部是仓库里跑出来的**（`grep` 命中数、文件行号、API 签名）。
> 判据与实现落地后另见 `docs/fx_system.md` 与 `tools/verify_fx.py`。

---

## 零、一句话结论

**"演"的部分够用，"算"的部分是空的。**

具体说：渲染、粒子、动画、相机、音频、UI、过场、存档 —— 这八层都已经到了"能直接做成品镜头"的程度；
但**玩法规则层（属性 / 伤害 / 状态 / 回合 / 牌库）一条代码都没有**，`Health` / `Attribute` /
`Combat` / `Buff` / `Skill` / `Team` / `Deck` / `Card` 在 `engine/` 下的命中数**全是 0**。

于是现在的真实状况是：**你能把一场战斗"演"得很好看，但"这场战斗怎么算"得从零写**，
而且只能写在脚本里，脚本里连"角色有 100 点血"都只能借旗标（`double`）凑。

更关键的一条：**打击特效的触发链是断的**。
`animation::FiredAnimEvent` 这个"动作打到第 0.3 秒了"的信号，全仓**只有自检在消费**
（`grep -rn "eventsThisFrame" engine/ editor/ runtime/` → 除 `AnimatorSystem.cpp` 与
`AnimationSelfTest.cpp` 之外 0 命中）。也就是说：动作能播、"命中帧"能算出来，
但**没有任何东西接住它去出火花**。这一条不补，所有打击感都只能靠脚本掐秒表。

## 一、先把"游戏类型"拆成能力面

不按"游戏类型"评估，因为类型是**能力的组合**，组合会掩盖缺口。
比如"卡牌游戏"看着是 UI 活，其实它要的三样东西（确定性随机 / 数据驱动 / 状态机）
恰恰是回合制 RPG 也要的，而大世界探险一样都不要。

引擎要为玩法提供的，是这 **12 个能力面**：

| # | 能力面 | 它回答的问题 | 谁最需要 |
|---|---|---|---|
| A1 | **空间与移动** | 角色怎么走、怎么被挡住、怎么上坡 | 大世界 |
| A2 | **交互与拾取** | 点/看/靠近一个东西，怎么知道是它 | 大世界、卡牌（手牌拖拽） |
| A3 | **数据驱动** | 100 张卡 / 200 个技能，属性从哪来 | 卡牌、回合制 |
| A4 | **状态与属性** | 血/蓝/攻/防/护甲/易伤，怎么叠怎么算 | 回合制、卡牌 |
| A5 | **结算与事件** | 一次攻击打到谁、扣多少、触发什么 | 回合制、卡牌、动作 |
| A6 | **时间控制** | 谁先动、能不能暂停/慢放/定格 | 回合制（回合调度）、动作（顿帧） |
| A7 | **确定性** | 同一个种子重放，结果一样吗 | 卡牌（回放/联机/撤销） |
| A8 | **表现编排** | 动作→特效→音效→镜头，一条时间轴上排 | 三者都要 |
| A9 | **反馈层** | 震屏、闪白、伤害数字、顿帧 | 三者都要，动作最重 |
| A10 | **界面** | 手牌/牌库/回合指示/结算面板 | 卡牌（命脉）、回合制 |
| A11 | **存档与流程** | 中途存档、章节切换、回到某一步 | 三者都要 |
| A12 | **内容管线** | 美术资产进得来、参数改得动、不用改代码 | 三者都要 |

> **这个拆法的用处**：以后加"自走棋""塔防""Roguelike"时，不用重新评估，
> 只要看它落在哪几个能力面上 —— 12 个面全覆盖 = 引擎准备好了。

## 二、逐类型判定

判定口径：✅ 有且好用 ／ 🟡 有但要绕 ／ ❌ 没有

### 2.1 大世界探险（当前最强项）

| 能力面 | 判定 | 证据 / 说明 |
|---|---|---|
| A1 空间与移动 | ✅ | Jolt 物理 + `CharacterControllerComponent`（P6 跳跃 v₀ 3.70 / `airControl 0.45`）；地形 `TerrainComponent` + `WaterComponent` |
| A2 交互与拾取 | ✅ | `PickingSystem`（BVH + `worldToScreen`）；关节 J5；`TriggerComponent` |
| A3 数据驱动 | 🟡 | `project::DataTable` 有，但**脚本读不到**（见 G5） |
| A4 状态与属性 | ❌ | 0 命中 |
| A5 结算与事件 | 🟡 | 碰撞事件有；"伤害"语义没有 |
| A6 时间控制 | ✅ | `timeScale`（`EditorApp::m_timeScale` / `runtime::GameLoop::timeScale`）+ 序列器 |
| A7 确定性 | 🟡 | 固定步长有；随机数没有（见 G2） |
| A8 表现编排 | 🟡 | Sequencer 强（镜头/事件/多机位），但事件只能落到"脚本自己轮询" |
| A9 反馈层 | 🟡 | 震屏有 trauma 模型 + 空间衰减；**闪白/顿帧/伤害数字没有** |
| A10 界面 | ✅ | `ui2`（6 控件 + SDF + 布局 + 焦点 + `{key}` 绑定） |
| A11 存档与流程 | ✅ | G16/G17 全量存档 + 悬挂父修复；G19 关卡流送刚落地 |
| A12 内容管线 | ✅ | FBX/glTF 三索引闭包 + 打包 `game.pak` |

**结论：大世界探险"能做"。** 缺的是"玩法深度"（A4/A5），不是"能不能跑起来"。

### 2.2 回合制 RPG（战斗部分基本从零）

| 能力面 | 判定 | 说明 |
|---|---|---|
| A3 数据驱动 | 🟡 | 表存在、编辑器能编（C1/C2 配表面板 ✅），但运行时/脚本取不到 |
| A4 状态与属性 | ❌ | **最痛的一条**。"护甲先扣再扣血""易伤 ×1.5 持续 3 回合"没有任何地方能放 |
| A5 结算与事件 | ❌ | 没有伤害管线，没有"伤害来源/类型/暴击/免疫" |
| A6 时间控制 | 🟡 | 有 timeScale，但**没有"回合"这个概念**；"行动队列/速度条"要自己写 |
| A7 确定性 | ❌ | 没有种子随机 → 战斗回放做不了，AI 行为不可复现 |
| A8 表现编排 | 🟡 | 每次技能演出要手写脚本协程（`wait` + `playAnim` + `spawn`），没有"技能 = 数据"这条捷径 |
| A10 界面 | 🟡 | 6 种控件够摆面板，**但缺列表/滚动/网格**（回合制要"敌人列表""行动顺序条"） |

**结论：回合制 RPG 的"战斗骨架"必须新建。** 这是本文 G1 要解决的东西。

### 2.3 回合制卡牌（缺口最大）

卡牌游戏 90% 是 **UI + 规则状态机**，而这两样恰好是引擎最薄的两处。

| 能力面 | 判定 | 说明 |
|---|---|---|
| A2 交互（拖拽） | ❌ | `ui2` 有 hover / pressedEdge / releasedEdge，**没有 drag 语义**。拖一张牌到敌人身上 = 卡牌最核心的操作，现在要自己用"按下位置 + 移动 + 抬起"手搓，且没有"拖拽中高亮合法目标" |
| A3 数据驱动 | 🟡 | 同上，表进不了运行时 |
| A4 状态与属性 | ❌ | 同上 |
| A7 确定性 | ❌ | **卡牌必须要**：抽牌顺序、随机效果、敌方意图，全要种子可复现，否则"读档重开就换一副牌"是 bug 级体验 |
| A8 表现编排 | 🟡 | 卡牌特效是"短、频繁、打断式"，比 RPG 技能更密；现在没有特效池（见 G4） |
| A10 界面 | ❌→🟡 | **6 种控件做不出手牌扇形、牌堆滚动、悬停放大、翻面**。缺：Scroll/Grid、变换（旋转/缩放/透明度动画）、九宫格之外的遮罩裁切 |
| A11 存档 | 🟡 | 全量存档有；但"战斗中间存档"要能存**牌库/手牌/弃牌堆**这些纯数据 |

**结论：卡牌"能做，但先要两件东西"** —— ① 确定性随机 + 纯数据存档；② UI 的拖拽与列表。
这两件都不难，但**都不存在**。

## 三、五个硬缺口（按"不补就做不出来"排序）

### G1 · 玩法状态层（属性 / 伤害 / 状态效果）

**现状**：`engine/` 下 `Health` `Attribute` `Combat` `Buff` `Skill` 命中 **0**。
**痛点**：现在写"打一下掉 12 血"，只能 `setFlag("hp", getFlag("hp") - 12)`。
旗标是 `double`，没有"类型/上限/来源/持续时间/叠加规则"，
一旦有"护甲减伤""易伤""中毒每回合掉血"，旗标法立刻崩。

**要建什么**（`engine/gameplay/`）：

```
AttributeSet    一组命名数值（hp/maxHp/atk/def/armor/speed...），带 clamp
StatModifier    加算/乘算/覆盖 三种运算 + 来源标签 + 优先级
StatusEffect    一段有寿命的状态：每回合触发 / 立即触发 / 只改数值
DamageSpec      一次伤害：数值 / 类型 / 来源 / 是否暴击 / 是否穿甲
DamageResult    实际扣了多少、被什么减掉了（**必须回传**，否则表现层不知道飘什么数字）
```

**⚠⚠ 为什么 `DamageResult` 必须存在**：表现层要飘数字。若是"引擎算完了只告诉你 hp 变了"，
表现层就得**把公式再算一遍**去猜飘多少 —— 两处一漂移，玩家就会看到"飘 -12 但血掉了 -9"。
这是所有自研引擎都会踩一次的坑。

### G2 · 确定性随机（种子 + 可序列化状态）

**现状**：`engine/` 下 `Rng` / `mt19937` 命中 **0**（只有粒子的 `forceRandomize`）。
**痛点**：卡牌的"抽牌顺序"若用 `rand()`，**读档/重开/回放全都不一样**；
回合制的"敌方意图"若不可复现，做不了"预测下回合"这种核心玩法。

**要建什么**：`engine/gameplay/Random.h`
- PCG32 / xoshiro 一类的**小状态**生成器（`uint64 state` —— 能直接进存档）
- **流分离**：`deck` / `loot` / `vfx` 三条独立流。
  ⚠⚠ **特效随机必须与玩法随机分开**：出火花的角度用 `vfx` 流；
  如果它和 `deck` 共用一个流，**每多一个粒子就改变下一张抽到的牌** —— 症状是
  "关掉特效后抽牌顺序变了"，极难查。

### G3 · 动画事件没有消费者（打击链断在这里）

**现状**：`animation::AnimEvent` + `collectAnimEvents()` + `AnimatorSystem::eventsThisFrame()`
全部就绪且有用例（B2 ✅），但**消费方只有自检**。
**痛点**：所有"第 0.3 秒出刀光"的活，只能脚本 `wait(0.3)` 掐秒表 ——
而 `dt` 抖动 + `timeScale` 一改，秒表就错位；换一段动画就得重掐。

**要建什么**：**事件路由**（`engine/fx/AnimEventRouter`）：
把 `(kind, payload)` 映射到动作。作者在 Inspector 的事件表里填 `Hit|fx/sword_hit`，
引擎自动出特效/音效/震屏/伤害判定。**这就是"打击感不需要写代码"的分界线。**

### G4 · 特效动词缺失（脚本只能 `playAnim` / `spawn`）

**现状**：`svc.act.*` 全部动作（`grep -o` 去重）：
`axis` `getFlag` `held` `joints` `loadScene` `openUI` `playAnim` `playSequence`
`player` `pressed` `released` `setFlag` `showDialogue` `spawn`

**没有**：`playEffect` / `shake` / `playSound` / `hitstop` / `damage` / `setTimeScale`。
**痛点**：`spawn` 是"造一个实体"，用它出一次火花意味着**每次命中都要实例化/销毁实体** ——
既没有池，又踩 `render_resource_lifetime` 的铁律（CB 录制中引用过的对象不能销毁）。

**要建什么**：`EffectService`（见 §4.2）+ 6 个动作动词。

### G5 · 配表进不了运行时

**现状**：`project::DataTable` / `TableStore` 齐全（`rowById` / `num` / `str` / `flag`），
编辑器有配表面板，但**脚本与运行时读不到**（`grep "TableStore" engine/script/` → 0）。
**痛点**：卡牌数据（费用/攻击/稀有度/效果文本）只能硬写进脚本 → 改一张卡要改代码。

**要建什么**：把表**快照进运行时上下文**（`svc.table.get("cards", "fireball", "cost")`），
并且**打包时随 `game.pak` 一起带上**（`kEngineAssetDirs` 那条纪律）。

## 四、特效方案

### 4.0 先分清三种"特效"，它们的驱动源完全不同

这是方案的地基。混在一起设计，最后一定做成"每次都要手写脚本"。

| 类型 | 例子 | **谁决定它什么时候出现** | 生命周期 |
|---|---|---|---|
| **状态型** | 附魔光、中毒绿雾、护盾壳、奔跑尘土 | **存在即播放**（挂在实体上，随实体生死） | 与实体同寿 |
| **事件型** | 刀光、火花、命中闪光、脚步烟 | **一个瞬间事件**（动画事件 / 伤害结算 / 脚本动词） | 一次性，播完即回收 |
| **环境型** | 雨雪、萤火、飘叶、瘴气 | **区域/全局**，与角色无关 | 长驻，跟关卡流送同寿 |

> ⚠ 现在引擎只有"状态型"能直接用（`ParticleEmitterComponent` 挂在实体上 + `enabled`）。
> "事件型"要靠 `spawn` 手搓（无池），"环境型"要挂在一个大触发器上硬凑。
> 所以 §4.2 的 `EffectService` 主要解决**事件型**，顺带把环境型收进"区域挂载"。

### 4.1 四层架构

```
① 数据层   EffectAsset(.veffect)   —— 一个特效 = 粒子 + 音效 + 震屏 + 材质闪 + 时长
                  ↓ 被谁引用
② 编排层   AnimEventRouter / Sequencer SeqEvent / 脚本动词 三条入口
                  ↓ 统一成一次请求
③ 调度层   EffectService —— 池化实例、优先级抢占、同时数量上限、时间缩放
                  ↓ 分发给执行者
④ 表现层   粒子 / 音频 / 相机震动 / 后处理闪白 / 材质参数 / 伤害数字
```

**为什么要"数据层"这一层**：没有它，`Hit` 这个事件在不同角色上要写不同的脚本；
有了它，作者只要在事件表填 `Hit|slash_a`，`slash_a.veffect` 里打包好
"3 个粒子发射器 + 1 个音效 + 震屏 0.35 + 闪白 0.08"，全项目复用。

### 4.2 `EffectService`（调度层）

接口草案：

```cpp
namespace fx {

struct EffectRequest {
    std::string asset;            // fx/slash_a.veffect
    glm::vec3   position{0.0f};
    glm::vec3   normal{0.0f, 0.0f, 1.0f};   // 火花朝向
    float       scale = 1.0f;
    float       speed = 1.0f;     // 播放速率（暴击可以 0.6 倍慢放）
    uint32_t    attachTo = 0;     // 非 0 = 跟随这个实体（附魔类）
    int         priority = 0;     // 同帧超上限时谁先被挤掉
};

class EffectService {
public:
    void init(Scene*, assets::AssetManager*, audio::AudioSystem*, CameraSystem*);
    // 立即播（事件型）。返回实例 id，0 = 被丢弃。
    uint32_t play(const EffectRequest& r);
    void     stop(uint32_t id);
    void     update(float dt, float timeScale);   // ⚠ 见 4.3 的顿帧陷阱
    std::size_t activeCount() const;
    void     setBudget(int maxInstances);
};

} // namespace fx
```

**四条必须写进实现的纪律**：

1. **⚠⚠ 池化，不是实例化实体**。
   `render_resource_lifetime` 的铁律是"一条 CB 在 recording 状态时，它引用过的对象都不能销毁"。
   特效若是"每次 `spawn` 一个实体再 `destroy`"，会在录制中途销毁资源 → `invalid state` 刷屏 + submit -4。
   池化 = **实体永不销毁，只切 `enabled` 与参数**。
2. **⚠ 同时实例上限 + 优先级抢占**。卡牌一次结算可能 20 个特效同帧触发；
   低端 GPU（本机 Iris Xe）必须能"少出几个"而不是掉到 15 fps。
   抢占规则要**确定**：`priority` 相同则**先来的存活**（晚到的被丢），否则同一帧的
   播放顺序不同 → 画面每次不一样（自动化截图判据会 flaky）。
3. **⚠ 播放速率与 `timeScale` 解耦**。`speed` 是**这个特效自己的**速率；
   `timeScale` 是全局的。两者相乘（慢动作时特效也慢），但**顿帧期间特效不能停**（见 4.3）。
4. **⚠ 资源解析走 `tryLoadTexture` 那套容错**。"写了容错分支 ≠ 容错生效"——
   上游 `throw` 的分支跑不到。缺一个 .veffect 应该是"这次不出特效 + 一条 WARN"，
   不是整场战斗崩。

### 4.3 打击感：五个旋钮 + 一个陷阱

打击感不是"加更多粒子"，是**五个旋钮的时序配合**。以下数值是可直接用的起点
（以 60 fps 为基准，实际按秒存，不按帧存 —— 否则高刷屏上顿帧会变短）：

| 旋钮 | 典型值 | 做法 | 加了会怎样 |
|---|---|---|---|
| **顿帧 hitstop** | 轻击 0.05s / 重击 0.09s / 暴击 0.13s | `timeScale` 压到 **0.05~0.1**（不是 0） | 只有它能让"打到"有重量感。压到 0 会像掉帧 |
| **震屏 trauma** | 轻 0.15 / 重 0.4 / 暴击 0.55 | `CameraSystem::shakeAt(命中点, amount, falloff)` | 已有，且**带空间衰减**（远处爆炸轻微）|
| **闪白** | 0.06~0.10s，强度 0.25 | 后处理叠加（见下） | 让命中"亮一下"，是廉价但极有效的 |
| **粒子 burst** | `bursts[0] = {time 0, count 12, cycles 1}` | `ParticleEmitterComponent` 已有 4 条 burst | 火花主体 |
| **音效变调** | pitch `1.0 ± 0.08` 随机 | `playOneShot(clip, SFX, pos, vol, pitch)` | 连击不"打碟"（同一个音反复播会很假） |

**⚠⚠ 陷阱：hitstop 的计时器必须用「真实时间」，不能用 scaled dt。**

```cpp
// ❌ 错：timeScale 压到 0.05 之后，这个计时器慢 20 倍 → 停顿 1.6 秒
hitstopLeft -= dt * timeScale;

// ✅ 对：真实时间
hitstopLeft -= realDt;
```

更隐蔽的一种：**在 hitstop 里 `timeScale = 0`** —— 计时器永远不走，停顿永不结束，
表现是"打一下之后整个游戏卡死但渲染正常"。这是必测的一条（否定测试：故意设 0，
断言 N 帧后 `timeScale` 必须恢复）。

**⚠ 第二陷阱：顿帧必须"叠加重置"而不是"叠加延长"**。
连击时第二下把剩余时间重置成新的值（取 `max(剩余, 新值)`），
否则 5 连击会把停顿累加到 0.5 秒 —— 手感变成"卡"。

**闪白怎么加（不新开 pass）**：
`PostVolume` 已有 `chromaStrength` / `vignetteStrength` / `autoExposureBias` 这类
"区域覆盖"字段。**最省的做法**是加一个 `flashStrength` + `flashColor`，
由 `EffectService` 在运行时**临时压一个"全屏、priority 极高、blendDistance=0"的 volume**。
好处：走已有的 volume 混合路径，不用碰 `PostProcess` 的 pass 结构（改一处要同步改 N 处的老坑）。

### 4.4 角色动作特效（三类挂点）

角色动作特效不是"整体加一层"，是**三个不同的挂点**：

| 挂点 | 做法 | 引擎现状 |
|---|---|---|
| **骨骼挂点**（刀尖、拳、法杖头） | 每帧把粒子发射器/拖尾锚到骨骼世界变换 | ✅ `BoneAttachmentComponent` 已有 |
| **动作事件**（第 N 秒出刀光/脚步/音效） | 动画事件 `Hit\|slash_a` → 路由 | ❌ G3 |
| **轨迹拖尾**（挥砍残影） | 顶点历史带（ribbon） | ❌ 0 命中（`Ribbon` / `Trail` 无实现） |

**拖尾的最小可行做法**（不用新 pass）：
把最近 N 帧的"刀尖世界坐标 + 时间戳"存进一个环形缓冲（N=16），
生成一条 **CPU 拼的三角带**，塞进已有的粒子/网格几何上传路径。
透明度按"年龄"衰减，`timeScale` 慢放时拖尾自然变长 —— 这正好是慢动作最想要的效果。
> ⚠ 拖尾必须**跟着"这一帧的刀尖"而不是根骨**：挂根骨的话，转身时残影会甩出去。
> `BoneAttachmentComponent` 已经能算骨骼世界矩阵，直接复用。

### 4.5 回合计/卡牌专用表现（三个高频动作）

| 动作 | 做法 | 注意 |
|---|---|---|
| **伤害数字** | `PickingSystem::worldToScreen` 把命中点投到屏幕 → `ui2` 文本飘字 | ✅ 都有；⚠ 飘字必须**用独立的一层**，混进 `UiDocument` 会被布局裁掉 |
| **卡牌翻面 / 悬停放大** | `UiWidget` 加"变换"（旋转 Y / 缩放 / 透明度）| 现在 `UiWidget` 只有矩形 + 颜色 → 要加 4 个字段 |
| **手牌扇形** | 每张牌按序号算一个角度 + 弧线位置 | 纯数学，但**必须能拿到"手牌数量"** → 要 A3 数据层 |

**为什么伤害数字要用"独立一层"**：`ui2` 的布局是"锚点 + 树"，
飘字是**屏幕空间绝对定位 + 每帧换位置**的，塞进文档树每次都要重算布局，
而且会被父节点的裁切掉。单独一层 = 一个 `UiCanvas` 的直接绘制批次。

### 4.6 环境型：跟关卡流送绑一起

`G19` 刚落地（`LevelStreamer`）。环境特效应该作为**关卡的一部分**：
每张关卡在自己的场景文件里挂几个"区域发射器"实体，流送进来就活、卸掉就停。
> ⚠ 卸载时**必须先 `stop` 再销毁实体** —— 反过来会命中池里的空指针。
> 这条要和 `LevelStreamer::unload` 的销毁循环写成同一段代码，不能靠"使用者记得"。
