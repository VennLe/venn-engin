# 地形笔刷的圆环为什么会变形

> 2026-10-23 · 用户报障："在 LandScape 地形模式下，Raise/Lower 这个笔刷操作
> 地形时，笔刷的圆圈明显在变形。"
> 验收：`tools/verify_brush_ring.py`（5 条，像素级判据）
> 相关：`editor/LandscapeEditor.cpp` 的 `viewportInput`（笔刷光标那一段）

---

## 0 · 症状与取证

在斜坡上悬停时，外圈还勉强是个椭圆，**内圈（falloff 核心圈）会拧成一个
歪嘴的、带凹口的团**；笔心那个小十字也不在圆心，而是贴在圆的右边缘。

取证方法：把视口截图的像素按颜色筛出圆环（叠在地形绿上呈淡黄
`R>225, G>195, B∈[110,205]`），再对 `r(θ)` 做谐波分析。

**为什么是谐波**：一个躺在**水平面**上的圆，透视投影**严格**是一条圆锥曲线
（椭圆）。也就是说 `r(θ)` 只允许存在 0 次与 2 次谐波（DC 半径 +
`cos2θ`/`sin2θ` 的拉伸）。高次谐波冒出来 = 这条曲线不再是椭圆 = 眼睛看到的
"变形"。指标就是高次分量的 RMS，归一化成百分比。

半山腰处实测（修复前）：

| 圈 | 非椭圆 RMS | 峰峰 |
|---|---|---|
| 外圈 | 3.5% | 2.38 px |
| 内圈 | 更差（肉眼可见的凹口） | — |

---

## 1 · 根因：圆环"贴着被自己推起来的地表"取点

旧代码每个采样点都做两件事：

```cpp
const glm::vec3 wp0 = model * vec4(lp, 1.0f);      // 水平面上的环点
glm::vec3 wp = wp0;
wp.z = heightAtWorld(wp0.x, wp0.y);                // ← 再按**当前**地表抬起来
```

看起来"贴着地表"很讲究，实际有三个问题：

1. **它爬的是自己刚堆出来的山包。** 一按下去地形就开始长，环点跟着长；
   落在半山腰的那半圈被抬得比另半圈高得多，投影之后椭圆被拉歪、压扁。
   `m_falloff = 0.6` 时内圈半径只有外圈的 0.67 倍，整圈都落在坡上 → 拧得最凶。
2. **它和真实作用区不一致。** `applyStroke` 是按 **XY 距离**筛格点的
   （`t = sqrt(dx²+dy²)/rs`），作用区是一个**水平**圆盘。给圆环逐点改 z 只是
   让它"看起来贴着地"，覆盖范围一点没变 —— 画出来的形状反而在骗人。
3. **得不偿失。** 这个圆环是画在视口图像**之上**的 2D 覆盖层（`ImDrawList`，
   没有深度测试），"贴着地表"完全不产生任何遮挡关系，纯粹是把形状搞坏。

## 2 · 修法

整圈取**同一个高度**：命中点的 `localHit.z`。

```cpp
const glm::vec3 lp(localHit.x + cos(a) * r,
                   localHit.y + sin(a) * r,
                   localHit.z);          // ← 整圈同一个 z
```

水平圆的透视投影严格是圆锥曲线，所以**屏幕上的形状只由机位决定**，无论
地形怎么被推、圆环怎么跨坡，它永远是那条光滑的椭圆。

顺带三处：

* **笔心十字**原来画在 `outer[0]` —— 那是"角度 0 的那个环点"，也就是圆的
  **右边缘**。改成投影命中点本身。
* 段数 32 → **48**：半径 12 m 贴脸看时直径有三四百像素，32 段的折角看得出来。
* 填充从 `AddConcavePolyFilled` 换成 `AddConvexPolyFilled`：水平圆的投影是
  凸的，凹多边形三角化在旧版"拧过的"形状上会画成一团乱麻，现在不会了。

代价：陡坡上圆环会插进/浮出地表。UE / Unity 的地形笔刷也是这么画的（一个平的
圆盘），这是行业惯例 —— 因为笔刷覆盖的本来就是水平圆盘。

## 3 · 修复后的实测

| 场景 | 非椭圆 RMS | 峰峰 | 笔心 |
|---|---|---|---|
| 平地 | 0.8% | 0.80 px | 在圆心 ✔ |
| 半山腰 | 0.9% | 1.21 px | 在圆心 ✔ |
| **修复前半山腰** | **3.5%** | 2.38 px | **在圆环右边缘 ✘** |

`tools/verify_brush_ring.py` 的判据（全部像素级，不接受"看着还行"）：

* **A** 圆环画出来了（颜色掩码 > 200 px）
* **B** 平地上非椭圆分量 < 2%
* **C** 质心 ±3 px 内必须有圆环色像素 —— 这一条专抓"笔心画在 `outer[0]`"，
  修复前必然失败
* **D** 堆一个山包、把圆环压在半山腰，仍然 < 2.2%

这套判据在**旧代码上实测 2 条 FAIL**（C 与 D），在新代码上 5/5 PASS ——
也就是说它真的能分辨这件事，不是一条恒真的断言。

## 4 · 还没做的

* 圆环**不随地形遮挡**（覆盖层永远画在最上面）。要让它被山挡住的话，得把
  它做进 3D 管线（描边 pass 或 depth-tested 覆盖几何），代价远大于收益。
* `tools/verify_landscape_ground.py`（2026-10-20 写的地形笔刷用例）目前有
  8 条失败：面板加了分区之后，第 7/8 个工具按钮排到了可视区之外、
  默认机位也不再让笔心落在"视口 16%/72%"那一格。**与本轮改动无关**
  （它在旧二进制上同样失败），修它需要补 `scroll_into_view` + 固定机位。
  本轮的圆环形状由 `verify_brush_ring.py` 单独看守。
