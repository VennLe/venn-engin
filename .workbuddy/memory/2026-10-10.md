# 2026-10-10（周六）—— venn 编辑器：视口导航两项优化

## 需求（用户原文要点）
1. Viewport navigation 里 Sensitivity 的两个加减按钮去掉，数值框加宽到能显示完整数值。
2. 视口左下角加 Blender 风格 Navigation Gizmo（红 X / 绿 Y / 蓝 Z），可拖拽旋转视图、
   点轴名切换正视图，数字键也能切视图（和 Blender 一样）。

## 实现
- **Sensitivity**：`InputFloat` 的 step 参数置 0（不再渲染 +/- 按钮），宽度常量
  `kSensitivityFieldW = 88`（放下限 0.00 ~ 上限 20.00 都够）。HUD 浮层宽高计算同步更新。
- **导航球（`ViewportPanel::drawNavGizmo`）**：
  - 三根世界轴投影到屏幕：`d·r → 屏幕 x`，`-d·u → 屏幕 y`，深度 = `-d·f`；
    六个轴端小球（正轴实心 + 字母白、负轴暗底描边 + 字母用轴色）按深度远→近排序绘制。
  - 交互在 `InvisibleButton`（整个方形区域，四角也吞鼠标，和 Blender 一致）：
    按下记 `m_navPressDir`，位移 > `kGizmoClickSlop(5px)` 算拖拽（绕注视点 orbit），
    否则松手算点击 → `snapViewTo` 吸附正视图。
  - **关键设计：切视图/拖拽都"绕当前注视点"转**（snapViewTo 里先存 target，
    改完 yaw/pitch 再 `setTarget(pivot)` 钉回去）—— 原地转头会让被观察物飞出视野。
  - 顶/底视图 yaw 是退化量，**保留当前 yaw**，画面水平朝向才连续。
- **相机俯仰上限**：原来三处硬编码 `1.52f`（≈87°），顶视图会明显偏斜。
  改为 `Camera::kPitchLimit = 1.5533f`（89°，留 1° 防止 forwardAxis/rightAxis 掉进兜底分支）。
- **数字键视图切换（`ViewportPanel::handleViewShortcuts`）**：
  1/3/7（+ 小键盘同号键）= Front/Right/Top，Ctrl+ = Back/Left/Bottom；
  2/4/6/8 = 15° 步进（repeat=true 可长按连发）。主键盘数字用的枚举名是 `ImGuiKey_1` 等。
  在 `EditorApp::handleShortcuts` 里**必须放在 `io.KeyCtrl` 分支之前** —— 那个分支
  末尾会 return，把 Ctrl+1/3/7 一起吞掉。
- **调试钩子**：`drawNavGizmo` 末尾在 `MYVK_LOG_RECTS` 下打 `NAV-CAM yaw=%.4f pitch=%.4f`
  （变化 > 0.02 rad 才打），给自动化脚本做数值断言。

## 第二轮：坐标系 Z-up + 工具栏精简 + 动画/Run 分离（用户 5 点需求）

**① Z-up 右手系（引擎级）**：世界 up Y→Z。改动点：
- `Camera`：`kWorldUp=(0,0,1)`；`angleDir = {cp·cos yaw, -cp·sin yaw, sin pitch}` —— **yaw 分量取负**是为了保住"yaw+=视线向右"的手感（Z-up 下 `d(forward)/dyaw = cross(forward, worldUp)` 依然成立）。视图映射：Front=相机在 -Y（yaw=+π/2）、Back=+Y、Right=+X（yaw=0）、Top=+Z（pitch=+kPitchLimit）。
- `Mesh.cpp` 基元：`toZup(p)=(x,-z,y)` 后处理 cube；plane 直接换基（n=(0,0,1),u=+X,v=+Y）；球体⚠**必须用旋转不能直接换 y/z 分量**（交换是 det=-1 的反射，绕序翻 CW 球会内外翻）——参数化写成 `{sinφcosθ, -sinφsinθ, cosφ}`。
- `MeshLoader.cpp` glTF：节点树根部预乘 `kYupToZup`（绕 X+90°），节点 TRS 随之转换。OBJ 不转（DCC 默认 Z-up 导出）。
- `grid.vert/frag`：地面 z=0（`world=vec3(x,y,offset)`、`p=vWorld.xy`）、轴线 X 红/Y 绿。
- `ShadowPass` up 兜底互换；`GizmoController::planeBasis` 参考 up→+Z、`right=cross(fwd,(0,0,1))`；`Renderer` `yOffset`→`planeOffset`；`EditorScene` 贴地改 `box.min.z`、SpotLight 默认朝下 (0,0,-1)、机位 target z=0.5。
- 验证：verify_nav_gizmo.py 四断言 PASS（点 Z+ 球→Top、1→Front、3→Right、7→Top）；verify_asset_drag.py 真鼠标拖拽 `box.min.z=-0.5→bottom=0.0000` PASS（glTF Y-up 转换后 box01 直立贴地）；冒烟两趟 exit=0。

**② 工具栏精简**：`Toolbar::drawPlayControls`→`drawBar`。Save/New→File 菜单；Move/Rotate/Scale→视口工具条；Fullscreen→F/F11；播放按钮→Content 底行。工具栏只剩左侧 gizmo 模式提示文字 + 右对齐 Undo/Redo。

**③ Run 与动画语义分离**：
- `EditorContext::AnimState{Stopped,Playing,Paused}` + `animPlay/animPause/animStop`：动画=**编辑场景自身**跑脚本；animPlay 先拍 JSON 快照，animStop 用快照整体恢复（+applyEditorCameraMode+清 undo 历史+置 dirty）。与 Run 互斥：play() 时丢弃动画快照，animPlay 在运行态被拒。
- `EditorApp::runScriptsOn(scene,t,dt,errors,tag,frame)` 共用内核；runRuntimeScripts/runAnimScripts 两个薄包装；m_animFrames/m_animErrors 独立于运行态。
- **播放条在 ContentBrowser 底行**（就是原 "N entries | path" 那行）：Run（绿，运行中变红 "Exit Run"）+ 动画 Play（青蓝）/Pause（琥珀）/Stop（红，animActive 才可用）；统计文字右对齐，面板窄到放不下就整个省略（截断更难看）。
- Space 仍然 = Run 的 play/pause（togglePlayPause 未动）。

**验证脚本同步**：verify_asset_drag.py 正则 `box.min.y`→`box.min.z`；verify_nav_gizmo.py 点球目标 绿Y+→**蓝Z+**（键位断言数值恰好不变）。

### ③ "四边形的阴影" —— 4 个引擎级 bug 叠加（全部修掉）
复现：Cube+Cylinder 在场时，地面被一条**笔直的硬边**切成"暗四边形 + 亮区"。

**(a) 阴影正交范围退化（`engine/render/Renderer.cpp`）**
原来只用**实体世界原点**算包围盒（`worldMatrix(e)[3]`）：单个物体 → 包围盒退化成 1 个点 → `radius = 0+2 = 2m`。阴影贴图只覆盖原点 ±2m，屏幕上就是一块方形边界。
→ 改为遍历**投影物体**（`forEachShadowCaster`）用**网格世界 AABB**（局部盒 8 角过世界矩阵）：`radius = 半对角线 + 2`。无投影物体时以 `camera().target()` 为中心给 25m 兜底（不再用原点±2m，否则边界正好在镜头里）。
实测：Cube+Cylinder → `casters=2 center=(1.10,0.70,0.50) radius=4.06`（与解析值一致）。

**(b) 阴影深度空间 GL[-1,1] vs Vulkan[0,1]（`ShadowPass.cpp` + `pbr.frag`）**
`glm::ortho` 输出 OpenGL 约定 z∈[-1,1]，而 Vulkan 只在 clip z∈[0,1] 内保留几何 → 阴影图写进去的深度与 `pbr.frag` 采样时算的参考深度**不在同一空间**，覆盖区内一切表面被判"被遮挡"（暗），覆盖区外 `return 1.0`（亮）→ 暗四边形。
→ `glm::ortho` → **`glm::orthoRH_ZO`**（近=0 远=1，GLM 1.0.1 的 `gtc/matrix_transform.hpp` 已含）；`pbr.frag::shadowFactor` 改成**只对 xy** 做 `*0.5+0.5`（z 已经是 [0,1]，再压一次会变成实际深度的一半）。

**(c) `envColor` 用错"上"轴（`pbr.frag`，Z-up 遗留）**
`float t = dir.y*0.5+0.5` —— 本引擎是 **Z-up**，"朝上"是 `dir.z`，用 dir.y 等于让环境天空梯度沿世界 **+Y（水平方向）** 变化 → 地面出现"近处暗、远处亮、中间一条硬边"的明暗带。
→ 改 `dir.z`。逐行中位数亮度剖面的硬台阶（-15）消失，剖面变成平滑梯度；法线贴图色彩空间修好后最大单步跳变从 -51 降到 -1。

**(d) 默认"平坦法线"贴图被当成颜色贴图建（`Texture::makeSolid` → `fromPixels` srgb 默认 true）**
`Renderer::createDefaultTextures` 的 flatN=(128,128,255) 若建成 `R8G8B8A8_SRGB`，硬件采样时 sRGB→线性解码 → `(0.216,0.216,1.0)` → `nSample = *2-1 = (-0.568,-0.568,1.0)`，即"平坦法线"其实被整体**扳了约 39°**。大面片（地面）上切线基 TBN 一退化（`cotangentFrame` 的 `m<1e-12` 兜底分支切换）法线朝向整块翻 → 又是一条笔直硬边（N.z 看不出，N.x/N.y 翻了）。
→ `makeSolid(..., uint32_t size = 4, bool srgb = true)` 加显式色彩空间参数；默认白 ORM 与平坦法线都传 `srgb=false`；`m_source.srgb` 同步记录。**数据贴图（normal/ORM）必须 UNORM，颜色贴图（albedo/emissive）才 SRGB。**

### 定位方法论（值得复用）
- 先在 `Renderer` 加 `MYVK_SHADOW_DBG`（env 门控）打 casters/center/radius → 立刻确认"空场景 casters=0 却有暗区" ⇒ 不是阴影。
- 着色器二分：把中间量当 `outColor` 直接输出（`vec3(NdotV, specDir.z, N.z)`），一次跑一张三通道探针图；再用**常量输出** `vec4(0.5,0.5,0.5,1)` 排除后处理/帧缓冲。
- 图里量不出结论就**转数值**：逐行取中位数亮度（排除栅格线），找"最大单步跳变"的位置/幅度，比肉眼可靠得多。

# 追加：同日第二轮（缩放轴错位 + Material 面板纹理小方块）

## 需求（用户原文要点）
1. 3D 视图切到 Scale 调整大小时，拖 Y 轴却在 Z 方向拉伸、拖 Z 轴却在 Y 方向拉伸。
2. 纹理贴图直接在 Material 栏添加：Base Color / Roughness / Metallic / Emissive
   右侧各放一个**带加号的小方框**，贴图拖进去即生效，成功后框里显示**文件名**。

## ① 缩放轴错位 —— 根因不是"抓错轴"，是"写错维"
- `TransformComponent::scale` 是**局部**的（`localMatrix = T·Rx·Ry·Rz·S`），缩放作用在
  **物体自己的三根轴**上；而手柄拖的是**世界**里的方向。物体一转，两套轴不再重合 →
  旧代码 `sc[axisIdx] = m_startScale[axisIdx] * factor;` 把"世界里的倍率"直接塞进
  "局部分量"，必然写错维度。
- 实测复现（`tools/_probe_gizmo_scale.py`）：绕 X 转 90° 后拖 Y → `scale.z` 在变（竖着长）、
  拖 Z → `scale.y` 在变（横着长）—— 与用户描述逐字一致。日志
  `gizmo begin: handle=Y ... axis=(0,1,0)` 证明手柄**抓对了**，问题在映射。
- **修法**：把拖拽方向**投影到物体的局部轴**上再分配缩放量
  ```cpp
  for (i) w[i] = |dot(axis, localAxisWorld[i])|;        // 单轴手柄
  for (i) w[i] = |dot(U, L[i])| + |dot(V, L[i])|;       // 平面手柄（两条腿）
  sc[i] = m_startScale[i] * (1 + (factor - 1) * w[i]);
  ```
  轴对齐时 w 退化成 (1,0,0) 之类 → 与旧行为一致；物体转过之后自动落到对得上的那一维。
  整体等比（既非单轴也非平面）与朝向无关，`sc = m_startScale * factor` 保持原样。
- 新增 `m_localAxisWorld[3]`（恒定局部轴）与 `m_dragLocalAxes[3]`（拖拽开始时冻结），
  `beginDrag()` 冻结并打一行 `localX/localY/localZ` 供自动化断言。
- **可断言的不变量**：不是"拖 Y 改 scale.y"，而是
  **"物体在世界里长大的方向 ≈ 被拖手柄的世界方向"**；
  长大方向 = `Σ(Δscale[i] · 局部轴 i 的世界方向)`。

## ② Material 面板的六个"属性 + 小方块"纹理槽
- `Material` 新增 **roughnessMap / metallicMap / emissiveMap** 三个独立槽。刻意**不复用**
  `ormMap`：UE5 语义是每个因子各挂一张图，而 ORM 是打包图，共用槽会让"只想换粗糙度"
  变成"必须提供打包图"。
- 与因子的合成方式：roughness/metallic **相乘**（默认绑**纯白** → 恒等）、emissive
  **相加**（默认绑**纯黑** → 恒等）。用"加白"会让所有没绑自发光图的材质整片发白光。
- `Renderer`：新增 `m_defaultBlack`；`kTextureSetCount` 3 → **6**；主前向管线与栅格管线的
  `setLayouts` 都从 4 个扩到 **7** 个（字段数不一致会报 VUID-...-08600）。
- `assets/shaders/pbr.frag`：新增 `set = 4/5/6` 的 `roughnessMap/metallicMap/emissiveMap`。
- sRGB：颜色贴图（albedo/emissive）`srgb=true`，数据贴图（normal/orm/roughness/metallic）
  `srgb=false`；**必须编进缓存键** `slotCacheKey(rel, srgb)`，否则同一张图当两种用途
  会拿回同一份 GPU 纹理（法线被 gamma 一次 → 光照方向全歪）。
- UI（`InspectorPanel::drawTextureChip`）：`ImGui::Dummy(w, kChipH)` 占位 —— 它给 ItemAdd
  传的 ID 是 **0**，而 `BeginDragDropTarget()` 在 ID 0 时退回 `GetIDFromRectangle()`，
  所以**整个方块天然就是落点**，不需要额外的 `InvisibleButton`。空槽 = 22px 小方块 +
  正中两笔画出的 `+`；绑定后向右长成"缩略图 + 文件名"胶囊（宽度受面板剩余空间限制），
  右键清空。
- 行布局：`SetNextItemWidth(kFactorWidth)` 定宽控件 + 标签，`chipRow` 用
  `ImGui::SameLine()` 把方块接在标签右边。**不钉固定列** —— Inspector 默认只有 ~315px，
  "定宽控件 + 标签 + 槽位"三样塞不下，标签会被压扁、槽位会叠到控件上（试过，截图可见）。
- `SceneSerializer`：写 `roughnessMap/metallicMap/emissiveMap`；读盘后**必须显式补写** ——
  `makeMaterialPBR` 命中名字缓存时不会碰这几个新字段，不补就静默丢失。

  而透视投影下"62% 的世界长度"在屏幕上的占比会超过 62%。改 `GRAB_T = 1.0`（轴端）。
- 抓错手柄时物体已经被改了 → 断言前**先更新基准 prev**，否则后面每条都跟着假失败。
- `endDrag()` 开头先把 `handleName()` 拷走：下面会清 `m_dragHandles`，否则日志/状态栏
  只能打出 `-`（实测到的既有 bug）。
- 假失败：albedo 槽的"空态"断言 —— 空场景的 Ground 材质本来就带一张默认底色图
  （`_default_tex`，纯浅灰），上屏就是"已绑定"、宽 114px。测试对它豁免空槽检查。
  （截图里 Base Color 行那个灰方块就是这张图的缩略格，chip 仍是单块，不是多画了一个。）
- `fitText(name, availPx)` 按 `ImGui::CalcTextSize` 逐字退、**从左边截**（保住扩展名）；
  按字符数截是"显示宽度"不是像素，会溢出。
- 首个拖拽偶发丢事件 → 每个槽 3 次重试。
- `MYVK_EDITOR_SCENE` 指向不存在的文件时，编辑器是"**空场景 + 默认地面**"（`resetToEmptyScene`

## ② 碰撞体系统
**engine/physics/ 四个新文件**：
- `ConvexHull.{h,cpp}` —— **QuickHull**（期望 O(N log N)，Bullet/PhysX/CGAL 的默认三维凸包算法）。
  必须配**冲突表（conflict list）**：UV 球 1150 顶点/1150 面的输入，无冲突表 = 15 亿次距离计算。
  核心循环：最远点 → 泛洪收集可见面（stamp 访问标记，与 dead 分离）→ 地平线边 → p+地平线重建面 →
  重分配冲突点。外侧判据 `dot(n,p)-d > eps`；退化面（Plane 共面输入）`d=+inf + dead=true`；
  `maxIterations = N*4+64` 防死循环。
- `ConvexShape.{h,cpp}` —— `Kind{Hull,Capsule,Sphere}` + `supportLocal(dir)` +
  `TransformedShape::support(worldDir)`。**支撑函数与变换**：`support_{M·S}(d) = M·support_S(Mᵀ·d)`
  （`glm::mat3 dirXform = glm::transpose(glm::mat3(xform))`）——方向按 M⁻ᵀ 变换，**非均匀缩放也精确**。
  胶囊轴 = 局部 +Z。
- `ConvexCollision.{h,cpp}` —— **GJK + EPA**：`gjkIntersect`（两凸体相交 ⟺ 原点在 Minkowski 差内）
  与 `collide`（EPA 求 MTV）。用"最近点+单纯形约简"写法（Ericson §5.1.5），**不依赖绕序**：
  四面体面朝向用 `originOutsideFace(a,b,c,opp)` 对顶点定向；EPA 初始 4 面按 `n·v>0` 定向。
  接触点 = `0.5*(a.support(n)+b.support(-n))`。**glm 这个版本没有 `length2`** → 用 `glm::dot(v,v)`。
- `CollisionWorld.{h,cpp}` —— 场景级：`setupHullCollider/setupCapsuleCollider`（按 mesh AABB 拟合）、
  `refreshHullGeometry`、`meshAabb/colliderLocalAabb`（"刚好包裹"断言用）、
  `collectColliders`、`resolveBodyOverlaps`（4 轮：AABB 粗筛 → collide → 各推一半 → **立刻重建这俩
  collider**，避免同轮用旧矩阵重复判同一对）、`resolveCamera`（半径 0.25 球推出，`pos -= n*(depth+ε)`）、
  `translateEntityWorld`（分离改实体 position，世界位移用父节点世界矩阵的逆换回局部）。
- **"刚好包裹"的默认摆放**：凸包/胶囊顶点按 AABB 中心**居中**，平移记进 `cc.position`。
  居中很关键——否则缩放手柄会把碰撞体从实体原点往外拉而不是绕自己放大。
  胶囊拟合：轴=AABB 最长维（转局部 +Z），半径=另两维半长的**外接圆**半径（内切会让角露在外面）。
  退化凸包兜底：Plane 共面输入 → 2cm 厚薄板（零体积集合上 GJK/EPA 退化）。

**组件与序列化**：`ecs::CollisionComponent{shape,position,rotation,scale,capsuleRadius,
capsuleHalfHeight,hullPoints,hullEdges,solid}`，`localMatrix()=T·Rx·Ry·Rz·S`（与 TransformComponent
字段名/类型/欧拉序完全一致 → 手柄数学零改动，只换指针）。序列化只存 7 个参数，**凸包顶点不存**
（读盘后按 mesh 重建）。

**编辑器**：
- 右键菜单（`ViewportPanel::drawObjectMenu`）：右键按下记位置+pick 判"按在选中物上"；松开位移
  **<6px** 才算点击（与右键转相机共存，UE 同款判定）。菜单：Add Collision Body ▸ Convex Hull
  (QuickHull)/Capsule、Remove、Edit with W/E/R、Solid。tag 带 `#<seq>`（logRect 去抖）。
- 碰撞框线框（`editor/ColliderView.{h,cpp}` 新建）：**走 ImGui draw list 不走 3D 管线**
  （免 PipelineLayout/描述符同步；天然 X-ray 透视可见，UE 碰撞线框也这样）。
  凸包"边"必须从面提取（顶点两两连会糊成一团）。颜色：青(空闲)/金黄(选中)/橙(编辑中)。
  只读遍历用 **const** `w.each<T>`（非 const 会为不存在的类型建空池）。
- 手柄支持碰撞体：`GizmoController::TrsPointers`（编辑态换指针读写 CollisionComponent）；
  `m_onCollider` 时世界矩阵 = `worldMatrix(entity)*cc.localMatrix()`；endDrag push
