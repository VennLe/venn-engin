## MinGW 链接失败：dbghelp（11-04，用户报 `[337/341] Linking Game.exe` FAILED）

症状：`libVennEngine.a(LuaSelfTest.cpp.obj): undefined reference to
__imp_SymFromAddr` 等 7 个符号，**只有 Game.exe 炸，Editor.exe 正常**。

根因：`engine/script/LuaSelfTest.cpp` 的崩溃处理器用 Sym*/StackWalk64，靠
`#pragma comment(lib, "dbghelp.lib")` 带库 —— **这条只有 MSVC 认**，g++ 静默忽略。

为什么 Editor 不炸（别被它骗了）：`LuaSelfTest.cpp.obj` 在 `libVennEngine.a`
里，静态库只把**被引用**的 obj 拉出来；全仓只有 `runtime/main.cpp`（`--selftest
lua`）调 `runLuaSelfTest` → 链接 Editor 时那个 obj 根本没参与。**"Editor 过了"
不能证明库链全了，只有 Game 会说话。**

修法：`CMakeLists.txt` 的 WIN32 分支加 `dbghelp`（`-ldbghelp` 进命令行），
源文件里的 pragma 用 `#if defined(_MSC_VER)` 包住并注明"两边都得留"。

### 顺带两条工具链教训
- **别在后台把 ninja 管进 `Select-Object -Last N`**：g++ 有 warning 输出时会被
  管道背压卡死，两个 g++ 0% CPU 挂了 27 分钟，kill 后重跑 29 秒就完。
  后台构建一律 `> build/_x.log 2>&1`，再 tail 日志。
- `ScriptRuntime.cpp` 那 10 条 `unknown conversion type character 'z'`
  （`%zu`）是 **MinGW 的误报**：实测 `VK_LOG_INFO("total=%zu", 42)` 打出
  `total=42`。想消掉得把 `Logger.h` 的 `format(printf,2,3)` 在 MinGW 下换成
  `gnu_printf`（会触发全量重编，暂不动）。

## ★ 最值钱的一条：ImGui 一直在做**两次** sRGB 编码

症状：顶栏像一条"白杠"、整个编辑器发灰、文字对比度被压平。
取样：菜单栏屏幕值 `(95,96,99)`，主题里写的是 `#1D1E20 = (29,30,32)`。

根因：交换链是 `B8G8R8A8_SRGB`（硬件在写入时做 linear→sRGB），而 ImGui 的
顶点色**本来就是 sRGB**，后端自带的片元着色器又原样写出去 → 编了两次。
`0.1137 → 0.370 → 95`。`ui2.frag` 顶部早就写过这个坑（"漏掉反编码整块 UI
亮一大截"），但只有引擎自己的 UI 通道做了反编码，**ImGui 这条路径一直漏着**。

修法：`ImGui_ImplVulkan_InitInfo::CustomShaderFragCreateInfo`（1.93 新口子）
换掉片元着色器，`assets/shaders/imgui.frag` 里做精确 `srgbToLinear`。
**不碰 third_party**（后端 shader 是预编译 SPIR-V 数组，改不了）。

⚠⚠ 只反编码**顶点色**，贴图不能碰：UI 贴图（类型卡插图/封面/缩略图）都是
  `loadTexture(..., srgb=true)` → 采样时硬件已解码，再解一次插图黑一大截
  （实测 152→79 / 113→43 / 96→32，截图均值和源图一对比就见分晓）。
  字形图集是 UNORM + 白色 RGB，两种写法都对 —— 所以"只解顶点色"是唯一安全解。
验收口径：菜单栏应读到 **29**（读到 95 就是漏了这步）。

**连带发现**：动漫档的 `darkenThemeColors(t, 1.45)` 就是给这个显示 bug 打的
补丁（注释原话"这台机器的交换链会把 0.106 显示成 RGB 92"）。`pow(c,1.45)`
对暗部是乘性压缩，压完 `frameBg` 与面板底**只差 1 级** → 输入框、下拉框、
未勾选的勾选框全成"只有字没有框"。现在压暗之后按**加法**重排一次控件层
阶梯（加法在深底上的绝对差不会被幂函数吃掉）。

## 观感两条：地面"镜面反射" + 夜晚"太蓝太亮"（2026-11-05 晚）

用户原话：`1.地面的镜面反射效果太强了，你放大看看非常的明显… 2.天气与大气的

这里只留**判据与反直觉点**：

- ⚠⚠ **夜里的"湿地 / 镜子"主要是 IBL 环境镜面，不是 SSR**。实测：关 SSR 地面
  亮度只变 2~3%；关 IBL 地面 lum 28 → **153**。所以"地面像镜子"先查
  `sky.ibl` 的环境反射，别一上来改 SSR。
- ⚠⚠ **改天空会连带重烘 IBL**：`setSkyParams → m_skyDirty → tickSkyRebuild →
  Environment::rebuild()` 把 irradiance / prefilter 一起重做。这既是"夜空压暗
  之后地面不再泛蓝"的原因，也意味着**动夜空就动了所有物体的环境光**。
- ⚠⚠ **`sky.ibl=false` 不能当"关 IBL"的对照**：那条旧路径用**写死的**解析天际色
  （`envColor()`），不跟天空预设 —— 夜里亮到 lum 153，拿它当参照会得出反向结论。
- ⚠ **SSR 菲涅尔必须按粗糙度收敛**：全屏 pass 拿不到逐像素材质，旧式
  `0.04+0.96(1-NdotV)^5` 对水平地面（NdotV≈0.1）算出反射率 0.6 → 地面叠 36%
  倒影。新增 `ssr.roughness`（默认 0.72，`MYVK_SSR_ROUGHNESS`），
  **取 0 与原公式逐字等价** → 拿它做 A/B 不需要旧二进制。
- `SsrPush` 112 → **128 字节**；链 pass 的 `pushConstant.size` 本来就是 128，
  不用改（但要记着这 16 字节余量已经用掉了）。
- ⚠⚠ **`find_window("Venn Editor")` 会抓到别人的编辑器**（桌面上可能开着第二个）。
  驱动脚本必须按 **PID** 枚举窗口 —— 否则截出来是旧画面、`WM_CLOSE` 关掉的是
  用户正在用的那个（本轮真踩了，用户的编辑器被我关掉）。
- ⚠ 天空面板是**浮动窗口、id = `environment`**；不想点 UI 就直接

## ⚠⚠ 一个 ImGui 的槽位冲突（会再踩）

# 角色模型这块：UE 的四个分层 + 抄过来的两件事（2026-11-05 深夜）

用户原话：
> "继续学习下关于角色模型这块的处理逻辑，借鉴下其中比较好的部分"

## UE 的角色资产是**四层**，我们只有两层

| UE | 我们 | 差别 |
|---|---|---|
| `USkeleton`（骨架资产，多网格共享）| `assets::Skeleton` 挂在 `Model` 里 | 两份 FBX 用同一套 rig → 两份骨架，动画片段也不共享 |
| `USkeletalMesh`（网格 + LODInfo + 材质槽 + 插槽）| `assets::Model` + `SubMesh` | 没有资产级插槽、没有 per-LOD 覆盖 |
| `USkinnedMeshComponent`（实例：LeaderPose / 可见骨 / 包围盒策略）| `ecs::SkinnedMeshComponent` | **原来没有 LeaderPose** |
| `UPhysicsAsset`（布娃娃刚体 + 约束）| 无 | 未做 |

关键结论：**模块化角色（身体/头发/衣服分开导出）在 UE 里不是"多个角色"，
是一个角色 + 若干 follower 组件。** 我们这边每个 Mesh 各自采样，症状是
"跑起来头发比身体慢半拍"，而单看每一份都是对的。

## 抄 #1：`FReferenceSkeleton::BoneNameToIndexMap`

`findJoint` 原来是 `for 每根骨 { 复制一份小写串; 比较 }` —— 100 根骨 ×
每帧十几次调用 = 每帧上千次 `std::string` 构造/释放。改成懒建两张表
（原样名 / 小写名）+ 一份小写名数组，精确轮 O(1)、包含轮只读现成数组。

⚠ 三条语义必须逐位保住，自检里各有名字钉着：
  · 重复名取**数组里第一个** → 建表用 `emplace`（不是 `insert_or_assign`）；
  · 精确轮压过包含轮（`hand_end` 不许退到 `hand`）；
  · **失效口径**：`joints` 长度变了自动重建；长度没变但**名字改了**
    （`RigEdit::bake` 从旧骨架拷出来，骨数可能一样）必须显式
    `invalidateNameIndex()` —— 否则"新名字查不到、旧名字反而查得到"。

## 抄 #2：`LeaderPoseComponent`

`SkinnedMeshComponent::leaderName`（存**实体名**，不存 id —— 与
`BoneAttachmentComponent::hostName` 同一条理由）。`AnimatorSystem::tick`：

  1. **预扫描**：`follower id → leader id`，同时记下"谁被指为 leader"；
  2. **主遍历**：follower 直接 `return`（不采样/不分层/不跑 IK/弹簧 ——
     弹簧尤其不能跑，质点会被推两次然后漂掉）；
  3. leader 算完 `poseToJoints` 后，**只对"被指到的"** 留一份**局部姿态**副本；
  4. **后处理**：`buildLeaderBoneMap` + `remapPose` → follower 自己的
     `poseToJoints`。位置在挂点之前（否则帽子跟着上一帧的头走）。

**为什么抄局部姿态而不是 UE 的 component-space**：两者在"同名同层级"的
骨架上代数等价（`world(j) = world(parent)·restLocal(j)`）。而且 follower
多出来的骨（裙摆/发梢）**天然**就是 `world(祖先)·自己的 restLocal` ——
正是 UE 在 `GetMissingLeaderBoneRelativeTransform()` 里沿父链上溯拼出来的
那个 `CommonAncestorBoneIndex + RelativeTransform`。同一个式子，一个顺带
算出来，一个专门拼出来。

⚠ 只做**精确匹配**（不分大小写），不含 substring：`hand_l` 匹到
  `hand_l_end` 的后果是"整只手反着长"。
⚠ 缺 leader → **回退自采样**（不是定在上一帧）。统计口径
  `followers = applied + missing`，ANIM-LEADER 一行报三个数。

## 没做、但看清楚了的三件事

1. **资产级插槽**（`USkeletalMeshSocket`：SocketName / BoneName /
   RelativeLoc·Rot·Scale / bForceAlwaysAnimated）。我们的挂点是运行时组件
   + 每实体各填一遍偏移；UE 是资产里的命名锚点，代码按名字取。
2. **per-LOD 覆盖**（`FSkelMeshComponentLODInfo`：HiddenMaterials /
   OverrideVertexColors / OverrideSkinWeights / SkinWeightProfileStack）。
   我们连骨骼网格的自动 LOD 都还没开（`Lod.h` 里写着为什么顶点聚类不行）。
3. **包围盒策略**（`bComponentUseFixedSkelBounds` /
   `bUseBoundsFromLeaderPoseComponent` / `BoundsScale`）：UE 明确不每帧按
   顶点算包围盒。我们现在拿静止姿势的 bounds，暂时够用。
