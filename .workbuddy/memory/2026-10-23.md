## 下午轮：启动器推荐分辨率 + 角色走路卡顿/陷地（用户第二轮反馈）

- **启动器 Step3 默认分辨率**：`Window::primaryMonitorResolution()`（`glfwGetVideoMode`，
  桌面真实分辨率，不扣任务栏）。`onInit` 里同步WizardRoot 后填初值：命中预设选预设、
  否则 preset=3(Custom) 预填桌面值；**必须放在 `MYVK_LAUNCHER_TEST_RES` 之前**（env 显式 > 猜默认）。
  本机实测 2160×1440 → preset=3 ✅（kit 探针验证）。日志锚点 `LAUNCHER-WIZARD res-default=`。
- **编辑器 Play 走路卡顿根因**：runPlayers 下坡分支"比新地表高 0.02m 就交给重力"→
  起伏地形每帧掉出贴地窗口 → `onGround` 反复翻 false → 状态机 walk↔jump 横跳
  （restartOnSwitch 每次从头迈步）。修法：落差 ≤ 本帧步长×tan(slopeLimit)+0.02 →
  贴地跟随；真正的坡沿才掉下去。
- **陷地根因**：贴地只取胶囊**中心**一个点的 heightAt → 斜坡上前脚那半边地表更高，
  模型脚插进坡面。修法：editorGroundHeight 取**足迹内最高点**（中心+±r 四点 max，
  r=cc.radius）；运行时 PlayerController 在 stepCharacter 之后同样抬到足迹 max
  （只对 onGround 生效，不碰抛物线）。verify_player_ground 8/8（G4 gap 上限变 +0.039，
  容差 0.30 内）。
- **验收**：launcher_display PASS / player_ground 8/8 / player_jump 10/10 / char_locomotion 15/15。
- **坑**：Launcher.exe/Editor.exe **正在运行** → 增量链接 exit 1168（ERROR_NOT_FOUND）。
  先问用户再 taskkill（编辑器里有未保存场景）。下坡跟随没有独立用例，后续可补。
