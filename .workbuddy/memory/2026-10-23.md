## P7 · 编辑器加角色点 Run 就崩（0xC0000005）

用户报："在引擎编辑器3D视口中，我添加了一个第三人称角色，然后直接点击运行游戏，
然后引擎编辑器直接崩溃退出了。"

### 根因（不是角色，是地形高度场的所有权）

`ScenePhysics::attachTerrain` 把 `Heightfield::heights` 指向
`SceneBinding::terrainHeights`（vector<float>）的堆内存。而
`EditorApp::buildPhysicsWorld` 里 `SceneBinding binding` 是**局部变量**，
只 `std::move(binding.world)` 把世界搬走 —— 函数返回，vector 析构，
`m_physics->heightfield()->heights` 从此悬垂。

它在 P6 之前不爆，是因为**编辑器里没有代码读 heightfield**；P6 给编辑器 Play
加了 `editorGroundHeight()`（贴地要读地形），一按 Run 就踩雷。

### 定位手法（没有 pdb）

WER 只给了 `Editor.exe+0x1ec64e` + `0xc0000005`。直接
`objdump -d --start-address=0x1401ec58c` 反汇编，偏移落在
`physics::Heightfield::raw()` 的 `movss (%rax)` 上，而 `rax = *(hf+0x18) +
(col*rows+row)*4` —— `+0x18` 正是 `heights` 字段（cols0/rows4/mpp8/
heightScale12/origin16/heights24）。raw() 里 col/row 已钳制 → 不是越界下标，
是**指针本身死了**。这条链路一步到位，值得记住。

### 修法

`PhysicsWorld::setHeightfield` 从"借指针"改成**拷一份**：
`m_terrainOwned`(unique_ptr<Heightfield>) + `m_terrainHeights`(vector<float>)，
`heights` 指向自己的 vector。258 KB 一次性拷贝，换掉一个悬垂崩溃。
`SceneBinding::terrainHf/terrainHeights` 保留但不再承担所有权（头文件注释已改）。
RuntimeApp 原先靠 `m_binding` 当成员侥幸没事，现在这条隐性依赖也消失了。

### 对照实验（关键）

同一份代码只换场景：sandbox（无 Terrain）alive；water_bowl（有 Terrain）
**必崩 0xC0000005**；修复后 water_bowl alive 且 `z=1.708` 稳定。
用 `git stash push` 只暂存 PhysicsWorld.* 做了这个对照，验证完 pop 回来。

## P8 · 编辑器 Play 的鼠标两态（点视口接管 / Esc 交还）

用户报："游戏启动运行后，必须要鼠标左键在 3d 视口中点击后才能开始正常和
游戏画面内的角色开始交互操作，并且此时鼠标是隐藏不显示的。按下 Esc 键，
此时就正常显示鼠标。"

运行时 Game.exe 早在 P5 就有这套（`RuntimeApp::m_mouseCaptured`），
**编辑器 Play 一直没有** —— 这次补的就是编辑器侧。

### 改了什么

- `engine/core/Input.h/.cpp`：新增 `mouseDeltaRaw()` —— 不受 `setUiCapturing`
  门控。捕获态下 ImGui 鼠标被关掉（`io.MouseDelta` 恒 0）、`WantCaptureMouse`
  又把普通 `mouseDelta()` 掐死，只有 raw 能读到。
- `EditorContext.h/.cpp`：`m_playMouseCaptured` + `m_playCaptureRequested` +
  `m_playCursorDirty`。`play()/pause()/stop()` 一律复位；进 Play 那次**直接
  置脏**（绕开"值没变就不脏"的短路），否则 `captured=0` 锚点打不出来。
- `ViewportPanel.cpp`：Play 态 + 未捕获 + hovered + 左键 → `requestPlayMouseCapture()`
  + 锚点 `PLAY-CLICK`。Play HUD 多加一行提示（"点视口接管"/"操作中 - Esc 取回"）。
- `EditorApp::updatePlayMouse()`：请求→接管、非 Playing 强制交还、脏了才改
  `window().setCursorVisible()` + `ImGuiConfigFlags_NoMouse`，锚点 `EDIT-MOUSE`。
- `EditorApp::handleShortcuts`：Play 态 Esc 改成 **if/else 分流**（先交还鼠标，
  鼠标已可见才退全屏），并在 `runPlayers` 里用 `active = playMouseCaptured()`
  门控视角/WASD/跳跃/冲刺（**重力与贴地照跑**，否则空中按 Esc 会悬在天上）。

### 两个真 bug

1. **Play 期间内容区不一定是 3D 视口**：`drawPanels` 里
   `hosted = viewportTabDrawnPanel()`，用户把标签切到 Scripts 等页后按 Run →
   `hosted >= 0` → **视口整块不画**（`ViewportPanel::draw` 根本不执行），
   表现是"游戏跑起来了但看不见画面、也点不到视口"。修法：
   `hosted = isEditing() ? viewportTabDrawnPanel() : -1`。
   这条花了 5 轮诊断才定位（PLAYDBG 打点法：先证明 ImGui 收到了左键，
   再证明面板没执行，最后查 drawPanels 的 hosted）。
2. **未接管时鼠标划过视口就转镜头**：`if (mouseInViewport) yaw += ...` 在
   编辑态合理，Play 态等于"光标路过就转"。改成只在捕获态转。

### 验收基建的坑（值得记）

`verify_player.py` 的鼠标注入是 `PostMessage(WM_MOUSEMOVE, 逻辑坐标)` +
`SetCursorPos`。**捕获态下这是错的**：GLFW 在 `CURSOR_DISABLED` 算 delta 用
`x - lastCursorPos`，而它每帧 warp 光标回中心并刷新 lastCursorPos —— 逻辑坐标
一旦不同步，delta 会反号（实测"下移"变成"抬头"）。捕获态改用
`mouse_event(MOUSEEVENTF_MOVE, dx, dy)`。
教训：验收的注入方式必须与被测真实输入路径同源。

## P9（2026-10-23 晚）· 移动+转视角"卡顿" + 笔刷圆环变形

用户报两条：
1) "游戏运行后，角色在移动时尤其是鼠标移动转换视角时，明显感觉角色动作在

2) "在 LandScape 地形模式下，Raise/Lower 这个笔刷操作地形时，笔刷的圆圈明显
   在变形。"

### ① 卡顿 = 时基，不是动画

新增逐帧探针 `MYVK_LOG_DT=1`（`FRAME-DT` 锚点：dt / pos / animT 三合一），
配 `tools/_probe_frame_dt.py`。修复前实测（W + 甩鼠标）：
dt = 2.08 ms ± 0.63 ms（**抖动 31%**，480 fps）、速度 cv 0.7%、
ΔanimT/dt = 1.0000、状态切换只有 idle→walk→idle。

**结论：每一帧都是对的，脏在"这些帧什么时候被显示"。** 根因是
`Swapchain` 有 MAILBOX 就用 MAILBOX → 60 Hz 屏上跑 470~490 fps，
渲染帧与刷新非整数倍 → 合成器取样相位 ±12% → 匀速运动一顿一顿。

修法：新建 `engine/core/RunMode.h`（`automationRun()` + `vsyncEnabled()`），
Swapchain 默认 FIFO，`MYVK_VSYNC=0/1` 可覆盖，自动化（任何 MYVK_* 变量）
默认不锁；`core/Time.h` 加单帧步长上限 0.1 s（防长停顿后瞬移）。
修后 dt = 16.64 ms ± 0.82 ms（**4.9%**）、零尖刺、60.1 fps。

### ② 圆环变形 = 逐点改 z

`LandscapeEditor::viewportInput` 的 `projectRing` 原来每个环点写
`wp.z = heightAtWorld(x,y)`（贴着被自己推起来的地表）→ 环点爬上自己堆的
山包，投影后不是椭圆。改成整圈共用 `localHit.z`（水平圆盘，与 applyStroke
按 XY 筛选的作用区一致），段数 32→48，填充改 Convex，并修掉
"笔心十字画在 `outer[0]`（圆的右边缘）"这个 bug（应投影命中点）。

像素级判据：`r(θ)` 的非椭圆分量（水平圆的投影只允许 0/2 次谐波）。
半山腰 3.5% → 0.9%；峰峰 2.38 px → 1.21 px。

### 决定性坑：VRM 的 matrix_local 与网格 bind 脱节

Blender 的 glTF 导入器重建骨轴用启发式（只有 head、tail 是猜的）：
`LeftArm head=(−0.071,−0.009,1.271) tail=(−0.071,−0.009,1.480)`（指向头顶），
而真正的手在 `x=−0.497`、水平 0.43 m 外。于是**任何"搬源骨世界旋转"的做法
都绕错轴**：Copy Rotation WORLD → 扭成一团；rest-delta 换算 → 自检
`err=0.00000` 但手举过头顶（`POS LeftHand z=1.687 > 身高 1.652`）；
约束 + nla.bake → 同。

`err=0` 而画面错 = 错的是 `A` 这个量的**语义**，不是推导。教训：自检通过
不等于姿势对，**必须量"手在哪"这种可证伪的量**。

### 解法：不搬动画，用世界轴自己写

`RX/RY/RZ` 显式写世界 delta（左臂沿 −X 下垂 = `RY(∓72°)`，迈步 `RX(±25°)`），
再 FK 递推成 basis：`A[n] = (A[父] @ R_rest[父]⁻¹ @ dloc) @ dst_rest_local[n]`。
关键：蒙皮只关心 `W_t·W_rest⁻¹`，所以骨轴 roll 怎么歪都不影响 —— 用世界轴
写 delta 是安全区，搬别人的世界旋转不是。

## P11-续 · 资产接上后仍然播成 T-pose：两层根因

> ⚠ **上面 §P11 有两处说法被本人（下一轮）证伪，读旧段以本节为准：**
> 1. "解法"里那条 `A[n] = (A[父] @ R_rest[父]⁻¹ @ dloc) @ dst_rest_local[n]`
>    **是错的那一版**（把 rest local 当世界矩阵用）。正确写法见下面「根因 A」。
> 2. C5c 的采样间隔 0.45 s / 全窗口像素比**判不出 T-pose**，已改 1.0 s /
>    角色矩形内 / 阈值 0.15%。见下面「验收陷阱 2.0」。

现象：`ANIM-SKIN entity=2 clip=[Idle] play=1 joints=128`、帧率正常、日志全绿，
**画面却是不动的 T-pose**。两层根因叠在一起，拆掉任一层都复现不出来。

### 根因 A（烘焙侧）：`build_clip()` 把 rest **local** 当世界矩阵

`A[n] = (A[父] · R_rest[父]⁻¹) · D_local[n] · R_rest[n]` —— 对非根骨，rest
local 与 rest world 差着整条父链，`basis` 恰好抵消回 rest 旋转，**delta 被
自己吃掉**。证伪手段：直接解析 `.vmesh` 二进制，`Idle` 的 `LeftArm` 旋转是
`0.5736/0.8192` = rest quat **逐位相同**。

修：改用 Blender 官方 `matrix_basis` 语义 —— 绕**自己的头**转（世界轴），
父骨的搬动先继承：

```
M[n]    = M[父] · (T(h) · R · T(h)⁻¹)          h = rest4[n] 的平移
rel     = rest4[父]⁻¹ · rest4[n]
basis   = rel⁻¹ · (M[父]·rest4[父])⁻¹ · (M[n]·rest4[n])
basis(根)= rest4[根]⁻¹ · (M[根]·rest4[根])
```

自检改成**可证伪的物理量**：`LeftHand.head.z` 必须从 T-pose 的 1.264 掉到
胯部 `≈0.852`（`SELF Idle hand head=(-0.160,0.001,0.852) M_err=0.00000`），
脚本里硬编码 `if hand.head.z > 1.10: SELF-FAIL`。

### 根因 B（导出侧）：FBX 节点基础变换 = 导出那一刻评估出来的 pose

曲线全对，但导出时姿态停在最后一段 clip 的末帧 → FBX 把**那个 pose** 写成
节点基础变换 → AssetC 当 `restLocal`/`invBind` → `W_t·W_rest⁻¹ ≡ I` → 曲线
怎么变都原地不动。

修：导出前 `pb.matrix_basis = Identity(4)` + 清 action + 清 NLA + 打
`POSE-RESET` 自检（期望 `LeftHand head=(-0.497,-0.008,1.264)`，实测逐位相同）。

**四种导出模式都实测过，别再试**：

| 模式 | 结果 |
|---|---|
| NLA strips + 复位 | 四段 clip 全静止（AssetC `keys 0`） |
| NLA strips + `use_nla=False` | 同上（照当前 rest 姿势烤） |
| strips 静音 / 挪到帧 100+ / `extrapolation=NOTHING` | 导出器直接跳过，零 take |
| **all-actions + 复位** | ✅ rest 干净 + 曲线完整（`keys 3684`） |

代价：take 名变 `<armature>|<action>`（`ALICIA|Idle`）。

### `|` 前缀归一化：必须改**两处**

`Skeleton::findClip` 是 `c.name == name` 逐字比较，不加归一化（语义不动）。
归一化放在**读资产**这一步：`assetio/FbxImport.cpp`（AssetC 烤 vmesh）**和**
`engine/assets/FbxLoader.cpp`（运行期兜底）。只剥第一个 `|` 之前、且 `|` 后
必须有内容（`"A|"` 保留）。

> 踩坑：AssetC **只链 `VennAssetIO`、不链 `VennEngine`**（CMakeLists 第 768
> 行注释写了），所以只改 `FbxLoader.cpp` 时 `AssetC --info` 仍显示
> `ALICIA|Idle` —— 改了没效果先怀疑这条。

同时把 `ANIM-CLIP-MISSING n=.. clipName=[..] available=[..]` 升级成**正式保留**
的警告（治"静默退回 rest、日志全绿"这种失败）。

### 验收陷阱 2.0：C5c 第一版判 PASS 但角色是 T-pose

跑出 0.871% 判过，实际角色区域 diff **0 pixel** —— 那 0.871% 全来自视口里
`Click the viewport to take control` 这行 tooltip 的刷新。修法三条一起上：

1. 先点 `VTAB-viewport` 标签把预览窗口挤下去，**等 0.9 s** 让自动布局切完；
2. 间隔 **1.0 s**（Idle 幅度小，0.45 s 只有 ~0.03%，与文字刷新同量级分不开）；
3. 阈值 **0.15%**，且 `diff_ratio(a,b,rect)` **只算角色矩形内**。

修后实测 0.467~0.471%，静止 ≤0.05%。

### 脸部（唯一剩下的看得见缺陷）

第一次跑通贴图后脸是"白底 + 一个红嘴巴"。真相：`Alicia_face.png` 有 **97%
像素完全不透明**，它就是脸本身（肤色底 + 很淡的五官）；**眼睛在
`Alicia_eye` / `Alicia_eye_white` 两块独立网格上，位置在脸皮里面**，靠
MToon 的描画顺序盖上去。`.vmesh` 没有 `alphaMode`、导入材质一律 Opaque →
眼睛被脸皮整片挡住。

试过两条"离线删面"偏方，**都不成立**（写进脚本注释当教训）：
1. 按贴图 alpha 删所有透明面 → **身体的头整块被删掉**，变成一个洞。
   原因：`Alicia_body` 贴图头部本来就透明（等 face 层盖住）。
2. 只删名字含 face/mastuge/hair_trans 的叠层 → 还是"白脸 + 红嘴巴"，
   因为脸皮本身几乎全不透明，眼睛在它后面，抠不掉。

正解是给 `.vmesh` 加 `alphaMode` / 描画顺序（bump 版本 + 载入器 + 着色器
变体），超出这一刀范围，记为遗留。
