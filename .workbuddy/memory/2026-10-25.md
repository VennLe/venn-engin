# 2026-10-25

## 引擎「二次元 3D 游戏」定位差距审计

用户要求重新审视引擎是否适配"专门开发二次元风格 3D 游戏"的定位，检查重大缺陷并列出改进清单。
产出：`docs/anime_gap_audit.md`（完整审计报告，带证据行号 + 分阶段改造路线）。

**核心结论：渲染底座是"现代通用 3D 引擎"水准（甚至超前），但 NPR/表演层几乎全空。**
用 6 轮调研（NPR 能力 / 角色动画 / 工程健壮性 / 内容管线 + 变体机制）交叉验证，关键数据：

- NPR 着色 / 描边 / 面部 SDF / 表情（BlendShape）/ 头发物理 / 状态机 / IK / LookAt / 过场 / 对话 = **全部 0 行**
- 当前 Alicia 的"卡通感"来自贴图里烘死的渐变（`docs/alicia_import.md:44`），不是着色器算的 → 换光就崩

**三个"根因级"缺陷（不是缺功能，是架构挡路）：**

1. **着色器变体是全组合笛卡尔积** —— `ShaderKeywords.h:56-75` 只有 6 bit，`CMakeLists.txt:383-413` 用
   `foreach(MASK RANGE 0..1<<N)` 无条件全展开。实测 `build/bin/shaders/` 有 **128 个 pbr 变体**
   （64 组合 × pbr.frag + pbr.bindless.frag）+ 62 其他 = 190 个 .spv / 11 MB。
   NPR 要加 9 个新维度 → 15 bit = 32,768 组合 × 2 = **6.5 万个 .spv（约 5 GB）**。这条路物理上走不通。
   正解：按着色模型拆文件（toon.frag / toon_hair.frag / toon_eye.frag）+ 变体改**显式白名单** +
   Permutation Domain（分组互斥，组合数是"和"不是"积"）。**这是所有 NPR 工作的前置，必须第一个改。**

2. **材质是"单层 PBR 参数包"** —— 无 `sortPriority`/`renderQueue`/第二 UV/ramp 槽/MatCap。
   二次元的脸 = 脸皮+眼球+虹膜+睫毛+眉+腮红，靠**固定绘制顺序**叠加而非深度。
   加剧因素：`.vmesh` **不存 alphaMode**，导入一律 `opaque`（`MaterialImport.cpp:481-486`），
   项目自己已记录后果"眼睛被脸皮整片挡住"（`docs/alicia_import.md:367-375`）——**当前引擎连一张正常的脸都做不出来**。

3. **角色管线 = 一个 Model 一套骨架一段 clip** —— 顶点 80 字节 6 属性已用满（`Mesh.h:22-42`）、
   无 morph 通道、无 `findJoint`（无法挂点）、`AnimatorSystem` 无骨骼后处理阶段（做不了弹簧骨/看向）。

**工程债里最危险的 4 条**：
- `Renderer` 上帝类：6812 行 / **212 个数据成员** / `recordFrame` 单函数 805 行
- 错误单通道：`VK_CHECK` throw → `main` catch → 退出，**catch 里不调 `onShutdown()`** → 崩一次丢全部未保存数据
- 无 device-lost 恢复（项目自己已通过"逐帧重建+TDR"触发过）
- 编辑器 Play 与运行时是**两套玩家运动逻辑**（`runPlayers` 458 行 vs `stepCharacter`），代码自己在 `EditorApp.cpp:2254-2259` 承认

**顺带确认的事实（可选做）**：`verify_*.py` 130 个但零单元测试（104/130 是靠 grep 日志文本断言）；
`AssetManager` 4 张表**永不淘汰**；`m_lods` 以裸 `Mesh*` 为键；验证层**硬编码常开**（`Instance.h:5,15`）；
`docs` 里记录的已知 Vulkan 事故 3 次（设备丢失 / 20 对象泄漏 / 描述符池耗尽）。

**给用户的关键判断**：过去几轮的优化目标实际是"做高质量通用渲染器"，与"二次元"定位存在目标漂移。
PBR 与 Toon 在同一材质上无法共存（要么走物理正确要么走美术指定），所以 P0-1 变体拆分不只是性能优化，
它是"两种世界观能否在同一引擎里共存"的架构前提。

## 晚：P0-1 落地（变体白名单） + A1 赛璐璐着色

### 机制
`kKeywordCount` 只看守**位空间**（7 位），编多少份由 `CMakeLists.txt` 的**分组白名单**决定：
`SHADING_MODELS` / `GROUP_alpha` / `FEATURES_<model>` / `SHADER_MODELS_<file>`，
组合数 = `Σ_模型(alpha数 × 2^该模型特性数)` = pbr 24 + skin 24 + toon 12 = **60**（旧机制 128）。
`static_assert(kKeywordCount == VENN_KEYWORD_COUNT)` 把 C++ 与 CMake 的位宽锁死。
白名单外的旧 `.spv` 在 configure 阶段 `file(REMOVE)` 清掉 —— **`add_custom_command` 只生成不删除，
留着会让运行时静默读上一版着色器**（改造中真踩过：144 份旧 pbr 变体残留）。

实测：pbr 族 128→60，全仓 190→182 .spv，11M→9.8M；将来加 hair/eye/face 从 1024→96 份（10.7×）。
零回归证据：`FORCE_MASK=0 vs 4` 逐像素 **max diff = 1 LSB / mean 0.1293**。

### Toon（`VENN_SHADING_TOON` = bit6，`ShadingModel::Toon`）
两个只有像素证据才抓得到的错，**下次做 NPR 别再犯**：
1. **背光面被 `shadowFactor()` 清零** —— 它在 `N·L<=0` 时返回 0（写实正确），
   但赛璐璐暗部是一笔颜料。整项乘 shadow ⇒ `mix(dark,lit,band)*0==0`，球下半部三通道全 0。
   修法：`mix(dark, lit*shadow, band)`，阴影只衰减**受光档**。
2. **交界处没有台阶** —— `lit` 在 `ndl≈0` 是 `0.55·albedo`，暗部 R 也是 `0.52·albedo`，
   两者几乎相等 ⇒ 明暗交界线消失。亮档抬到 `0.80~1.00`、暗档压到 `0.45~0.62`（1.78× 台阶）。
另：IBL 中性天光（约 +0.14 线性）会把冷色冲淡（B/R 只有 1.07），所以 Toon 变体里
**环境光也按亮暗分档压一次**；写实路径不动。

### 验收脚本的两条硬纪律（`tools/verify_toon_shading.py`）
- **VP-RECT 会拿到旧尺寸**（`SetWindowPos` 后编辑器连出几帧旧矩形，实测 x1=1259/y1=834
  而截图只有 1258×744）→ `run_once` 现在**截图前重读一次** rect；`center_patch` 还要夹到图片范围内。
- **采样区必须盖住球**：`size=5` 时 patch 里 93% 是背景（三种着色模型都算出 R=0.0 —— 测的是天空）；
  `size=20` 时球溢出视口。实测 `size=10`（≈380px，视口 448×531）正好。
- **光要侧着照**：默认光从相机背后打，可见半球 100% 受光，暗部在球背面根本看不见。
- **强度不能削顶**：2.6 时受光面全 255、暗部全 0，std/色比全失真；取 1.2。
- 亮度标准差是可用判据，**"总变差更低"是错的**（Toon 的硬高光制造更大局部梯度）。

`verify_toon_shading` 已登记进 `run_regression.py` DEFAULT + TRIGGERS
（非横切项：`editor/InspectorPanel.*`、`engine/scene/SceneSerializer.*`），
`check_regression_map.py` 的 `InspectorPanel.cpp → 面板块全家族` fixture 同步加了一项。

## 深夜续：P0-2/B 渲染顺序 + P0-3 alphaMode（S1 完成）

### 先把 P0-2 拆成三个正交问题
- **A 同像素叠加**（SDF/ramp/腮红/matcap）：在着色器里做完，排序不参与 —— **仍未做**
- **B 跨网格叠放**（眉/睫/眼/发 vs 脸皮）：语义优先于距离 —— **本轮做完**
- **C 部件透不透明**（Opaque/Mask/Blend）：决定写不写深度 —— **本轮做完**

### 三条 GPU 通道全满（下次做 A 类先看这里）
1. `PushConstants` **恰好 128 B**，唯一空位 `emissive.w` 已被 bindless 页号占
2. `kTextureSetCount = 7` + set0 = 8 = `maxBoundDescriptorSets` 规范下限 → 非 bindless 加不了第 8 张
3. `GpuMaterialPage` 32 B / 8 槽用了 7 个，**`tex1.w` 空着** → A 类只能扩页表到 96 B

### B 类实现要点
- `Material::renderQueue=2000` / `sortOrder=0`（OverrideBits 追加 bit12/13，`kOvScalarMask` 12→14 位）
- 排序 `(renderQueue, sortOrder, -viewDepthSq)` + **`std::stable_sort`**（三键相同的项在 std::sort 下顺序未定义）
- 覆盖带 `renderQueue >= 3000` → `depthTest=false`（VK_FALSE = 片元全通过且不读深度）+ `depthWrite=false`
- **默认 2000/0 让三键退化成单键** → 玻璃/烟雾/既有场景逐像素不变
- 带序（美术起点）：2000 身体 / 2400 脸皮 / 2900 后发 / **3000 前发 / 3100 眼 / 3200 睫 / 3300 眉**。
  ⚠ 头发必须 < 眼睛（眼睛压在刘海上），所以"按类别自动分类"行不通

### `VENN_OVERLAY` 是纯状态位（P0-1 机制的第二次兑现）
位宽 7→8，但**不进任何 FEATURES_**，白名单不变、组合数仍 60、零 .spv 增量。
关键两行：`m_spvMask = kKeywordAll & ~kKeywordStateOnly`；
`variantShaderFile(base, key & m_spvMask)` —— 缓存键有 bit7，文件名没有。

### P0-3 真相
`assetio::SourceMaterial` 里**连 alphaMode 字段都不存在**（不只是 .vmesh 不存）。
修：SourceMaterial 加 AlphaMode+alphaCutoff；.vmesh 材质段 v1→v2 **末尾追加**，
读端 `if(v>=2)` → 旧资产读成 Opaque **不需重烤**；FBX 两条路径同判据推 Blend。
⚠ 只推得出 Blend 推不出 Mask（FBX 没有 alpha test 概念，那是美术意图）。
⚠ 这条**不修**"眼睛被脸皮挡"—— 眼睛不透明，那条的正解是覆盖带。

### 验收 `tools/verify_render_queue.py`（已登记 DEFAULT + TRIGGERS + fixture）
两颗同心球：近红(rq 2000, t=34) / 远绿(t=48)，远球投影完全在近球轮廓内。
绿色占比：plain **0.000** / overlay(远 3100) **0.994** / semantic(近 3000 远 3100) **0.994** /
order_rev **0.000**。第1组与第2组只差 renderQueue 一个字段。

### 三个坑（写进 docs §8.7）
1. **沿 +Z 挪远球是错的**：机位斜（下俯16°），沿 Z 后退会偏离视线 10.7 单位（球径 8）→ 只露边缘 → 0.111 的"半对半错"假象
2. **采样区不能用视口中心**：实测球心比视口中心**偏上 52px**（360 vs 412）→ 0.614 假象。
   改成从第 1 组红球轮廓反推球心。**判据没错时先怀疑几何**（toon 那次同一条教训）
3. **`MYVK_SHADER_FORCE_MASK` 不能影响绘制顺序**：队列分类改读 `mat->isOverlay()`，
   否则强制掩码会把 overlay 从 transparent 队列挪到 opaque，像素对照比的不是同一顺序
另：overlay 项必须 `skipDepthPrepass`，否则预通道写深度 → 后面透明物 early-Z 被剔。

Editor/Game/Launcher 三个二进制均已重链（Launcher 上次因用户开着而 link 失败，这次好了）。

## 表演层第一刀：L4 弹簧骨 + L2 LookAt（C 类 / P1-7）

### 用户问的是"怎么做"，不是"写代码"
"角色管线没有表演层，你觉得可以怎样优化改进？" → 先拆层再动手。
**表演层不是一个编号，是五层正交**：L0 状态机 / L1 分层遮罩 / L2 修正(LookAt·IK) /
L3 表情(BlendShape) / L4 次级运动(弹簧骨)。五层的流水线插入点是同一处
（`采样→混合→遮罩→IK→根运动→局部转世界→乘 invBind→上传`）→ 先落一层不返工。
按"收益×成本"选 L4+L2 开工（零资产改动），L3 必须等 P0-5（顶点格式）一起做，
否则要改两遍。用户通过 AskUserQuestion 选了"弹簧骨+LookAt"和"占位字段标灰"。

### 新文件
`engine/animation/SpringBone.{h,cpp}`、`LookAt.{h,cpp}`；
`Pose.cpp` 抽出 `poseToWorld()`（`poseToJoints` = 它 + 乘 `invMeshNode*invBind`，
表达式顺序不变 → A0-5 的 memcmp 等价断言仍成立）；
`Components.h` +SpringBoneComponent/LookAtComponent；
`SceneSerializer` +springBone/lookAt 两段读写；`InspectorPanel` 两段 UI + 标灰。

### 弹簧骨的关键决定
- **链判据**：自己匹配前缀 **且** 父骨也匹配 → 模拟；自己匹配父骨不匹配 → attach。
  这样"缝在 head 上的第一根头发骨"自动成为固定端，**资产不用标注锚点**。
- **默认前缀是裸 `hair`/`skirt`**。第一版写 `hair_`/`hair.`/`tail`，在 alicia 上
  **一个都没匹配到**（她的骨叫 `hair1_L`，下划线在数字后）；`tail` 更不能放
  （人体骨架里指尾椎）。实测 128 骨里认出 **27 根**。
- `SpringRig` 缓存**必须 `std::map`**（返回引用，unordered_map rehash 会悬垂）。
- 重力是 `(0,-9.8,0)` —— `Pose` 在 glTF 场景空间（Y-up），Y-up→Z-up 在
  `PushConstants::model` 里，所以不是 -Z。

### LookAt
必须在**父骨空间**算（否则转身时头拧在原地）；`angleDeg()` 用 `|q.w|`（q≡-q）；
`shortestArc` 反向 180° 要挑垂直轴避免 NaN。

### 编辑器 dt=0（真机才发现）
非 Play 态 `tick` 传 `dt=0` → 弹簧骨永远不动。症状：`ANIM-TICK f=1 dt=0.00000`
**且只有 f=1 一条**（编辑器加载完跑一帧就停在等交互）。
修：`physDt = (dt>0) ? dt : m_wallDt`，`m_wallDt` 来自 `steady_clock` 并 clamp(0,0.05)。
Play/自检走 dt（确定性优先），编辑器非 Play 走真实帧间隔。

### 假开关标灰
`animator` 的 `controllerPath`/`stateIndex`/`floatParams`/`triggerParams`/`rootMotion`
七个字段**进了序列化 + Inspector 有控件，但全仓无运行时消费者**。
比"没这个功能"更伤信任。用 `BeginDisabled()` 标灰 + 提示，**不删**（等状态机要用）。

### 验收
`verify_anim_runtime` **42 项全 PASS**（15 项新增），已登记 TRIGGERS 并加
`engine/scene/SceneSerializer.*` 依赖。真实资产一次性 A/B/C（未进回归）：
无弹簧 / 有弹簧无风 mean=7.17 / 有弹簧+风8 mean=10.71（人物区域）。
图：`E:/code/cpp/_venn_verify/spring_bone_abc.png`。

### 三个坑（写进 docs §9.7）
1. **手写场景 JSON 的 `skinned` 块不建子网格渲染实体**。骨骼/clip/ok=1 全对，
   但 20 个子网格是 `instantiateModel` 建的 → 视口空白而
   `CULL-STATS renderables=1 tris=2`（那 1 个是地面），**一个错都不报**。
   要看角色必须走 `ModelInstance`：运行时 `createPlayer` / 编辑器拖入 / `MYVK_EDITOR_IMPORT`。
2. **运行时跑不出表演层是因为 `Game.exe` 是旧的**。只重编 VennEditor 就会得出
   错误结论"运行时没有表演层"。`msvc-build.cmd build <target>` **只吃第一个 target**。
3. **只有 skinned 实体的场景踩 BVH 越界**（`std::vector<Bvh::Node>::operator[]`），
   加一块静态地面绕开；对照组同样崩，与本轮无关。

Editor/Runtime/Launcher 三个二进制已重链。文档 `docs/anime_gap_audit.md` §9 已补，
§1.C 与 P1-7 已标部分落地。下一步：L0 状态机（把七个占位字段接上）→ L1 遮罩 →

## 第三刀：NPR 描边（P1-2）—— 不加一遍几何的做法

用户："继续下一步"（顺序 = 状态机 → **描边** → 格式手术 → IK → 表情 → 面影 → 过场）。

### 关键决定：不走 inverted hull
roadmap 原本推荐 inverted hull（正面剔除 + 平滑法线外扩）。**没走**，三条成本：
1. 要**再画一遍**所有要描边的几何；
2. 需要**平滑法线**（第二套平均法线），而顶点 location 0~5 已用满 →
   要么动顶点格式、要么加图。P0-5（BlendShape）本来就要动它，
   为描边先动一次 = **改两遍**；
3. 逐物体遮罩本来就要顶点色/UV2，也是同一笔手术。

改走**后处理边缘检测**：总成本 = 预通道多一个颜色附件 + post 里 9 次采样。
顺带把"深度+法线"交到后处理手里（SSAO/DOF/线宽补偿/色调分离都吃这份）。

## 第四刀：材质页 32 B → 96 B（A 类语义槽）

### 关键决定
1. **只做 ⑤ 材质页，不做 ④ 顶点格式。** 原计划"④⑤ 一起做，因为顶点变动
   要重烤资产"——动手前核 `assetio/MeshFormat.h` 发现那个理由只对 ④ 成立：

## 第五刀（承接第四刀）：顶点格式 80 → 112 B（§13）

## 第六刀（承接第五刀）：morph 数据链 §14

### 关键决定
1. **这一刀不接 GPU**，理由是硬的：`PushConstants` 128 B 满仓，
   `skin` 四个分量（jointBase / POM 深度 / 蒙皮标志 / alphaCutoff）各有主；
   morph 权重是 per-instance，四条通道全堵死。GPU 形变单独一刀，候选方案
   写在 §14.8（pbr.w 挪 ao 进材质页 spare / MDI aux.y / joint 块尾接）。
2. **`reserved0` → `morphCount`**（第 92 字节）。这是 §13 留那 4 字节的
   **原本目的**，不是语义漂移。**顶点 stride 仍是 112，MESH 区块版本仍是 2**
   —— 老 v2 资产的（哨兵, 0）被解释成"没有 morph"，正确。
3. **MORPH 区块是可选区块**（id=6），没有 morph 就不写。
4. **delta 记录 32 B 与 GPU 布局对齐**：pos(12) target(4) nrm(12) vertex(4)。
   最后 4 字节在 GPU 上是填充位、在文件里是**校验锚**（流的顺序 == 顶点顺序）。
5. **target 下标是子网格内局部的**（与 joints 是"骨架内下标"同一套路）。
   alicia 烤出 88 targets 而不是 60，就是材质分桶的复制。

③ buildMorphStream（最后）：展平成流 + 写真 base/count

## 第七刀：GPU 形变 + 四条欠账清算（④-b2，2026-10-25）

> 上面「仍缺」那五条**全部已落地**，本节取代它。

### 通道方案（§14.8 的三套候选全废）
PushConstants **128 B 已满**（model/baseColor/pbr/emissive/skin），morph 要
「delta 基址 + 权重基址 + target 数」三样，一个 `pbr.w` 装不下 →
**三块固定容量 SSBO**：

```
25 MorphDeltas   MorphDelta[] 32 B × 786432 = 24 MB
26 MorphWeights  float[]      × 1048576     =  4 MB
27 MorphSlots    uvec4[]      × 8192        = 128 KB
```
`kGlobalSetBindings` 25 → **28**。全是 `VK_SHADER_STAGE_VERTEX_BIT`。
**永不重建**：换 buffer 会让主视口有一帧读到空 buffer。超限降级成
`targets=0`（不形变），`m_morphBudgetWarned` 只打一次日志。

### 数据链改造
- MORPH 区块 **v1 → v2**：目标表后追 channel 表
  `(nameStr, keyCount, keyCount × (f32 targetWeight, u32 target))`。
- `MorphChannel` = `(targetWeight, target)` 点列，`kNoMorphTarget=0xFFFFFFFF`
  是**插值断点**（不是整条丢）。
- offset_weights **预乘进 delta**（32 B 布局不动），`ow==0` 的偏移直接丢。
- 新 `engine/assets/MorphRig.*`：88 逐桶 channel → **49 唯一名字**；
  `setMorphWeight(rig, w, name, v)` / `morphWeight`；重名 key 烤制时加 `#i`。
- 有 morph 的网格**不建 LOD 链**（`LOD-SKIP-MORPH`），不做"给 LOD 补 delta"
  —— 减面后 delta 要重投影，且 `subMeshIndexOf` 找不到 LOD 的 Mesh。
- `SceneSerializer` 的 morph 权重**按名字存**（按下标存重烤后静默套错），
  0 值不写，认不出的名字忽略。

### 着色器（顺序铁律）
`localPos = skinMat * vec4(inPos + morphPos, 1)` —— delta 与 `inPos` 同空间
（烤制时已过 `geometry_to_world` 线性部分），`skinMat` 是「静止→当前」。
写成 `skinMat*inPos + morphPos` 只在**非静止姿势**下炸，静止姿势看不出。
顶点属性 `7=morphBase / 8=morphCount`（R32_UINT）；属性表**不是连续前缀**
→ `attributesFor({0,1,2,3,4,5,7,8})`，不是 `attributeDescriptions(count)`。

### 最大 bug（必须记住）
**同一个 targetWeight 上的多个材质桶 ≠ in-between 关键帧。**
第一版 `evaluate` 拿 `points.front()/back()` 当关键帧链，alicia 所有点
`weight==1.0` → `w <= front.weight` 恒成立 → **只驱动第一个桶**（一只眼睛动）。
`verify_morph.py` 34 项全绿，GPU 差异 **0.000%**。
修法：先按 targetWeight **去重成级**，再在级间插值，第 3 步**循环覆盖所有点**。
修后 3 个桶全 `w0=1.00`，G2 → **0.048%**。
发现路径：`MYVK_MORPH_DBG=1` 打 `MORPH-FRAME` 逐槽位 dump —— 没有这份
dump，"像素差 0%" 有一百种解释。
防回归：**G4d**（最后一帧 `w0=1.00` 的槽位数 ≥ 2），守"是不是只有一块在动"。

### 槽位三条路径
MDI 走 `MdiInstance.aux.y`，且必须由**目录带过来**（`gl_InstanceIndex` 是
紧凑化后的下标）；基线批走 `gl_InstanceIndex` 且批构建时逐个 `writeMorphSlot`；
阴影现场求值 + `m_instanceOffset++`。`targets==0` 必须**显式清零**（槽位复用）。
求值缓存键用 **`MorphComponent` 的地址**（`const void*`），不用实体 id
（20 个子网格是独立实体，会求值 20 遍）。

## 第八刀：两骨 IK + 挂点 + `Skeleton::findJoint` 收敛（§16）

三个新文件 + 一次收敛，动机是"共用一个中间层"：IK 要找骨、挂点要读关节
世界矩阵、而 `Animator` 与 `LookAt` 里各写了一遍名字匹配。

### 交付
- `engine/animation/TwoBoneIK.{h,cpp}`（143 + 267 行）：解析解（余弦定理），
  **不是** FABRIK —— 唯一理由是"必须能断言同一输入逐位相同"，迭代解在
  `acos` 边界必分叉，`ik_deterministic` 这条断言就写不出来。
- `engine/animation/BoneAttachment.{h,cpp}`（89 + 147 行）。
- `engine/assets/Skeleton.{h,cpp}`：`findJoint(name, flags)` +
  `findJointsWithPrefix`，标志位（Exact/CaseInsensitive/Substring/
  SkipEndTips）而不是三个函数。
- 组件 `TwoBoneIKComponent` / `BoneAttachmentComponent`；序列化 `ik` / `attach`
  两段（`poleMode` 存**字符串**，存整数会在枚举插档时静默错位）；
  Inspector Animation 页签两段；控制台 `ik.set/ik.weight/ik.list/attach.bind`。
- `AnimatorSystem::applyPerformance`：顺序 **LookAt → IK → 弹簧骨**。

### 关键事实（写下来免得下次重推）
- **`jointMatrices[j] = invMeshNode·world(j)·invBind(j)` 不是骨骼世界矩阵**。
  反推：`subTransform·jointMat·invBind⁻¹ = YupToZup·world(j)`，可直接接宿主 world。
- **极向量每帧从 `(mid−root)` 投影到 ⟂`root→target` 平面的分量反推**，不缓存。
  退化三级兜底：动画投影 → `poleVector` 垂直分量 → `cross(dirAT,+X)` 再 `+Y`
  （必须试两次，`dirAT=+X` 时第一次叉乘为零向量→normalize 出 NaN）。
- **`maxReachScale=0.999f`**：1.0 时 `acos(1.0000001)`=NaN，整条链从视口消失。
- **第二根骨的父骨世界旋转必须用改完之后的 root**（`W'=qA·W`），用旧的症状
  是"腿越弯脚踝偏得越多"，伸直时完全正常。
- **`diff_stats` 返回占比 0..1，不是百分数**（本轮最大的判据 bug，见下）。
- `findJoint` 精确那一轮**不过滤** endtip（否则显式要 `Head_end` 永远 -1）。
