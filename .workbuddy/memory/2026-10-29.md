# 2026-10-29 · R8 动画摄影表（Dope Sheet，#320）

## 做了什么

新增第三个动画作者面板：`editor/DopeSheetWindow.{h,cpp}`（~1100 行）+ 数据层的
关键帧类型与三个批量操作（`engine/animation/ClipEdit.{h,cpp}`）+ 18 条中文化词条
（`engine/i18n/ZhTable.cpp`）+ 端到端回归 `tools/verify_dope_sheet.py`（7 组）。

- **通道树**：骨架模式按 `topoOrder` 走，缩进 = **有键的祖先个数**（用全部祖先
  会让同层骨缩进不同）；折叠骨的子行隐藏；骨架里找不到的骨**照样列出**并追加在
  末尾（"我的帧去哪了"的唯一界面线索）。没骨架时平铺、按首次打帧顺序。
- **一棵树 + 一张网格必须是一块画布**：两个 `BeginChild` 各自滚动 → 通道名和
  菱形错行 → "点到了隔壁骨"。
- **关键帧类型** `Key/Extreme/Breakdown/Inbetween`：形状编码类型（实心+外圈 /
  空心 / 小圆点）、颜色编码悬停、外圈编码选中。**完全不进求值**。`types` 与
  `times` 平行且**允许更短**（老文件/手改坏的 JSON 都能读，缺项当 `Key`）；存盘
  只在非默认才写 → 老资产重存一次逐字节不变。
- **批量操作**：`moveKeys` / `mirrorKeys` / `alignCycle` / `setKeyTypes` 放在
  `engine/animation/ClipEdit`，UI 与注入脚本共用同一份实现 → 验收不依赖鼠标坐标。
- **缩放/滚动**：Ctrl+滚轮绕鼠标锚点缩放、Shift+滚轮平移、滚动纵向。

## 踩过的坑（都已修在代码注释里）

1. **float 不保"间距不变"**：`(a+d)−(b+d)` 与 `a−b` 在指数变化时舍入不同 →
   自检与回归都挑 2⁻⁴ 的整数倍 + 0.25 位移，才能断言"逐位"。
2. **镜像用 double 中间值**（`2.0*p − double(t)`）→ 与 Python `float32` 逐位一致，
   验收才敢用 `==`。
3. **对齐循环末帧走特判**：`lo+(hi−lo)·scale` 可能差 1 ulp，而"对齐到 1.5 秒"
   必须精确，否则循环点每转一圈差一丁点。
4. **`Esc` 取消用整份 `EditClip` 值拷贝**回滚，不是反向位移（float 上
   `(t+d)−d ≠ t`，长拖会漂且看不出是取消造成的）。
5. **`G` 抓起来又原地松手**：`delta == 0` 直接返回，否则白跑一遍重建 → 会把
   同刻容差内本该分开的帧合并掉 = 静默丢数据。
6. **删除不能按下标**：`removeKey` 每删一个后面前移、轨道空了还整条 erase →
   按 (骨名, path, 时刻) 收集受害者在删。
7. **`selrow:<joint>` 按骨名不按行下标**：折叠会换行号，展开时摘要行没有点 ——
   命令语义不该随 UI 状态漂移（首版按下标，脚本里 `collapse` 与 `selrow` 同一帧
   执行 → 拿到上一帧的行集 → 选不中）。
8. **`collapse` 日志要打在动作本体里**：打在鼠标点击点上，脚本那条路径就静默。
9. **`dumpkeys` 的 px 必须自带视图**：脚本里 `zoom`/`pan` 会立刻改 `m_t0`，而
   本帧菱形还画在旧换算率上 → 日志加了 `DOPE-DUMP` 头（px0/px1/t0/t1/pps）+
   `m_lastT0`/`m_lastPlotMax` 成员，否则验收只能猜"这批 px 属于哪一帧"。
10. **绑定形态下窗口不能关**：`bind()` 把 `m_open` 置真，`!open` 分支再关上就是
    每帧关开一次、日志刷满；`m_dopeSheet` 必须在 `m_characterWindow` **之后**声明
    （成员逆序析构，先析构才不悬空）；浮动窗口稳定 ID 必须 = `trayWindowName(id)`
    = `###panel_dope`（#311 踩过）。

## #336 S-C 约束栈 —— `engine/animation/Constraint.{h,cpp}`

任务书的落点不是"多五个特性"，而是**一个有序栈**：`Constraint{type,target,influence,enabled}`
挂在骨上，`std::vector` 按顺序求值。第一批 `LimitRotation` / `CopyRotation` /
`CopyLocation` / `ChildOf`，第二批把 `TwoBoneIK` 迁进栈（补 `ChainLength`/`PoleTarget`/`Stretch`）。
`influence` 是**可打帧的 float**，所以"FK 切 IK"就是给它打 0→1 两帧，采样链里
不需要再写一个混合分支 —— 这是整个设计成立的前提。

### 这一层唯一"截图看不出来"的性质：顺序即语义

同两条约束，`[限位 → 复制]` 得 **60°**、`[复制 → 限位]` 得 **20°**。
所以它同时落在数值断言（`constraint_order_limit_then_copy_deg` /
`..._copy_then_limit_deg`）和 `digest` 往返里（`constraint_order_digest_differs`、
`verify_constraints` C 组跨进程摘要）。

### 三条硬底线

1. **"没生效"必须逐位不动，不能用乘 0 实现**。`slerp(q,q,0)` 不是浮点恒等（1e-7 漂），
   所以 `influence<=0` / `!enabled` / `LimitRotation` 落在限幅内 —— 三种情况都
   **提前 return、一个字节不写**（`memcmp` 断言）。
2. **IK 入栈后与直接调 `solveTwoBoneIK` 逐位相同**（`constraint_ik_via_stack_bitwise`）。
   栈里那份是薄包装，不是第二套解算。
3. **存读往返摘要不变**（E 组）；JSON 里骨**同时写名字和下标**，读盘只用 `boneIndex`
   并校验越界 —— **绝不按名字猜**，同名骨在不同导入批次可能指不同关节。

### 求值器的两条实现约定

- **世界矩阵按需重算**：`LimitRotation` 不看世界；`Copy*` / `ChildOf` / IK 必须看到
  **上一条改完之后**的世界矩阵。`EvalCtx::touched()` 置脏，下一条 `getWorld()` 才重算。
  漏了这条的复现条件是"两条以上约束且顺序在前的那条改了父骨" —— 只测单条永远发现不了。
- **`worldRotationOf` 按第 0 列长度归一**（`r /= length(r[0])`），不是
  `quat_cast(mat3 / determinant)`：后者在均匀缩放下得到 `R/s²`，既不正交也不归一。
  `Constraint.cpp` 与 `TwoBoneIK.cpp` 共用同一份。

### 实测坑

- **`ChildOf` 对后代是恒等** —— 第一版拿 `weapon`（`armL` 的子骨）测 ChildOf，
  父子链本来就带它转，对照组 `naive=0.000000`，证明不了任何事。改成**跨层级**
  （`armR` 跟 `armL`）后 `naive=0.273616`，对照组才算成立。
  > 教训：测一个"补偿父子关系"的特性，被测对象**不能是**目标的直系后代。
- **`glm::angle(a,b)` 不存在**（glm 只有 `angle(q)`）。求两四元数夹角要
  `angle(normalize(inverse(a)*b))` + `if (d.w<0) d=-d` hemisphere 对齐。
- **`report()` 与 `reportFlag()` 日志格式不同**：前者**没有 `detail=` 字段**，后者有。
  用一个正则套两种会静默漏掉全部数值断言 —— `verify_constraints.py` 第一版
  A1 只数到 16 条（应 23），根因就是 7 条 `report()` 被漏。
  已加 `SELFTEST_NUM_RE` 二次扫描。
- **注入脚本 `add`/`sel` 必须同步 Rig 页选中骨**，否则 `drawConstraintsSection` 里
  `c->bone != bone` 直接 return，类型参数锚点（`CHAR-CON-INFL` 之后）全无。
- **面板铺在 Rig 页底部会顶出可见区**（实测锚点高度 0）→ 改 `CollapsingHeader`，
  有约束时 `SetNextItemOpen(true, ImGuiCond_Once)`。

## S-D · 骨骼曲线（Graph Editor 终于接到骨骼上）

任务书只有一句"把 `AnimTrack` 换成 `Curve`"，但真正要紧的不是"能画出来"，
是**接上之后什么都没变**。所以这一轮八成精力花在"逐位不变"上。

### 三条关键判断

- **"逐位不变"里，平移/缩放是"碰巧"，旋转是"根本不走那条路"。**
  `evaluateCurve` 的 Linear 分支是 `v0 + (v1-v0)*w`，`assets::sampleTrack` 是
  `a + (b-a)*u` —— **同一个式子、同一份 u**，所以 T/S 逐位相同。但这是个
  脆等式：换成 `glm::mix`（`a*(1-w)+b*w`）就断，而且**画面毫无变化**。
  旋转更糟：老路是 `slerp`，分量曲线是 nlerp。所以
  `sampleRotationEased` 里那句 `if (w == u) return assets::sampleTrack(...)`
  是**结构性**的，不是优化 —— 文档 §5 第 8 条专门写了这一句，免得被人当
  "多余分支"删掉。
- **nlerp 与 slerp 在 u=0.5 处恰好相等**（都是角平分线）。
  `curvebake_slerp_nlerp_distinct` 第一版取 0.5，差 3e-6 直接被打回。
  同理 **smoothstep 在 u>0.5 时超前于线性**：断言"缓动使值变大"必须在
  u<0.5 处取（`plain=0.6` vs `eased=0.648` 的反例）。
  > 教训：测"两条插值路径不同"和"缓动让曲线滞后"，探针点必须各选在
  > 差异最大的那一半，不能想当然取中点。
- **`skipped=63` 是诚实读数，不是遮掩。** 旋转 Linear 段运行时走 slerp，
  画布上是分量曲线（nlerp），两者**本来就该不一样**。装作差 0 才是错的。

### 两个"绿灯挂在没跑上"的形态（本轮各栽一次）

- `BONEC-CHECK samples=0 skipped=0`：`open()`/`reload()` 在 `rebuildCurve()`
  **之前**调 `revalidate()`，所以第一帧的 xcheck 是在空投影上算的 —— 永远
  "全 0 = 通过"。修法是三处补 `rebuildCurve()`，且 `revalidate()` 自己也先
  调一次防将来。
- `curvebake_*` 只数到 6 条（应 32）：`SELFTEST_RE` 把 `detail=` 写在
  `result=` **之后**，而 `reportFlag()` 实际是 `... tol=0 detail=X result=PASS`
  （detail 在**前**）。**同一个坑第二次踩**（S-C 时是 `report` vs
  `reportFlag`），这次把正则彻底拆成两条。
  > 定式：一条日志解析不上，先 `cat` 原始行确认字段顺序，别信自己的记忆。

### 写回的两个坑

- `applyCurveToTrack` 第一版**边清边读**（`tr.values.clear()` 之后还从
  `tr.values` 取其它分量），写出来 y/z 全是 0 —— 而"单分量"的断言看不出来。
  改成先快照 `origValues / origTypes / origTimes`。中途还写了个更糟的
  "占位 + 裸指针反查"版本，整文件重写才干净。
- **写回不增删帧**：`keys.size() != 轨道帧数` 就整条 `skipped` 拒绝。
  曲线编辑器改形状，Dope Sheet 改帧数，两边都能改帧数就没人守得住
  `findTrack` 的不变量。

### 为什么另开一个面板（`BoneCurvePanel` 而不是给 `CurveEditorPanel` 加分支）

相机一条段只有**一组归一化手柄**（四通道共用），骨骼**每键存绝对偏移**
（分量独立）。靠 `if` 隔离的代价是每次改动都要重答"这个手柄归谁"，
答错的症状是"拖了手柄另一条通道跟着变"。共用只有 `animation::Curve`
求值器与几个 UI 习惯，画布重复约 150 行 —— 但那是**两种不同东西**的画布。

`V` 键的语义也正好相反：相机 = 换算并写回（写完就是 Free），骨骼 = **存类型**
（AutoClamped 得一直跟邻居重算）。这条差异写进了两个头注释，免得将来被"统一"。
