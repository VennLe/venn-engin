# 2026-10-29 · R8 动画摄影表（Dope Sheet，#320）

## 做了什么

新增第三个动画作者面板：`editor/DopeSheetWindow.{h,cpp}`（~1100 行）+ 数据层的
关键帧类型与三个批量操作（`engine/animation/ClipEdit.{h,cpp}`）+ 18 条中文化词条
（`engine/i18n/ZhTable.cpp`）+ 端到端回归 `tools/verify_dope_sheet.py`（7 组）。

- **通道树**：骨架模式按 `topoOrder` 走，缩进 = **有键的祖先个数**（用全部祖先
  会让同层骨缩进不同）；折叠骨的子行隐藏；骨架里找不到的骨**照样列出**并追加在
  末尾（"我的帧去哪了"的唯一界面线索）。没骨架时平铺、按首次打帧顺序。
- **一棵树 + 一张网格必须是一块画布**：两个 `BeginChild` 各自滚动 → 通道名和
  菱形错行 → "点到了隔壁骨"。
- **关键帧类型** `Key/Extreme/Breakdown/Inbetween`：形状编码类型（实心+外圈 /
  空心 / 小圆点）、颜色编码悬停、外圈编码选中。**完全不进求值**。`types` 与
  `times` 平行且**允许更短**（老文件/手改坏的 JSON 都能读，缺项当 `Key`）；存盘
  只在非默认才写 → 老资产重存一次逐字节不变。
- **批量操作**：`moveKeys` / `mirrorKeys` / `alignCycle` / `setKeyTypes` 放在
  `engine/animation/ClipEdit`，UI 与注入脚本共用同一份实现 → 验收不依赖鼠标坐标。
- **缩放/滚动**：Ctrl+滚轮绕鼠标锚点缩放、Shift+滚轮平移、滚动纵向。

## 踩过的坑（都已修在代码注释里）

1. **float 不保"间距不变"**：`(a+d)−(b+d)` 与 `a−b` 在指数变化时舍入不同 →
   自检与回归都挑 2⁻⁴ 的整数倍 + 0.25 位移，才能断言"逐位"。
2. **镜像用 double 中间值**（`2.0*p − double(t)`）→ 与 Python `float32` 逐位一致，
   验收才敢用 `==`。
3. **对齐循环末帧走特判**：`lo+(hi−lo)·scale` 可能差 1 ulp，而"对齐到 1.5 秒"
   必须精确，否则循环点每转一圈差一丁点。
4. **`Esc` 取消用整份 `EditClip` 值拷贝**回滚，不是反向位移（float 上
   `(t+d)−d ≠ t`，长拖会漂且看不出是取消造成的）。
5. **`G` 抓起来又原地松手**：`delta == 0` 直接返回，否则白跑一遍重建 → 会把
   同刻容差内本该分开的帧合并掉 = 静默丢数据。
6. **删除不能按下标**：`removeKey` 每删一个后面前移、轨道空了还整条 erase →
   按 (骨名, path, 时刻) 收集受害者在删。
7. **`selrow:<joint>` 按骨名不按行下标**：折叠会换行号，展开时摘要行没有点 ——
   命令语义不该随 UI 状态漂移（首版按下标，脚本里 `collapse` 与 `selrow` 同一帧
   执行 → 拿到上一帧的行集 → 选不中）。
8. **`collapse` 日志要打在动作本体里**：打在鼠标点击点上，脚本那条路径就静默。
9. **`dumpkeys` 的 px 必须自带视图**：脚本里 `zoom`/`pan` 会立刻改 `m_t0`，而
   本帧菱形还画在旧换算率上 → 日志加了 `DOPE-DUMP` 头（px0/px1/t0/t1/pps）+
   `m_lastT0`/`m_lastPlotMax` 成员，否则验收只能猜"这批 px 属于哪一帧"。
10. **绑定形态下窗口不能关**：`bind()` 把 `m_open` 置真，`!open` 分支再关上就是
    每帧关开一次、日志刷满；`m_dopeSheet` 必须在 `m_characterWindow` **之后**声明
    （成员逆序析构，先析构才不悬空）；浮动窗口稳定 ID 必须 = `trayWindowName(id)`
    = `###panel_dope`（#311 踩过）。

## #336 S-C 约束栈 —— `engine/animation/Constraint.{h,cpp}`

任务书的落点不是"多五个特性"，而是**一个有序栈**：`Constraint{type,target,influence,enabled}`
挂在骨上，`std::vector` 按顺序求值。第一批 `LimitRotation` / `CopyRotation` /
`CopyLocation` / `ChildOf`，第二批把 `TwoBoneIK` 迁进栈（补 `ChainLength`/`PoleTarget`/`Stretch`）。
`influence` 是**可打帧的 float**，所以"FK 切 IK"就是给它打 0→1 两帧，采样链里
不需要再写一个混合分支 —— 这是整个设计成立的前提。

### 这一层唯一"截图看不出来"的性质：顺序即语义

同两条约束，`[限位 → 复制]` 得 **60°**、`[复制 → 限位]` 得 **20°**。
所以它同时落在数值断言（`constraint_order_limit_then_copy_deg` /
`..._copy_then_limit_deg`）和 `digest` 往返里（`constraint_order_digest_differs`、
`verify_constraints` C 组跨进程摘要）。

### 三条硬底线

1. **"没生效"必须逐位不动，不能用乘 0 实现**。`slerp(q,q,0)` 不是浮点恒等（1e-7 漂），
   所以 `influence<=0` / `!enabled` / `LimitRotation` 落在限幅内 —— 三种情况都
   **提前 return、一个字节不写**（`memcmp` 断言）。
2. **IK 入栈后与直接调 `solveTwoBoneIK` 逐位相同**（`constraint_ik_via_stack_bitwise`）。
   栈里那份是薄包装，不是第二套解算。
3. **存读往返摘要不变**（E 组）；JSON 里骨**同时写名字和下标**，读盘只用 `boneIndex`
   并校验越界 —— **绝不按名字猜**，同名骨在不同导入批次可能指不同关节。

### 求值器的两条实现约定

- **世界矩阵按需重算**：`LimitRotation` 不看世界；`Copy*` / `ChildOf` / IK 必须看到
  **上一条改完之后**的世界矩阵。`EvalCtx::touched()` 置脏，下一条 `getWorld()` 才重算。
  漏了这条的复现条件是"两条以上约束且顺序在前的那条改了父骨" —— 只测单条永远发现不了。
- **`worldRotationOf` 按第 0 列长度归一**（`r /= length(r[0])`），不是
  `quat_cast(mat3 / determinant)`：后者在均匀缩放下得到 `R/s²`，既不正交也不归一。
  `Constraint.cpp` 与 `TwoBoneIK.cpp` 共用同一份。

### 实测坑

- **`ChildOf` 对后代是恒等** —— 第一版拿 `weapon`（`armL` 的子骨）测 ChildOf，
  父子链本来就带它转，对照组 `naive=0.000000`，证明不了任何事。改成**跨层级**
  （`armR` 跟 `armL`）后 `naive=0.273616`，对照组才算成立。
  > 教训：测一个"补偿父子关系"的特性，被测对象**不能是**目标的直系后代。
- **`glm::angle(a,b)` 不存在**（glm 只有 `angle(q)`）。求两四元数夹角要
  `angle(normalize(inverse(a)*b))` + `if (d.w<0) d=-d` hemisphere 对齐。
- **`report()` 与 `reportFlag()` 日志格式不同**：前者**没有 `detail=` 字段**，后者有。
  用一个正则套两种会静默漏掉全部数值断言 —— `verify_constraints.py` 第一版
  A1 只数到 16 条（应 23），根因就是 7 条 `report()` 被漏。
  已加 `SELFTEST_NUM_RE` 二次扫描。
- **注入脚本 `add`/`sel` 必须同步 Rig 页选中骨**，否则 `drawConstraintsSection` 里
  `c->bone != bone` 直接 return，类型参数锚点（`CHAR-CON-INFL` 之后）全无。
- **面板铺在 Rig 页底部会顶出可见区**（实测锚点高度 0）→ 改 `CollapsingHeader`，
  有约束时 `SetNextItemOpen(true, ImGuiCond_Once)`。

## S-D · 骨骼曲线（Graph Editor 终于接到骨骼上）

任务书只有一句"把 `AnimTrack` 换成 `Curve`"，但真正要紧的不是"能画出来"，
是**接上之后什么都没变**。所以这一轮八成精力花在"逐位不变"上。

### 三条关键判断

- **"逐位不变"里，平移/缩放是"碰巧"，旋转是"根本不走那条路"。**
  `evaluateCurve` 的 Linear 分支是 `v0 + (v1-v0)*w`，`assets::sampleTrack` 是
  `a + (b-a)*u` —— **同一个式子、同一份 u**，所以 T/S 逐位相同。但这是个
  脆等式：换成 `glm::mix`（`a*(1-w)+b*w`）就断，而且**画面毫无变化**。
  旋转更糟：老路是 `slerp`，分量曲线是 nlerp。所以
  `sampleRotationEased` 里那句 `if (w == u) return assets::sampleTrack(...)`
  是**结构性**的，不是优化 —— 文档 §5 第 8 条专门写了这一句，免得被人当
  "多余分支"删掉。
- **nlerp 与 slerp 在 u=0.5 处恰好相等**（都是角平分线）。
  `curvebake_slerp_nlerp_distinct` 第一版取 0.5，差 3e-6 直接被打回。
  同理 **smoothstep 在 u>0.5 时超前于线性**：断言"缓动使值变大"必须在
  u<0.5 处取（`plain=0.6` vs `eased=0.648` 的反例）。
  > 教训：测"两条插值路径不同"和"缓动让曲线滞后"，探针点必须各选在
  > 差异最大的那一半，不能想当然取中点。
- **`skipped=63` 是诚实读数，不是遮掩。** 旋转 Linear 段运行时走 slerp，
  画布上是分量曲线（nlerp），两者**本来就该不一样**。装作差 0 才是错的。

### 两个"绿灯挂在没跑上"的形态（本轮各栽一次）

- `BONEC-CHECK samples=0 skipped=0`：`open()`/`reload()` 在 `rebuildCurve()`
  **之前**调 `revalidate()`，所以第一帧的 xcheck 是在空投影上算的 —— 永远
  "全 0 = 通过"。修法是三处补 `rebuildCurve()`，且 `revalidate()` 自己也先
  调一次防将来。
- `curvebake_*` 只数到 6 条（应 32）：`SELFTEST_RE` 把 `detail=` 写在
  `result=` **之后**，而 `reportFlag()` 实际是 `... tol=0 detail=X result=PASS`
  （detail 在**前**）。**同一个坑第二次踩**（S-C 时是 `report` vs
  `reportFlag`），这次把正则彻底拆成两条。
  > 定式：一条日志解析不上，先 `cat` 原始行确认字段顺序，别信自己的记忆。

### 写回的两个坑

- `applyCurveToTrack` 第一版**边清边读**（`tr.values.clear()` 之后还从
  `tr.values` 取其它分量），写出来 y/z 全是 0 —— 而"单分量"的断言看不出来。
  改成先快照 `origValues / origTypes / origTimes`。中途还写了个更糟的
  "占位 + 裸指针反查"版本，整文件重写才干净。
- **写回不增删帧**：`keys.size() != 轨道帧数` 就整条 `skipped` 拒绝。
  曲线编辑器改形状，Dope Sheet 改帧数，两边都能改帧数就没人守得住
  `findTrack` 的不变量。

### 为什么另开一个面板（`BoneCurvePanel` 而不是给 `CurveEditorPanel` 加分支）

相机一条段只有**一组归一化手柄**（四通道共用），骨骼**每键存绝对偏移**
（分量独立）。靠 `if` 隔离的代价是每次改动都要重答"这个手柄归谁"，
答错的症状是"拖了手柄另一条通道跟着变"。共用只有 `animation::Curve`
求值器与几个 UI 习惯，画布重复约 150 行 —— 但那是**两种不同东西**的画布。

`V` 键的语义也正好相反：相机 = 换算并写回（写完就是 Free），骨骼 = **存类型**
（AutoClamped 得一直跟邻居重算）。这条差异写进了两个头注释，免得将来被"统一"。

### 还差

- 运行时（`AnimatorSystem`）不读缓动表 —— 它吃 `assets::AnimationClip`，
  缓动住在 `EditClip` 上。与 S-C 的"运行时读同一份约束栈"是同一批活
  （都要动 `ecs/Components.h`），一起做。
- `Noise` / `Sine` 曲线修改器、`Extrapolate::Cycle*` 在骨骼轨上未接。
- Action 级曲线（一个曲线驱动多根骨）未做。

## R9 · NLA（时间轴片段）

任务书只有三行，但第一行就点明了这一轮的**主要风险不在实现**：
"与现有 `AnimLayer` 的关系必须写清楚"。所以八成设计时间花在"这两个东西
到底哪里不一样"上，而不是代码。

### 一句话把两者分开（文档与头注释都用了这张表）

| | `AnimLayer`（B1） | `NlaTrack`（R9） |
|---|---|---|
| 问的问题 | 此刻身上盖着哪几段动作 | 第 3.2 秒该演什么 |
| 有没有时间轴位置 | 没有（播放头自己跑） | 有（起止 + 整条轴一个播放头） |
| `weight` 的意思 | 遮罩内**换成**这一层的姿态 | 这一刻按多少**参与混合** |
| 典型用途 | 挥手 + 走路 | 过场 / 演出 / 精确对时的连招 |

**共存，各走各的。** 共用只有遮罩解算与 `blendPoseMasked` —— 那两处共用是对的。
"硬合并"不是风格问题：合并之后那个 `weight` 字段就同时意味着两件事，
美术永远调不明白（症状就是任务书里那句"我把片段拖上去，上半身被整段替换了"）。

### 四条约定（都是"省了就错"）

1. **空 `nlaTracks` = `pose` 逐位不变** —— 老场景一帧都不许变。
2. **`span` 决定"占多久"，`speed` 决定"span 里塞几遍"，不是"播多快"。**
   让 strip 单独跑快就得回答"提前跑完了画什么"（停住 / 循环 / 拉伸到 end），
   三种答案在时间轴上一样、画面上完全不同。
3. **strip 只在 `[start, end]` 内存在**，区间外不"停在末帧" —— 否则首尾相接
   的两条在接缝处会各贡献一次，接缝位置出现一次没人要的混合。
4. **`Add` 是 rest 相对增量，不是两个姿势相加。** 直接相加 = 静止姿势数两遍，
   角色一开 NLA 就变形成两倍大。

### 两个坑

- **`Add` 里不许顺手 `normalize`。** 乘单位四元数在浮点下是**精确**的
  （乘 1、加 0），所以"这条 strip 没碰这根骨"时结果与输入逐位相同；
  加一次 normalize 就引入 1 ulp 偏差，而且只出现在**没被碰过的骨**上 ——
  最难查的那种"看起来全对"。漂移也不会有：`pose` 每帧由 `samplePose` 从资产
  重建，不是跨帧累乘。
- **存读往返的存盘进程必须复用同一份建库脚本。** 第一版验"NLA 存进场景"时，
  存盘进程只跑了 `save` —— 存下去的是**空** NLA，而"文件里有 `nlaTracks`"
  照样成立（存的是别人之前写进去的）。断言全绿、什么都没验到。
  > 定式：验"X 被写进文件"时，写盘那个进程必须**先建出 X**，
  > 并且断言用的是**两个进程各自的摘要**，不是"文件里有那个键"。

### 顺手做的一件小事

`smoothFade` 从 `AnimatorSystem.cpp` 的匿名命名空间搬到 `Pose.h/.cpp`：
层的淡入与 strip 的淡入是同一件事，两个三行式子迟早有人只改一边，
然后就变成"层的淡入和片段的淡入手感不一样"——没人会报这种 bug。
表达式一字未改，行为逐位不变。

### 还差

- strip 上**不发事件**（B2）：事件表按 clip 名索引，与 strip 自己的时间映射
  对不上；做对要按 `[prevSrc, curSrc]` 派发。
- 曲线（S-D）/ 约束（S-C）不进 strip —— 与它们各自记的"运行时没接"是同一批活。
- `Multiply` / `Subtract` 混合模式（落到四元数上要先选插值路径）。

## 换掉演示角色：Animate_Girl 真的能用了（蒙皮权重 + 轴向）

用户原话：「你创建的 anime_girl 的模型太粗糙了不能用，能否用
`E:/dev/UE-resources/Animate_Girl` 中的这个试试」。

这件事 **2026-10-23 已经做过一次**，当时卡在 `docs/animate_girl_import.md`
§5 那条"引擎侧蒙皮一画就塌"，文档写着"未解决"。这次把它结了。

### 三条把方向掰正的判断

**① "静止姿势就变形"这个症状，几何上不可能由蒙皮矩阵引起。**
§5 当年怀疑 `invMeshNode · world · invBind` 算错。可是 `world_rest ·
inv(world_rest) = I` 是恒等式 —— 那三个量在静止时必然互相抵消，再怎么
取错也不会让静止的模型变形。按这条把整个怀疑方向丢掉之后，只剩下
"顶点根本不在蒙皮结果里"或"资产本身不是这个样子"两种可能。

**② 先量，再猜。** 离线解 GLB 算出静止 `jointMat` 与单位阵的最大偏差是
**1.8e-6** —— 资产自洽。再用 Blender 比源雕塑与管线产物的几何：X 完全一致
（-0.512~0.512），Y/Z 只是"脚底归零 + 水平居中"，顶点 27394→17535 是焊接。
**几何没坏。** 一帧并排截图确认静止造型与源雕塑一模一样。

**③ 于是问题只剩两个，都在资产侧**：
   · **Y-up 喂给了 Z-up 引擎**。仓库的约定是 glTF 自带 Z-up（旧
     `anime_girl.glb` 的 Hips 在 z=-0.87）。`MeshLoader` 里那个 `kYupToZup`
     对蒙皮网格会被 `invMeshNode · world` 约掉 —— 蒙皮顶点只走 `jointMat`。
     修法是给唯一的根节点（`Armature`）加 +90°X，子节点一个都不用动。
   · **权重是跨肢体混杂的垃圾**。胸口一个顶点：
     `Hips 31% + LeftUpLeg 29% + HeadTop_End 27% + RightUpLeg 13%`，
     和 = 100%。全资产 22.95% 的顶点有"手臂骨 + 腿骨同时拉"，
     另 16 根骨一个顶点都没绑到（含 `Head` / `Neck`）。

### 这轮最该记住的一句

> **权重归一化只证明"权重是一组概率"，不证明"这组概率是对的"。**

旧文档 §4 拿"权重和精确 1.0000、outliers=0"当资产达标的证据，
所以全绿了一整年。真正该问的是"这组概率合不合理"。

### 做法：不碰 Blender，直接重写 JOINTS_0 / WEIGHTS_0

`tools/rebuild_skin_weights.py`（1 秒，纯 Python，确定性，只改两个
attribute，几何/骨架/clip 逐字节不动）。四条关键约定：

1. 骨段 = "父关节 → 本关节"，权重记在**父关节**上。记给子关节的话骨盆
   整圈判给左右大腿（实测：质心 (0,1.018,-0.045) 的壳主导是 `LeftLeg`）。
2. **层级跳数约束 ≤2**：只允许与主导骨在关节树里 2 跳以内的骨参与混合。
   没有这条，垂在胯边的手会被及膝长发同时拉给 `LARM` 和 `LLEG`（8.4%）。
   2 跳刚好：`Spine2→LeftShoulder→LeftArm` 是 2 跳（肩该混），
   `LeftHand→LeftUpLeg` 6 跳（该断）。
3. **小件（包围盒对角 < 0.12 m，887 个）继承最近大壳顶点的权重**。
   纽扣/发饰/贴片本来就贴着身体表面，让它跟"贴着的那个面"一起动。
   这条之前，发饰球和胸口小片是渲染里最显眼的"漂浮碎片"。
4. 壳内两轮邻接平滑，只对 >300 顶点的大壳。

结果：病态混杂 **22.95% → 0.00%**，未绑骨 **16 → 0**。

### 判据被实测否掉两次，值得记

`tools/verify_skin_weights.py` 七条：A 权重和 / B 影响数 / C 跨肢体混杂 /
D 主导骨距离 / E 左右不串边 / F 静止 `jointMat ≈ I` / G 骨覆盖。
带 `--baseline` 拿旧资产对照，它在 C/E/G 上判红（22.95% / 2.73% / 16 根）——
**判据能证伪它要防的那个错**。

- **D 的阈值不能拍脑袋**：卡 0.25 m 会把"及膝长发"判成错（发梢离任何骨
  都 0.5 m）。改成 0.50 并在注释里写明"这条阈值是按资产定的，不是通用常量"。
  1.9 m 那种"关节位置算错空间"的错依然立刻红 —— 这个数就抓到过我自己。
- **E 写坏过两版**：① 逐骨比左右总权重 → 那只是握拳的，右手中指骨真的
  一个顶点都没有，红的是解剖不对称；② 整条肢体比总质量 → 她是"一腿前一
  腿后"的站姿，`LLEG`/`RLEG` 顶点数天然差 40%（旧资产 48%），比不出真假。
  最后改成几何判据"右半身顶点不许被 Right 侧骨占去大头"—— 只跟
  `JOINTS_0` 的下标有关，与这具身体长什么样无关。

### 还差

- **演示场景没切过去**（不是改一行）：`anime_demo.json` 是照旧资产写的
  （7 子网格实体 / `#Skin`·`#Hair` 材质 id / 遮罩根骨 `chest`·`hips`），
  另有 13 个 `verify_*.py` 的断言钉在旧资产的骨名与 clip 名上。顺序应当是
  `first_level.json`（单个 `.glb` 实体）→ 重烤演示场景 → 一轮一两个 verify。
- 玩家默认角色仍是 `alicia.vmesh`，没动（要跟着考虑胶囊尺寸与朝向补偿）。
- 观感残留：侧摆的小发饰偶尔偏出几厘米；胸/腿上的薄贴片轻微错位。
  真正的长发跟头走需要给资产加发骨。

### 追加：跑更大范围回归又挖出四个问题（全部已修）

12 条用例一次跑出来 7 条红，逐条挖完发现**没有一条是"新资产坏了"**：

1. **模板的"来源资产"没被记录** → `verify_anim_events` / `verify_root_motion`
   红成"模板里没有蒙皮实体"。它们只判 `os.path.isfile(TPL)`，资产一搬，
   模板里每条 `mesh.path` 都指空但"文件在"照样为真。
   修法：`bake_template()` 在模板旁写 `.src.json` 记来源资产+机位，
   `ensure_template()` 比对不上就重烤。
   **教训：判"文件在不在"不够，得判"是不是按这份资产生成的"。**
2. **`.vmeta` 是测试间的污染源**。`vmeshIsFresh()` 用 mtime 判缓存过期；
   任何用例只要加载一次 fixture，`finishModelImport()` 就新建一份 `.vmeta`
   （新文件必然更新）→ 之后所有用例悄悄回退 FBX 解析。
   `verify_morph` 的 E1（数 VFMT 行数）把这个抓出来了。
   修法：`verify_world_api` 里那条 `spawn()` 是源头，收尾负责删掉。
   **谁写出来的，谁删掉。**
3. **Content Browser 显示 `.trash`**（`tools/safe_fs.py` 的同目录回收区）。
   每跑完一次用例就冒出来 → 任何"这层正好 N 项"的断言随机红。
   修法：`ContentBrowser.cpp` 跳过 `.` 开头的条目（`.git`/`.vs` 同理）。
4. **拖拽用例钉死"哪个文件在第几行"**。`anime_girl.fbx` 已不在
   `assets/models` 根下 → `verify_content_browser` ③ 组拖不到。
   修法：Content 直接指 `assets/models/_fixtures`（三文件零子目录，永远第一行）；
   **没换成拖静态模型** —— 这条用例的本意含"拖蒙皮 FBX 建
   SkinnedMeshComponent 并贴地"，换掉就丢了这一层。
   另给 `verify_asset_drag` 补了"找不到格子就滚一滚"的兜底。

外加一条与资产无关的老账：`runtime_test/mat_conflict_probe.json` 的两个箱体
只有 `primitive` 没有 `mesh` 块 —— 读端只在 `resolveMesh()` 拿到网格时才建
`MeshComponent`，`primitive` 只是**挂在已有网格上的意图**。所以那两个箱体
一直是空物体，`verify_material_instances` B1 长期 `A=None`。
修法：夹具补 `"mesh": {"kind":"builtin","shape":"cube"}`；同时把 `primitive`
加进序列化器"不算空壳"名单（读写两份）——**存盘不该顺手把读进来的字段抹掉**。

### 追加：粗糙模型「搬家」不算移除（用户打回）

上一轮我把 `anime_girl.{fbx,glb,vmesh}` 用 `git mv` 搬进
`assets/models/_fixtures/`，自认为"退役了"。用户当场否掉：
**名字还是 `anime_girl`、内容还是那具粗糙模型，只是换了个位置** —— 要求
彻底删掉，所有拿它当夹具的用例改指新角色。

于是这一轮的主线变成"删除 + 全量换夹具"，`_fixtures` 整个目录 `git rm -r`，
生成器 `blender_make_girl.py` / `export_test_fbx.py` 一起删（留着就会有人
再跑一遍把模型造回来）。

**连带项三条（少一条都会出"看不懂的红"）：**

1. **`verify_clip_dedup` 的夹具不是角色**，它要的是"take 名重复"这一特性
   —— 两个同长 action（Idle/Walk）打成一份 FBX。为它现写了
   `tools/export_clip_dup_fbx.py`（产物 58 KB，1 骨 1 方块），日志逐字对齐旧输出
   （`FBX-CLIPDUP take='Rig|Idle' ... action=drop` ×2、`clips=2`）。
   ⚠ 顺序必须 **Idle → Walk**：去重保留首次出现，NLA 轨道顺序即输出顺序，
   写反了 C 组 `(Walk,Idle) != [Idle,Walk]`。
2. **实体名跟着资产文件名走**（`instantiateModel` 的规则）：`anime_girl` →
   `animate_girl`、`anime_girl_1/_2` → `animate_girl_1/_2`。所有
   `MYVK_EDITOR_SELECT` / `anim.time <t> <name>` / `select=` 实参都要改。
3. **名字判据全要重量**：骨数 21 → 65（mixamo）、子网格 6 → 7、材质名
   `Skin/Hair/…` → `材质`/`材质.001..006`、镜像轴默认 Y → X。

**"换资产"不是改路径，是把每一处按名字/按数量写死的地方都重新问一遍。**
这一轮 47 处路径 + 4 个脚本的实体名批量替换之后，仍有 9 条用例红，
逐条挖完发现**没有一条是引擎坏了**，全是判据本身在描述旧资产：

- `verify_vertex_format` B0 写死"六个资产" → 改成 `len(BASE)`（删一个就红）。
- `verify_weights`：`mesh:0` 是新角色的**头发/头部**，顶点全挂 Head/Neck，
  没有 L/R 骨，`flipSide` 换不出对侧 → 永远 "试 119 个、成 0 个"。
  改成**挑顶点最多的子网格**（躯干四肢一定在里面）。
  同时 `RigEdit::mirrorAxis` 默认 1(Y) 是照旧资产定的，新角色左右对称面在
  **X** 上 → 权重脚本新增 `axis:<0|1|2>` 命令，用例显式 `axis:0`。
- `verify_pose_mode`：9 条命令全 `CHAR-POSE-SCRIPT-BAD`。根因是
  **mixamo 骨名自带冒号**（`mixamorig:RightArm`），而脚本分隔符也是冒号，
  `split(':')` 把名字切碎后 `a[1]` 只剩 `mixamorig`。
  修法：按"尾部还剩几段"拼名字（`jn(a,3)` 给 `setrot:<name>:x:y:z`），
  六处调用全改。**任何"用分隔符切分、其中一段是用户数据"的协议都是雷。**
- `verify_anim_layers`：遮罩根骨 `thigh`→`upleg`、`chest`→`spine2`
  （`buildBoneMask` 去大小写**子串**匹配，写 `Spine` 会同时命中
  Spine/Spine1/Spine2，必须写带数字那节）。

**`verify_anim_layers` 只能用 glb，不能用 fbx —— 两个理由都是实测的：**

- `characters/animate_girl.fbx` 烤出来的 `.vmesh` 是**散的**：7 个子网格各
  带一份错的节点变换，渲出来头/躯干/鞋分离。静态尺寸看不出来
  （`verify_model_scale` 只量包围盒，量到 1.928 m vs 几何 1.626 m，err 18.6%
  就是"最上到最下"而不是身高），但**比像素的用例一散全废**。
- 换 glb 之后还要**重新取景**：旧机位 `2.10,-2.10,0.85,45,6` 是照旧资产
  1.556 m 定的，新角色 1.626 m 且**底面在 z=0.40**（glb 根节点补的 +90°X
  把原点从脚底挪上去了），结果角色被顶到画面顶边、两条横线全落在身体外面
  —— "上半身没动"量到 7.1%，**看着像遮罩失灵，其实是取景漂移**。
  新机位 `1.96,-1.96,1.79,45,12`（沿视线 2.8 m，fovY=45° → 可见高 2.3 m），
  角色占视口 y=0.14~0.94。

**教训：`UPPER_END` / `LOWER_START` 这类"画面分带"常量是机位的函数。**
换机位不重量，判据会静默退化成"两边都算它一半"。所以写了
`tools/_probe_anim_layers_bands.py`：出一张视口图 + 两条逐行变化剖面，
直接给"腿动区间 / 上半动区间"，抄回常量即可。本轮量到
腿 0.343~0.936、上半 0.143~0.593，于是 `UPPER_END=0.32`、`LOWER_START=0.64`
（各留一格余量），16 条判据逐个 PASS，① 噪声地板 0 px。
