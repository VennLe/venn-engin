## R3-3 光源修饰（区域光 / IES / light function）✅ 完成

用户要求"完成任务R3-3（选做）区域光 / IES / light function"。
三种修饰都挂**射灯**（共享灯的局部正交基，只有射灯有方向）。

### 交付
- **`render/LightTextureLibrary.{h,cpp}`** —— cookie 与 IES 剖面共用一张
  `sampler2DArray`（256²，16 层，`R8G8B8A8_UNORM`）。第 0 层恒全白。
  内建 7 层：white / cookie:grid|rings|bars / ies:narrow|wide|batwing。
  支持运行时 **LM-63 Type C** `.ies` 解析（跳关键字行 → 头行 10 数 →
  竖/横角数组 → candela 网格 → 双线性重采样到 (u=水平角, v=竖直角)）。
- **`scene::LightExtInstance`**（32B）+ `Scene::collectLights(out, mods*)`：
  修饰走**并行 SSBO**（binding17），下标与 lights[] 严格对齐 ——
  `LightInstance` 保持 64 字节不动。
- **`pbr.frag::shadeLocalLightMod`**：IES（角度剖面）/ cookie（锥内投影）/
  区域光（球光代表点：漫反射最近球面软化接触，高光沿反射光取球面最近点）。
- 组件 `SpotLightComponent` 加 areaWidth/areaHeight/iesProfile/lightFunction；
  序列化存取；Inspector 加 "Modifiers" 段。
- `kGlobalSetBindings` 17 → 19（17=LightExt SSBO，18=lightTex 2D array）。
- 环境变量 `MYVK_IES` / `MYVK_COOKIE` / `MYVK_AREA_LIGHT`（默认全关）、
  `MYVK_IES_FILE="name:path;…"`、`MYVK_LIGHTX_DBG=1` 打 `LIGHTX-DBG`。
- `tools/verify_light_modifiers.py`（6 组全 PASS），进回归 DEFAULT。

### 关键判断
- **基线逐位一致**：三开关全关 → 逐灯记录全零 → 走**原样的**
  `shadeLocalLight`（而不是"新函数里 mod=1"）—— 避免浮点重结合让最后一位不同。
- **为什么不扩展 LightInstance**：它被阴影/分簇按 64 字节算偏移，
  扩它要动所有着色器；并行数组 + 下标对齐更安全。
- **区域光用球光代表点而非 LTC**：LTC 需要预烘 LUT（本地没有、离线环境也不好
  搞），代表点近似是现成解析式，能做出"柔高光"这一验收点。

### 踩坑（重要）
- **测试场景必须先确认信号可见**：首版把射灯摆在相机正下方，光池在 FOV 外，
  cookie/IES 差分**全 0**，一度以为着色器没生效。实际是"信号不在画面里"。
  验证脚本里加了 `bright_bbox` 自检光池可见性。
- `textureSize(sampler2DMS)` 无 lod 参数（R3-2 已知）；GLSL 里 `(void)x` 非法。
- `.ies` 头行要用 `std::streamoff` 存 tellg，`std::streampos` 不能直接赋 0。
