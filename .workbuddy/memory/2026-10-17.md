## 3 · 逐点技术定论

### 3.1 主题多风格（第 1 点）

- 把写死的 `applyVennStyle()` 提炼成 `ui::applyTheme(int)`；**尺寸度量与颜色解耦**（度量不动，只换色）。
- **VennDark 逐字段照抄改动前** → 默认主题**逐像素不变**（硬约束）。
- 其余 4 套（`UeDark` / `BlenderDark` / `UnityDark` / `Daylight`）由 **3 个锚点**（bg / accent / text）
  经 `deriveDark()` / `deriveLight()` 派生；浅色主题走 `StyleColorsLight()`。
- **发现并修掉"深色孤岛"**：浅色主题下**顶栏 / 工具条（`drawTransportBar`）/ Inspector 图标条 /
  视口叠加片**原来都硬编码深色 → 在浅色主题里像贴了块黑板。
  修法 = 新增 **`Token.barBg`**（与 `MenuBarBg` 同源）+ 视口叠加片按 `isLight` **额外推 `Text/TextDisabled` 为浅色**
  （深色主题不推 → 逐像素不变）。

### 3.2 启动闪白（第 2 点）

- **现象**：窗口先以系统默认（白）背景露脸，首帧渲染完成才变黑。
- **修法**：① 构造函数**不立即 `glfwShowWindow`**，改 `applyDarkBackgroundBrush()`
  （`SetClassLongPtrW(hwnd, GCLP_HBRBACKGROUND, CreateSolidBrush(RGB(27,28,30)))`）；
  ② 首帧真正呈现后调 `show()`（幂等 + `glfwFocusWindow`）；③ **缓冲 2 秒**（`kStartupShowDelay`）。
- 自动化兼容：`MYVK_NO_WINDOW_SAVE` 会顺带跳过缓冲 → 新增
  **`MYVK_STARTUP_DELAY=1`** 强制保留缓冲（测试既要不写 `imgui.ini`、又要能测缓冲）。

### 3.3 胶囊线框（第 3 点）

- 旧版 = "上下两个半圆盘 + 4 条母线"，球冠收口难看 → 用户说"不完整"。
- 新版：**12 条贯通经线**（北极 → 上半球 → 直段母线 → 下半球 → 南极）+ **4 个纬线环**
  （`ringZ[4] = {h, -h, h+zc, -h-zc}`），球冠**完整闭合**。
  分段常量：`kCapsuleRingSegments=24` / `kCapsuleArcSegments=6` / `kCapsuleMeridians=12`。
- **几何量测**（`verify_capsule_shape.py`）：显式 `R=0.35 / halfHeight=0.90` → **H/W=3.571**、
  上下对称 100%、球冠收窄、桶身直段 —— 全部符合解析预期。
- ⚠ **重要事实**：`MYVK_EDITOR_COLLIDER=capsule` 走"拟合"路径时，对 **1m 立方体必然拟合出球**
  （`r = sqrt(half²+half²) = 0.707`，`halfHeight = max(half − r, 0) = 0`）。**这不是 bug**，
  是"胶囊整体盖住 AABB"的必然结果 —— 已把这条钉成用例 B 的期望。

### 3.4 吸附默认全开（第 4 点）

- 三套吸附（`m_snapMove/m_snapRotate/m_snapScale`）构造默认 `false → true`；
  步长 **`0.1m / 10° / 0.1×`**。
- **同步改 prefs 的 `def`**（否则老存档逐键覆盖会把开关顶回关）。
- 新增 `MYVK_EDITOR_SNAP=0|1` 钩子（拖拽脚本暂未用，实测不影响既有用例）。

### 3.5 地面栅格（第 5 点）

- **确认**：`minorStep = 1.0` / `majorStep = 10.0` → **确实 1m×1m 单元格**（10m 一条粗线）。
- **放大**：`extent 60 → 250`（半边长 → **500m 见方**，对齐 UE5 默认规模）；
  `fadeStart 45 → 200` / `fadeEnd 60 → 250`。
- ⚠ 实际淡出被 `min(fadeEnd, extent, far*0.95)` 再夹一次（相机 far 默认 200m）。
- ⚠ `GridSettings.color{0.72,0.76,0.82}`（浅青）**会与碰撞体线框的青色判据撞色** → 见 §6 那条既有缺陷。

### 3.6 中英语言切换（第 6 点）★硬约束

- 调用点**只写英文**，`tr("English")` 运行时查 `kZh[]` 词典返回中文；`trId(name, id)` 返回
  `"译文###stableId"` —— **窗口 ID 保持稳定**（ImGui 用 `###` 后的部分做 ID）。
- **机械包装**：`_wrap_tr.py` 向 ~15 个 `editor/*.cpp` 插入 **792 处 `TR(...)`**；
  13 处 `Begin→trId`；**9 处字符串拼接误包**改回"只翻字面量片段"；
  **11 处"包装前就是中文"**改回英文原文 + 词典补条；43 处 `setStatus/notify` 前缀包装。
- **结果**：`editor/` 下**未包装中文字面量 = 0 处**；词典 **约 609 条**。
- Preferences 新增 **Language 下拉**（English / 简体中文）。
- ⚠ 踩坑：ImGui **窗口名兼作窗口 ID** → 翻译后 ID 变了会丢布局 → 必须用 `trId()`。

### 3.7 Hierarchy 锁定/可见（第 7 点）★真因

**锁定点了没反应** —— 真因不是逻辑没写，是**控件收不到事件**：

- `imgui.cpp:5121` `ItemHoverable`：
  ```cpp
  if (g.HoveredId != 0 && g.HoveredId != id && !g.HoveredIdAllowOverlap) return false;
  ```
  行尾的 `InvisibleButton`（🔒/👁）**叠在 `TreeNodeEx` 的行矩形上**，而节点**先提交** →
  命中测试在节点那一帧就把 `HoveredId` 锁死 → 图标**永远收不到 hover/click**。
- **修法** = 节点加 **`ImGuiTreeNodeFlags_AllowOverlap`** → 命中改成 **front-to-back（后提交者优先）**。
- **否定测试确认**：去掉 `AllowOverlap` 重编译 → 断言 A2-1/A3-1 **必 FAIL** → 修复是 load-bearing。
- **第二个坑**：`Scene::light()` **懒创建**的太阳实体只加了 `NameComponent` + `DirectionalLightComponent`，
  **没有 `VisibilityComponent`**（`Scene::createObject` 才会无条件加）→ 行尾 👁 缺失。
  修法 = 懒创建时**补齐可见性组件** + `sunVisible()` 语义 + `Renderer` 太阳 UBO 认它。
  另：👁 **改成无条件画**（无组件 = 可见），点它时按需补 `VisibilityComponent`。
- 顺带：行悬停改**矩形判**（`IsWindowHovered(ChildWindows) && IsMouseHoveringRect(...)`）——
  否则鼠标移到行尾图标上时 `IsItemHovered()` 会抖。

## 4 · 语言层：为什么"代码零中文"是硬纪律

用户第 6 条原话：**"显示中文时只是一个映射替换，实际在引起代码逻辑中请务必继续保持英文"**。

- 理由：中文一旦进**源码字面量**，就会同时进 `std::string` 比较、`find`、序列化 key、
  ImGui ID 计算、日志解析 —— 任何一处都会变成"改个词就静默坏"的雷。
- 落法：**`editor/` 下所有 UI 文案只写英文**，中文只存在于 `Localization.cpp` 的一张表里。
- 复查口径：`TR-CJK` 类别扫描 `editor/*.cpp` 中**未被 `TR()` 包裹**的中文字面量 → **0**。

## 5 · 偏好存档 schema 门（`kPrefsVersion=2`）

**发现的坑**：偏好是**逐键覆盖**（`loadEditorPrefs` 把 `prefs{key:number}` 每个键覆盖到出厂默认上）。
于是**老存档里存的旧默认值会把新默认顶回去** —— 用户升级后看到"我明明改了默认，怎么没生效"
（本轮正好改了吸附默认 + 栅格默认，必踩）。

**修法**：给**偏好**单独一个 schema 版本 `kPrefsVersion`（布局继续用 `kFormatVersion`，互不牵连）。
`loadEditorPrefs` 里 `version < kPrefsVersion` → **整份作废、回出厂默认** + 记 `VK_LOG_INFO`。
**注意**：`kPrefsVersion` 与 `kFormatVersion` 是**两套独立门**，别混。

## 7 · 量测坑（本轮新增，值得进纪律）

- ⚠ **sRGB 交换链二次编码（旧坑 #34）在像素判据上的体现**：ImGui 字节色被当**线性值**再编码一次 →
  实测面板底亮度 **深色 85~132 / 浅色 225~245**。**像素判据必须用"上屏实测值"**，
  阈值也要跟着放松（不能按理论 sRGB 亮度定）。
- ⚠ **整窗均值会被 3D 视口拽平** → 主题/语言用例的判据改成**只取 `PREFS-WIN` 矩形内部**的亮度。
- ⚠ **`logRect` 的 tag 只吃 `[A-Za-z-]`**（`RECT_RE` 限制）→ 中文页名不能用，
  `PREFS-TAB-<页名>` 必须用**英文页名**。
- ⚠ **`verify_startup_show` 别用"find_window 后再 sleep"** —— `find_window` 自己会吃掉 0.8s 预算，
  探针会晚到 3.0s 才跑 → 误报。改**连续轮询**、用"**首次可见时刻**"当观测量。

## 13 · 咨询：把引擎变成"能开发完整 3D 游戏"还缺什么（2026-10-17 上午）

用户问"要完整开发出一个 3D 游戏，还缺哪些功能和设计"。做了一次**代码事实核查**（不是凭印象）：

**核查结论（关键发现）**：

| 领域 | 实测状态 | 证据 |
|---|---|---|
| 渲染/场景/资产 | **很强** | forward+ clustered / bindless / MDI+GPU cull / Hi-Z / CSM / SSGI / TAA / 曝光 / LUT / 动态分辨率 / froxel 体积雾 / 面光源 / POM / 延迟贴花 / SSS / 反射探针 / GPU 粒子 |
| 物理 | 刚体可用 | `engine/physics` 25 文件；**无** collision 回调 / trigger / physics material / 角色控制器 |
| 脚本 | **已有自研 `.vks`** | `editor/script/ScriptEngine.*`（属性动画级：move/rotate/setColor…；热重载；沙箱） |
| 动画 | **只有采样** | `Skeleton::sample(clip,time)`；**无** AnimatorComponent / 状态机 / 混合 / 根运动 / 事件 / IK |

## 收尾追查：角色预览"白剪影"的真因（FBX 自发光漏乘 Factor）

用户四项需求交付后，复核角色面板截图时发现预览仍是纯白 —— 一路查下去挖到一个
**引擎级材质 bug**，和四项改动无关、但一直被它挡着。

### 症状与否定测试
- 模型内部亮度：p5..p95 = **11 级**、std 3.5、R−B std 1.1（灰白、无色、无明暗）。
- `m_previewScene.light().intensity` 改 1.8→1.1→0.65→**0.0**、`ambientScale` 改
  0.6→0.25→0.12→**0.0**、颜色改 **纯红 ×3.0** —— 画面**一点没变**（230~232）。
- 一度误判成"预览没绑自己的 set 0"。加日志逐层验：`uploadSceneState` 上传的值、
  `recordOffscreenTarget` 拿到的 `m_sceneGlobalSet`、`ensureOffscreenUbo` 的
  描述符写入**全是对的**（`PREVIEW-CALL ... lightInt=3.00 col=(1.00,0.00,0.00)`）。
- **决定性对照**：同一模型的 `anime_girl.glb` 在**同样红光**下渲染成**鲜红且明暗分明**
  → 预览光照链路完全正常，问题在 FBX 的材质数据。

### 真因
`assets/models/anime_girl.fbx` 的 7 个材质全是：
`pbr.emission_color = (1,1,1)` 且 `fbx.emission_factor = 0.00`。
FBX 里 `EmissiveColor` **恒写 (1,1,1)**，"发不发光"由 `EmissiveFactor` 决定
（Maya/Blender 导出普遍如此）。`fbxMaterial()` 只取 `pbr.emission_color.value_vec3`、
**丢掉了 Factor** → 每具 FBX 模型都在以纯白自发光渲染，任何光照都被盖住。
`.glb` 没有这个问题（glTF 的 emissiveFactor 默认 0），这就是"glb 正常 / fbx 发白"
的全部原因。

### 修法
`engine/assets/FbxLoader.cpp`：`if (mat.fbx.emission_factor.has_value) emissive *= factor;`
其余一律不动（Factor=1.0 的资产逐位不变；Factor=0 的不再发光）。

### 效果（同一窗口、同一机位实测）
| 指标 | 修前 | 修后 |
|---|---|---|
| 明暗动态范围 (p5..p95) | 11 | **138** |
| 亮度 std | 3.5 | **45.6** |
| R−B std（色彩离散） | 1.1 | **14.3** |

模型露出真实材质色（紫发 / 肤色 / 粉裙）—— 之前全被白色自发光糊成一片。

## 傍晚 · 三件用户需求：栅格虚化 / 抽屉层级 / Content 三栏

### 一、栅格"虚化 / 部分不可见" = **共面深度冲突**（不是 LOD）
**判定证据（一眼就能看出来）**：同一帧里，**40 m 地板覆盖的像素上格线完全消失，
出了地板边界（深色背景）格线立刻出现**。1 m 小格精确地顺着地板边缘开始 ——
LOD 是连续淡出，不会这样，所以是遮挡。

数值证据（俯视 40 m / 45°）：地板内 p98=175（= 地板本色 167，没有线）→
把顶点偏移从 `1e-6` 临时放大到 `1e-3` 后 p98=208（线全回来了）→ 确认深度问题。

根因：栅格与地板都在 z=0，原来只在**顶点**里 `clip.z -= 1e-6*clip.w`；而这个
四边形横跨 ±2000 m，光栅化要在 4 km 跨度上插值 clip.z，误差与 1e-6 同量级。
放大到 1e-3 能盖住但等于把栅格抬高 4 m（20 m 处），隔壁物体穿模。

**修法**：把深度搬到片元里 —— `grid.frag` 里用 `vWorld`（这个像素自己的地面点）
重算 `proj*view`，`gl_FragDepth = clip.z/clip.w - 1e-5`；`grid.vert` 的偏移删掉。
`1e-5` NDC = 4 cm@20 m / 4 m@200 m，只是"深度上更靠前一点"，看不出位移。
代价：这条管线失去 early-Z（栅格本来就排在不透明之后、不写深度，可忽略）。

**复测**：6 个机位截图 + 像素统计；地板内 p98 175 → **206.7**。
回归地图补了 `verify_fxaa` / `verify_local_shadow` 的 `grid.*` 触发器
（它们的视口截图里一直有栅格，只是以前被深度冲突吃掉，依赖是隐形的）。

### 二、抽屉层级 + 分割线渗透
1. **层级**：ImGui 的绘制顺序 = `g.Windows` 顺序，而**点中某个窗口会把它挪到

## 第四轮（晚）：顶栏重做 / 面板最小化 / 粒子类型化

**需求三条**：① Character 叉号关不掉 + Output Log/CMD 打不开 + 所有浮动面板要有最小化（收回到 + 右侧托盘按钮）；② 顶栏按 UE5 重做（选择模式下拉 + Add + 播放条），1/2V/2H/4 挪到"透视"右边成下拉，移除 Move(W/E/R)/View:lit/Reload Shaders/Undo/Redo；③ 粒子按类型命名 + 序号后缀、右键重命名/删除、新增雨/雪/闪电。

**落地**
- 面板注册表 ⇄ 窗口对象的同步**必须**放在每帧无条件执行的地方（`drawCharacterWindow`），写在 panel 的 `drawFn` 里是死路（`drawPanels` 只在 panelOpen 为真时派发）。用 `m_characterWasOpen` 区分"用户点 × 关的"与"刚被勾上的"。
- 最小化按钮：`Begin()` 内部画完标题栏，没官方入口 → 所有窗口画完后 `FindWindowByName` + `window->DrawList` 手画 + 手算命中（要求 `g.HoveredWindow == w`）；位置 = 关闭 X 左边一格（`Pos.x+Size.x - FramePadding - FontSize*2 - 2`）。
- `panelTrayEligible ≠ panelFloating`：Console 不长托盘按钮但必须有最小化按钮 → 拆出 `panelFloating(p) = layoutSlot==kSlotNone && draw`。
- 顶栏：`Select Mode ▾` │ `+ Add ▾` │ 右对齐 `▶ ▶| ⏸ ■ ⋯`。播放图标是矢量（字符 ▶ 在自带字体里是豆腐块）。`+ Add` 与 `Shift+A` 共用工厂函数，落点改为 2m 环排队。
- `1/2V/2H/4` → 视口工具条"透视"右边下拉，**并真正接通分屏**：主目标只渲一格（不摊薄分辨率），其余格用 `Renderer` 子视口目标（格 0 透视 + 格 1..3 前/顶/右），交互只在格 0。两条切布局入口共用 `editor::applyViewportLayout()`。
- 粒子：预设 3→6，`<类型> <序号>`（从 1 起），行内重命名（记 id 不记下标）/复制（`Rain 1`→`Rain 3`）/删除。

**坑**
