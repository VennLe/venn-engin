## 一、通用 RenderTarget 抽象

### 结构

`render::RenderTarget` = `HdrTarget`（MSAA + HDR + 深度）+ `PostProcess`（Bloom + 合成 +
FXAA）+ ImGui 输出纹理 + 尺寸/脏标记/绑定的 scene&camera + `slotIndex`。

`setSize(w, h)` 的两条语义：

| 情况 | 语义 | 结果 |
| --- | --- | --- |
| `w` 或 `h` 为 0 | **直写交换链**（游戏模式） | `m_offscreen=false`，HDR 跟交换链尺寸，`postViewport` 传 `{0,0}` |
| 两者都非零 | **离屏**（编辑器模式） | 下限 16x16 |

`apply(swapViews, swapExtent, postInputViews)`（waitIdle → 懒建/重建 → refreshTextures）与
`recreatePost(...)`（只重建 Post，供链激活翻转 / 热重载用）分离。

### 裸指针桥接策略（关键设计）

`Renderer.cpp` 全文有 ~59 处 `m_hdrTarget->` / `m_post->` 调用。把这两个成员从
`unique_ptr` 改成**非拥有裸指针**、指向 `m_targets[0]` 内部 —— 全部调用点**一行都不用改**。

```cpp
std::vector<std::unique_ptr<render::RenderTarget>> m_targets;  // [0] 主视口（常驻）
                                                              // [1] 角色预览（懒建）
                                                              // [2] 额外视角（MYVK_EXTRA_VIEW=1）
render::RenderTarget* m_hdrTarget;  // 别名 -> m_targets[0]->hdr()，兼容既有 59 处
render::RenderTarget* m_post;       // 别名 -> m_targets[0]->post()
```

### 顺带修掉一个既有真 bug：每离屏目标一份相机 UBO

`FrameUBO` 是 HOST_VISIBLE + 常驻映射、在**录制期** memcpy 的。一个命令缓冲里先后录制
"主视口"与"预览/额外视角"两个场景时，memcpy 只有最后一次能留在 buffer 里，GPU 执行时
**先录制的场景也会读到后一次的值** —— 主视口被渲染成预览相机的视角。旧注释里写着
"预览场景会把主场景的 UBO 覆盖掉，但主场景命令已录制完毕……安全"，**其实不安全**。

修法：`FrameResources::OffscreenUbo{ ubo, mapped, set }`（`std::vector`，下标 =
`m_targets` 序号 - 1），离屏目标各持一份 UBO + 各自 set 0，其余 14 个 binding 与主链共享。

## 三、相机特效：分层落点

| 效果 | 需要什么 | 落点 |
| --- | --- | --- |
| DoF / 运动模糊 | 深度 + 相机矩阵 | **FrameGraph 链**（前向后） |
| 色差 / 暗角 | 显示域单次采样 | **PostProcess 合成**（共享既有 push，0 额外 pass） |

### FrameGraph 链扩到 5 个 pass

`kPasses[5] = {SSGI, SSR, GODRAYS, DOF, MOTIONBLUR}`（镜头效果排最后，作用于最终画面）；
`chainActive(s, fx)` / `passCount(s, fx)` / `outputView(fi, s, fx)` / `execute(..., s, fx, in)`；
`kMaxPasses = 5` + `static_assert(sizeof(kPasses)/sizeof(kPasses[0]) == FrameGraph::kMaxPasses)`。

* **DoF 推常量（32B）**：`DofPush{ vec4 cam(zn,zf,focus,aperture); vec4 params(maxRadiusPx, texelX, texelY, _); }`。
  着色器用 `vennViewDepthFromNdc` 线性化深度算 CoC（不需要 invProj，故从 96B 缩到 32B）；
  `radiusPx < 0.75` 直接返回原色（对焦区逐像素不变）。16 样本黄金角螺旋（`kGoldenAngle=2.39996323`），
  样本权重 `smoothstep(0, radiusPx, scr)` 防 halo。
* **运动模糊推常量（96B）**：`MotionBlurPush{ vec4 cam(P00,P11,zn,zf); mat4 clipFromView; vec4 params(strength,samples,maxVelUv,_); }`。
  `clipFromView = prevViewProj × inverse(view)` —— 一个矩阵把"视图空间点 → 上一帧屏幕 uv"
  整条链压完（放不下 curVP+prevVP+invProj 三个 mat4）；片元用 P00/P11 解析反投影重建视图点。
  首帧 `prev = cur` → 速度恒 0 → 像素不变；着色器内 `len < 1e-5` 短路返回原图。
* **合成推常量扩到 32B**：`vec4 params(exposure, bloomStrength, tonemapMode, vignette)` +
  `vec4 camfx(chroma, vignettePower, 0, 0)`。`PostCameraFx{chroma, vignette, vignettePower}` +
  `setCameraFx()`；`makeFullscreenPipeline(..., pushSize)` / `drawFullscreen(..., push, pushSize)` /
  `recordFullscreenPass(..., push, pushSize, ...)` —— bloom/fxaa 传 16B，合成传 32B。
  暗角改 `1.0 - w*pow(r2, camfx.y)`（幂 = 1 时退化为旧公式）；色差 `chroma<1e-6` 走逐字相同的旧路径。

### 后处理体积

`scene::PostVolume{ boundsMin/Max, priority, blendDistance, 六个浮点覆盖 + 四个三态 int 开关(-1/0/1) }`，
哨兵 `kNoOverride = -1.0f`。`PostVolumeSet::evaluate(camPos)` 按 priority 升序叠加，AABB 内权重 1、
过渡带线性衰减到 0；`blendFloat` 按 w>=0.5 采用、否则与已覆盖值插值。
`Renderer::updateCameraEffects(scene)` 把覆盖叠到 `m_cameraFx` 得 `m_effectiveCameraFx`。

### 关断基线保证

色差 0 / 暗角幂 1 → `post.frag` 逐字相同路径；DoF 对焦区 `radiusPx<0.75` 短路；
运动模糊静止/首帧 `len<1e-5` 短路；链全关时 0 pass、PostProcess 直采 HDR。

## 五、⚠ 回归排查：verify_character_window 的 CHAR-CLIP

### 现象

双轮回归第一轮 22/23，唯一失败是 `verify_character_window`，唯一失败断言
"拿到动画条目矩形（CHAR-CLIP）"。`_venn_verify/_reg_round1.log`（10-12 14:51）显示该用例
此前 `PASS rc=0 18.7s`，所以按"本轮引入的回归"立案。

### 关键线索

1. 该断言不涉及像素比对，只是 `wait_clip_rect`（5s 超时）没等到 `CHAR-CLIP-<名字>=(...)`；
2. 其余 9 项全 PASS，含"独立预览离屏链创建（第二套渲染目标）"；
3. 日志里 `Preview render size -> 934x701 (offscreen)`，但窗口客户区只有 1578x844
   —— **预览子区比窗口还大**，不可能；
4. 截图里角色窗口**不可见**（只剩右边缘一条）。

### 根因

`build/bin/imgui.ini`（**gitignored、未跟踪**，纯本地布局产物）：

```ini
[Window][character]
Pos=1559,597
Size=1263,794
```

* `1263 - 280(左栏) - 内边距 ≈ 934`、`794 - 标题栏 - 内边距 ≈ 701` —— 与日志的 `934x701` **精确吻合**；
* `Pos=1559` 而客户区宽只有 1578 → 角色窗口几乎整体在客户区右/下**之外**；
* `Pos=1559,597` 在**全屏**会话（`editor_window.ini` 记着 3840x2054）里完全正常 ——
  这个坐标就是最大化手动会话留下的；
* 脚本用 `SetWindowPos` 把窗口缩到 1600x900 后，ImGui 把存档坐标读回来 → 窗口跑到屏幕外：
  ImGui 照画、`logRect` 照打坐标，**脚本按那段矩形点击全部落在窗口外且不报错**
  → Animation 标签永远切不过去 → 没有 `CHAR-CLIP`。
* 而且是**持久化**的：每轮都写回，一次踩脏永久复现。

### 修复

`InspectorPanel.cpp` 里早有一句注释——"ini 被 MYVK_NO_WINDOW_SAVE 关掉了"——**这个约定
一直缺实现**（`MYVK_NO_WINDOW_SAVE` 此前只管 `editor_window.ini`）。补上：

```cpp
// engine/ui/ImGuiManager.cpp, init() 内
if (std::getenv("MYVK_NO_WINDOW_SAVE") || std::getenv("MYVK_FRAMES")) {
    io.IniFilename = nullptr;
    VK_LOG_INFO("ImGui settings persistence disabled (automation run)");
}
```

（ImGui 的 load 与 save 都有 `IniFilename != NULL` 守卫，置空即彻底停用；主面板 Pos/Size
由 `computeLayout()` 每帧显式设定，本就不依赖 ini，故不受影响。）

修复后单独跑：`RESULT: PASS`，`Preview render size -> 431x467`（760x560 窗口的正确值，
而不是 934x701），`CHAR-CLIP` 与 `play clip 'Rig|Walk'` 均通过，截图里角色窗口正常显示

**结论：这不是本轮代码的回归，是自动化环境里的布局污染；但暴露了一个真实缺陷

## 六、本轮踩到的其它坑（已记入 MEMORY.md #80~#85）

1. **一个命令缓冲录多相机 → FrameUBO 必须一相机一份**（录制期 memcpy 会互相覆盖）。
2. **尺寸重建路径顺序**：`recreateScreenSpace()` 必须早于 `postInputViews()`，否则写进
   即将销毁的工作图句柄，验证层报 `Invalid VkImageView Object 0xaa00...`。
   所有 `m_mainTarget->apply(...)` 第三参改传空 vector，收尾走 `rewireMainTargetChainInput()`。
3. **`updateCameraEffects` 必须排在尺寸重建之前**（尺寸路径要靠 `m_effectiveCameraFx`
   决定接哪张图；用上一帧的生效值会漏接一次）。
4. **`MYVK_MB_SIM_YAW` 必须绕相机自身位置偏航**，绕世界原点转会撞速度上限 `params.z=0.25`
   饱和 → 强度参数失效（B3 断言假通过）。
5. **差异像素计数在阈值处会饱和**，强度类断言应看**平均差**（线性量）。
6. **`RT-TARGETS` 名字按指针身份而非下标**（预览目标懒建，下标会错位）。
7. **预览关闭不能走 `setSize(0,0)+apply`**（会按交换链尺寸白建一张 1600x900 的 HDR）。

其它过程性教训：

* 构建期间不能替换 exe：`ninja` 报 `no work to do` 但 exe 仍是旧的 —— 先
  `taskkill //F //IM Editor.exe` 再确认 `ls -la build/bin/Editor.exe` 时间戳比源码新。
* `FRAMEGRAPH passes=2 msaa=1` 里的 `msaa` 是**布尔**（1 = MSAA 开），不是采样数。

## 十二、R1-1 TAA 时域抗锯齿（11:45-12:30）

清单第三项（docs/render_roadmap.md 阶段 1 的首项）。

### 交付

* **assets/shaders/fg_taa.frag**：YCoCg 空间 3×3 邻域**方差钳制**（mean ± k·sigma，
  Salvi 2015 式）+ 时间混合 `mix(clamped_history, current, blend)`；重投影复用
  `clipFromView`（= prevViewProj × inverse(view)）；历史失效三情形
  （push valid=0 / w≤0 / uvPrev 出屏）直接输出当前帧 —— 后者顺便天然处理
  disocclusion 与相机跳变。同样编 `.msaa` 变体（MSAA 深度共存，不强制降 1x）。
* **FrameGraph 的 TAA 预 pass**（链的**头**，不是 kPasses 里的普通项）：
  每帧两张持久图 `m_taaOut`（视图**固定**：做链源头 + PostProcess 输入）与
  `m_taaHist`（被采样），加一次 out→hist 的 `vkCmdCopyImage`；TAA 自己的
  descriptor set 是一个 set 三个 binding（本帧色 / 深度 / 历史）。
  `chainActive` 带上 `s.taa`；`passCount` 仍只数写工作图的 pass；
  `outputView` 在"只剩 TAA"时返回 `m_taaOut[fi].view`。
* **Renderer**：帧首 Halton(2,3) 子像素抖动（`ubo.proj[2][0]/[2][1] += j`，
  **按帧槽各持一个相位计数器**）；抖动排在视锥提取**之后**（剔除必须帧间稳定）；
  重投影链修正为 `m_prevViewProj(未抖动) × inverse(view)`（见下）；
  `MYVK_TAA / _BLEND / _CLAMP / _PHASE` env；面板 TAA 勾选 + Blend / Clamp 滑块。
* **tools/verify_taa.py**（回归第 26 例，8 轮）：A 日志（taa=1/hist=1、关时无行）、
  B 关=基线逐像素恒等、C 开≠基线、D 抗锯齿（Laplacian>20 降幅 + 边缘局部性）、
  D3 MSAA=1 显著、E 两次运行**无可见差异**、F 抖动相位 0 vs 1 显著、G 零 VUID。

### 顺带修掉一个既有真 bug（运动模糊的重投影矩阵）

`m_curClipFromView = m_viewProj * inverse(ubo.view)` —— `viewProj = proj·view`，
乘上 `inverse(view)` 后**恒等于 `proj`**。也就是说原来的运动模糊只对"投影变化"
有反应，相机真正平移/旋转时反而不动。verify_camfx 的 B2/B3 之所以一直能过，
是因为它们走 `MYVK_MB_SIM_YAW` 钩子**直接覆盖**了那个矩阵。现改为
`prevViewProj(未抖动) × inverse(view)`，运动模糊第一次真正跟相机运动挂钩；
B1（静态 = 恒等）不受影响。

### 踩的坑（MEMORY #92~#96）

1. 抖动相位用全局计数器 → 两个帧槽各只见一半相位、收敛到两张不同图，
   跨运行不可复现（E1 挂：max 77 / 611 px）→ 改成 `m_taaPhase[2]` 各槽 +1（max 8 / 0 px）。
2. 首帧跳过 barrier → 历史图停在 UNDEFINED，验证层按 **SPIR-V 静态判定**
   认定它会被采样 → VUID 09600（片元里的 if 拦不住）。必须无条件迁移布局。
3. TAA 不能 ping-pong 输出图（PostProcess 输入描述符只在 recreate 时写）→ 固定 out + 每帧 copy。
4. 抗锯齿判据用一阶梯度几乎不动（TV 守恒，只 1.3%）→ 换二阶差分（−53%）+ 边缘局部性（14.8×）。
5. 收敛判据不能写"逐像素全等"（8 相位极限环 + 抓拍相位）→ 改"无可见差异（>18 为 0）+ 平均差上界"。

### 结果

* 单跑 verify_taa：**全部断言 PASS**。实测 MSAA=1 下 Laplacian>20：10361 → 4877（−53%），
  边缘/非边缘变化比 14.8×；两次独立运行可见差异 0 px。
* 完整回归（第 1 次，26 用例）：`_reg_r11_round1.log` —— **23/26**，
  失败：`verify_frustum_cull` / `verify_bvh` / `verify_ibl`。

## 十四、R1-3 色彩分级 LUT（32³）（13:13-13:35）

### 做了什么

`docs/render_roadmap.md` R1-3：影视感调色的标准载体。五个调色参数
（lift / gamma / gain / contrast / saturation）在 **CPU 侧烘成 32³ 3D LUT**，
合成 pass 里**一次三线性采样**。
* `PostProcess::bakeLut()`：按固定顺序把调色作用到 32³ 格点（全程显示域，
  与 LUT 的定义域一致）→ `glm::packHalf2x16` 打包 **R16G16B16A16_SFLOAT**
  → staging 一次性上传 3D 纹理 → 迁到 `SHADER_READ_ONLY` **永久停留**。
  参数变了才重烘（`beginFrame` 比对快照）。格式优先 16F，退 8-bit UNORM
  （用 `findSupportedFormat` 查线性过滤支持）。
* `post.frag`：新增 `set = 2, binding = 0` 的 `sampler3D`；LUT 插在
  **tonemap 之后、暗角之前**（信号已是显示域 [0,1]；暗角属于镜头不属于调色）。
  采样坐标 `c·(N-1)/N + 1/(2N)`。推常量 32B → 48B（多一个 `vec4 lut`）。
  合成管线 set 数 2 → 3、pushSize 32 → 48。
* 调色数学（顺序固定）：`lift c += l·(1-c)` → `gamma c = c^(1/g)` →
  `gain c *= g` → `contrast c = (c-0.5)·k + 0.5` → `saturation c = mix(lum,c,s)`。
* `PostSettings` 加 `colorGrading / cgLutBlend / cgLift[3] / cgGamma[3] /
  cgGain[3] / cgContrast / cgSaturation`；`PostVolume` 加 `cgLutBlend` 覆盖项；
  编辑器面板加勾选 + 5 组滑条 + reset（`LUT-COMBO`）；env 一组 `MYVK_CG*`。
* 新增 `tools/verify_color_lut.py`（8 轮 / 6 组断言），接入 `run_regression`
  （现 **28 例**）。

### 关键设计与坑点（MEMORY #101~#104）

1. **构造时立即烘一次**（哪怕默认恒等）：只有主目标的 `PostProcess` 会被
   驱动 `beginFrame`，副目标若延迟烘焙会让 LUT 图停在 `UNDEFINED`，而描述符
   声明的是 `SHADER_READ_ONLY` → 验证层报错（同 TAA 的 VUID 09600）。
2. **恒等 = 仿射** → 硬件三线性可**精确重建**，这才是"开着但默认 ≈ 不变"
   可断言的原因；采样坐标映射写错会整体偏色（B 组两条断言专治这个）。
3. **⚠ 并发跑 GUI 测试会互相残杀**（`kill_stale_editors` 是无差别
   `taskkill /IM Editor.exe`）—— 本轮因此废掉一整轮回归。
4. **空图脆性**修到共享入口：新增 `capture_window.capture_nonempty()`（重试到
   非空、拿不到返回 None），`verify_shader_variants` / `verify_auto_exposure`
   / `verify_color_lut` 全部改走它。

### 验证结果（单跑 verify_color_lut，全部 PASS）

* **A 关闭**：`enabled=0`；同配置两次运行视口**平均差 0.0000**（逐像素一致）。
* **B 恒等 LUT**：与基线 **>18 的像素 = 0**、最大差 **1**、平均差 **0.060**。
* **C 对比度方向**：`contrast=1.8` → 亮度 std **37.6 → 67.9**（展宽，
  与基线平均差 60.1）；`contrast=0.5` → **13.2**（收窄）。
* **D LUT 真被采样**：`saturation=0` → 视口 **|R-G| = |G-B| = 0.000**（中性灰）。
* **E blend 单调**：变化量 恒等 **0.06** → 半开 **19.9** → 全开 **60.1**。
* 全程零 VUID。

## 十五、R1-4 动态分辨率 + TSR 式升采样（13:55-14:12）

### 做了什么

`docs/render_roadmap.md` R1-4（原本标"选做 / 可无限后置"）：按 GPU 耗时
自动调 render scale；TAA 历史上采样。

* **分辨率解耦**（`PostProcess`）：单一 `m_sceneExtent` 拆成
  · `m_outExtent` —— **全分辨率输出**（视口 / 交换链）：合成 pass 的
    viewport/scissor、FXAA 中间图、离屏输出图（ImGui 采样那张）；
  · `m_sceneExtent = m_outExtent × renderScale` —— **场景渲染分辨率**：
    HdrTarget / 深度 / SSAO / FrameGraph 链（含 TAA 历史）/ bloom / 分簇 /
    光照簇全跟着缩。
  两处尺寸各算一次（`RenderTarget::apply` 建 HdrTarget、`PostProcess::recreate`
  定 m_sceneExtent）→ 共用一个 `scaledRenderExtent()`。
* **TSR 式升采样**（`post.frag`）：合成仍写全分辨率，线性采样器 + 归一化
  UV 得双线性升采样，再叠一道**对比度自适应的边缘感知锐化**（局部对比度
  调制 unsharp + 钳制到邻域范围抗振铃）。推常量 48B → **64B**。
* **按 GPU 耗时的自动缩放**（`PostProcess::updateDynamicResolution`）：
  GpuTimer 整帧耗时 → 指数平滑 → `scale' = scale·√(target/measured)` →
  夹紧 → **3% 死区 + 1/16 量化 + ≥12 帧冷却**。Renderer 在量化值变化时走
  `applyRenderScale()`（与 `applyViewportSize` 同一套重建序列）。
* `PostSettings` 7 个新参数 + 面板 + env 一组 `MYVK_DRS*` / `MYVK_RENDER_SCALE`。
* 新增 `tools/verify_drs.py`（8 轮 / 5 组断言），接入 `run_regression`
  （现 **29 例**）。

### 关键设计与坑点（MEMORY #105~#109）

1. **两个尺寸必须共用同一个计算函数**（HdrTarget 侧与 PostProcess 侧各算
   一次，不一致就炸）。
2. **离屏输出图的复用判据要用输出分辨率** —— 否则每次 DRS 变动都把
   ImTextureID 白换一次。
3. **"关闭 = 基线逐像素不变"要在着色器里落实**：`upsampleScene()` 在
   `ups.z<=0.5` 时**第一句就 return 单次采样**，与引入前逐字相同。
4. **控制器不要给目标帧时间做无理由的下限夹紧**：`max(target, 0.5f)` 在空
   场景（实测 0.22ms）上是反效果 → 目标高于实测 → 缩放比永远不动
   （回归 D1 卡在 1.0 达 12265 帧）。改成 `max(target, 1e-3)` 即正常。
5. **回归读"渲染分辨率"日志要取最后一条**：编辑器启动早期会先按交换链
   尺寸建一次目标（950×648），面板稳定后才切到视口尺寸（608×492）。

## R2-2 Multi-draw indirect + GPU 剔除

### 目标与设计

一次 `vkCmdDrawIndexedIndirect` 画一组"同管线 + 同材质 + 同网格"的批，
**CPU 不再回读可见性、不再据此重建提交列表**，draw 参数（每批的
`instanceCount`）由 GPU 在紧凑化 pass 里**直接写出来**。

与 R2-1 的分工：R2-1 把遮挡测试结果写 `vis` 标志位、**回读到 CPU**、
延迟两帧应用（会 pop）；R2-2 让 GPU **自己紧凑化并写 draw 参数**，
且因为紧凑化排在"本帧深度预通道之后、前向之前"，**零帧延迟**。

### 新增 / 改动

* `assets/shaders/hiz_test.glsl`（新）：`vennHizOccluded()` 公共判据，
  `occlusion_test.comp`（R2-1）与 `mdi_compact.comp`（R2-2）**共用同一份
  数学** —— 两边判据一旦有逐字差异，"CPU 说可见、GPU 说被挡"会变成
  随机丢物体的疑难杂症。
* `assets/shaders/mdi_compact.comp`（新）：`local_size 64`；binding 0 =
  Hi-Z 图、1 = AABB、2 = Catalog、3 = ObjBatch、4 = Instances（writeonly）、
  5 = Indirect（裸 `uint cmds[]`）；push 112 B。核心是**一次 atomicAdd
  兼做"槽位分配"与"计数"**：`slot = atomicAdd(cmds[base+1], 1u)`，
  旧返回值 = 批内第几个可见实例 = 紧凑化槽位；[1] 终值 = 本帧要画几个。
  **不需要第二遍 finalize pass。** `firstInstance`（[4]）= 该批候选数的
  前缀和 → 任何槽位都落在预留区间内（上界 = 候选总数）。
* `assets/shaders/pbr.vert`（改）：新增 `VENN_MDI` 分支，从 binding 15 的
  `MdiInstance { mat4 model; ivec4 aux; }` 取 model + `aux.x`(jointBase)。

  （MDI / 合批 / 基线）**只换数据从哪来，数学逐位不变**。
* `CMakeLists.txt`：`glslc -DVENN_MDI=1 pbr.vert → pbr.mdi.vert.spv`。
* `engine/render/MdiDraw.h/.cpp`（新）：4 条缓冲**构造时一次分到底**
  （catalog / objBatch / instances / indirect，全 HOST_VISIBLE；indirect

  `mdi_compact` 管线（`kMaxObjects=8192` / `kMaxBatches=4096`，约 1.5 MB/槽）。

  覆盖 instances/indirect 的 buffer barrier；`readBack` 只累加各命令的
  `instanceCount`（**回读量 O(批数)**，不是 R2-1 的 O(物体数)）。
* `engine/assets/Mesh.h/.cpp`：新增 `bindGeometry(cmd)`（只绑 VB/IB），
  `drawInstanced` 改为复用它。
* `engine/render/Renderer.h/.cpp`：
  * set 0 binding 数 15 → **16**，新增 `bindings[15]`（STORAGE_BUFFER /

  * `buildMdiFrameData()`：生成 catalog（批序、下标=物体号）、objBatch、

1. **`vkCmdDrawIndexedIndirect` 不带 VB/IB** —— 必须自己绑。这是本次唯一

## R2-3 Bindless / descriptor indexing

### 目标与设计

材质不再各占 set 1..6。所有贴图进 set 1 binding 0 的**运行时大小数组**
`sampler2D textures[]`，材质到纹理下标的映射进 set 1 binding 1 的**页表**
`GpuMaterialPage pages[]`；逐 draw 只 push 一个**页号**。片元里：

```glsl
gMat = pages[uint(push.emissive.w + 0.5)];   // main() 开头查一次
vec4 c = texture(textures[gMat.tex0.x], uv); // = 原来的 texture(albedoMap, uv)
```

于是"一个 draw 绑几个描述符集"这件事**与材质数、纹理数都无关**了 ——
set 0 + set 1，两次 `vkCmdBindDescriptorSets`（而且 set 1 是整个 Pass
绑一次，逐 draw 只有一次 128 B push）。

### 三个关键取舍

* **页号借 push 常量的空闲位（`emissive.w`）**：push 被硬件卡在 128 字节，
  pbr.frag 只声明到偏移 112，最后 16 字节（`emissive.w`）在任何编译单元里
  都没被读过。非 bindless 时一律推 1.0（= 旧值），bindless 时推页号。
  这样两条路径的 `PushConstants` 结构与 push range **逐字段完全相同** ——
  不必为 bindless 另立一套推常量布局（那会连带影响所有管线的 layout
  兼容性判定，是"set 0 被中途打断"那条 VUID 的高发区）。
  另开一个字段会直接越过 `maxPushConstantsSize`（保底 128）。
* **纹理下标跨帧稳定、页号每帧可变**：`textureIndex()` 惰性注册，同指针
  第二次是 O(1) 哈希命中，下标永不回收（注册一次写一次描述符；sampler/view
  句柄变了才重写 —— 纹理流收尾会重建 sampler）。`materialPage()` 相反，
  每帧从 0 开始惰性分配、按指针去重。页表缓冲**按帧槽分离**，`beginFrame`
  在 in-flight 栅栏之后整表重写 —— 用同一槽的上一帧早已跑完，不会撕裂。
* **顶点着色器一份没改**：bindless 只改片元的贴图来路。pbr.vert /
  pbr.inst.vert / pbr.mdi.vert 三份原样复用（顶点阶段从不采样材质贴图，
  管线布局里多出来的 set 对它没有影响）。规模因此比路线图预估的
  "所有 pbr 变体 shader"小一档。

### 新增 / 改动

* `engine/rhi/Device`：整组启用 Vulkan 1.2 的 descriptor indexing 特性
  （`descriptorIndexing` / `runtimeDescriptorArray` /
  `shaderSampledImageArrayNonUniformIndexing` /
  `descriptorBindingPartiallyBound` /
  `descriptorBindingSampledImageUpdateAfterBind`）+ 1.0 核心的
  `shaderSampledImageArrayDynamicIndexing`。**要么全开要么全不开**，
  暴露 `supportsBindless()`。
* `engine/rhi/DescriptorSet`：池支持 `VkDescriptorPoolCreateFlags`；
  `makeSetLayout` 支持 per-binding flags；新增 `writeTextureAt()`。
* `engine/render/Bindless.h/.cpp`（新）：每帧槽一份 update-after-bind 集
  + 页表缓冲；`textureIndex` / `materialPage` / `beginFrame` / `bind`。
* `assets/shaders/pbr.frag`：`#if VENN_BINDLESS` 分支 —— 六条
  `#define albedoMap textures[gMat.tex0.x]` 之类；函数体一字未改。

### 验证结果（单跑 verify_bindless，24 条断言全 PASS）

场景：6 个物体 × 6 个材质，**每个材质的 6 个贴图槽全部非空**（任一条下标
映射错位都会立刻改画面，被逐像素对照抓住），贴图池只放 14 张（相邻材质
**故意共享**）。

* 关闭：`bl=0` / `blTex=0` / `blPages=0`、无 `BINDLESS-STATS`、两次运行
  视口逐像素一致（平均差 0.0000）。
* 打开：`bl=1`、**`blTex=17`**（= 14 场景贴图 + 3 缺省图；若不去重会是 39）、
  **`blPages=6`**（= 材质数）、set 1 每帧绑一次。
* `drawnOpaque` 6→6、`drawCalls` 7→7：**提交量完全不变**（bindless 只减
  描述符绑定：每 draw 6 次 → 0 次）。
* **开 vs 关视口逐像素不变（>18 像素 = 0、最大差 0、平均差 0.0000）**。
* bindless + MDI 同时开着（覆盖间接绘制那条独立的 push 填充分支）也
  逐像素不变。全程零 VUID。

### 踩坑（详见 MEMORY.md #120~#123）

1. glslang 对"非常量下标访问采样器数组"要求显式
   `#extension GL_EXT_nonuniform_qualifier : require`，而且 `#extension`
   必须排在**任何非预处理记号之前**（只有 `#version` 能在它前面）。
   下标其实来自 push 常量（动态 uniform，不需要 `nonuniformEXT()`）。
2. 数组容量必须按设备 `maxPerStageDescriptorSamplers` 收窄（集显可能只有
   128）；update-after-bind 的那几个上限在 `VkPhysicalDeviceVulkan12Properties`
   里，**不在** `VkPhysicalDeviceLimits`（写错直接编译不过）。
3. 页表必须按帧槽分离，`beginFrame` 只能在 in-flight 栅栏之后调。
4. 默认定义为 0 的开关不能用 `#ifdef` 判断 —— 文件中部那条
   `#define VENN_BINDLESS 0` 之后 `#ifdef` 恒为真，症状是"基线 .spv 里也走了
   bindless 分支"（编译不报错、画面全错）。正确写法 `#if VENN_BINDLESS`。
