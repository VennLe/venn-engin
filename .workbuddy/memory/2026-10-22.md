# 追加：用户报障 —— 第 5 块地形崩溃（同日）

原始输出：`[VK_CHECK] Vulkan error -1000069000 at engine/rhi/DescriptorSet.inl:61`
+ `vkDestroyDevice(): 3 leaked objects`（3 个连续 VkSampler）+ `Fatal`。

## 诊断

- `-1000069000` = **VK_ERROR_OUT_OF_POOL_MEMORY**（不是 DEVICE_LOST）。
- `DescriptorSet.inl:61` 是 `vkAllocateDescriptorSets`，**内联**在
  `DescriptorAllocator` 里 —— 所有 pass 共用这一行，行号**指不出**是哪个池。
- 真凶：`TerrainPass` 的池写死 `DescriptorAllocator(*m_device, 4, 4, 44)`
  = **4 块地形**（每块 1 set + 11 sampler：4×(albedo+normal)+splat+height+hole）。
  场景里第 5 块地形 → 池满 → throw。
- 3 个泄漏 sampler = 次生：`createInstanceResources` 里 sampler 建在
  `allocate` **之前**，throw 时那个 `Instance` 还没进 `m_instances`，
  而 `Instance` 没有析构函数 → 3 个裸句柄漏掉（句柄连续就是这个指纹）。

## 修复

1. `rhi::DescriptorAllocator` 改成**池链**：`OUT_OF_POOL_MEMORY` /
   `FRAGMENTED_POOL` 时 `addPool()` 追加同规格池再试（上限 8 个）。
   旧池**不能销毁**（里面的 set 还被引用）→ `std::vector<VkDescriptorPool>
   m_pools`，`m_pool` 只表示"当前往哪个池要"。扩容打 `DESCRIPTOR-POOL 扩容`。
2. `TerrainPass::Instance` 补析构回收 3 个 sampler；`clearInstances` 销毁后
   置空，避免二次销毁。Instance 里新存 `VkDevice device`（只为析构用）。

## 验收

- 新用例 `tools/verify_multi_terrain.py`（6 块地形 / 120 帧）全 PASS：
  零 VK_CHECK、零泄漏、**必须看到扩容日志**（T4 是前提断言，否则会假绿）。
- 复现场景（5 块）实测：第 5 块触发 `追加第 2 个池`，正常跑完 90 帧。
- 冒烟：`verify_template_scene`、`verify_terrain_physics` 仍全 PASS。

## 第十一轮补充：抬山保存 → 地形变砖 → DEVICE_LOST

用户报 `TERRAIN-INSTANCE-FAIL reason=height_not_normalized min=0.000
max=8.000` + `VK_CHECK -4 at Renderer.cpp:6619`。**三层缺陷叠加**：

1. **写端/读端值域契约矛盾（根因）**：抬升笔刷故意允许冲到
   `kMaxNorm = 8.0`（`LandscapeEditor.cpp`，"不撞平顶"的余量），而
   `height.r32` 契约是归一化 `[0,1]`。老 `saveAssets` 原样落盘 →
   下次读盘硬拒 → 工程打不开。`max=8.000` 那个整数就是 kMaxNorm。
   第十轮把 `kMaxStrength` 16→64，撞顶从十几秒变 0.36 秒，**显影**了它。
2. **失败被放大成每帧全量重建**：`syncTerrains` 的
   `same = items.size() == m_terrainEntities.size()`，而后者只装成功的 →
   建失败就永远 false → 每帧 `clearInstances()`（waitIdle + 重传 3 MB）→
   帧时间冲破 Windows TDR 2 秒 → DEVICE_LOST。
3. **存量坏资产无出路**：读端硬拒，用户连打开都做不到。

**修法**：

- `engine/terrain` 新增 `normalizeHeightRange()` / `rewriteMaxHeight()`。
  收敛逻辑放**资产层**而不是编辑器：`.r32 ∈ [0,1]` 是资产契约，笔刷只是
  其中一个生产者。同乘同除，世界高度 `h × maxHeight` 恒等（无损）。
- `saveAssets` 落盘前收敛，**内存 + 撤销栈一起缩**（`StrokeRecord::height`
  是归一化 float；不缩的话撤销会跳回 8 倍高）。所有"米"量不受影响。
- `loadTerrain`：`hi > 1.01` 改为**救援**（重整 + 打 `TERRAIN-RENORMALIZE`
  + 置 `TerrainAsset::rescaled`）。负高度/`hi > 1e6` 仍硬失败。
- `syncTerrains` 判据换成 `m_terrainRequested`（请求全集），失败后按
  `kTerrainRetryFrames = 120` 帧节流重试，并加 `TERRAIN-DEGRADED` 日志。
  `tc.dirty` / `refreshSurface` 失败两处清空时**必须连 requested 一起清**。
  顺带修了 `else` 分支的下标错位（items[i] 配 instanceAt(i) 会串位）。

**验收**：`MYVK_RUNTIME_SELFTEST=terrain` **39/39**（新增 E 组 12 条，
E3/E4 走真实文件往返写系统临时目录）。新增 `tools/verify_terrain_renorm.py`
三组全 PASS，最有价值的是 **C1：坏资产失败日志 120 次 → 2 次/120 帧**
（那 120 次重建正是 DEVICE_LOST 成因）。`verify_terrain_physics` /
`verify_multi_terrain` 复跑仍 PASS。已登记进 `run_regression.py`
（DEFAULT 93 条 + TRIGGERS 5 个 glob）。

**遗留**：启动器 WM_CLOSE 偶发不响应又复现了一次（这次窗口存在、消息送达、
10 s 不退）。用 GLFW `glfwWaitEvents`，不是"最小化分支吞消息"那个陷阱；

syncWaters; }`（`offscreenSlot` 本来就是"主链 UBO vs 离屏槽"的判据，
`Renderer.h` 已这么写）。**不要用 `resetSkinning` 当判据** —— 它已经被
"统计口径"占着了。

state` 里点名。别从后往前读。另外设备丢之后地形重试机制会再 load 一次，

动画**；③静止满 8 秒触发 idle，此后每 8 秒继续；④任意 clip 可在角色动画面板
绑键触发；⑤角色面板放进视口标签栏（已有，本轮只是验收）。

**为什么抽 `engine/animation/Locomotion.*`**：这套"按速度选 clip"原本只长在
`runtime/RuntimeApp.cpp`，于是同一角色两只程序表现不同 —— Game.exe 会迈步，
编辑器 Play 腿一动不动（clip 停在实例化时挑的第一段）。抽成共用实现后谁改都
只改一处。锚点前缀做成参数（`GAME-ANIM` / `EDIT-ANIM`），日志措辞与 P3 逐字
一致，老脚本正则不用改。

**三个设计决定**：
1. **用物理真值判状态**（水平速度 / 是否贴地），不用输入轴。输入轴判的话
   "按着 W 撞墙"→ 原地蹬腿，而日志全正常（最难发现的手感 bug）。
2. **空中优先**：先判 `!onGround → Jump` 再看速度，否则"跳到一半突然迈步"。
3. **`runSpeed <= 0` = 自动**（`maxSpeed × 1.15`）。写死会"走路在跑"，
   而这种错最难被当成 bug（腿在动、位置在变，只是不像走路）。

**静止 8 秒语义 = 重放不是才开始**：停下**立刻**进 idle 循环（否则僵在上一个
姿势干等 8 秒），之后每满 `idleTriggerSec` 把 `time` 归零重头播。实测
`retrigger=1 idle=8.00s` → `retrigger=2 idle=16.01s`。移动则两个计时器清零。

**默认资产**：`assets/models/characters/default_character.vmesh`，由
`AssetC samba_dancing.fbx --strip-skin --autorig --procanim` 烤出。23 骨、
Idle 2.40s / Walk 1.00s / Run 0.70s / Jump 0.90s、身高 1.805m、35440 顶点、
2 submesh。装配时按 `-min.z` 抬一次（玩家原点是脚底，模型 pivot 在几何中心），
胶囊与相机距离跟身高同源重算。

**按键映射**：`ecs::AnimKeyMapComponent`（`animKeys` 进 JSON），挂实体上跟着
角色存盘，与全局 `InputMap` 分工不同（前者是"这段动画想看就按这个键"的演出席
语义，后者是玩法语义）。键码翻译表 `engine/ui/KeyCodes.*`：GLFW ↔ ImGuiKey
↔ 显示名，**不收**修饰键与 Esc（Esc = 取消绑键）。同一个键被两段占用时旧的自
动回收。

**五个坑（都已修）**：
- **`core::Input::keyPressed` 在编辑器里恒 false** —— 被 `g_uiKeyboard`
  （每帧按 `io.WantCaptureKeyboard` 设）门控，Play 时 ImGui 拿着键盘焦点就永
  远 false。表现是"按了没反应、日志一行没有"。修法：`pollKeyTrigger` 的判定
  函数做成参数，编辑器传 `ui_keys::pressed`（`ImGui::IsKeyPressed`）。
- **`.vmesh` 传给 `loadFBX` → 第二次起永远失败**（重大）。`vmeshPathFor(p)==p`
  且 `.vmeta` 是加载成功**之后**才写 → mtime 永远更新 → 判过期 → 回退按 FBX
  解析 `.vmesh` 抛异常。**极具迷惑性：第一次正常，删掉 .vmeta 又好一次。**
  修法：`MeshLoader.cpp` 加"情况 0"短路（源就是 `.vmesh` → 直接 loadVMeshModel），
  并删掉误生成的 `.vmeta`。
- **阻塞式 `hold_key` 拍出的"走路截图"里人站着** —— 返回时键已松、人已回
  idle。必须自己 `key_down`/`key_up`，在按住 W 的**当中**截图。
- **日志并发追加让"第 N 个匹配"错位** → 假红。改按**行号偏移**单调向后扫。
- **编辑器 Play 没有重力**，`onGround` 恒 true → `jump` 段走不到，只能靠按键
  强播验证。

**验收**：新增 `tools/verify_char_locomotion.py`（C0~C10，15 条，约 35 秒）
→ **PASS 15/0**。第一轮实测 8 条红，逐条修绿 —— 每条都能独立变红。
**C6 是唯一不靠日志的判据**（截图里真的在迈步，世界坐标 2.358→-2.305 ≈ 3m/s），
**C9 顺带证明 `animKeys` 存读闭环**（Play 副本是 `sceneToJson`→`sceneFromJson`
出来的）。已登记 `run_regression.py` 的 `DEFAULT` + `TRIGGERS`；
`check_regression_map.py` 补两条夹具（Locomotion 期望是并集：`engine/animation/**`
已被 anim_runtime / character_import / player_character 占着）。
**`engine/ui/KeyCodes.*` 故意不登记**：`engine/ui/**` 在 `GLOBAL_GLOBS` 里，
改它本来就全量，写进 TRIGGERS 会在 `--narrow` 下假跳过 → 映射自检 **PASS**。

**文档**：新建 `docs/character_locomotion.md`（用法 / 设计 / 六个坑 / 验收表）；
`docs/character_pipeline_roadmap.md` 头部进度改为 **A2a ✅**，A2 章前加偏离说明，
§5 锚点总表补 6 行。

**仍未做**：crossfade（四态硬切）、`.anim.json` 控制器资产、根运动（滑步）、
IK、手指骨、非人形绑骨。`Run` 段在默认 `moveSpeed` 下走不到（需超 `runSpeed`
自动值 = maxSpeed×1.15），属预期。

## P5 · 运行时手感四件事（2026-10-22）

用户报障四条：①脚陷地 + 出生点不是 GameStart；②必须点视口才能操作、操作时
隐藏鼠标、Esc 退出；③**移动没朝视线方向**（最关键）；④状态切换生硬。

### ③ 横着走的根因（本轮最重要的一条）

**模型正面朝 -Y，而实体 yaw 语义是"0 = 朝 +X" → 侧身平移。**

推理链：Mixamo 源（Y-up）正面朝 +Z → ufbx `right_handed_z_up` 映射
`(x,y,z)→(x,-z,y)` → 引擎 Z-up 里落在 **-Y**。

**确认方法（不靠猜）**：相机钉在 -X 看 +X（yaw=0），按 W（走 +X）截到
**侧面**，按 D（走 -Y）截到**正脸朝镜头** —— 两句合起来只有"正面 -Y"一个解。

修法：`ModelInstanceOptions::yawOffsetDeg`（度），装配时**预乘** `Rz(offset)`。
⚠ 不能给 `rotation.z` 加偏移量：子变换可能带 x/y 旋转，欧拉角逐分量相加
≠ 绕世界 Z 转。默认角色 +90°，两个入口必须同源：
`RuntimeConfig::PlayerVisual::modelYaw = 90` / `EditorScene 的 kDefaultModelYaw = 90`。

**机器判据**：人形 AABB 的左右跨度必须 > 前后跨度。
`GAME-PLAYER facing yaw=90 spanX=0.364 spanY=1.947 shouldersAlong=Y ok=1`
—— `spanY` 是 **T-pose 臂展**（1.947），不是肩宽 0.45，别拿肩宽当基准。
反向验证过：modelYaw 改 0 → `spanX=1.947 spanY=0.364`，只有 R2 红、
其余 9 条仍绿。
⚠ 刻意不截图比对：角色像素 bbox 的 w/h 实测 0.367~0.429 飘（摆臂撑宽），
是 flaky 判据。

### ① 脚陷 + 出生点

**脚陷 = 程序化动画把髋部往下压**。ProcAnim 三段 hips 垂直偏移原本"围绕负值
振荡"：Idle ±6mm / Walk [-32,0]mm / Run [-56,+28]mm。最低点正好是支撑腿接近
伸直那一帧 → 腿长不变、髋下沉 → 脚只能进地里。改成**只向上**同振幅：
`0.006·(sin+1)/2`、`0.016·(1-cos2w)/2`、`0.042·(1-cos2w)/2`。
Jump 的 `-0.115·crouch` 保留（蹲姿有膝盖吸收 + 腾空相人不在楼上）。
改完**重烤 vmesh**，并检查目录里没有 `.vmeta`（那个文件会让"第二次加载起
永远失败"，P4 已踩过）。

**出生点**：语义分界 = 编辑态 Player 摆哪只是看着方便、GameStart 才是出生点。
`EditorContext::play` 在 sceneFromJson 之后加 `placePlayerAtGameStart`
（脚底 = GameStart position，yaw = rotation.z + g.yaw，胶囊中心再抬
hh+r），并清 `PlayerComponent::started`。
R0 判据：把 GameStart 故意摆在 (5,3,0)，断言 `spawned at GameStart feet=(5,3,0)`
—— 只在原点测的话"用没用 GameStart"根本看不出来。

### ② 鼠标两态

`RuntimeApp::m_mouseCaptured`（唯一 bool，不要再单独存"光标可见"）。
启动 = false（光标可见、玩家 update 被门控）→ 左键点视口 = true
（`setCursorVisible(false)` 内部就是 `GLFW_CURSOR_DISABLED`）→ Esc/Pause = false。
⚠ **回到 Gameplay 不自动捕获**：从菜单点"继续"后仍要点一次视口，否则
"鼠标突然消失、镜头开始跟鼠标转"会被当成鼠标失灵。
⚠ 只门控 `m_player->update`，**不动** `tickPlayerAnimation` —— 否则人僵在
出生点像卡死，点了才突然开始呼吸。

### ④ crossfade

`Pose`/`samplePose`/`blendPose`/`poseToJoints` 在 A0-5 就拆好了
（AnimatorSystem.h 注释甚至写了"A2 只需加第二次 samplePose + 一条 blendPose"）。
`SkinnedMeshComponent` 加 fadeFromClip/fadeFromTime/fadeT/fadeDur（不进存档）；
`Locomotion::setClip` 记旧 clip + **当时**的播放头（有 Animator 要取 an->time，
取错会从旧片段第 0 帧淡入 → 腿"缩回去再迈出来"）；`AnimatorSystem` 双采样 +
`blendPose`。三个要点：权重用 **smoothstep**（线性权重角速度两端突变，
"做了过渡还是僵硬"就是这么来的）；旧 clip 播放头**继续走**（冻住会
"腿在半空不动"，比硬切更怪）；**只对换 clip 生效**，idle 重放仍硬切。

### 五个坑

- **`ANIM-TICK` 不能当高频锚点**：每 60 帧一行，过渡只有 12 帧 → 实测
  `fading_seen=0`（功能好的、判据瞎的）。加 `ANIM-FADE begin`（一帧一条）。
- **Popen(stdout=PIPE) + Vulkan validation = 死锁**：日志几十毫秒填满 64KB
  管道 → 子进程阻塞在 write → 窗口永不出现（表现是"没找到窗口"，像崩溃）。
  **stdout 必须直接写文件**。
- **`ld returned 1 exit status` 且无 undefined reference** = exe 被进程占用
  （这次是用户开着的 `Launcher.exe`）。`tasklist` 一眼看出来，别怀疑代码。
  绕开办法：`--target VennEditor VennRuntime VennAssetC`。
- 重烤后 `.vmeta` 要检查（同上）。
- 编辑器 facing 自检要加 `#include <glm/gtc/matrix_transform.hpp>`。

### 验收

新增 `tools/verify_player_feel.py`（R0~R9，10 条，约 18 秒）→ **PASS 10/0**。
R4 是"未捕获时按 W 位移 < 0.02m"（门控真的生效），R6 是"点击后 Δx>0.5m
且 state=walk"，R7 要 `blend=0.20s` + `ANIM-FADE begin` **两条都有**。
已登记 `run_regression.py` DEFAULT + TRIGGERS；`check_regression_map.py`
补两条夹具（`Locomotion` / `ProcAnim` 的期望是并集）→ 映射自检 **PASS**。
P4 的 `verify_char_locomotion` 复跑仍 **15/15**。

### 文档

新建 `docs/player_feel.md`（四症状→四根因 + 每条的设计与坑）；
`character_pipeline_roadmap.md` 进度改 **A2b ✅**（下一项 A3，`.anim.json` 并进

## P6 · 默认操控 / 真实跳跃 / 脚踩地形 / 角色预览

用户提三条：①WASD 走、右键长按跑、空格跳全部内建不绑键，Jump 动画换成
"双脚离地"，高度/滞空/弧线/空中控制要符合物理直觉；②脚踩地形时不许陷到
地面以下；③角色面板预览要能播动画、带栅格地面+gizmo、看得见胶囊并能用鼠标
选中、分别调角色/胶囊的位置・旋转・大小。

### 改了什么

- `engine/core/InputMap.cpp`：出厂 `Sprint` 由 LShift → **鼠标右键**
  （+ 手柄 LB）。老工程 `config/input.json` 存过 LShift 不会自动改，需"恢复默认"。
- `CharacterDesc::jumpSpeed` 5.0 → **3.7**、`airControl` 0.25 → **0.45**；
  `kGravity` 移到 `CharacterController.h` 顶层供编辑器 Play 共用。
- `assetio/ProcAnim.cpp`：`poseJump` 重写（蹬伸→收腿→最高点→伸腿→落地缓冲），
  `jumpSpec` 时长 **0.75 s**；新增可断言的 `PROCANIM-JUMP jumpFootLift`
  （实测 0.3714 m）。资产已重烤并 cp 到 `build/bin/assets/models/characters/`。
- `editor/EditorApp.cpp`：编辑器 Play 手写同一套抛物线（`pc->velocityZ` +
  `physics::kGravity`）+ `editorGroundHeight()`；Space 只在 `isEditing()` 时
  切 Play/暂停，Play 态归跳跃。
- `CharacterWindow.*`：预览叠加层（胶囊线框 / 坐标轴 gizmo / 选中框）、
  点选、位置-旋转-大小控件条；`syncPreviewSkinning` 修"预览模型不动"；
  预览根抬 `footLift` 让脚底踩 z 0；工具栏 `Grid` 复选框。
- `engine/render/Renderer.*`：预览栅格**独立参数**（`previewGridEnabled` /
  `previewGridSettings`，默认开，extent 4 m / minor 0.10 / major 0.50）。

### 两个真 bug（都是"窗口比一帧位移还窄"）

1. **快速下落穿地形**：接触窗口死写 ±0.02 m，而一帧竖直走 0.078 m → 整帧跨过
   → `excess` 下一帧已 −0.05 被判"不是地面" → 一路掉到 **−277 m**。
2. **跑上坡穿地形**：水平一帧 0.15 m，46° 坡抬升 0.155 m → 同样跨过 → `ground`
   翻 0，之后**不可恢复**（竖直射线从胶囊中心打不到头顶的地面）。

修法：`sweep = |vz|·dt + hStep·tan(slopeLimit) + 0.02`，`excess<0` 直接抬出来；
`PlayerController` 再加一道 `GAME-PLAYER-RESCUE`（>0.25 m 才触发，打 WARN）。

### 坑

- **二进制比源码旧**：锚点日志没打出来，误以为是日志没写，实际 Editor.exe 比
  .cpp 旧。改完先看时间戳。
- 胶囊线框位置不能按"中轴 ± r"算：默认机位 `off=(37,29)`，母线到中轴垂距是
  **37** 不是 47 px → 改成 overlay 画线时记 `m_capScrSegs`，点选量真实线段。

- 拾取漏加 `m_capsulePos` → 幽灵胶囊高 0.9 m。
- 验收采样窗口混进出生自由落体段（点击视口前玩家冻结）。
