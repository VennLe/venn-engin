**② 创建出来的工程有什么游戏代码**（回答"用什么完成"）
- 答案是 **VKS 脚本**（`assets/scripts/*.vks`，引擎自带的小语言，热重载）。
  C++ 只提供能力（渲染 / 物理 / character 控制器 / 输入），工程**不编译 C++**。
  `CodeMode::Cpp` 只是枚举 + 标签，创建流程固定写 `Vks`（`ProjectCreate.cpp:510`）。
- 模板从"两行 print"升级成能通关的小游戏，改的是 `tools/gen_templates.py`：
  - `main.vks`（挂 Player）：参数区 / 状态区 / `on start` / `on update`；
    计时、收集进度、`SCORE n/5`、`GAME-COMPLETE`/`GAME-TIMEOUT`。
  - `pickup.vks`（挂 5 个光球）：自转 + 浮动 + 1.6 m 拾取 + 世界黑板 +1。
  - `portal.vks`（挂 Portal）：自转；收齐后 `setEmissive` 点亮 + 加速。
  - `README.md`：工程导览（代码在哪 / 怎么改 / 三个别做的事）。
  - 场景 8 实体：Ground / Player / Pickup_1..5（环半径 4）/ Portal。
  - `template.json.files[]` 从 4 项 → 6 项（加 README.md、pickup.vks、portal.vks）。
- `template.json` 的占位符白名单没变（`__PROJECT_NAME__` / `__TEMPLATE_ID__`），
  替换是**全文白名单替换**，所以 README / .vks 里的占位符也会被换。

**踩过的坑（都写进了生成器注释）**
1. `setEmissive` 是 **3 参数、只对自己生效**（`Builtin` 表 `{3,3}`，实现里
   用的是 `material()` 而不是传实体）。想在 A 脚本里点亮 B 只能给 B 挂脚本 ——
   第一版写了 `setEmissive(portal, r,g,b)`，编译报 "expects 3 argument(s), got 4"。
2. **模板脚本编译错误原来只进面板、不进日志**（`EditorApp::preloadScripts` 只
   `m_scripts->logLine`）→ 日志里只有一句 `1 with errors`，查不下去。
   已补 `VK_LOG_WARN("Editor: script compile error '%s' line %d: %s")`。
3. **脚本 `print` 默认不落日志**（只进 `m_printLog` 面板）。加环境变量开关
   `MYVK_LOG_SCRIPT_PRINT=1` → `VKS-PRINT <path>: <line>`，自动化才有硬证据。
4. **传送门"看不见"**：第一版放在 (0,6)、1.4 m 高，出生点完全不可见（Play 态
   相机朝向 + 半 FOV 27.5°），日志零提示；加到 4 m 高也时有时无。最后把
   **通关判定改成"收齐即通关"**，传送门降级为视觉奖励 —— 模板的第一局必须
   保证一定走得完，不该押在镜头上。

**三个真 bug（都是"看着像没实现，其实是别的东西坏了"）**
1. ⚠⚠ **笔刷每 80 ms 走一次 `tc->dirty`** → `clearInstances + createTerrain` →
   销毁还在飞行中的帧引用的 sampler → 验证层报 `vkDestroySampler ... in use by
   VkCommandBuffer`，几秒后 **`VK_ERROR_DEVICE_LOST`**，编辑器进程直接没了。
   症状极具误导性：`LS-STROKE-BEGIN` 有、`LS-STROKE-END` 永远没有、截图拿到空图。
   → 新增 `TerrainComponent::heightsDirty/splatDirty` + `TerrainPass::refreshSurface`
   （只原地重传 R32/RGBA8 两张图 264 KB）+ `clearInstances` 里 `vkDeviceWaitIdle`。
   **能吃这个红利是因为 `terrain.vert` 里 `pos.z += texture(heightMap,uv).r*maxHeight`**
   —— 顶点是平坦格子，改高度不用重传 VBO。
2. ⚠ **浮动面板 ID 必须是 `###panel_<面板表 id>`**。写成 `###landscape_panel` 后，
   底栏托盘的 `FindWindowByName("###panel_landscape")` 拿不到窗口 → 抢层级那步跳过 →
   点一下视口，视口跑到 `g.Windows` 末尾把面板整个盖住。**表现是"面板自己关了"，
   其实它还开着**（`PANEL-XCLOSE` 一条都没有）。排查方法：日志里没有 XCLOSE 就是被盖住。
3. ⚠ **"聚焦"不能独立取 z**。`z = hCenter + A·tan(pitch)`，A = 视距；平均高度要
   **从高度图算**（不是猜 0.35×maxHeight）。否则视线落在相机前方 20 m，画面是
   "一堵绿墙 + 一条地平线"，起伏完全看不见。

## 地形 / 植被：参数与操作做厚（用户："这个实现效果是否有些过于粗糙了"）

不加新功能大类，只把两套工具的**参数**与**操作**补齐；全程未跑全量回归（遵守纪律）。

**地形 · 参数**：笔刷 5 → **6**（`Noise` 特征尺度/倍频/图案种子、`Erode` 休止角/每帧迭代）
+ `Max displacement per stroke`。`drawToolParams()` 按当前工具切换面板。

**地形 · 操作**
- **笔划撤销/重做**：`LandscapeEditor` 自带栈（`kUndoDepth=24`）。按下全图拷贝
  (`beginSnapshot`)，松开扫**脏矩形**只压那一块 (`commitSnapshot`)，Ctrl+Z 写回。
  ⚠ 必须排在 `EditorApp::handleShortcuts()` 的 `if (io.KeyCtrl)` **之前** ——
  否则 Ctrl+Z 落到 `EditorContext::undo()`（整场景快照）上，一笔撤不掉反而把
  所有实体和相机弹回去。
- **笔划插值**：`step = max(radius*0.25, mpp*1.5)`，一帧拆最多 16 步 → 快速拖动
  不再是一串断开的圆点；按下时立刻刷一次（单击也有反应）。
- **滚轮调半径**（Shift = 强度）。⚠ 不要指望 `[` `]`：它们是 **OEM 键**，某些键盘
  布局下 GLFW 给 `KEY_UNKNOWN`，ImGui 收不到事件（实测 `LS-KEY-DIAG` 一条都打
  不出来，而同一进程里 Ctrl+Z 正常）。方括号只作补充。
- 整块操作三档：全图平滑 / 全图加噪 / 重置为默认地貌（各算一步撤销）。

**植被 · 参数**：物种 3 → **5**（新增 `Flower` 0.35 m / `Rock` 1.4 m，各带程序化网格
+ **`SceneSerializer` 分支** —— 少了那个 `if (shape=="flower")`，存盘再开就全丢）
+ `Random tilt` / `Edge density falloff` / `Erase all kinds` / `Placement rules`
（坡度上限 + 高度带，逐物种不同：岩石 70°、树 26°）；上限 4000 → 6000。
**观感四招**：逐实例色差（5 档亮度变体材质，**只动亮度**，动色相会出紫草粉树）、
随机倾斜（按地表法线算 rx/ry 再叠抖动，石头额外随机翻滚）、坡度/高度过滤
（日志给 `skippedSlope`/`skippedHeight`，让"没撒上"可诊断）、边缘密度衰减。

**踩到并修掉的两个真 bug（都属于"看着像功能没做"）**
1. **岩石层覆盖率 0.0%**。门限 `clamp((slope-0.35)/0.55)` 要求 19° 起步，而我按
   实测算这片默认地形：高度 0.082..0.830（均值 0.461），坡度 tanθ **p50 0.150 /
   p90 0.266 / max 0.391（22.4°）** —— 门限永远够不着，材质表第 3 层一次都没
   显示过。另外旧写法 `wGrass = 1 - wDirt` + 整体归一化会把岩石稀释一半。
   → 改成"岩石先占位，雪/泥土按 (1-岩石) 依次让位，草取余量"，门限按实测改成
   岩石 11.3°~18.8°、雪 0.64~0.74、泥土 0.46~0.54 淡出到 0.64。
   **四层权重实测 草 62.0% / 土 22.4% / 岩 9.3% / 雪 4.2%**（改前 草 67.9 / 土 28.9
   / 岩 0.0 / 雪 3.2）。
   ⚠ 教训：**层带门限要按实测分布定，不是按教科书角度定**；改完要用覆盖率数字
   验证，别只看截图。调参脚本思路（复刻 `generateDefaultHeights/Splat` 后算
   权重占比与主导像素）值得复用。
2. **"聚焦"只装得下地形横向 ~34%**。固定 `A = 0.42·边长 = 215 m`，与视口长宽比
   无关；而 SplitLayout 下视口常年竖窄（实测 950×689 aspect 1.38，窄时 0.85），
   45° 竖直视场对应水平半视场只有 19°。画面成了一条连绵绿带 —— **看着像"地形
   全是草"，其实只是没装进去**。
   → `focusCamera()` 改自适应：`d ≥ (0.5·span·1.06)/(tan(fovY/2)·aspect)`，
   再乘 `cos(pitch)` 换水平后退量；`placeCamera(back, pitch, yaw=π/2)` 把 yaw
   参数化，聚焦用 `yaw = π/2 - 0.30` 的 3/4 视角（正对时地形边界与画面边框平行，
   平缓地表被压成一条色带）。`EditorContext` 补 `viewportSize()` 读端
   （以前只有 `setViewportRect`，没有读的地方）。
3. 「Focus」按钮补 `logRect("LS-FOCUS")` 锚点 —— 自动化要摆相机只能靠它。

**验收**：`tools/verify_world_tools.py` **25 条全绿 / 0 VUID**（A 地形 14 / B 植被 10 /
C 日志 1）。撤销精确性用 `absdiff`（逐点绝对差之和）判，**不要用 sum**（噪声抬一半
压一半，sum 可能不变）。演示图：`_venn_verify/show_landscape.png`、`show_foliage.png`
（植被 5 种计数 Grass 97 / Bush 20 / Tree 7 / Flower 48 / Rock 15，共 191 实例）。

**演示脚本的坑**：`OUT` 指到工程**外面**的 `../_venn_verify`；`MYVK_GRID=0` 关栅格
（否则地形全被网格线盖住）；**必须先点 Focus** —— 启动时 `MYVK_EDITMODE` 走的是
"初始化"分支，那时 `hasTerrain()` 还是 false，自动聚焦被跳过，开局相机是贴地默认位。

**收尾时补的两个漏（都不是本轮新增，是本轮暴露出来的）**
1. **i18n 覆盖率原本是 FAIL**（25 项）：上一轮重写地形/植被面板时，19 条字面量包了
   `TR()` 但词典没条目（屏幕上仍是英文），另有 6 条格式串没包 `TR()`。补完
   `ZhTable.cpp` 后 **1818 条 / 0 缺失 / 0 占位符漂移 → PASS**。
   - 5 条 `snprintf` 命中是**纯 ID**（`LS-TOOL-%d` / `FO-KIND-%d` /
     `TB-EDITMODE-ITEM %s` / `foliage/mesh/%s` / `foliage/mat/%s/%d`），
     加进 `verify_i18n_coverage.py` 的 `FMT_KEEP` 豁免表并写明理由 ——
     它们是回归脚本按名字等的锚点、且从不上屏，翻了反而抓不到。
   - `"amp %.3f"` 是 SliderFloat 的显示格式 → 包 `TR()` 得到"振幅 0.060"。
   - ⚠ 译文占位符**顺序必须与英文一致**（F 组按序列比对）：
     `"%.0f deg max for %s"` 只能翻成 `"最大 %.0f 度 · %s"`，
     写成 `"%s 最大 %.0f 度"` 会判漂移。
2. **`verify_edit_modes.py` 完全没有前台聚焦逻辑**（而 `verify_world_tools.py` 有）。
   症状会是"界面正常、日志不动、后半段全 FAIL"。已补 `focus_window()`
   （ALT 解锁 → `SetForegroundWindow` → `SwitchToThisWindow` 兜底），
   并把模块里的 `click` 包了一层统一聚焦（十来处调用点逐个改容易漏）。

## 2026-10-20 晚 · 地形共面 + 挖洞/坡道笔刷 + 六个编辑模式全部落地

用户两条要求（原话）：
1. 「地形模式下的地面应该要和原来栅格化的地面保持同一平面才是，并且地形模式下的
   笔刷种类还不够丰富，不支持挖洞的模式，还有，笔刷的力度区间可以调更大一下」
2. 「模式下拉列表中的其他模式和功能也需要一一实现完整，具体方案可以参考 UE5 中的思路」

### A 共面（栅格在 z=0 → 地形最低点必须是 0）
`generateDefaultHeights` 乘**边界渐变**（`kEdgeFade = 0.12`，smoothstep 到 0）。
实测四边 `min=max=0.000000`，中心 `max=0.7285`。
⚠ 副作用：边界渐变把最大坡度从 22° 抬到 **65°**（p90 37.5°），旧的 splat 门限
（岩石 `(slope-0.20)/0.14`）整圈被判成岩石，岩石覆盖飙到 35.7%、雪只剩 1.5%。
按实测重设：岩石 `(slope-0.40)/0.40`、雪 `(h-0.55)/0.13`、泥土 `0.36..0.46 淡出 0.56`
→ 草 60.9 / 土 17.3 / 岩 13.1 / 雪 8.7。

### B 挖洞 + 坡道 + 力度
- **挖洞**走片元 `discard`（`terrain.frag` 首行 `if (texture(holeMap,vUv).r < 0.5) discard;`）。
  不能靠"顶点压到地下"——高度图是双线性插值，洞边三角形会被拽成尖刺。
  遮罩独立成 `holes.r8`（R8_UNORM，255 实心 / 0 挖穿），**不复用 splat 通道**
  （RGBA 四通道已被 4 个材质层占满，且挖穿之后层权重没有意义）。
  链路：`TerrainDesc::holeFile` → `TerrainAsset::holes` → `TerrainPass` binding 5 →
  `TerrainComponent::holesDirty` → `TerrainPass::refreshSurface(i, splatToo, holesToo)`。
- **坡道**：按 `p0→p1` 投影比例插值两个端点高度。⚠ 格子的米坐标必须
  `hf.origin + index*mpp`（写 `c*mpp` 会整体偏半个地形，`origin = -0.5*worldSize`）。
- **力度**：`Strength` 0.01..**16**（对数滑条）、`Radius` 1..500、`Max displacement` 0..200。
  ⚠ 键盘 `,`/`.` 与 `[`/`]` 那两支的钳位**忘了跟着改**（还停在 1.0 / 200 m），
  已改成 `kMaxStrength` / 500 —— 否则"键盘调到头就上不去"，看着像没实现。

### C 六个编辑模式（`editor/ToolkitEditors.{h,cpp}`，1293 行）
MeshPaint（顶点色）/ Modeling（细分/平滑/挤出/收缩/镜像/翻转法线）/
Fracture（包围盒抖动网格切块 + 可选刚体）/ BrushEdit（box/cylinder/sphere 在 z=0 盖章）/
Animation（transform 关键帧时间轴）/ PCG（抖动网格采样 + 坡度高度过滤）。
- `EditModes.cpp::editModeImplemented` 九项全 true；`EditorApp::serviceEditMode`
  重写成**表驱动**（`editModePanelId(EditMode)`），开新面板/关旧面板/sync/focus 一份表搞定。
  日志 `EDITMODE-PANELS mode=%s landscape=%d foliage=%d panel=%s open=%d`（老字段保留，
  已有脚本按它断言）。
- 顶点色：`assets::Vertex` 加 `glm::vec4 color`（64→80 字节，`location=5`），
  `pbr.vert/frag` 传 `vColor`，albedo 乘上去；**LOD 合并必须 `c.col += vin.color` 求平均**，
  否则拉远变白。
- 改网格 = **换 Mesh 指针**：`registerMesh("toolkit/<key>/<rev>", ...)`，

### 踩过的坑（都是"看起来像功能没实现"的那种）
1. `ToolkitEditors.h` 用了 `assets::Vertex` 却没 include `Mesh.h`（EditorContext.h 只前向声明

2. `TR()` 来自 `editor/Localization.h`，**不是** `i18n/I18n.h`。
3. `if (auto* vis = ...) {...} else { ecs::VisibilityComponent vis; }` —— if-init 的 `vis`
   在 else 分支里仍在作用域内，同名 = 重声明。
4. `Scene` **没有** `destroyObject`（它只管世界矩阵/遍历/父子关系，生命周期归 `World`）。
   用 `World::destroy` + **手动清父节点的 `children`**（destroy 不会回头改别人的组件）。
5. PCG 面板的 Generate 排在末尾，被挤到 660 px 窗口**可视区之外**（y≈958 vs 窗口底 750）——
   `logRect` 报的是 ImGui 算出的 item 矩形，被裁掉的行照样有窗口外坐标，
   所以"锚点存在"≠"点得到"。已把主动作提到面板第一行（UE5 的习惯）。
6. `generate()` 里 `if (!mesh) return;` 是**静默**提前返回，而前面已经打了 `PCG-CLEAR`，
   现场变成"旧实例没了、新的没撒、也没报错"。改成 `PCG-GEN-FAIL` + 开头 `PCG-BEGIN`。
7. `LS-TOOL` 日志打的是 **enum 值**，而 `LS-TOOL-<i>` 锚点用的是**按钮视觉序号**，
   两套编号不一致（Ramp 在第 4 格但 enum=7）。改成同时打 `index=` 与 `name=`。

### 收尾又挖出三个真 bug（截图和日志健康检查逼出来的）
1. **`materials/default` 根本不存在**。Brush/PCG 都拿它当默认材质 → 指针为空 →
   渲染层是 `if (!it.material) continue;`（**只有深度预通道画**），于是
   "撒了 120 个实例、层级里全在、屏幕上一个都看不见"，而且一条错都不报。
   改成 `resolveToolkitMaterial()`：先试调用方给的（岩石→terrain_rock、草→terrain_grass、
   cube→crate、sphere→metal）→ 再试 `materials/{default,ground,crate,wall}` →
   都没有就 `makeMaterialPBR("toolkit/mat/<名>", nullptr ×3, tint, …)` 造一份纯色。
   `PCG-GEN` 日志加了 `mat=`，验收里断言它非 `-`。**这是我唯一能可靠断言"看得见"的方式。**
2. **`notify(TR("PCG placed %d instances"))`** —— `TR()` 只查表替换、**不跑 printf**，
   屏幕上原样显示 `PCG placed %d instances: 120`（截图里一眼看见）。
   拆成 `TR("PCG placed ") + std::to_string(n) + TR(" instances")`。
   ⚠ 顺带被 `verify_i18n_coverage.py` 抓到一次：我**在注释里**写了这个字面量，
   扫描器把它当成了调用点。注释里别写成 `TR("...")` 的样子。
3. **`location 5` 顶点色引发 Vulkan 校验警告**（4 条）
   "Vertex attribute at location 5 not consumed by vertex shader"：
   `Vertex::attributeDescriptions()` 声明了 6 个属性，但 shadow.vert / decal.vert
   不读顶点色。加了 `attributeDescriptions(int count)` 重载，
   ShadowPass / LocalShadowPass / DecalBuffer 传 5（少喂一个，语义也更准确）。

## 第二轮：三个"只做了一半"的补齐（关键帧序列化 / Voronoi 断裂 / Blender 式选区）

用户原话：「关键帧只存在编辑器会话里，没进场景序列化；Fracture 的切面始终轴对齐
（是"碎掉的感觉"，不是真正的断裂解算）；Modeling 只有全局几何操作，没有边/面选择。
把这些也都实现一下，Modeling 可以按照 blender 建模软件去实现。」

### 1) 关键帧进场景序列化
- 新增 `ecs::AnimationClipComponent`（`TransformKey{t,pos,rot,scale}` + duration/loop/
  autoplay/time/playing）。挂在**实体**上，不是编辑器成员。
- `SceneSerializer`：写 `je["animClip"]`，读回时 sort keys、钳 duration、`playing = autoplay`。
  **`time` 存盘、`playing` 不存盘**（重开由 autoplay 决定）。
- 组件注册是模板自动的（`World::pool<T>()` 惰性建），加组件**不用**改注册表 ——
  只要定义 struct + 在 Serializer 读写。
- 两处 `hasNonMeshContent` 都要加 `je.contains("animClip")`，否则"只有关键帧的实体"
  会被当成空实体丢掉。

### 2) Fracture：Voronoi 真断裂（不做 CSG）
- 种子 = 规则格心 + `irregularity*0.48` 抖动；每三角形用"本种子与邻居种子的中垂面"
  做 3D Sutherland-Hodgman 裁剪 → 扇形三角化 → 断面用 2D 凸包（Andrew monotone chain）封口。
- 实测：`srcTris=12 outTris=108`、8 胞腔、`caps>=1`、碎块三角形数 `[12,13,14,15,16]`。
  **`caps>=1` 是排除旧 grid 实现的硬证据**（轴对齐盒子切法不可能有封口面）。
- 工作量上限 6000000（超了 `FRACTURE-FAIL` + notify）。Grid 切法保留可对比。

### 3) Modeling 按 Blender Edit Mode 重做
- **选区只有一份权威**：`m_sel` = weld 组 id 集合。面 = 三角三个顶点全选中；边 = 两端点都选中。
  三份选区分别维护一定会漏同步。
- 必须按**位置量化（1e-4）weld**：GPU 缓冲里立方体一个角有 3 份渲染顶点（法线不同），
  不焊就"选不中一个角"。实测 24 → 8 组。
- 法线要在**渲染顶点**上重算，按 weld 组平均会把硬边磨圆。
- 视口点选：射线反变换到物体空间 → Möller–Trumbore 双面 → 顶点按屏幕距离 24px、
  边按 18px 挑最近。模态（G/S/R）每次从 `m_modalBase` **重算**，累加会漂移且 ESC 回不去。
- **`TR()` 只查表不跑 printf** —— 带 `%d` 的字面量包在 TR 里会上屏原样显示。

### 修掉的 4 个真 bug（都是"注释说了、代码没做"或"UI 挡住"）
1. **工具面板默认摆在 `DisplaySize.x*0.30`**，1600 宽窗口下正好盖住视口中心 →
   建模模式里点模型**完全没反应**（`IsItemHovered()` 被浮动窗口压成 false，
   `viewportInput` 连调用都不发生）。挪到 `0.60`。
2. `extrude()` 注释写"选区跟着顶面走"、代码只有 `m_sel.clear()` → 挤出完 Delete 立刻
   `skip=no-face-selected`。修法：记下 pushOut 的**副本渲染顶点**，upload 重建拓扑后
   按 `weldOf` 反查组号回填 `m_sel`。
3. `subdivideSelected()` 1→4 后新中点不在 `m_sel` 里 → 四个子面一个都选不中；
   `mergeSelection()` 合并后也清空。两处都改成保留（细分补中点组、合并保留那个点）。
4. 验收脚本把 `=(` 当"锚点行"判据，`FRACTURE ... bounds=(..)-(..)` 整条被吃掉，
   误报"Grid 切法没反应"。**锚点格式是 `TAG=(..)-(..) center=(..)`，只能用 `center=(` 判。**

### 鼠标注入的两条硬规矩（写视口类验收必看）
1. **窗口没有焦点时，Windows 会把点击当成"激活窗口"吃掉** → GLFW 鼠标回调不触发，
   `io.MouseDown[0]` 永远是 0，整个视口输入链路一步都不走。面板按钮"看起来能点"
   是因为之前的 click() 已经聚焦过了。`click()` 里必须 `focus_window()` 且**确认成功**。
2. **相机默认 distance=14 时 1 米立方体只有 ~42px**，按视口比例 0.3~0.7 扫点几乎必空。
   正确做法：先按 `F`（聚焦选中）把它挪到屏幕正中，再在 ±48px 内细扫。
   `MODEL-PICK-MISS` 是为这个准备的 —— 有 MISS = 射线打空，是**脚本瞄错**，不是功能坏。
