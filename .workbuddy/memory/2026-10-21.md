### 需求 2 是两个独立 bug
**(a) 落点不对 = 存储序，不是射线/矩阵**
- `.r32`/`.rgba8`/`.r8` 与 `physics::Heightfield` 是**列主序** `heights[col*rows+row]`；
  Vulkan 纹理是**行主序** `texel(x,y)=data[y*w+x]`；`terrain.vert` 用
  `uv=((col+0.5)/cols,(row+0.5)/rows)`。原样上传 = 整片地形绕对角线**镜像**。
- 实测 hills 257×257：CPU 峰值 (64,-40) m，不转置画到 (-40,64) m，**偏差 147 m**，
  **99.6% 采样点数值不同**。
- 修法：`TerrainPass::toRowMajor()`，上传前三张图都转置；`inst.asset.heights`
  保持列主序不动（物理/笔刷插值全按列主序写的）。

**(b) 不实时 = 每 80 ms 一次"写盘→再读回"**
- 原来 `saveAssets` 写 264 KB~1 MB，渲染层 `loadTerrain` 再读回来；`refillImage2D`
  每次还新建/销毁 VkBuffer + `vkQueueWaitIdle`。
- 修法一：`TerrainComponent` 挂 `liveHeights/liveSplat/liveHoles`，渲染层直接用编辑器
  那份 vector（零 I/O）；缺任何一份**整份退回读盘**（部分直传会让三张图版本不一致）。
- 修法二：`LandscapeEditor` 拆成 `publishToRenderer()`（只置脏位 + 挂指针）与
  `saveAssets()`（落盘 + publish）。**拖拽只走前者，抬笔才落盘**。
  `clearLiveBinding()` 在换资产/解绑时清指针 + 清脏位（否则悬垂）。
- 数据：`src=memory 7/7、src=disk 0`；`lastMs=1.40 maxMs=1.40`；一笔 30 步落盘 **1 次**。

## 第四轮 · 地形三件事（贴地 / 形状雕刻 / Raise 锥形）

用户三条原话 → 三个独立根因，全在 `editor/LandscapeEditor.cpp`。

### 1. 新建地形悬空 + 盖住初始场景
- 根因①：`generateDefaultHeights()` 的原始正弦没归一化，硬钳到 [0,1] 后一大片顶在 1.0（=60 m）。
- 根因②：`createTerrain()` 建完实体没落座，`position.z` 留 0；模板场景实体（Ground/Player/Pickup/Portal）全在 z≈0..1，被 60 m 地形盖平。
- 修：先算原始正弦再整体归一化到 `[0, kDefaultPeak=0.12]`（峰值 7.2 m，谷底严格 0）；实体 `z = kGroundEpsilon = 0.02f`（2 cm，躲开与模板 `Ground` 的 z-fighting）+ `LS-CREATE-SEAT` 日志。

### 2. 挖洞破拓扑 → 形状雕刻 Carve
- 旧 `Tool::Hole` 写 `holes.r8` + frag `discard` = 真的把地面剖开，拓扑被破坏。用户明确要"不能破坏拓扑"。
- 改成形状压印：`CarveShape{Sphere,Box,Cylinder}` + `m_carveDepth`，只改高度图，**一行遮罩都不写**。球=碗状、方=平底直壁、柱=竖井；`bottomN=(centerM-half)/unitM` 只往下削，Shift 反向堆隆起（同一算子两个符号）。
- 关键：`m_carveCenterM` 在**落笔那一刻锚定**，整笔不动。第一版每帧按当前地表重算 → Shift 隆起每帧把中心往上顶，自激到 480 m，`A9b` 假通过。
- UI：工具网格行高 28→22 + ItemSpacing(8,5)。第 8 个按钮原本下沿 859 > 面板底 842，**17 px 在面板外**，点中心会打到底部 dock 把视口标签切成 Console，之后整段视口操作全落空。

### 3. Raise 收尾成平顶（"想刷山峰结果成了火山"）
- 根因一行：`h = clamp(h, 0, 1)`。笔心先撞 1.0 停住、外圈还在涨 → 必然收成台地。
- 修：`kMaxNorm = 8.0f`（1.0 只是"等于 maxHeight"，不是墙）+ `raiseHeadroom(h)` 渐近余量：<1.0 恒 1、之后越近上限越慢。全文件 5 处 clamp 上限同步改 kMaxNorm。

### 4. 顺带修掉 `localHit.z` 单位误用（三处）
`physics::Heightfield::height() = raw * heightScale`，`raycast()` 传的 heightScale 已是 `maxHeight*m_heightScale` → **`hit.point.z` 就是米**。三处又乘了一次：
- `m_carveCenterM = localHit.z * unitM - ...` → 形状体到 807 m 高空（A8d 恒 0 点变低）→ 改为 `localHit.z - m_carveDepth*R`
- `m_flattenHeight = localHit.z * maxHeight * heightScale` → Flatten 顶到上限 → 改为 `localHit.z`
- `m_rampStartH = localHit.z`（米）和归一化 heights 插值 → Ramp 把地形推向 8.0 → 改为 `localHit.z / unitM`

## 第六轮：水体有体积（侧壁）+ 贴地 + 面板"消失"（2026-10-21 傍晚）

### 1. 水体从"一张纸"变成有厚度的水
- 顶点加 `part`（0=水面 / 1=侧壁顶 / 2=侧壁底）。侧壁与水面在同一次 draw 里画。
- **侧壁高度不进顶点**：只依赖 `level` 与 `bedLevel` 两个标量，放 UBO 的 `p4 = (bedLevel, skirtBottom)` → 拖水位只写 16 字节，不重建缓冲。
- 侧壁顶圈**也要加波浪位移**，否则水面一波动就与侧壁脱开一条缝。
- `shadeSkirt()` 单独一条路径：不做折射（背后是土），只做 Beer–Lambert（离水面越深越暗）+ 菲涅尔 + 噪声水线。
- `WaterUboGpu` 8×vec4 → 9×vec4（144 字节），`static_assert` 同步。

### 2. 贴地（用户说的"反重力"）
- `WaterBody` 新增 `bedLevel`（footprint 内最低地形）与 `autoFit`（用户手动拖过水位就置 false）。
- 水位 = **岸线最低点** `rimMin` + 0.18 —— 不是池底。岸线决定一个水平面能抬多高而不溢出；池底再深也不该把水面拽下去。
- 侧壁底 = `min(bedLevel - 0.75, level - 0.4)`，保证任何起伏都被地形遮住。
- `GroundProbe`：**构造时加载一次**地形（否则 150 个采样点 = 150 次读 264 KB），之后每点 O(1) 双线性插值。**只在松手时采样**（拖动期间读盘掉帧）。
- 圆形采样 3 圈×48 段 + 圆心，矩形 7×7；约 150 点。

### 3. 参数面板"消失"的三个真因
1. 选中态把"新建"段挪到最后并默认收起 → 首屏固定 `＋ 新建水体` 按钮。
2. 新建/选中切换后 ImGui 保留旧 `scrollY` → 切换时 `SetScrollY(0)`。
3. **`select(ecs::Entity{})` 取消不了选择**：它不清 `m_selectionName`，下一帧 `validateSelection()` 按名字把实体找回来 → 按钮点了、日志打了、面板纹丝不动。改用 `m_ctx.clearSelection()`。这是最隐蔽的一条。

### 4. 修掉的 bug
- **`rimMinZ` 被圆心污染**：`measureGround` 用第一个采样点初始化 `rimMinZ`，而圆形第一个点是**圆心（碗底）**。176 m 的湖 rim 记成 2.00（碗底）而不是 14.00（台地），水面只盖住碗底一小圈。改成只对 rim 点取 min，初值 +∞。
- **岸线白带像结冰**：`smoothstep(0,1.5,depth)` 在缓坡上覆盖好几米。收窄到 0.10 + 阈值化噪声打散；`foam` 系数 0.55→0.30。
- **水面像灰白塑料**：掠射角菲涅尔≈全反射 + 灰色天空。反射乘水色 `mix(vec3(1), shallow*1.8, 0.28)`，`bodyMix` 里 opacity 系数 1.0→0.5（2 m 深的湖原本 82% 被水色盖住，一点底都透不出来）。

### 5. 测试资产
- `assets/terrain/water_bowl/`：257²、2 m/px、maxHeight 40，中心 2 m、台地 14 m，碗底带 ±1.2 m 噪声。
- `assets/scenes/water_bowl.json`：地形 + 一块 25 m 水塘，打开即看效果。
- ⚠ `scenes`/`terrain` 不在 CMake 每次拷贝列表里，`verify_water_depth.py` 自带 `ensure_scene_assets()` 同步，否则场景静默回退到默认场景、贴地断言全变 `src=flat`。

## 水体第七轮：W/E/R 可操作 + 浪况合成单一参数 ✅

用户两条要求：
1. 水体创建后能在 3D 视口用 W/E/R 移动/旋转/缩放；
2. 浪花波纹由**一个**浮点参数控制（0 = 无任何波纹的平静水面，10 = 汹涌）。

### ① W/E/R —— 病灶与做法
- **病灶**：水体没有网格组件，gizmo 只认 `TransformComponent`；而
  `WaterPass` 建模用 `body.center/level/rotation/halfExtent`，**完全忽略实体
  变换** → 手柄拖了水面不动。
- **做法**：把 Transform 当"手柄载体"，每帧**成对**同步（`WaterEditor`）：
  `syncTransformFromBody` → `gizmo.update` → `applyTransformToBody`。
  调用点在 `ViewportPanel` 里成对夹住 gizmo；只做一半会互相打架。
- ⚠⚠ **缩放必须乘比值，不能乘绝对值**：gizmo 写的是 `m_startScale * factor`
  （绝对倍率），每帧直接 `halfExtent *= tf.scale` 会把累计量反复叠进去 ——
  实测一次拖拽把半径 18 干到 **2.4e9**。改成 `halfExtent *= 本帧/上帧`，
  并夹 [0.5, 2000] m 兜底。修好后一次拖拽 = 精确 ×2（手柄一格）。
- **拾取**：`PickingSystem::pick` 补了水面拾取（射线 vs 水平圆/矩形）。
  水体不在 BVH 里 → 必须放在 PICK-DBG 自检**之后**，否则 `same` 恒为 0。

### ② 浪况 0..10
- `WaterBody::waves` 是唯一输入；`deriveWaves(waves)` 派生
  `amp = 0.60·t^1.35` / `λ = 3.2+16.8t` / `ripple = 1.70t` / `foam = 0.95·t^2.2`
  （t = waves/10）。**t == 0 直接返回全零**（不走 pow，避免 1e-9 残留）。
- **唯一映射**：`WaterPass` 与面板都调 `deriveWaves`，不许各写一份。
- 旧 `waveHeight/waveLength/ripple/foam` 降级 legacy：仍读写 JSON，不参与渲染；
  老场景（无 `waves`）由 `waveHeight` 反推等效浪况（实测 0.55 → 能量 0.88，
  与 waves≈9.4 一致）。
- 面板：4 个滑块合成 1 个 `Waves`，且必须放**首屏** —— 面板是滚动子窗口、
  比窗口高；放在水位后面时滑块在 y=759 而客户区只有 753（正好被裁）。
  现在放在 Shape 段最前面（形状按钮之前），y=654。

### 验收（`tools/verify_water_motion.py`，7 组全 PASS）
- move：center.x 0 → 3.90；没串到 y/高度
- scale：halfExtent 18 → **36.00**（×2）；圆形保持 x==y；没挪位置
- rotate：rot −70°；尺寸/位置不变
- 浪况单调：水面高频能量 **0.15 → 0.50 → 0.92**（waves 0/4/10）；
  waves=0 < 1/3·waves=10；**控制组**两次 waves=0 差 < 0.05
- 面板滑块真的点得动：0 → 10
- 老场景迁移：只有 waveHeight=0.55 → 能量 0.88 > waves=4 的 0.50

### 踩坑（都是"测不到"而不是"没实现"）
- ⚠ **NO_HUD 会连带关掉变换手柄**（设了之后 `GZ-ORIGIN` 一条都不打）→
  拖手柄的用例必须传 `no_hud=False`。
- ⚠ `logRect` 给的是**客户区**坐标，`SetCursorPos` 要**屏幕**坐标 →
  必须用 `verify_asset_drag.move_to(hwnd,…)`，否则整段拖拽平移、抓不到手柄。
- ⚠ 相机俯角变了之后水面会跑出 FOV：`GZ-ORIGIN` 会出现在 y=1824（窗口才 800）。
  本次把水体中心挪到视线落点 (0,−24) 才对准。
- **词表解析器不认相邻字符串拼接**：`{"a\n" "b", "..."}` 会被截成 `"a\n"` →
  i18n 报"缺译文"。长 key 必须写成**单个**字面量。
- `logRect` 与 `IsItemDeactivatedAfterEdit()` 必须**紧贴** SliderFloat：中间插
  一行 TextDisabled，松手事件就认到那行字上，日志永远不打。

### 顺带修的
- `verify_water.py` 之前只打"全部通过。"（无 `结果: PASS`）→ 回归框架认不出，
  单跑必判 FAIL。已补标准结果行。

  `WaterPass.*` 补进 `RENDER_MODULES`（check_regression_map 之前一直漏）。

### 已知与本轮无关的失败（跑受影响集时看到）
- `verify_primitive_roundtrip` / `verify_material_roundtrip`：都挂在 Inspector
  的拖拽上，且 rect 落到窗口外（y=1021 而窗口 900）→ 是**面板 docking 重构**

## 水体第八轮 + 新工程初始场景（地形 + GameStart）✅

## 第九轮：GameStart 可点选/落地/聚焦 + 地面"糊"的根治

用户四条反馈，三条已修、一条未能复现。

### ① GameStart 点得到、拖得动、落得地（需求 1）
- **根因**：GameStart **没有网格** → 不在 BVH 里（`PickingSystem::pick` 点不中），
  也没有 AABB（`dropSelectionToGround` 以 "no mesh bounds" 跳过）。
  两件事同一个根因，所以"没有 gizmo"和"数字键 0 不落地"一起出现。
- 修：
  · `pick()` 在 BVH/水体之后加**竖直胶囊**求交（r=0.45、高 1.75）；
  · 落地对 GameStart 用合成 AABB（脚下→头顶），并且**地面高度改用地形**
    （`LandscapeEditor::heightAtWorld`，没地形时返回 0 → 老场景不变）。
- 数字键 0 其实早就同时绑了 `ImGuiKey_0` 和 `Keypad0`（EditorApp 3123），
  真正的拦路虎是上面两条。验收里用 `keybd_event(VK_NUMPAD0)` 真按了一次。

### ② 地面/栅格"模糊重影"（需求 2）
- **先排除**：TAA 开/关逐像素相同（0.000）、阴影开/关相同、栅格开/关 0.05%
  → 不是后处理、不是阴影、不是栅格 z-fighting。
- **真因**：地形材质**一张贴图都没有**（`TERRAIN-LAYER ... albedo=default
  normal=default`）。几百像素的纯色渐变 + 8bit 量化 = 看着又糊又像有重影。
- 修：
  · `gen_templates.py` 纯 Python 生成**无缝** albedo + normal（PNG 编码
    自带 zlib/struct，不依赖 PIL —— 宿主裸 python 没装）；
  · `materials/template_ground` 挂上两张图；
  · ⚠ **顺带修了个真 bug**：`TerrainPass::loadLayerJson` 把材质里的相对路径
    直接交给 `Texture::fromFile`（= 相对**进程 cwd**），没走
    `assets::resolveAssetPath` → 地形层一带贴图就 `can't fopen` → throw →
    **整个编辑器 Fatal**。引擎自带两块地形都没贴图，所以这条从没被走到。
    顺手加了 try/catch：贴图丢了降级成纯色，不再拖垮编辑器。
- 效果：地面高频能量 0.81 → 3.11（3.8×），视觉上从"米色渐变"变成"土黄颗粒"。

### ③ Hierarchy 双击 → 视口聚焦（需求 3）
- 双击原来是**就地重命名**；改成"选中 + 相机聚焦"，重命名保留在 F2 / 右键菜单。
- 实现落在新文件 `editor/EditorFocus.h::focusCameraOnEntity`：三类没有网格的
  实体（GameStart / 水体 / 灯）各有自己的尺寸估算，否则要么框不到要么怼脸。
- ⚠ 先试过"面板往 EditorContext 挂 pending-focus、视口消费"，**永远不被消费**
  （连 requestFocus 的日志都不打）。改成两个面板各自直接调同一个自由函数，
  一次就好 —— 面板间共享状态能少则少。

### ④ 模式面板点击别处就消失 —— **未能复现**
- 实测：切 Landscape / Water 模式后面板出现；点视口（真鼠标点击）之后
  `WATER-PANEL` / Landscape 面板**仍然在**（只是布局矩形变窄）。
- 另外 `verify_edit_modes` 有一条既有断言：切回 select 时
  `landscape=0 foliage=0`（即"离开模式就关掉该模式面板"是有意的约定），
  所以不能简单改成"永不关闭"。
- 需要用户补充：哪个模式、点的是哪里、面板是"整块没了"还是"切到别的页签"。

### 验收
- 新增 `tools/verify_gamestart_edit.py`（进 DEFAULT+TRIGGERS，3 组全 PASS）：
  点标记 → `GZ-ORIGIN` 出现且落在标记上；小键盘 0 → `dz=-2.0000`；
  双击 → `FOCUS-ENTITY` + 标记矩形随相机变化。
- `verify_template_scene` 增两条："材质带 albedo/normal 且文件存在"。
- `check_regression_map` PASS；template_scene / gamestart_edit /
  template_play / i18n 全 PASS。

### 踩坑
- ⚠ 双击用例里**不能复用** `click()`：它点完 sleep 0.55s，两次点击就超过
  ImGui 的 0.30s 双击窗口 → 永远只是"两次单击"。
- ⚠ `World::alive()` 还比对 generation；层级树回来的句柄可能过不了那一关，
  表现是"函数直接 return、一条日志都没有"。没有强依赖就别查 alive。
