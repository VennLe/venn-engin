## Clustered Forward 分簇前向渲染（完成）

需求：室内场景 30~200 盏动态点光/射灯、影响范围小、保留透明 + MSAA、
compute 剔光、Depth pre-pass、主 Pass 从 SSBO 读本像素所属簇的灯列表。

### 数据流（5 个 Pass）
```
ShadowPass → DepthPrePass(独立 RP) → ClusterBuild(compute) → Forward(MSAA→resolve) → PostProcess
```
compute **不能**在 RenderPass 内部执行 → 深度预通道必须独立成 RP，
中间留出 compute + buffer barrier。

### 核心设计
- **固定槽位 SSBO**（`lightIndices[clusterIdx*cap + i]`）：无原子追加、无越界、
  结果与线程调度顺序无关（**可复现**，截图对比才有意义）。代价是按 `clusterCount*cap` 预分配。
- 编址三处必须完全一致：`(z*gridY + tileY)*gridX + tileX`，深度切片
  `d(k) = clusterNear·(zf/clusterNear)^(k/slices)`，指数分布。
- **深度切片起点是 `clusterNear` 而不是 `zNear`**：投影用 `glm::perspective` 且未定义
  `GLM_FORCE_DEPTH_ZERO_TO_ONE` → NDC z ∈ [-1,1]，Vulkan 只留 [0,1]，
  真正可见的最近深度是 `2·zn·zf/(zn+zf)`（本例 0.199）。从 zn 起算会有若干层切片落在裁剪区外。
- **射灯只按 range 球剔除**（锥角在片元里算）：锥 vs AABB 保守性难保证，
  漏光比多算几盏灯难查得多。
- **窗口化平方反比衰减** `win = 1-(d/range)^4, att = win²/d²` → range 处严格归零，无硬边。
- 灯数据全挤进 set 0（binding 2/3/4/5）：Vulkan 只保证 4 个 set 可同时绑定。

### 本轮踩的坑（都是真 bug）
1. **compute dispatch 未绑定 descriptor set 0** → 验证层刷
   `statically uses descriptor set 0, but ... never bound`。
   `dispatch(..., nullptr, 0, ...)` 漏了 set。修法：`record()` 加 `VkDescriptorSet globalSet`
   参数，Renderer 传 `frame.globalUBOSet`（与 compute 管线 layout 同源）。
2. **`pbr.frag` 硬编码 `kMaxLightsPerCluster = 32`** —— 与 C++ 的 `maxLightsPerCluster`
   是同一份语义却写死在两处。调大 C++ 侧不会报错，只会**静默截断**灯表。
   修法：上限改从 `ubo.lightParams.w` 读，单一数据源。
3. **深度预通道关掉 → 前向通道读到未定义深度**。前向 RP 的深度附件是 `LOAD`，
   深度内容完全由预通道产生；预通道原本 `if (!enabled) return;` 直接跳过了整个 RP
   （连清深度都没做）。修法：RP **无条件**执行，只把"画几何"这一步用开关包起来。
4. **`enum class Type : float`** 非法（底层类型必须是整型）→ 改 `: int`。
5. **`scene::LightStats`** 实际是 `scene::Scene` 的嵌套类型 → 要写 `scene::Scene::LightStats`。
6. 相机 yaw 用了默认值 `-0.8`，正好落在房间对角线上，被 (±4.8,±4.8) 的一根柱子糊住整个画面。
   → 显式 `setYaw(0.15)`，让远景柱子分列左右当参照。

### 验证证据（全部通过，validation 全程开启且 0 报错）
| 对比 | 期望 | 实测 |
|---|---|---|
| 剔除 ON vs OFF（cap=256 ≥ 灯数） | 一致 | **0 差异** |
| 预通道 ON vs OFF | 一致（纯优化） | **0 差异** |
| MSAA 4x vs 1x | 不同 | 2377 px（0.26%）差，bbox 覆盖全幅（几何边缘） |
| 灯 64 vs 0 | 不同 | 60.1% 像素差，mean 46/255 |
| **200 盏灯 / 出厂默认(cap=128) vs 有效暴力参考(cap=256 关剔除)** | 一致 | **0 差异** |

遥测（`MYVK_CLUSTER_STATS=1`）：64 灯 → 平均每簇 **8.01** 盏、4800/14720 空簇；
200 灯 → 平均 **28.47** 盏、单簇最大 **79**、overflow=0。
即 200 盏灯时每像素只循环 ~28 盏而不是 200 盏（**约 7×** 削减），这就是分簇的收益。

`maxLightsPerCluster` 默认定 **128** 的依据：**它只花显存不花时间**（compute 侧无论 cap
多大都要遍历全部灯，片元侧遍历的是真实灯数 `clusters[].y`）。实测 200 灯时单簇峰值 79，
128 零截断；32/64 会出现上百个溢出簇。1080p 约 16 MB/帧。

## editor/ 编辑器层落地（8 个面板 + 独立可执行目标，已跑通）

需求：在引擎之上加 `editor/`，8 个部件（EditorApp / ViewportPanel / SceneHierarchy /
InspectorPanel / ContentBrowser / Toolbar / GizmoController / PickingSystem）+ 9 项能力
（ImGui 面板、picking+gizmo、文件系统+缩略图、JSON 序列化、命令模式撤销、脚本语言+热重载）。
三条硬约束：① 编辑器模式不跑游戏逻辑 ② 渲染目标是 ImGui 子窗口而非全屏 ③ EditorScene/RuntimeScene 分离。

### 接缝（引擎侧只加了两个口子，其余一行没动）
1. `Application::activeScene()` 虚函数 —— 引擎"更新/渲染哪一份场景"全问它，
   编辑器返回 `EditorContext::activeScene()`（按 Play 状态分发到编辑态/运行态）
2. `Renderer::setViewportSize(w,h)` / `viewportTextureId()` —— 3D 从直写交换链改为写离屏图，
   再由 `ImGui::Image()` 贴进 Viewport 面板。HdrTarget/分簇/Bloom 全跟 `renderExtent()` 走

### 关键设计
- **两套 scene 靠内存态 JSON 快照复制**（`sceneToJson`/`sceneFromJson`）：Play=复制，Stop=丢弃。
  编辑态**一个字节都没被改过**，"停止后回到播放前"天然成立。复制法把风险挡在编辑态外
- **撤销栈分工**：值编辑用 `RawBytesEditCommand`（memcpy 泛型，Inspector 用），
  结构性编辑用 `SceneSnapshotCommand`（整场景 JSON）。`structuralEdit(name, fn)` 统一入口
- **Gizmo 自研**（third_party 里没有 ImGuizmo）：画在 `ImDrawList` 上 + 射线数学，
  欧拉角用 XYZ 顺序与 `TransformComponent::localMatrix` 对齐
- **布局不用 docking 分支**：每帧算固定矩形（`LayoutRects`），面板用 `FirstUseEver` 落位，
  `relayout` 标志做 "Reset Layout"
- **自研 .vks 脚本语言**（lexer/parser/AST/evaluator 各一份，仅 2 个文件）：
  `ScriptHost{scene,entity}` 是脚本能碰到的**唯一**接缝，语言里没有文件/网络/系统调用，
  安全性是结构上的。热重载按 mtime 轮询，编译失败**保留上一个可用版本**
- **ECS 遍历时不能增删实体**（会让遍历失效）→ SceneHierarchy 的删除/复制/新建/改父子关系
  全部走 "pending 队列 + 树画完再 flush" 的两段式

- 新增 `Editor` 可执行目标（`GLOB_RECURSE editor/*.cpp`），与 Sandbox 平行、共用 `engine/`

### 编译期踩坑（都是真错误）
1. **同一文件的两处 Edit 并行下发会互相覆盖** —— 工具报告成功但前一处改动被回滚。
   教训：**同一文件的多处修改必须串行**（不同文件可以并行）

3. `PanelVisibility` 是 `EditorContext` 的嵌套类型 → 面板里当类型名用必须写

## Makefile 构建/打包封装（完成）

需求：用 Makefile 把「配置 + 编译 + 运行 + 打包」收敛成 `make build / run / clean / package`。

### 交付物
- `Makefile`：CMake 的薄包装。目标 = `build / configure / sandbox / editor / shaders / run /
  run-editor / smoke / clean / rebuild / distclean / package / info / help / install-make-alias`
- `make.cmd`：Windows 上 MSYS2 只装 `mingw32-make.exe`（无 `make.exe`），
  这个批处理把 `make <args>` 原样转发，让根目录能直接敲 `make`
- `.gitignore` 追加 `dist/`

### 关键设计
- **配置戳** `build/.configured-$(BUILD_TYPE)`：`BUILD_TYPE` 写进文件名，
  `make BUILD_TYPE=Release` 会自动重新 configure；反复 `make build` 不再跑 cmake 配置
- **配方双 shell 兼容**（cmd.exe 与 sh 都要能跑，GNU Make 选哪个取决于 PATH 里有无 sh.exe）：
  不用 rm/mkdir/cp/del，一律 `cmake -E` 内置命令；路径正斜杠；环境变量用 `cmake -E env` 注入
- **`echo` 纯 ASCII**：Makefile 是 UTF-8，但 cmd.exe 用 GBK(936) 代码页，中文 echo 会乱码；
  且 `echo A -> B` 的 `>` 会被 cmd 当重定向。注释可中文（不回显）
- **`make run` 用 `cmake -E chdir build/bin` 启动**：ImGui 把布局写成 `<CWD>/imgui.ini`，
  从根目录跑会把 imgui.ini 甩到仓库根，chdir 后落在 build/bin 下，仓库根不脏
- **`make package` 用 `cmake -E tar --format=zip`**（不依赖未安装的 zip 命令）产
  `dist/MyVulkanEngine-<版本>-<类型>-win64.zip`
- `RUN_ENV` 变量只在非空时注入（`ifneq` 组装），避免给进程塞一堆空环境变量

### 验证（全部通过，validation 开启 0 报错）
| 项 | 结果 |
|---|---|
| `make build` 幂等 | 首次 7.1s 配置，二次 1.2s 不重配 |
| `make clean`→`make rebuild` | 全量重编 44.7s，两个 exe + 着色器 + 资源产出 |
| `make smoke` | 两个二进制各跑 120 帧，编辑器 Play 态 3 脚本 0 失败 |
| `make run` | 60 帧退出，仓库根 imgui.ini **未被动过**，build/bin 下的被更新 |
| `make package` | 21 MB zip，**从 dist/ 独立运行成功**（资源按 exe 同目录解析） |
| `make distclean`→`make build` | 冷启动全量 77s，两个 exe 重建 |

### 本轮踩坑
1. **`CONFIG_STAMP` 用了 `:=` 却定义在 `BUILD_TYPE` 之前** → 展开时拿到空值，戳名变
   `build/.configured-`。修法：把 `BUILD_TYPE` 等变量挪到 `CONFIG_STAMP` 之前
2. **`make.exe` 在 PATH 里不存在**：MSYS2 装的是 `mingw32-make.exe`（ucrt64）与
   `make.exe`（usr/bin，本沙箱跑不起来）。用 `C:\msys64\ucrt64\bin\mingw32-make.exe` 直接驱动
3. 本环境 PowerShell stdout **不回显**、bash coreutils（dirname/ls/grep/head）**全缺**、
   且 PowerShell 不能调 cmd.exe（安全策略）→ 所有验证结果写文件 + Read/Grep 读；
   `*>` 重定向是 UTF-16，验证输出要用 `| Out-File -Encoding utf8`
4. **`make.cmd` 是 UTF-8（含中文注释）→ cmd.exe 用 GBK 解析乱码 + BOM 被当字符，
   陷入刷屏死循环**（help 输出膨胀到 2.8MB）。修法：批处理文件**纯 ASCII**，注释全英文。
   这是用户在实际敲 `make` 时暴露的（PowerShell 默认不加载当前目录命令，提示改用 `.\make`，
   一跑就炸了）。与 Makefile 的"echo 纯 ASCII"同源但更严重——批处理是**整文件**受影响

## 修复编辑器 run-editor 断言崩溃（ContentBrowser 拖拽）

用户跑 `make run-editor` 时崩溃：
```
Viewport render size -> 1875x941 (offscreen)
Assertion failed: 0, file: imgui.cpp, line 15137
Exit code 0xc0000409
```

根因：`ContentBrowser.cpp` 的缩略图条目拖拽源调 `ImGui::BeginDragDropSource()` **没带**
`ImGuiDragDropFlags_SourceAllowNullID`。缩略图是 `Image()`/`TextWrapped()` 这类"无唯一
交互 ID"的 item，`BeginDragDropSource()` 默认（`None`）会走 imgui.cpp 的 uncommon path，
`g.LastItemData.ID==0` 时直接 `IM_ASSERT(0)`。SceneHierarchy 那处本来就有该标志，
ContentBrowser 漏了。

修法：`BeginDragDropSource(ImGuiDragDropFlags_SourceAllowNullID)`。改后 120 帧冒烟测试
exit 0，不再崩溃。

坑点：崩溃**只在视口尺寸变化后**才触发（日志停在 `Viewport render size -> ...` 后一行，
与渲染完全无关），`0xc0000409` 是 Windows 断言崩溃的特征码。

## 编辑器布局改造：分栏可拖拽 + 自适应（Blender 式）

需求：原布局"每帧算死矩形 + FirstUseEver 落位"太死板——面板被用户拖过就不再跟随窗口缩放。
改成 Blender 式：窗口缩放时按比例自适应 + 分栏交界可拖拽 + 侧栏可折叠（视口优先）。

### 设计：SplitLayout 分栏树
- 新增 `editor/SplitLayout.{h,cpp}`：二叉分栏树，内部节点 = 水平/垂直切分 + 比例(0..1)，
  半边可以是子节点（a/b >= 0）**或**叶子面板（panelA/panelB）
- 默认树：root(H) =「左栏(V: Hierarchy上/Content下) | 右区(H: Viewport/Inspector)」，
  与 Blender 默认 Screen 同构
- **比例存 0..1 float，按窗口尺寸换算像素** → 天然自适应；首帧把初始像素宽度
  （左 260 / 右 300）换算成比例
- 产出仍是 `LayoutRects`（`SplitLayout::apply` 填充）→ **面板代码的矩形消费逻辑零改动**

### 关键决策：面板改 Always 落位 + NoMove/NoResize
四个主体面板（Hierarchy/Content/Viewport/Inspector）从 `FirstUseEver` 改为 **`Always`** +
`NoMove/NoResize/NoCollapse`：位置完全由分栏树决定，不再允许拖动窗口本身
（分栏由分隔条控制）。Toolbar/StatusBar 同样 Always（跟随窗口宽度）。
这是"自适应"的**必要条件**——FirstUseEver 只在首帧落位，窗口缩放后面板不会跟。

### 分隔条交互（在所有面板之后处理）
- 画线用 `ImGui::GetForegroundDrawList()`（盖在面板上，保证可见）
- 拖拽用**鼠标位置手动命中**（`|mouse.x - splitterX| <= 3px` + `!IsAnyItemHovered()`），
  不用 InvisibleButton——后者必须在窗口上下文里，放面板之前没有窗口、放之后会被面板吃掉
- 拖动改 ratio：`clamp(aSize + mouseDelta, minA, w - minB)`，按像素 clamp 再换算比例
- **双击分隔条 = 折叠/展开 A 区**（存 savedRatio，展开恢复）
- 调用顺序：computeLayout → 各面板 draw → handleSplitters → relayout 消费

### 踩坑
1. **首版树结构写错了**：把 left/right 节点建成了 `a=-1,b=-1` 的叶子却期待它切两格 →
   `resolve` 的叶子分支只写 panelA，`content`/`inspector` 矩形永远没人写（保持默认 0），
   Content 被挤成 90px 一条、Inspector 消失。修法：半边要支持"子节点或叶子"二选一，
   resolve/processSplitters 对 a/b **各自独立**判断
2. `beginFrame` 在头文件里写了内联定义、.cpp 里又定义一次 → redefinition；
   `writePanel` 忘了在头文件声明 → no declaration matches。都是头文件/实现不同步

### 验证（validation 全程开启 0 报错）
| 项 | 结果 |
|---|---|
| 编译 | SplitLayout 新文件被 GLOB 自动拾取（CONFIGURE_DEPENDS 触发 re-run CMake） |
| 首启动截图 | 四格布局正确：Hierarchy 左上 / Content 左下 / Viewport 中央 1024x749 / Inspector 右 |
| **缩放压测** 1600x900→1024x640→1440x810→1280x720 | 视口离屏目标逐帧跟随（1024x749→635x433→905x603→801x513），布局比例保持 |
| `make smoke` | Sandbox 120 帧干净退出；Editor Play 态 3 脚本 0 失败 |

## 编辑器设置：字体缩放 + 工具栏高度可调（完成）

需求：编辑器字体太小，且工具栏高度太窄、不能手动调。要求在 Edit 菜单加设置功能。

### 实现
- **字体**：`ImGuiManager::init` 加载矢量字体 `assets/fonts/DroidSans.ttf`（18px 基础字号，
  随 imgui misc/fonts 一起由 CMake `myvk_copy_runtime_assets` 拷到 exe 目录，用
  `assets::resolveAssetPath("fonts/DroidSans.ttf")` 定位；找不到则回退内置位图字体不致命）。
  运行时缩放走 `ImGui::GetIO().FontGlobalScale`（`ImGuiManager::setFontScale` 写入，
  `beginFrame` 里在 NewFrame 之前应用）→ **即时生效、无需重建字体图集**。
- **工具栏高度**：`EditorContext` 存 `m_toolbarH`（默认 48，原 40），`SplitLayout` 加
  `setToolbarHeight()` 替换文件内写死的 `kToolbarH` 常量（apply 与 handleSplitters 两处都改）。
  `EditorApp::computeLayout` 每帧 `m_split->setToolbarHeight(m_ctx->toolbarHeight())` 同步。
- **设置弹窗** `EditorApp::drawSettingsPanel()`：居中弹窗，Font scale 滑块(0.75~2.0) +
  ±0.10/重置按钮，Toolbar height 滑块(32~80px) + 重置。Edit 菜单加 `Settings...` 项
  （`m_ctx->showSettings()` 布尔开关）。`onImGui` 开头 `renderer().ui().setFontScale(...)`。

### 关键点 / 坑
1. **工具栏"拖拽"不可行的原因**：工具栏窗口用 `SetNextWindowSize(Always)` 每帧覆盖，
   ImGui 原生拖 resize 会被下一帧冲掉。所以高度走**设置滑块**（写 EditorContext，SplitLayout
   读），比原生拖拽更可靠。`NoResize` 标志保留。
2. `ImGuiWindowFlags_NoDocking` 在此 imgui 版本(1.93 WIP 无 docking 分支)**未定义** →
   编译报错，删除该标志（改用 `NoCollapse`）。
3. `renderer().ui()` 返回 `ui::ImGuiManager&`（`Renderer::ui()`），是编辑器设置字体的入口。

- 冒烟 `MYVK_FRAMES=180`：validation 开启 **0 报错**，日志 `ImGui font loaded: ...DroidSans.ttf (18px)`
