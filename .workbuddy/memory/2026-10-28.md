  `makeAssetRelative` 配反查表，避免把缓存绝对路径写进场景。
- 出包：`--pak` → 先照旧拷成目录树、再收进 `assets.pak`、**再删目录树**（保证包内容

## G30 Shipping 剔除 `make ship`（✅ 2026-10-28）

文档 → `docs/ship_roadmap.md` §10 的 G30；`docs/package_roadmap.md` §9；
判据 → `tools/verify_shipping.py`（A~D **39 条**，全绿）。

- `make ship` → `build-ship/bin/Game.exe`（RelWithDebInfo + `-DVENN_SHIPPING=ON`）。
  **Editor / Launcher / AssetC 的 target 在 shipping 里根本不声明** → `bin/` 里只有一个 exe。
- 风味唯一事实源 = `engine/core/Build.h`（`kShipping` / `kBuildFlavor` / `kGitDescribe` /
  `buildStamp()`）。**任何地方不许自己 `#ifdef NDEBUG` 猜** —— 猜错的方向恒是"以为关了其实开着"。
- 开发钩子**编译期**剔除（不是运行期 `if`）：`--selftest` / `--dump-scene` / `--package` /
  `MYVK_RUNTIME_SELFTEST` / `MYVK_FIXED_DT` / `MYVK_PHYS_DUMP`。实测出货 exe 里这几个串
  **各 0 次**，dev exe 里各 > 0（**对照区**）。"验证少了什么"只能靠字节 + 行为，不能靠"能起来"。
- 校验层：shipping 下 `Instance` **强制** false（env 也不给翻盘），日志 `INSTANCE build=… validation=off`。
- git 号：CMake `git describe` → `VENN_GIT_DESCRIBE` → `--version` / `GAME-BUILD` / shipping 标题栏
  `[<git>]`。⚠ 是 **configure 时刻**的快照，只 build 不 configure 不会更新。
- 出包：**dev 版当工具、出货版当内容**（`--engine build-ship/bin/Game.exe`）。
  `build.json` 增 `flavor` / `git` / `pdb`；pdb 归档 `dist/<Name>/debug/`（**不在 exe 旁**），
  默认**跟风味走**（shipping 归档、dev 不归档）。风味是跑 `--version` **探**出来的（`probeExeFlavor`）。
