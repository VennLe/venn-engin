## 一、分隔条穿过所有浮层（用户报的第 1 点）

**症状**（用户原话）："在 Content 面板中点击 + 按钮时打开的菜单列表中间会穿插着层级面板和
Viewport 面板之间的分割线，也包括其他所有的面板窗口或子菜单都有这个问题。"

**根因**：`SplitLayout` 的分隔条画在 `ImGui::GetForegroundDrawList()` —— 它压在本帧**所有**
窗口之上，所以任何弹层（`+` 菜单、右键菜单、下拉、浮动面板、tooltip）都会被穿。原机制只支持
**一个**遮挡矩形（`setOccluder`，2026-10-17 为 Content 抽屉特设），其余浮层全靠运气。

**改法**（`editor/SplitLayout.h/.cpp` + `editor/EditorApp.cpp/.h`）：
- `setOccluder` 换成 `clearOccluders()` / `addOccluder(x0,y0,x1,y1)` 的**列表**；空矩形自动
  忽略、坐标自动排序、多块重叠自动合并。
- 绘制时对每条分隔线的可行区间做 `sort → merge → 相减` 求可见 `spans`，命中测试 / 抓手 /
  tooltip **都记在最长的那一段**上（否则日志里的矩形会飘）。
- 新函数 `EditorApp::collectSplitOccluders()`：**必须排在所有窗口都画完之后、`handleSplitters()`
  之前**。来源 = 浮层形态的 Content 抽屉 + `g.Windows` 里所有
  `WasActive && !Hidden && 非 ChildWindow && Size >= 2px` 的顶层窗口。
- ⚠⚠ **必须排除落在 `LayoutRects` 上的布局面板**：分隔线正好压在两个面板的公共边界
  （`A.x1 == B.x0`）上，拿面板自己的矩形去裁 → **整条线被裁成 0，等于把全部分隔条弄没**。
  排除用"四边都在 2px 内等于某个 LayoutRect"。
- ⚠ 用 `WasActive` 而不是 `Active`：菜单刚弹出那一帧 `Active` 还没置位 → 会漏切一帧、竖线闪。
- `computeLayout()` 里原来的 `setOccluder(true/false, ...)` 整段删除（只留说明注释）。

**实机验证**（`_tmp_occl.py`，用完已删）：
- Content 抽屉 → `CB-ADD-BTN` → 菜单（Material / Model / Scene…）放大 3 倍**完全干净**，
  没有竖线穿过；底栏 `+` 面板选择器同样干净。
- 空状态截图放大 8 倍：`层级 | 视口` 那条竖线**仍然在**（排除逻辑没写过头）。

## 三、Lightning 粒子预设重做成"雷雨天闪电"（用户报的第 3 点）

用户原话："我想要的是闪电，就是雷雨天的那种闪电。你做出的效果和闪电差得很远，而且闪电是有
一定的时间间隔频率的。" 还说"粒子特效的位置从视口看起来会超出视口的范围"。

**第一版（上一轮）的实测错误**：截图出来是**一根 0.9 m 粗、纯白过曝的实心光柱**。
原因逐条量出来的：Box 半轴 (0.45, 0.45, 3.1) → 0.9 m 截面；512 颗全挤在同一段高度；
拉伸 0.12 × 26 m/s = 3 m 长光丝；emissive 16 → 加色在任何重叠处直接削顶成 1.0。

**第二版（本轮）的做法**：
1. **截面收细 15 倍**：Box 半轴 → (0.03, 0.02, 1.8)；startSize 0.09→0.026。
2. **不再整根同时亮**：lifetime 0.22→0.16、speed 26→16、stretchScale 0.12→0.05（光丝 ≈0.8 m）。
3. **emissive 16→4.5**：保留得住冷蓝，不会全压成纯白。
4. **高度收进视口**：originZ 3.2→1.9、半轴 z→1.8 → 世界 z∈[0.1, 3.7]（3.6 m）；
   默认机位 9 m / 45° FOV 画面高约 7.4 m，所以既不冲顶也不穿地。
5. **频率**：duration 2.4 + looping + rate=0 → 每 2.4 s 打一次，每次 ~0.45 s，其余 2 s 全黑；
   主放电后 0.09 / 0.17 / 0.31 s 各补一发（`kBoltRestrikes`）= 多段回击。
6. **分叉**（关键，见下）。

⚠⚠ **数学结论：单个发射器画不出分叉。** 出生体是**轴对齐长方体**，速度只有"锥 + 恒定加速度"，
两者都**没有"x 与 z 相关"的自由度** → 箱子窄 = 一根直光柱，箱子宽 = 一片光幕。
实机截图证实了两种极端（0.9 m 柱 / 6 cm 柱）。所以加了一层结构性机制：

- `struct FxFork { offset, tilt, halfZ, size, emissive, countScale, orbital }` +
  `FxPreset::forks / forkCount`；`addPreset` 里抽出 `spawnEmitter(...)` lambda，主通道与每条
  支路都建成**独立的普通发射器**（层级里能单独选中、单独调，不是黑魔法）。
- 它们**共用同一张 burst 表 + 同一个 duration** → 永远同一瞬间一起亮（模拟时刻 t 是全发射器
  共享的，每轮都从 `mod(t, duration)` 算起）。
- 闪电 = 主通道 + **3 条 fork**：① 辉光鞘（同位置、粗 4 倍、暗 5 倍 → 做出"亮芯 + 外晕"，
  粒子没有 shader 级柔边，这是唯一办法）② 右上支路 ③ 左下支路。
- ⚠ **倾斜必须靠 `tc->rotation`，不能只靠 `orbital`**。`orbital` 是 `v += ω × (p-origin)`
  —— 柱顶柱底反向加速，得到的是"上下拧"的扇面，**不是一条斜线**（第一版分叉就踩了这个：
  三条**平行**光柱）。Transform 的矩阵是 `Rz·Ry·Rx`（`Components.h:41-43`），所以
  `rx = π + radians(tilt.y)` → 轴朝 +Y 偏；`ry = radians(tilt.x)` → 轴朝 -X 偏。
  两个都写 0 时与原来的 `(π,0,0)` 逐位相同。
- ⚠ 倾斜只对 `flipDown` 的预设（雨/雪/闪电）生效，火/烟/火花保持 `(0,0,0)` —— 老行为逐位不变。

**实测时间序列**（`_tmp_bolt.py`，4.2 s，已删）：
```
t=0.05…1.9   bright_px=0            ← 上一轮的间隔
t=1.96…2.36  bright_px≈6700~7300    ← 一次雷击（多段回击）
t=2.47…4.2   bright_px=0            ← 又黑回去
```
峰值亮像素从上一版 49196 → **13120**（不再过曝），周期 ≈2.4 s，符合"有间隔频率"。
截图 `_venn_verify/_bolt_lightning_v2.png`：亮芯 + 蓝白辉光 + 两条斜支路，树杈状。

## 四、⚠⚠ `verify_viewport_bar` 一直是"全 PASS 却判 FAIL"

`tools/verify_viewport_bar.py` 收官只打 `ALL PASS`，而 `run_regression.py` 的 `OK_RE` 只认

改法：`check()` 里显式 `global total; total += 1`，尾部打
`结果: PASS` / `结果: FAIL: ...`（与 `verify_frustum_cull.py` 同一写法）。改完重跑 **PASS**。
⚠ 这是"脚本结尾必须是 `结果: PASS`"这条纪律的**第 4 次**踩坑，而且是**别人写的脚本**里
潜伏的 → 新写/接手脚本先 `grep -c "结果:"`，或直接照抄已通过脚本的结尾块。

## 八、"做完整游戏还缺什么"盘点（用户问，纯分析，未改代码）

结论：**瓶颈已从渲染挪到玩法闭环**（渲染/编辑器 ~95 分，闭环 ~20 分）。七条断链：
1. **动画运行时**（最硬）：`Skeleton`/`AnimationClip`/GPU 蒙皮（`pbr.vert` jointBase）/`sample()` 全在，
   但 `SkinnedMeshComponent` 只有 `clipName/time/speed/playing`，而 **`time` 只有
   `editor/CharacterWindow` 在推进** → Game.exe 里动作是**冻的**；即便推进也只是单 clip 循环
   （无状态机/混合/层遮罩/根运动/事件/IK）。
2. **游戏 UI/HUD = 0**（屏幕上的字全是 ImGui 编辑器层）；要 SDF 字体 + 图集 + 正交批 + 布局/焦点四件套。
3. **音频 ≈ 0**（`engine/` 无音频代码，`game.json` 的 `audioDevice` 是空挂字段）。
4. **存档/引用/Prefab 被 GUID 卡住**：`Entity.id` 是运行时序号 → G16 是 G17/G18/G19 的共同前置。
5. **世界规模 = 纸做的**：地形/水/植被/动态天空全无（R6-2~R6-4），无 lightmap/DDGI（R5-2/3），
   无材质实例化；`assets/` 只有 **3.8 MB / 1 个 sandbox 场景**，还没有真实美术资产流过管线。
6. **脚本玩法**：vks 内置绑定只有数学 + `print` + transform → 玩法只能写 C++ 重编译。
7. **出包/运维 = 0**：无 `.pak`、无 Shipping 剔除、无 minidump、无运行时控制台。

两条底座病灶（不在功能表上但卡规模）：**无线程/Job 系统**（`AssetManager` 同步加载、无引用计数/
淘汰/异步/热重载 → 现在不疼只因 3.8 MB）；**无 RenderGraph**（pass 顺序硬编码在 Renderer.cpp）。

推荐顺序：P0 GUID→动画→音频→HUD→存档（打通一局 20 分钟）→ P1 Prefab/流送/地形水植被天空/烘焙 →
P2 打包/剔除/崩溃/控制台 + Job。

## 编辑器中文化收尾（第二轮）—— 把"漏网"从 158 条做到 0

### 三条新方法论（都是"看着在干活、其实没干"的变种）

1. **白名单用子串匹配 = 假进度**。D 组第一版 `FMT_KEEP` 里放了 `"%s"` 和 `"GB"`，判定用
   `any(k in decoded)` → `"view mode   %s"`、`"selected: %s"`、`"VRAM %.1f GB"` 全被
   "已豁免"静默放过：命中数 **42 → 11**，看着像快修完了。改成**整串精确相等**后回到 42 ——
   那才是真实数字。**豁免条目必须精确匹配**。
2. **`emplace` 先到先得 → 重复词条是隐形的**。`zhMap()` 用 `out.emplace(en, zh)`，同一个 en
   出现两次时**后者永远读不到**。查出来 15 处**译文冲突** + 27 处同文重复 —— 冲突那批全是
   上一轮精修过的新词（`Stats HUD`=统计浮层 / `Overlay panels`=浮层面板 / `Locked`=锁定…），
   写了却从来没生效过。**改词条前先查重**，C 组现在会报。
3. **控件显示格式串是第三类盲区**。`SliderFloat(TRL("Yaw"), &y, -180, 180, "%.1f deg")`
   —— 格式串是**最后一个参数**，B 组只扫 label、D 组只扫 snprintf，两边都看不见，
   屏幕上却明明白白写着 `35.5 deg`。E 组专门兜它（顺带 `UNIT_FMT` 正则兜 `%.3f m` 这种
   单字母单位 —— `needs_translation` 要求"剥掉占位符后 ≥2 个字母"，`m`/`s` 会被判成"没英文"）。

### 本轮踩到的其它坑

- ⚠⚠ **`Solid` 一词两义**：视口工具栏是"背景纯色"（对天空/环境），碰撞体面板是"实心"

   现象是"光标在按钮上却点不中"。
3. **焦点导航自测必须用"数组顺序故意打乱"的布局**（左右两列）。垂直单列里
   "几何最近"和"数组下一个"恰好一致，是最容易假绿的地方。
4. **`PostMessage` 的方向键必须带 `KF_EXTENDED`（lParam bit24）**。不带 → GLFW 把
   扫描码 `0x50` 翻成**小键盘 2** → 焦点一动不动，而日志里**没有任何痕迹**。
   同理 `verify_add_menu` 的扫��码表里没有 W，得自己带一张。

### 两条验收方法论（值得复用）

- **"暂停时按 W 不动"要同时断言两件事**：位置**逐位不变**（`GAME-PLAYER-POS` 一条不新增）
  **且** `UI2-FOCUS` **变了**（证明 W 到了菜单、不是被整条吞掉）。只断言前者，一个
  "把所有输入都屏蔽掉"的错误实现也能通过。
- **像素否定测试必须带对照区**：两次启动的窗口偏 1~2 px，中心区差异就冲到 100%，
  断言照样"通过"但只证明"两张图不一样"。判据改成"对照区 < 2% **且**中心区 ≥ 10× 对照"
  （实测 2.219% vs 0.000%）。

### 其它踩到的小坑

- **`frame` 是渲染帧号**（`time().frameCount()`），脚本却按**定步**求值 —— 一帧两个定步时
  `frame == 60` 会执行两次（实测 `damage(30)` 扣成 40、弹两个数字）。夹具因此用
  "`damage` 走一遍真实接口 + `setHealth` 绝对值钉死"的幂等写法。
- **GLFW 从 `CURSOR_DISABLED` 切回 `NORMAL` 会把光标还原到中心附近** → 正好压在暂停菜单
  某个按钮上 → `hoverAt` 抢走焦点。这是**正确行为**（悬停项就该是焦点），所以脚本的
  断言改成"在按钮环上"而不是钉死 `resume`。
- **`logFocusIfChanged()` 是私有的、由内部调用** → 打开菜单时不调 `focusFirst()` 就一条
  `UI2-FOCUS` 都不打，脚本分不清"菜单没开"和"开了没焦点"。已在 `tickUi` 里补"打开即立第一项"。
- **自检的 `fmt()` 参数个数必须覆盖格式串**：漏传第 4 个参数打出 `h=-9.25e61`，
  断言本身是对的、detail 是垃圾 —— 这种最难发现。

- **24-bit WAV 是 3 字节打包**；`data` 长度可能是 `0xFFFFFFFF`；shared mode 必须用 `GetMixFormat`。
- ⚠ **`engine/ecs/**` 是横切**（`run_regression.py:335`）→ 加 `AudioSourceComponent` 那一步会让

### 主序被改（这是文档 §2 的核心）

原 `ship_roadmap` §8 是"地形→水→植被→天空→烘焙"，按**渲染难度**排。

### 关键设计决策（都写了"为什么不是别的"）

- **D1 实例 = 母材质浅拷贝 + parent 指针 + 覆盖位掩码**（12 位写死，位序发布后不能改，
  改位序必须升版本 + 写迁移）。不做"逐字段问母材质"：`pbr.frag` 拿的是 push 常量数值，
  值语义让推常量就是 `memcpy 48 字节`，零分支。**只支持两级**。
- **D2 覆盖只存被覆盖的字段**（`overrides:{...}`）。存全量 → 母材质改了以后所有实例都
  "值 ≠ 母材质" → 全被当成覆盖 → 改母材质不生效（与 `persistence_roadmap` D3 同一个道理）。
- **D3 身份 = `模型路径#glTF材质名`**，序列化写 id、读时按 id 找、找不到按旧 key 回落。
- **D4 同名冲突 → 新建 + 唯一后缀 + `ASSET-MAT-COLLIDE` WARN**；参数逐字段相同时才真共享。
- **D5 地形 = 独立管线 + splat 权重打包成一张 RGBA8**（7 个纹理槽已满，height 用掉最后一位）。
- **D6 植被 = 独立顶点布局**（`Vertex` 64 B 无顶点色/UV2，改它是横切 + 带宽 +25%）。
- **D7 动态天空 = 重烘 LUT + 重烘 IBL，`sky.frag` 一个字不改**（它 27 行只是采样 skyCube；
  天空内容全在 `Environment` 的 compute 里）。**BRDF LUT 不重烘**（与太阳无关）。
- **D8 "室内不崩"的便宜解 = 探针当辐照度源**（`ReflectionProbe` 的 cube array 已在 binding 23），
  成本是 W9 的 1/10，排在 W9 之前。顺手做掉 R5-1 的 `blendDistance` 欠账（要同一个权重函数）。
