## 第五轮：Stats 的 CPU 分段 + 进程内存（B2 / C9）✅

**先纠一条审计错**：B2 说"Stats 只有 7 行、没有 draw call / 三角形数"是照旧行号
读的，**一半已过时** —— E15 那轮早把面板扩成 CPU/GPU 双栏，draw call / 三角形 /
BVH / LOD / CSM / 局部阴影 / shader 变体 / 环境贴图全在。真缺的只剩两样：
**各段 CPU 时间**（GPU 有 11 段时戳 + 堆叠条，CPU 只有一个 `io.Framerate`）和
**内存**。→ `engine/core/CpuProfiler.{h,cpp}`（12 段）+ `core/ProcStats.{h,cpp}`。

### ⚠⚠ 最值钱的一条：`kLogic` 不能包住运行时的 `onUpdate`

编辑器的 `onUpdate` 是纯逻辑；**运行时的 `onUpdate` 是整个 `GameLoop::tick`**
（固定步 + 变量步 + **渲染**）。在 `Application::run` 里对 `onUpdate` 整体打
一个 `kLogic`，render 就被算进 logic：

```
frame=30.59  logic=18.84  render=1.88   ← 错（logic 含 render，两段相加 > frame）
frame=30.59  logic=0.15   render=2.11   ← 对
```

**可怕之处：每个单独的数字看起来都合理**，只有五段加起来才发现重复计数、
堆叠条冲出 100%。所以判据里必须有一条 `顶层五段之和 <= frame` ——
这条比任何单个阈值都值钱。修法：`Application` 只在 `!ownsFrameRendering()`
时套 `kLogic`；运行时由 `GameLoop` 的 `cb.fixedUpdate` / `cb.variableUpdate`
自己打。

### 其余设计点

- **`beginFrame()` 推进的是上一帧**（推进历史环再清零）→ **不需要配对调
  `endFrame()`**，某帧 `continue`/`break` 不会污染历史。代价：日志里读到的
  `frame` 永远是上一帧的完整值（正是我们要的）。
- **`beginFrame()` 必须在 `pollEvents` 之前**：放之后的话"等 vsync 醒来"会被
  记进 `events`，而那恰恰是"CPU 空闲"最该被单独看见的一段。
- **累加而不是赋值**：同一个 Scope 允许多处打点（`ui` 在 `ImGui::beginFrame`
  与 `onImGui` 各一次；`logic` 在固定步与变量步各一次）→ 少一处合并逻辑。
- **不用 `high_resolution_clock`**（可能是 `system_clock`，会被对时往回拨 →
  负毫秒）。`steady_clock` + 析构里 `d > 0` 兜底（负值会让 max 永远对、avg
  被悄悄拉低）。
- `PROCESS_MEMORY_COUNTERS_EX` 的 `cb` 必须 `sizeof(EX)`，给基础版大小会被
  按基础版截断、`PrivateUsage` 恒 0。CMake 补 `psapi`。

## 第六轮：配表（C1）+ 本地化编辑（C2）✅

`assets/data/*.csv` 成了角色/技能/数值的真权威（`core/Csv` + `project/DataTable`

（`i18n/LocaleFile` + Localization 面板）。自检 18 + 18 条，判据四组。

### ⚠⚠ 两条最贵的纪律

- **本地化只写"覆盖行"，绝不把内置译文复制进 CSV**：否则静态表以后再改
  永远被旧 CSV 掩盖。与 `saveGameFile` 的"合并而非重写"是一体两面 ——
  那边防丢别人的键，这边防固化出厂值。
- **配表的"其它行原样保留"**：整表重写会丢注释列（`#note`）与引号，
  而丢东西**不报错**。C 组专门断言 `Big Boss` / `starter` 都还在。

### 设计判断

- **CSV 而不是 JSON**：策划能用 Excel 打开 / 不懂代码的人不会因少一个逗号
  整份失败 / diff 一行一行看得见。
- **没有类型行**：类型由访问函数（`num`/`str`/`flag`）决定。多一行就多一处
  要同步，而且"类型说 int、值是 abc"到底信谁说不清。写错 = 默认值 + 警告，
  不阻断整场景加载。
- **按列名取，不按下标**：下标会随插入一列全体错位，而错位后的值全都
  "看起来是个合法数字"。
- **空单元格 ≠ 缺省值**：`str()` 只在**越界**时给默认值；留空是策划表达
  "没有"的唯一手段。
- **撤销覆盖必须"清空重放"**：`addTranslation` 是后写覆盖，撤销没法用
  "再写一次旧值"表达（旧值就是内置值）。代价是别的模块若也调它会一起被清 ——
  目前全仓只有这里调。

- ⚠⚠ **新资产目录必须进 CMake 复制清单**（老坑第 N 次）：`assets/data` 与

  解析器坏了。已加 `VennDataCopy` / `VennI18nCopy`（`copy_directory` + `ALL`，
  与 scenes/scripts 同档）。
- ⚠⚠ **Windows 环境变量是 ANSI 代码页**：`MYVK_EDITOR_CONSOLE_CMD` 里的中文

  看起来像"文件不存在"（一次把两条判据一起染红）。**这是自动化钩子的限制，

## 第七轮：旗标表（A4）+ 脚本断点（C8）

### ⚠⚠ 最值钱的一条：编辑器 Play 根本没接 `svc.act.setFlag`

`grep -on "svc.act.*" editor/EditorApp.cpp` 只有 `axis/held/joints/player/
pressed/released` → Play 里 `setFlag("x",1)` 报的是
**`setFlag() is not available in this host`**，**不崩不中断**，剧本分支静默全走
else。表现成"剧本写错了"。A4 的核心是补这个洞，面板只是第二半。

→ 验收 C 组的判据是**反向**的：那句话**不许出现**。正向断言（"读到了值"）在
别的路径写进去时也会绿。

### ⚠ `GameFlags` 从 `runtime/` 搬到 `engine/scene/`（分层铁律）

`editor/` 不许 include `runtime/`（`runtime → engine ← editor`），而编辑器 Play
也是宿主。不搬则"编辑器里能调剧本分支"在**类型层面**就不可能。
`runtime/GameFlags.h` 降级成一行 `using GameFlags = scene::GameFlags;`（旧调用点零改动）。

### 语义（踩过才知道）

- **每个键记 `writer`**（`script:<path>` / `ui` / `editor` / `console` / `host`）：
  "这个值是谁写的"**只能**在写入那一刻知道，事后推断不出来；writer 不存档。
- **"类型"是看出来的**（`0/1→bool`、整数→`int`、其余→`real`），表里没有类型位
  （同 `project::DataTable` 无类型行）。只用于显示。
- **快照 = 整表替换** → 快照后新增的键必须消失（"回到某章开头"的语义）。
- **进 Play 清空 / Stop 保留**：Stop 就清 = 销毁证物；Play 不清 = 上一局见过的人
  带进下一局且**不报错**。
- `getFlag` 未设过 = 0 是正确语义 → 面板/命令必须同时报 `set=0/1`。

### 断点（C8）

- 断点按 **(路径, 行号)** 存，不按 `ScriptProgram*`（热重载重建、地址可能复用）。
- ⚠ 行号必须命中 `executableLines()` 里的一条真语句，否则**拒收**并报原因
  （`SCR-BP-ADD-FAIL ... has no statement`）。在注释行点断点永远不命中，
  "点了没反应"是最难自证的失败。
- ⚠⚠ **检查必须在"执行之前、ip 未动之前"**（否则 `x+1` 变 +2）。
- ⚠⚠ `drive()` 里三个判断必须是 **if / else-if 链**：两段独立 `if` 会让"继续"的
  放行标记被消费掉、紧接着又命中原行 → **"点继续原地不动"，不报错**。
- ⚠⚠ **暂停时不能置 `inst.started = true`**：断点落在 `on start` 里时，置位后
  恢复会整段跳过 `case 1` → "start 剩几行再也不跑"，一条错都不报。
- `Step::Paused` 与 `Step::Suspend`（wait）**分开报**；`SCR-PAUSE` 按 `wasPaused`
  去重（否则每帧刷一条，而它是自动化唯一能读到行号的地方）。
- 放行只能走自由函数 `resumeCoroutine()` / `stepCoroutine()`（协程布局只在
  `ScriptEngine.cpp` 完整）。

  8 个锚点全无，看着像"面板坏了"。G 组只能**编辑态点击 → 点 Play → 看停住**。

### 结论一句话

### 评估方法：不按游戏类型分，按 12 个能力面分
A1 空间移动 / A2 交互拾取 / A3 数据驱动 / A4 状态属性 / A5 结算事件 / A6 时间控制 /
A7 确定性 / A8 表现编排 / A9 反馈层 / A10 界面 / A11 存档流程 / A12 内容管线。
→ 好处：以后加自走棋/塔防/肉鸽不用重新评估，看落在哪几个面。

**矩阵**：大世界基本全绿；回合制 RPG 与卡牌的红色集中在 **A4/A5/A7/A9/A10** 五格。

### 五个硬缺口
- **G1** 玩法状态层（属性/修饰符/状态效果/伤害明细）—— 旗标是 double，做不了护甲/易伤
- **G2** 确定性随机（0 命中，只有粒子 `forceRandomize`）—— 抽牌顺序不可复现，回放/联机做不了
  - ⚠⚠ **特效随机必须与玩法随机分两条流**：共用一条的话"多一个粒子就改变下一张抽牌"
- **G3** 动画事件无消费者（见上）
- **G4** 脚本无特效动词（`svc.act.*` 只有 `playAnim`/`spawn`，没 shake/playSound/hitstop）

- **G5** 配表进不了运行时（`TableStore` 只在编辑器控制台命令里，`engine/script/` 0 命中）

### 特效方案要点（写给自己）
- **三种特效驱动源完全不同**：状态型（存在即播）/ 事件型（瞬间事件）/ 环境型（区域长驻）。
  混在一起设计 → 必然退化成"每次手写脚本"。
- 四层：EffectAsset(.veffect) → 三条入口(AnimEvent/SeqEvent/脚本) → **EffectService 池化** → 五执行者
- ⚠⚠ **hitstop 计时器必须用真实时间**（`-= realDt`）。用 scaled dt → timeScale 压 0.05 时
  停顿长达 1.6 秒；`timeScale=0` 则是**死锁**（永远不走，游戏卡死但渲染正常）。必做否定测试。
- ⚠ 顿帧要**重置**不是**累加**（`max(剩余, 新值)`），否则 5 连击累成 0.5 秒
- ⚠ 抢占规则必须确定：同 priority 时**先来的存活**，否则同帧多特效每次画面不同 → 截图判据 flaky
- 拖尾：环形缓冲 16 帧刀尖世界坐标 + CPU 三角带；⚠ 锚**刀尖骨骼**不是根骨（挂根骨转身残影会甩出去）
- 闪白：**不要新开 pass**，走 `PostVolume` 加 `flashStrength` + 临时压一个全屏高 priority volume
- 伤害数字：`PickingSystem::worldToScreen` + **独立一层**（混进 `UiDocument` 会被父节点裁掉）
- 环境特效跟 `LevelStreamer` 绑：⚠ 卸载必须**先 stop 再销毁**

### 路线
P1 打击链闭环（EffectAsset/EffectService/事件路由/6 动词/hitstop+闪白）→
P2 玩法状态层（AttributeSet/DamageSpec/Random/TurnQueue）→
P3 卡牌专供（配表进运行时/ui2 拖拽+变换+滚动/牌堆数据/伤害数字层）

  ⚠ 与 **E12** 是同一条教训（那里已经写过一次："跟采样相位无关的写法才是位移"）——
  写物理判据一律用**跨度 / 极值**，不用"末态值"。
  → **flaky 名单新增 `joints E15`**。
- ⚠ 顺手补了两条漏登记的 TRIGGERS：`assets/shaders/sky.frag` +

### 这一轮确立的语义（写进 `docs/cards.md`）
- ⚠⚠ **牌的身份是 `uid` 不是下标**。手牌一重排（拖拽/按费用排序）下标全变；
  存档存"第 3 张"→ 读档之后第 3 张是另一张。判据 M1/M24（不复用）/
  M14（读档重算 `nextUid`，否则新牌与老牌撞号 → "打出这张、那张消失了"）。
- ⚠⚠ **必须有第五个区 `Limbo`（结算区）**。打出的牌**不能**立刻进弃牌堆：
  否则"弃牌越多伤害越高"这类效果在结算里会读到**它自己** → 每张多算一次，
  而且只在弃牌数跨过倍数时跳变。`Limbo` 非空 = 一张牌正在结算。
  判据 B/D 直接断言 `play` 后 `discard=0`、`resolve` 后才 `discard=1`。
- ⚠⚠ **`move()` 的 `pos` 是目标位置，不需要 -1 补偿**。契约：
  `move(uid,to,pos)` 之后 `uidAt(to,pos)==uid`。我第一版写了
  `insertAt = pos-1`（那是"插到原数组第 pos 个之前"的语义），
  在 `[1,2,3,4]` 上 `move(1,Hand,3)` 得到 `[2,3,1,4]` 而不是 `[2,3,4,1]` —— 差一位。
  而差一位在 UI 上像"拖动有点飘"，几乎不会被当成 bug 报。判据 M10。
- ⚠⚠ **手牌满就停止抽，剩下的留在牌库**（不烧牌）；**牌库空自动把弃牌洗回**
  且**必须计数**（`reshuffles()` + `lastDrawReshuffled()`）。不计数的话
  "洗回没发生"的唯一表现是"中盘之后抽牌效果全部哑火"，而 `draw()` 返回 0
  与"游戏在正常跑"长得一样。判据 M3/M5、E 组。
- ⚠⚠ **`clear()` 不清定义表**。读档顺序 `clear → setDefs → deserialize`；
  漏中间一步整副牌变未知卡，而未知卡**不报错**（只是打出来没效果）。判据 M18。
- ⚠ **`draw()` 自己不开随机流**，一律收 `Random&`（调用方传 `streams.gameplay`）。
  放成员会让牌堆存档把 rand 状态一起带走，也与"三流分离可追"矛盾。
