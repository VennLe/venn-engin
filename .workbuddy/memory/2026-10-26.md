1. ⚠⚠ **色带 u=0 被共享 REPEAT 采样器回绕**：`rampMap` 走 `textures[]`（那把采样器
   必须 REPEAT），`u=0` → 纹素坐标 -0.5 → 绕到 255.5 → 线性过滤取首末两档各一半
   = **整条色带的平均色**。缺省色带首末都近白 → 逐像素看不出来；只有"整片被钉到
   u=0"才暴露，而那时人会先怀疑 SDF。修法：夹到首末纹素中心（`0.5/textureSize()`）。
   **定案靠一张纯红→纯蓝探针色带**（混成 `(0.5,0,0.5)` vs 纯红，一眼可辨）。

**实现**（`tools/verify_hair_aniso.py` 5 组全 PASS）：

  `anisoTangent()` 在 `vTangent` 长度为 0 时回退 `cotangentFrame`（LOD 层
  被刻意丢掉切线，没有回退就静默退回各向同性）。
- 材质 `anisoStrength=0`（硬闸门）/`anisoShift` → 页表 `spare.z/w`；
  位掩码 `kOvAnisoStrength=1<<22 / kOvAnisoShift=1<<23`，**`kOvScalarMask` 扩到
  `(1<<24)-1`**（A1 自检 `0xFFFFFF`，A2 表加两条 case）；序列化只在非 0 时写；
  Inspector「Toon/NPR」段 `INS-NPR-ANISO` / `INS-NPR-ANISO-SHIFT`。
- FeatureRegistry 加了 `{"hair", ...}` 条目，**params 为空**（A4 没有引擎级总开关，
  只有材质字段 —— 不为拍对照图去占 UBO 800 B 里不存在的空位）。

**六条踩坑**（已写进 `docs/anime_gap_review_2026-10-26.md` §A4 落地记录）：
1. ⚠⚠ **`shiftTangent` 不能"先投影再沿法线推"**：`anisoTangent()` 返回的 T 已在
   切平面（`dot(N,T)==0`），推的量恒为 0 → shift 是死参数，三档画面**逐像素相同**。
   正确写法 `normalize(T + N*shift)`。症状像"UI 没接线"，实为数学退化。
2. ⚠⚠ **判据不能拿"最亮 2%"当高光**：Toon 底色本来有明暗两档+硬交界，最亮 2%
   量到的是底色最亮处，与环无关 → 关/开差异被掩盖（sx 5.8 vs 5.3）。要用
   **diff 区域（on−off）**。
3. ⚠⚠ **取景错 = 判据全废**：侧光把环推到球右缘（质心 x=184，采样区宽 188），
   裁成 10×24 px。改光到 YZ 平面（x 分量为 0）→ `T·H=-H_y·cosθ` → 环正对相机、
   竖直贯穿。采样区也从视口中心 42% 改成**整个视口**（环宽约占球宽 1/3）。
4. ⚠⚠ **测形状要关 CSM+TAA**（`MYVK_SHADOW=0`/`MYVK_TAA=0`）：CSM 自遮挡边界会把
   diff 撑成 238×204（混进"中间横线+底部竖条纹"）；TAA 让"跑两次 0 px"退化成
   "TAA 收敛了"的同义词。
5. ⚠ **阈值按问题分开**：主环锐+副环宽淡是两层结构，副环 +30 铺满整个可见面。
   `diff>8` 量形状得 343×378（高/宽 1.10）；`diff>45` 只剩主环核心 **120×377
   （高/宽 3.14）**。所以"有没有"用 8、"什么形状"用 45（`RING_THR`）。
6. ⚠ **底色必须留余量**：albedo 0.45 + 太阳 0.72（受光面 sRGB≈155）。用 0.78×1.2
   时受光面 249，加高光只差 6 格 < 阈值 8 → "加了一整条环"变成 0 变化。

**核心那条语义（这是本轮唯一真正难的地方）**：区间必须是 **`[prev, new)`**。
- 闭区间 → 播放头**停在**事件上（dt=0 / 暂停）时每帧发一次；
- `(prev,new]` → `t=0` 永远发不出来（`0>0` 为假），而"开场音效"最常见；
- 半开 → 正好落在 `new` 上**不丢，只推到下一帧**（那一帧的 prev 就是它）。
⚠ 否定测试实测：改成 `(a,b]` → **11 条**断言立刻红（含 `ev_first_frame_t0` /
`ev_half_open_*` / `ev_t_at_duration_never_fires` / `ev_scene_seq`）。

**三个"看起来对但会错"的**：
1. ⚠⚠ **`t == duration` 永远不会发**（`wrapTime` 之后播放头到不了那里 + 半开排除右端）。
   面板上给了 `t >= clip duration: never fires` 的提示 —— 否则症状只是"加了事件但没响"。
2. ⚠⚠ **换 clip 时 `eventPrev` 必须归零**。真实来路是 `AnimController::switchClip`
   把 `time` 归零/按相位换算，而 `eventPrev` 还停在旧片段的位置 → `[0.5,1.0)` 被当成
   "这一帧跨过的区间" → 新片段 0.8 的事件立刻发一次。
   ⚠ **造这条否证必须同时改 clipName 与 time**：只改 clipName 的话 `time` 还是 0.5，
   `[0.5,0.5166)` 本来就不含 0.8 —— 第一版这么写，去掉修复照样全绿（假通过）。
   改成同时改之后，去掉修复 → `onSwitch=1` 立刻红。
3. ⚠ **日志里的 `t=` 必须是事件自身时间，不是播放头时间**。这是"序列不随帧率变"
   能逐条比对的原因；改成播放头时间，端到端 ① 会红，③ 也跟着失效。

**判据口径**：只比 **kind+t 的序列**，不比个数 —— 个数绑在"这段 clip 有多长"上，
而时长是资产烤出来的（换 FBX 就变）。一圈 3 条这种整数只用在自检夹具里。

**做了什么**：`engine/animation/RootMotion.{h,cpp}`（`resolveRootBone` 自动/按名选骨、

`Pose::composeLocalTRS`（导出，保证与 `poseToWorld` 逐字符一致）+ `AnimatorComponent` 的
`rootMotionBone`/`rootPrevWorld`/`rootBasePos`/`rootDelta` + `AnimatorSystem::applyRootMotion`
（接在表演层之后、`poseToJoints` 之前）+ Inspector 解除 `BeginDisabled` + 根骨输入框 +
序列化 + i18n 3 条。**不注册 `FeatureRegistry`**（动画特性、无 `MYVK_*`）。

**数值验收**：`MYVK_ANIM_TEST=1` → **`ANIM-TOTAL pass=181 fail=0`**（原 154 + 27 条 `rm_*`）；
`verify_anim_runtime.py` EXPECTED 补 27 行（155 项全出现）。
**端到端**：新建 `tools/verify_root_motion.py`，**5 组全 PASS**（只验接线，见下）。

**三个"必须自己发现"的坑（都有否定测试）**：

1. ⚠⚠ **剥离不能"减本帧增量"，要"钳回基准"。**
   第一版写的是 `pose.translation[root] -= delta`，看着天经地义。实际上每帧
   `samplePose` 是**重新采样**的，根骨已在"动画当前时刻的位置"（0.98 m），减掉本帧
   增量（0.016）只让它**滞后一帧**、并没有回原点 → 实体走 0.98 + 模型走 0.966 =
   **双倍位移**。修法：记下第一次提取时根骨的世界位置（`rootBasePos`），之后每帧
   把根**钳回那个点**。
   否证：把 base 改成跟着走 → `rm_in_place` 报 `p1=0.0167 p60=0.9666`（差 0.95 m）。
   ⚠ 这个 bug 最阴的是**每帧日志都对**，只有拿模型世界位置去比才看得见。
   ⚠ 为什么不钳到 `restLocal`：动画第 0 帧的根位置常跟绑定姿势不一样（美术绑完又调过
   骨盆高度），钳到 rest 会在 Play 第一帧**跳一下**。

2. ⚠⚠ **跨圈那一帧的增量必须丢。**
   走路循环接回首帧时根骨从"前方 1 m"瞬回原点，增量是 -1 m。不丢的话两圈跑完停在
   0.983（= 一圈的量），表现是"每走一步被拉回原地"。
   否证：去掉 `wrapped` 判断 → `rm_wrap_discard` 报 `x=0.983333`（应 ≈ 1.97）。

3. ⚠⚠ **glTF 与 FBX 给出的 `joints` 不在同一坐标系。**
   `parseSkeleton` 取的是**文件原始空间**（Y-up；Y-up→Z-up 的旋转藏在 `invMeshNode`
   里，两者相乘才约掉）；`FbxLoader` 用 `ufbx target_axes = right_handed_z_up` 在加载时
   就转成了 Z-up（`invMeshNode` 是单位阵）。渲染上完全看不出差别（`invMeshNode` 与
   `push.model` 抵消），但位移要写进 `TransformComponent`（引擎 Z-up）——
   不转的话 glTF 角色走路**朝天上飘**，俯视还完全不动。
   否证：`toEngine` 换成单位阵 → `rm_yup_to_zup` 报 `z=0.0, y=1.0`。
   **修法不是"在提取处写死一个旋转"**，而是给 `Skeleton` 加 `skeletonToEngine` 字段、
   由各 loader 自己填（glTF 填 `kYupToZup`，FBX 填恒等）。这条也是为什么
   `engine/assets/Skeleton.h` 值得被写进 B3 的知识点里。

**两条设计取舍**：

- **yaw 用 swing-twist，不用 `atan2(right.y, right.x)`**：世界矩阵的 X 轴在某些骨上
  会趋近垂直，`atan2` 在那一瞬间跳 ±π（"走着走着突然转身 180° 又转回来"）。
  `rm_twist_swing_is_zero` 钉住"绕 X 转 90°（纯 swing）的扭转角必须是 0"——
  否则角色每跳一下都会连带转朝向。另外四元数双覆盖要先取 `w>=0` 那一支。
- **`n`（真走了几个实体）不能用逐位比较**：原地动画的 `dist` 在 1e-6 量级抖动，
  于是 `n` 在 0/1 之间跳，日志出现 `n=1 dist=0.0000 yaw=0.00deg` 这种自相矛盾的行。
  加 0.1 mm / 0.01° 的物理阈值。⚠ 顺手把 yaw 的日志改成**角度两位小数**。

**端到端只验接线，不验位移（资产事实）**：
`anime_girl.fbx` 的 `Walk`/`Idle`/`Run`/`RigWalk` **四段全是原地动画**（实测
`ANIM-ROOTMOTION ... dist=` 恒 0.0000）。所以"角色真的走了 1 m"没法在真实资产上验，
只能靠数值夹具（匀速 1 m/s 的合成 clip）。5 组判据：
① 自动选骨 → `bone=hips`；① 原地动画（`n=0` 是预期的）；② 骨名填错 →
`ANIM-ROOTMOTION-BONE-MISS` + `bone=(none)`；③ `scene.save` 往返（`rootMotionBone`
保留、运行时字段不落盘）；④ Inspector 两个锚点在。
⚠ 因为"没日志"和"日志说 0"对排查是天壤之别，`ANIM-ROOTMOTION` 改成 **`cfg>0` 就打**
（哪怕 `n=0`）—— 第一版写成 `n>0` 才打，结果整条链"静默成功"。

**一个自己踩的实现 bug**：`m_rootBoneMissing = false` 原本写在遍历**之后**的汇总区，
而 `applyRootMotion` 在遍历**中**设 true → 每帧都被抹掉 → BONE-MISS 永远不打，
端到端 ② 直接红。挪到 tick 开头。
