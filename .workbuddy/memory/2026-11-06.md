## 第一／第三人称视角装配标准化（`character/ViewRig`）

用户原话：「第一人称和第三人称时的角色初始化模型及其动画和骨骼这块请按照它
的案例做标准化改造，尤其注意游戏中的角色动画的流畅性细节。」
随后补一句关键澄清：**"它的案例" = UE 源码里的那套**（`ACharacter` +
`USpringArmComponent` + `UCameraComponent` + `APlayerCameraManager`），
不是"照模板抄个大概"。

### 一份代码，两条宿主链

`EditorApp::runPlayers`（编辑器 Play）与 `runtime::PlayerController`
（Game.exe）以前各写一套"眼睛在哪、往哪走、镜头怎么摆"。现在收进
`engine/character/ViewRig.{h,cpp}`：身体度量 `fitBody` / 眼位
`resolveEye` / 视线基 `lookBasis` / 角度换算 `cameraAnglesFromLook` /
阻尼 `EyeDamp` / 过渡 `ViewTransition` / 可见性 `applyBodyVisibility`。

### UE 源码 → 本工程的对照表（判据，别再自己发明）

| UE | 这里 |
|---|---|
| `ACharacter::GetActorEyesViewPoint` → `GetMesh()->GetSocketLocation("head")` | 眼位 = **head 骨**的世界变换（走蒙皮公式 `jointMat·(invBind⁻¹·0)` 再乘 `push.model`），不是"脚 + 常数" |
| socket 的相对变换（美术在骨架里摆的那 4~5 cm） | `PlayerComponent::eyeOffset` / `GameStartComponent::eyeOffset`（**作者数据**，米、玩家局部轴） |
| `bUsePawnControlRotation` | 相机朝向永远来自输入；骨骼只借**位置** |
| `bOwnerNoSee` | 第一人称藏自己的网格（改 `VisibilityComponent`，不动 `MeshComponent`，所以影子里是当前帧姿势） |
| `bCastHiddenShadow` | `VisibilityComponent::castShadowHidden`，`Scene::forEachShadowCaster` 与 `forEachRenderable` 两套遍历器必须都认这一位 |
| `SetViewTargetWithBlend(..., BlendTime)` + `VTBlend_Cubic` | `ViewTransition`（`smoothstep` = `FMath::SmoothStep`；yaw 走最短角差） |

**唯一刻意的偏离**：平滑用 `1 - exp(-dt/tau)`，不用 `FInterpTo`
（后者是 `clamp(dt*speed,0,1)`，60 fps 与 144 fps 手感不同）。

### 2026-11-06 当天踩到/确认的四件事

1. **不要自动找 eye 骨**。我一度加了"头骨之下若有 `eye_L/eye_R` 就取重心"
   的启发式（alicia：Head 1.3468 / eye_L,R 1.3932，差 4.6 cm），用户澄清
   后**已回退** —— UE 的答案是 socket，偏移必须由作者给。补的正解是把
   `eyeOffset` 暴露成可编辑项（Inspector ▸ GameStart ▸ `Eye offset`，
   `INS-GAMESTART-EYEOFFSET` 锚点），并写进 `GameStartComponent` 与场景
   JSON（**只写非默认值**）。
2. **`EDIT-VIEW switched` 不是没打，是探针把它过滤掉了**。`tools/_probe_view.py`
   的 `dump()` 是**大小写敏感**子串匹配，传 `"view"` 抓不到 `"EDIT-VIEW ..."`。
   改成 `"VIEW"` 之后一切正常。教训：日志"没出现"先怀疑抓取，再怀疑代码。
3. **进 Play 的跨帧视角状态会串台**。`m_playEyeDamp` / `m_playViewBlend` /
   `m_playArmLen` 是跨帧状态，上一轮 Play 留下的值让新镜头从旧位置滑过来。
   判据用 `playTime` **倒流**（`playNow < m_lastPlayTime`），不能用实体 id
   —— EntityId 会被回收重用，新一轮大概率拿同一个 id。
4. **`fitBody().eyeHeight = 0.92 h` 是按"bounds 高度 = 人的身高"假设的**。
   alicia 的 bounds 1.652 里含头发，真实头骨顶 `HeadEnd` 只有 1.4188 ——
   所以 0.92h = 1.519 其实**在头顶之上**。这条只在"没有骨架"时兜底用，
   暂不动（改了会动第三人称构图与截图基线）。UE 的对应物是
   `APawn::BaseEyeHeight`（约 0.83 h）。
