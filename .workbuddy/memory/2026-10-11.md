## FBX 蒙皮/归位 bug 修复（#91 收尾）
- **根因 1**：`ufbx_matrix` 是 3x4（12 float），`memcpy` 到 glm::mat4 越界读 4 float → 垃圾平移（-6995550）。改为按列显式构造（FbxLoader toGlm）。
- **根因 2**：ufbx 的 `cluster->geometry_to_bone` 不带轴/单位换算（文件原始空间 cm/Y-up），而 `node_to_world` 已换算到引擎空间 —— 两者不可组合，蒙皮蜷成一团。
  **修复方案**：蒙皮顶点在加载时烘到"静止世界空间"（`v' = G2W·v`，法线乘线性部分），`invBind(j) = inv(W_rest(j))`，`invMeshNode = I` → 静止时 jointMat=I，多 submesh 共享骨架也严格正确。SubMesh::transform 蒙皮时取单位阵，归位段左乘 T(-center) 即 push.model。
- **restLocal 推导**：用 node_to_world（非 node_to_parent），root 的 node_to_parent 缺轴/单位调整；restLocal = inv(W_parent)·W_self。
- **动画采样**：`ufbx_evaluate_transform` 相对**直接父节点**；父非骨骼（Armature 对象）时需左乘父链静止世界变换 P 再 decompose。
- **资产端**：blender_make_girl.py 角色沿 +Y 站立（为 glTF 设计），FBX 声明 Z-up → 模型躺着。export_test_fbx.py 导出前把 armature 转 90°X（+Y→+Z），并去掉 bake_space_transform=True。
- **maxRestErr 诊断**：buildSkeleton 里算 W·invBind 与单位阵偏差，0.000000 = 静止姿势严格一致。
- **CharacterWindow**：左栏 220→280px（三标签放得下，不再溢出 ">>"）；CHAR-CLIP 日志 tag 去空格（CHAR-CLIP-<name>）。
- **验证脚本**：verify_character_window.py 补 report(fails) 调用（之前 FAIL 也返回 0）；新增 wait_valid_rect（过滤 (0,0) 未激活 tab）与 wait_clip_rect（解析 CHAR-CLIP-<name> 行）；注意 click() 收**客户区**坐标（之前传屏幕坐标导致二次换算点进视口）。动画播放链路：双击标签（首次点击只聚焦）→ 点 clip → "play clip" 日志 → 时间轴走动、姿势变化。

## 渲染三件套之二：BVH 空间加速结构
- 新增 `engine/scene/Bvh.h/.cpp`：扁平节点数组（0 号根）+ 显式栈迭代遍历 +
  中位数切分（最长轴 + `nth_element`）+ `build()` 重建 / `refit()` 只拟合包围盒。
  **父节点下标恒小于子节点**是 `refit` 倒序遍历的前提。
- `query(volume, out)` 给渲染剔除用（剪枝 + **叶子逐元素复测**），
  `raycastFiltered` 给编辑器拾取用（`d[i]==0 → 1e-20f` 防 NaN；栈里带 tNode 做
  "比已知最近还远"的子树剪枝）。
- **叶子逐元素复测是必须的**：叶子的 AABB 是成员的**并集**，并集相交 ≠ 每个成员
  相交。少了这一步，BVH 查询结果就和暴力扫描对不上（会多给出实体）。
- `Scene::spatialIndex()` 每帧调一次：实体集合（含**顺序**）没变 → `refit`，
  变了 → `build`。实体序列顺序也比对，因为 ECS 存储重排会让"叶子 ↔ items 下标"
  对应失效。渲染剔除与编辑器射线拾取**共用同一棵**。
- 拾取 `PickingSystem::pick` 从 O(N)×8角点 变为 O(log N)（`raycastFiltered`
  + `LockedComponent` 过滤器）。
- **本轮最值钱的 bug**：`buildRange` 用 `nth_element` **重排了 items 工作数组**，
  但 `m_leafItemIndex.push_back(i)` 记的是重排后的位置；`refit` 拿它去索引调用方给的
  **原始顺序**数组，于是每个叶子被拟合到别的实体的包围盒上 → 第二帧起**大面积漏画**
  （首帧走 build 路径反而正常，所以肉眼一看是"跑一会就掉东西"）。
  修复：`buildRange` 只重排 `std::vector<uint32_t> order`，items 只读，叶子存
  `order[i]`（原始下标）。
- `MYVK_BVH_DBG=1` 自检：BVH 结果 vs "逐个实体 transformAabb + 直接测视锥"的暴力
  对照，打 `BVH-DBG brute= bvh= missing= extra=`；`missing > 0` 就是会漏画的硬错误。
  定位这个 bug 全靠它（`missing=4 extra=8` 一眼看出是下标错位）。
- `tools/verify_bvh.py`：树健康（79 节点 / depth 7）、剪枝（visits 37 < nodes）、
  与暴力完全一致（missing=0 extra=0）、与线性基线逐值相同（culled=132/drawnOpaque=4）、
  射线拾取点中 Cube_0 且 `PICK-DBG same=1`。

## 渲染三件套之三：LOD 系统
- 新增 `engine/assets/Lod.h/.cpp`：`LodLevel{mesh,vertices,triangles,switchRatio}` +
  `LodChain`（`selectLevel(ratio,bias,current)` 带迟滞）。
  **阈值的语义**：`switchRatio[i]` 是**进入第 i 级的阈值**（`ratio < 它` 就用第 i 级），
  各级区间是 `[switchRatio[i+1], switchRatio[i])`。默认 {1.0, 0.25, 0.10, 0.04}。
  迟滞系数 1.15：往下切要 `< 阈/1.15`，往回切要 `> 阈×1.15`。
- **`bias` 是"除"在比值上**：`r = ratio / bias`，所以 `bias > 1` → 比值变小 → 更快落到
  低模（与 Unreal/Unity 的 LOD Bias 同向：数字越大越省、画质越低）。
- 屏幕占高比 = `包围球半径 / (距离 × tan(fovY/2))`（**相对视口高度**，与宽高比无关）。
  半径取世界 AABB 的**半对角线**（保守上界，宁可估大）。
- 链生成（`AssetManager::ensureLod`，**惰性**：`Application::run` 每帧对当前场景的
  可见网格调一次，幂等）：
  * 程序化图元：重新生成，只把细分逐级减半（球 48×24 → 24×12 → 12×6 → 6×3）。
    立方体/平面（12/2 三角形）减不动 → 链停在 1 级 = 不做 LOD。
  * 导入网格（OBJ/glTF/FBX 的**静态**部分）：顶点聚类简化（vertex clustering）——
    包围盒切 N³，同格顶点合并（位置取**平均**而不是格心，取格心会让形状缩水）、
    法线归一化平均、同格三角形直接丢弃。**格分辨率不写死**，按"目标 = 上一级一半
    三角形"二分搜索 [2,256] 找最细的满足档（写死 32³ 对 2k 顶点的模型几乎压不动）。
  * **蒙皮网格不生成**：LOD 网格是独立 Mesh 对象，而渲染层把关节矩阵 SSBO 基址按
    `Mesh*` 记（`m_skinJointBase`），换网格就查不到 jointBase。要支持得先改成按实体记。
- 渲染：`buildDrawLists` 里选层，`DrawItem` 加 `lodLevel` / `baseTriangles`；
  全局开关 `m_lodEnabled` / `m_lodBias` / `m_forcedLodLevel`（+ env `MYVK_LOD`、
  `MYVK_LOD_BIAS`、`MYVK_LOD_FORCE`）。迟滞状态存 `unordered_map<entityId,uint8_t>`。
  统计：`lodEntities / lodLevelCounts[4] / trianglesNoLod`（"全用 LOD0 会提交多少"）。
- **首帧落位 bug**：`selectLevel` 在 `current < 0` 时写成了"返回第一个满足 `r <= 阈值`
  的层"，正确是"从高模往下退，停在第一个退不过去的级上"。相邻阈值同时满足时
  （r=0.08 同时 < 0.25 和 < 0.10）会停在**更细**的一级 → 每个物体首帧都高估一档，
  靠迟滞在第二帧才纠回来（启动时 4 个物体 8 次切换就是它的指纹），而且
  `bias` 完全失效（因为迟滞路径只用当前级的阈值）。修复后启动切换数 3。
- 编辑器：Render 面板加 "LOD" 复选框 + Bias 拖条 + Auto/Force L0..L3 下拉；
  Stats 面板加 "LOD: N ents  L0../L1../L2../L3，tris 对比 noLod 与省下的百分比"。
- `tools/verify_lod.py`：4 个距离（3/12/30/80）摆同一颗高模球 → 恰好落 4 级；
  断言链生成、选层分布 1/1/1/1、三角形 3060 vs 9216（省 67%）、静止不抖、
  `MYVK_LOD=0` 退回全高模且截图 diff 0.034、`MYVK_LOD_FORCE=2` 全 L2、
  `MYVK_LOD_BIAS=2` 分布变 1/0/1/2 更省、立方体不生成链、
  **导入网格（自写 64×32 UV 球 OBJ，3968 三角形）简化出 3968/1840/920/384**、
  **anime_girl.glb 蒙皮链停在 1 级**。

## 一个真实功能缺陷：视口 hover 门控被 ImGui 键盘导航永久压制
- 症状：`tools/verify_player.py` 的鼠标视角断言长期全 0。
- 根因链：编辑器开了 `ImGuiConfigFlags_NavEnableKeyboard`。用户一按键盘，ImGui 进入
  nav 高亮态，`ImGuiItemFlags::ItemHoverable()` 里
  `if (g.NavHighlightItemUnderNav && ...) return false;` 让 `IsItemHovered()` 变为
  **永久** false（`NavHighlightItemUnderNav` 只在 `io.MouseDelta != 0` 时清除）。
  → 运行态按过 Space/WASD 之后，鼠标视角直接失效。这是**用户能碰到**的 bug。
- 修复：`EditorContext` 不再上报布尔 `viewportHovered`，改为上报视口**矩形**
  （`setViewportRect`），由 `mouseInViewport(io.MousePos)` 判定。
- 另：注入侧也要改 —— `SetCursorPos` 只在窗口外→窗口内那一次会产生 ImGui 看得到的
  MousePos；窗口内移动不保证。`verify_player.mouse_set_client` = `PostMessage(WM_MOUSEMOVE)`
  **+** `SetCursorPos`（后者是为了把**真实**光标留在窗口内，否则 Windows 会不停补发
  `WM_MOUSELEAVE` → `MousePos = -FLT_MAX` 抖动）。`verify_bvh.py` 的点击也改用这套。
