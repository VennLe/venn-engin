# 2026-10-09 —— 运行时架构调整：Play 改为弹出独立游戏窗口

## 用户需求
> "整个项目只需要构建和运行的功能，构建成功后运行成功后直接就只是打开引擎编辑器界面，
>  当点击工具条中的运行时，才会启动运行游戏画面窗口"

澄清后的三条决定：
1. `make run` 只打开编辑器；Sandbox.exe 保留为独立示例（不再是主入口）
2. 点 Play **弹出一个独立的游戏窗口**，不是编辑器内嵌视口
3. Play 期间编辑器视口**保持编辑画面**（脚本只在游戏窗口那个进程里跑）

## 结论：Play = 另起一个进程，而不是同进程开第二个窗口
`render::Renderer` 与 `ui::ImGuiManager` 都绑死在唯一一个 GLFW 窗口 + 唯一一条
`VkSwapchainKHR` 上（一个 ImGui context 也只能绑一个窗口）。同进程开第二个真窗口 =
把 Renderer 拆成可多实例 —— 伤筋动骨。而"游戏窗口"只需要一个干净主循环，所以：
编辑器以 `Editor.exe --play <场景快照>` **把自己再启动一次**，新进程跑 `PlayerApp`。
好处：天然独立窗口 / 独立 VkDevice / 崩了砸不到编辑器 / 编辑器既有代码零改动。

## 改动清单
### 新增
- `editor/GameProcess.{h,cpp}` —— 跨进程启动器。`CreateProcessA`（POSIX 走 fork+execv 兜底）。
  - 场景快照 → 系统临时目录 `<temp>/myvk_engine_play/play_scene.json`
  - 暂停标志 → **场景文件旁边**的 `pause.flag`（`pauseFlagFor(sceneFile)` 是两边唯一约定；
    放临时目录会隐含依赖 %TEMP% 在父子进程一致，挂在场景文件旁则是结构性一致的）
  - `bInheritHandles=TRUE` —— **必须**，否则子进程继承不到 stdout，游戏窗口的日志全丢
  - `currentExecutablePath()` 用 GetModuleFileNameA（不够就翻倍的循环）
- `editor/PlayerApp.{h,cpp}` —— 独立游戏窗口的 `core::Application` 子类。
  加载快照 → 预编译脚本 → 每帧跑脚本（time/timeScale/dt 语义对齐原来的 runRuntimeScripts）
  → 极简 NoInputs HUD。**`ImGui::GetIO().IniFilename = nullptr`**：否则它会把
  `build/bin/imgui.ini` 覆盖成空档，编辑器辛苦排好的面板布局全没。
- `assets/scenes/editor_scene.json` —— 从编辑器默认场景导出，让 `make play` 开箱可用。
- `tools/capture_window.py` 增加 `--args`（透传命令行参数）—— 用来抓游戏窗口。

### 改造
- `editor/main.cpp` —— 解析 `--play <scene>` 分派 PlayerApp/EditorApp。
  **帧数变量拆成两个**：编辑器读 `MYVK_FRAMES`，游戏窗口读 `MYVK_PLAY_FRAMES`。
  因为 CreateProcess 会继承环境块，共用一个名字会让 `make run FRAMES=300`
  顺带把弹出的游戏窗口也限成 300 帧。
- `EditorContext` —— `m_runtimeScene` **删除**；`activeScene()` 永远返回编辑态。
  `play()` 变成"导出快照 + 启动进程"，`pause()` 写标志文件，`stop()` terminate。
  新增 `tickGameProcess()`：每帧探活，用户直接关掉游戏窗口 → 自动回到 Stopped
  （否则编辑器会一直卡在 PLAYING，界面全只读，看着像死了）。
- `EditorApp` —— 删掉 `runRuntimeScripts`/`m_runtimeFrames`/`m_printLog`；
  改成 `preloadScripts()`（只编译不执行，供 Scripts 面板报错 + 驱动热重载）。
  Stats/Scripts 面板、Toolbar、ViewportPanel HUD、InspectorPanel、SceneHierarchy、
  GizmoController 的文案全部改口（不再有"runtime scene/copy"的说法）。
- `Makefile` —— `run` → 编辑器；新增 `run-sandbox` / `play`（`PLAY_FRAMES`/`PLAY_SCENE`）；
  `smoke` 三趟（Sandbox / Editor 自动 Play + 子进程 / 直接 --play）。
- `.gitignore` —— 忽略根目录 `/*.png`（截图工具默认输出落在仓库根）。

## 验证（全部通过，验证层 0 报错）
1. 构建干净无警告（先修了 `NOMINMAX` 重定义 —— MinGW 的 os_defines.h 已定义）
2. 编辑器独立运行 120 帧：`precompiled 3 script(s), 0 with errors`，EXIT=0
3. **完整链路**：编辑器 auto-Play → 导出 43 实体 → 子进程独立建 device/swapchain →
   加载 43 实体 / 编译 3 脚本 / `3 executed, 0 failed` → 子进程自己退出 →
   编辑器 `GameProcess: game window closed (exit code 0)` + 自动回 Stopped
4. 暂停标志：事先放 `pause.flag` → 子进程打 `Player: PAUSED by editor` 且不执行脚本
5. 截图确认：编辑器工具栏显示 `EDITING | 44 entities | game window closed`；
   游戏窗口全屏 3D + HUD `PLAY 703.1 FPS / 44 entities / 24 local lights`
6. Sandbox 仍然正常

## 踩到的坑 / 注意
- **CreateProcess 的环境块是继承的** → 父子共用 `MYVK_FRAMES` 会互相串味，必须换名
- **bInheritHandles 不留神给 FALSE，子进程就没有 stdout**（日志全消失，很难查）
- 冒烟测试要让编辑器**跑得比子进程久**（子进程建 Vulkan device 就要 ~1s，
  而编辑器关掉 vsync 后 400 帧只要 1s）——否则编辑器的 GameProcess 析构会把
  刚起来的子进程 terminate 在初始化途中
- Play 期间编辑器**只读**（gizmo/Inspector/层级增删都被 `isPlaying()` 挡住）。
  这是保底选择：那边跑的是导出那一刻的快照，改了也同步不过去。
  想做"边跑边编辑"要另开一轮设计。

## 待办 / 可选后续
- 游戏窗口 FPS 不设上限（703 FPS）—— 引擎层面本来就这样（present mode），未处理
- 想让编辑器在 Play 期间也能编辑 → 需要重新定义"编辑态改动如何进入运行中的游戏"
- 游戏窗口目前不支持把坐标/状态回传编辑器（单向快照）

## 用户需求（原文）
> "做几点修改：1.在运行游戏时，不用启动新的窗口去显示，就在原来的视口中去显示就好了，但在运行游戏时，
>  显示一个可全屏显示也可恢复原视图的按钮，或者可通过快捷键f来切换全屏和恢复原视图，
>  2.在游戏视图中，游戏视角的操作请借鉴ue中的方式，即通过wsad来去操控相机视角的方向，qd来控制上和下，
>  通过按住鼠标的左键来控制视角的灵活旋转，通过按住鼠标的右键可以控制视角的平视旋转。
>  3.在视角的右上角可以显示当前控制视角移动和旋转的灵敏度数字，默认是1，可以自己填一个浮点数（大于0）
>  来控制这个数字的大小，也可以通过鼠标的滑轮的上下滑动，上滑数字慢慢变大，下滑慢慢变小。"

**这把上午的跨进程设计整体推翻了。** 上午的理由（Renderer/ImGuiManager 绑死唯一窗口+交换链）
依然成立，但它只证明了"开第二个真窗口很麻烦"，**没证明"必须开第二个窗口"**：
视口本来就已经是一条离屏渲染链，只要让 `activeScene()` 在 Play 时返回 runtime 副本，
3D 就直接画进视口了 —— 零渲染器改动。全屏只是"把视口矩形撑满整窗 + 不画其它面板"。

## 改动清单
### 回退 / 删除
- **删除** `editor/GameProcess.{h,cpp}`、`editor/PlayerApp.{h,cpp}`（跨进程启动器 + 独立游戏窗口 App）
- `editor/main.cpp` 重写为**纯编辑器入口**：去掉 `--play` 解析、去掉两个头文件 include
- `Makefile`：去掉 `play` 目标 / `PLAY_FRAMES` / `PLAY_ENV` / `RUN_PLAYER` / `PLAY_SCENE`；
  `.PHONY` 与 `info`/`help` 同步；`smoke` 改两趟（Sandbox，Editor 配 `MYVK_EDITOR_PLAY=1`）

### 新增：视口内运行 + 全屏
- `EditorContext`：恢复 `m_runtimeScene`；`activeScene()` 变成
  `usingRuntime() ? m_runtimeScene : m_editorScene`（唯一分派点）。
  `play()` = `sceneToJson(编辑态)` → `sceneFromJson(运行时副本)`（**内存拷贝**）→ 副本相机
  `setUseGlobalInput(false)` + `setFlyMode(true)`。`pause()` 只翻状态，
  `stop()` 丢弃副本 + 复位全屏 + `validateSelection()`。
- 新增状态：`m_gameFullscreen` / `toggleGameFullscreen()` / `m_gameSensitivity`（默认 **1.0**，
  clamp **0.05..20**）/ `addGameSensitivity(delta)` / 常量 `kMinSensitivity`/`kMaxSensitivity`。
- `EditorApp`：`onUpdate` 在 Play 态 `advancePlayTime(dt)` + `runRuntimeScripts(dt)`（作用于 runtime scene）；
  新增 `drawFullscreenGame()` —— Play+全屏时把 `L.viewport` 设为整窗、只开 viewport 面板、其余全不画，
  由 `onImGui()` 开头 `if (drawFullscreenGame()) return;` 短路。快捷键：Play 态 **F** 切全屏 /
  **Esc** 退全屏；Play 态下 F 不再抢"聚焦选中"。Stats/Scripts 面板文案同步。

### 新增：UE 式相机（`engine/scene/Camera.{h,cpp}`）
- 新增飞行模式 `m_fly` / `m_flyPos` 与 `setFlyMode` `flyMode` `look` `moveLocal`
  `forwardAxis` `rightAxis`（私有 `angleDir` / `syncFlyTarget`）。
- **关键：轨道 ⇄ 飞行互为逆变换**（`target = position - angleDir()*distance`），
  所以 `setFlyMode()` 切换**不跳变**，`viewMatrix()`/`target()` 语义完好（拾取/gizmo 不用改）。
- 数学：`forward = -angleDir()`，`angleDir()=(cos p cos y, sin p, cos p sin y)`
  → 鼠标 +dx → +yaw **右转**；+dy → +pitch 且 `forward.y=-sin p` 减小 → **下看**（非反转，符合 UE）。

### 新增：视口导航 + 灵敏度 HUD（`editor/ViewportPanel.{h,cpp}`）
- `handleGameNavigation(hovered)`（Play 态替代原来的 `handleNavigation`）：
  **按住左键** = `look(dx,dy)` 自由旋转；**按住右键** = `look(dx,0)` 平视旋转；
  **WSAD** 水平移动 / **QE** 上下 / **Shift** ×3 加速；**滚轮** = `addGameSensitivity(wheel*0.1)`
  （上滑变大、下滑变小）。常量 `kGameLookPerPixel=0.0025` / `kGameMoveSpeed=5` / `kSensitivityStep=0.1`。
- `drawGameHud(vpPos, vpSize)`：视口**右上角**的面板，含 `Fullscreen (F)`/`Restore view (F)` 按钮、
  PLAYING/PAUSED + `t=%.2fs`、可编辑的 `InputFloat("Sensitivity")`（≤0 忽略并 clamp）、操作提示。

## 踩到的坑
- **HUD 被 3D 图盖住**：第一版把 HUD 做成 `ImGui::End()` **之后**的独立顶层窗口，
  但 ImGui **每帧会把聚焦窗口（视口）提到最前** → HUD 被压在下面（截图里只剩半截被裁掉）。
  **修法：HUD 必须是视口的 child window**（`SetCursorScreenPos` + `BeginChild` + `EndChild`，
  在 `ImGui::End()` **之前**画），child 永远画在父之后 → 一定在最上层。
- 本版 ImGui 的 child 签名是 `BeginChild(str_id, size, ImGuiChildFlags, ImGuiWindowFlags)` ——
  第 3 个参数是 **child_flags 而不是 border 的 bool**，别照老代码写 `true`。

# 第二轮：Gizmo 拖拽修复 + 三套吸附（对齐 UE5）+ y=0 地平面栅格

用户原始诉求（两点）：
> 1. 鼠标拖拽移动物体时方向反了、速度过快；给平移/缩放/旋转都加吸附，比例参考 UE5
> 2. 在 (XY0) 平面上显示地平面栅格，最小单位 1 m，右上角单选框控制显隐，默认显示

## 1. 拖拽"方向反 + 越拖越快" —— 两个独立缺陷叠加
先写 `tools/_check_axis_math.py` 把公式跑一遍（**数值复现，比截图快得多**），确认：
- **① 符号错**（`PickingSystem::closestOnAxis`，Ericson 5.1.9）：
  `s = (b*e - c*d)/(a*c - b*b)`，原实现写成分母 `b*b - a*c` → 参数整体取反 → 往右拖往左跑。
  修法：分母保留 `b*b - a*c` 只用于判平行，参数写成等价的 `(c*d - b*e)/(b*b - a*c)`。
- **② 正反馈环**（`GizmoController::applyDrag`）：每帧用物体**当前**位置当轴线原点，
  物体自己走过的位移被重新算进参数 → `D_new = Δ + D_old` → **指数加速**。
  修法：`beginDrag` 冻结 `m_dragOrigin / m_dragAxis / m_dragWorldLen`，`applyDrag` 只认快照。
- 脚本模拟确认：只修 ① 仍会加速；只冻结 origin 方向仍反；**两处同修才稳定 1:1 且停手不动。**

## 2. 三套独立吸附（`EditorContext`）
删掉旧的 `snapEnabled/snapTranslate/snapRotateDeg/snapScale`，改成三套 `开关 + 步长 + Ref`：
| 模式 | 量化对象 | 默认步长（UE5 换算） |
|---|---|---|
| 平移 | 位移增量（米） | **0.1 m**（UE5 10 uu，本引擎 1u = 1m） |
| 旋转 | 角度增量（度） | **10°** |
| 缩放 | **倍率 factor**（不是绝对值） | **0.1** |
- 缩放量化倍率：量化绝对值会让第一下拖拽从 0.37 跳到 0.4，像抽搐。
- UI：视口工具栏**第二行** `drawSnapRow()`（勾选框 + DragFloat + Presets 弹窗 +
  `current: move snap off`）；**G 键**切换当前工具吸附；拖拽时浮层实时读数 `Move X: +0.600 m  [snap]`。

## 3. y=0 地平面栅格
- **解析式、零顶点缓冲**：VS 用 `gl_VertexIndex` 拼 4 顶点大四边形；FS 用
  `fract(p/step + 0.5) - 0.5` 求到最近格线距离 → 除 `fwidth(p)` 得**像素距离** → 1px 抗锯齿，
  不依赖 MSAA；远处 `smoothstep` 淡出防摩尔纹。最小格 1 m / 主格 10 m / X 轴红 Z 轴蓝。
- **必须放 3D pass**（不透明之后、透明之前）：ImGui 图层永远压 3D 之上，栅格会穿透墙。
  现在能被柱子/箱子/墙正确遮挡，玻璃能叠在它上面。
- **共面 z-fighting**：地板顶面正好 y = 0 → VS 里 `clip.z -= 1e-6 * clip.w`。
- 开关 `Renderer::gridEnabled()`，`EditorApp::onUpdate` 每帧写 `= isEditing() && showGrid()`（Play 强制关）。

## ④ Gizmo 三种粒度（最大的一块）
- 原来是"只支持单轴"的 `m_hotAxis` 模型，整文件重写成 7 种 `Handle`：
  `AxisX/Y/Z` + `PlaneYZ/XZ/XY`（**枚举名 = 该平面的法线**，法线 X 的方片是红色，
  和 UE/Blender 一致）+ `Screen`（中心手柄）。
- 平移/缩放：单轴 + 平面双轴 + 中心整体（视平面自由移动 / 等比缩放、平面取两腿平均）。
  旋转：三轴环 + 外圈 arcball 自由旋转。
- 平面命中用 `pointInQuad()`（四角叉积同号）；平面拖拽加 `kMaxDragUnits=2000` 兜底
  （射线几乎与平面平行时交点跑无穷远，位移会瞬间爆炸）。
- arcball：屏幕偏移 → 单位虚拟球（球外投到赤道），`angle = atan2(|p0×p1|, p0·p1)`，
  轴从相机系（right/up/-fwd）转到世界系。
- 本引擎的欧拉序是 **R = Rx·Ry·Rz**，`glm::eulerAngles` 用的是 YXZ，**不能直接用** →
  自己写 `eulerFromRotation`（GLM 列主序下 `R_ij = m[j][i]`，含万向锁分支）。
- API 从 `hotAxis()/axisName()` 改成 `hotHandle()/handleName()`（外部只有
  `ViewportPanel.h` 的 `gizmoDragging()` 引用，改名安全）。

## 本轮的坑（已进 MEMORY.md）
- **`SetForegroundWindow` 静默失败 → ImGui 完全收不到拖拽**：只有前台进程（或被它启动的
  进程）才能改前台窗口。症状极具迷惑性 —— 坐标明明对、`SetCursorPos` 也返回 1，
  但拖拽中间态截图里连个跟随提示都没有。绕法：先按下再松开一次 ALT，
  系统就认为"用户在操作"，随后的 SetForegroundWindow 才被放行。
- **`logRect` 的正则必须用 `search` 而不是 `match`** —— 日志行有 `[INFO ] ` 前缀，
  行首锚定的正则会一条都匹配不到（我是先写成 `^` 然后 debug 出来的）。
- **改名前的连锁**：`mv` 报"另一个进程正在使用此文件" → 子目录能正常改名 ⇒ 锁在**项目根**
  本身（VS Code 的扩展宿主以工作区根为 cwd）。**需要用户先关掉 VS Code 那个窗口**。
- 上一轮记的"鼠标会被外部挪动"这轮没复现（脚本里每步都留了 0.16~0.3s 且分 6 步移动），
  但**闭环校验仍然值得做**。

## 收尾：目录改名落地（用户自己改成了 venn-engin）

改完直接 `./make run` 报：

```
CMake Error: The current CMakeCache.txt directory E:/code/cpp/venn-engin/build/CMakeCache.txt
is different than the directory e:/code/cpp/MyVulkanEngine/build where CMakeCache.txt was created.
ninja: error: rebuilding 'build.ninja': subcommand failed
```

**根因**：`build/` 里的 CMakeCache.txt / CMakeFiles/VerifyGlobs.cmake / build.ninja 全是
**绝对路径**，改目录名后 CMake 觉得"缓存跟自己在的地方对不上"直接拒跑。
（旧目录残留了一个 0 字节的空壳 `MyVulkanEngine/build/CMakeFiles`，一起清掉。）

1. 备份 `build/bin/imgui.ini`、`build/bin/editor_window.ini`（界面布局 + 窗口几何）到项目外；
2. 删 `build/` 与 `compile_commands.json`（`Remove-Item -Recurse -Force`；
   注意 `rm -rf` 会被工作区的 safe-delete 拦成"移到回收站"，对 197MB 的 build 很慢/会失败）；
3. 在新路径重新 configure：
   ```bash
   cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug \
     -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe \
     -DCMAKE_CXX_COMPILER=C:/msys64/ucrt64/bin/g++.exe \
     -DCMAKE_EXPORT_COMPILE_COMMANDS=ON "-DCMAKE_POLICY_VERSION_MINIMUM=3.5"
   ```

4. 全量构建（87 个目标，43s）+ 恢复两个 ini。
