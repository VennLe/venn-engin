## 脚本路线图 S4 协程 ✅（`--selftest script` 68 → 85 条全绿）

`ScriptRuntime` 的 `exec()` 改成**显式帧栈**：`Frame{ stmt, ip, locals }` + `Stmt::id`。挂起 = 把当前
帧栈整条存进 `ScriptCoroutine`，`wait()` 记 `wakeAt = simFrame + n`；恢复时按 `Stmt::id` **reattach**
回原语句（不重跑外层）。

三坑：
1. **先 `++ip` 再压子帧**（反了 = `wait` 醒来后整条 `if` 从头上重跑。
2. **`Frame&` 在 `push_back` 后悬垂** → 压栈前先把要改的字段拷到局部变量。
3. `simFrame` 是 **1-based**（`0` 当"未启动"用）。

`resetInstance()` 必须**换一条空协程**，只清 `wakeAt` 不够（旧帧栈还挂着）。

- 平均差：20°=5.54 / 80°=14.94 = 2.7×，**而且 45° 机位的 25.70 比 80° 还大**（非单调）——

- 实测位移（互相关）：试着加了 4 次渲染量 20°/80°，结果 **80° 给出 +0 px** —— 掠射端纹理
  周期 + 极度透视压缩让相关峰退化成一堆等高的假峰（C2 的注释早就写了"机位必须选 45°"）。
→ 撤回那 4 次渲染，阈值 3.0→2.0，断言措辞改成"单调显著变大"，并写明为什么**不能**断言 ∝tanθ。
2× 仍能把"固定 UV 偏移"（≈1.0×）判红。

### ⑤ particles：`fx_click` 既不等也不验 + `alive` 用了绝对容差

- H0b：`BAR-PICK-*` 是**弹层里的项**，弹层没弹出时矩形还没打 → 直接 return None。而且"点 +"
  和"点条目"混在一起，挂了看不出是哪一步。
  → 新增 `fx_ensure_picker()`：**先验证 `BAR-PICKER-WIN` 存在**（存在就不要再点，再点会关掉），
  不在就重读矩形再点，最多 6 轮；点条目走 `fx_click(confirm=FX-WIN 出现)` 重试 3 次。
  失败时把"看到了哪些 BAR-PICK-*"打出来 —— 断言失败要自己说明它看到了什么。
- G1b：`alive` 是瞬时量，跨运行实测差 **1 / 5 / 10**（三次），固定 8 扛不住。改成
  `max(8, 5%)`（364 时 = 18）—— **绝对容差在计数型量上不成立**，它会随基数漂。
- 顺带把 `fx_click` 从 `click_client`（真实事件）改成 `click_client_post`（直投）：后者不依赖
  前台/遮挡。⚠ 实测两者在这里都能打开弹层，不是"哪个更好"，是"少一个失败模式"。

**否定测试（5 条判据全做，实测）**：camfx "MB 没生效/静态不模糊" → n=0 红；taa "TAA 没跑"
（max=0）与"TAA 重画画面"（n=623、Laplacian 升）→ 都红；pom "固定 UV 偏移" → 倍数 1.00 红；
正例 3/3 绿。

**复跑**：5 个连跑 **5/5 PASS**（camfx 179.1 / taa 70.7 / pom 146.1 / particles 152.6 /
notifications 117.3）—— 连跑才是它们原来挂的场景。另跑 editor_round4 / script_editor（受
ConsolePanel 改动波及）**2/2 PASS**。
⚠ 全量 `--all` 没重跑（约 70 分钟），按纪律等用户另行下令。

## Vmeta.h 编译错误（自足性）

**症状**：`Vmeta.h:68: 'uint32_t' in namespace 'std' does not name a type`，紧跟
`Vmeta.cpp:81: too few arguments to function 'assets::fnv1a32(...)'`。

**根因**：`engine/assets/Vmeta.h` 用了 `std::uint32_t` / `std::size_t`，但只 include 了
`<array> <map> <set> <string>`，没有 `<cstdint>` / `<cstddef>`。`Vmeta.cpp` 第 1 行就是
`#include "assets/Vmeta.h"`（前面没有任何标准头替它把 cstdint 拉进来）→ 直接炸。
**第二个错误是派生错误**：返回类型解析失败后 GCC 把默认参数 `h = 2166136261u` 丢了，
于是看起来像"参数个数不对"。**看到"too few arguments"先别改调用点，先看声明本身是否报过错。**

**修**：`Vmeta.h` 补 `#include <cstddef>` + `#include <cstdint>`。
**验证**：`-fsyntax-only` 单独编译一个只包 `Vmeta.h` 的 TU 通过（默认参数可用）；全量
`cmake --build build -j 8` → 79 目标，`libVennEngine.a` + Launcher/Editor/Game 全部链接成功，零错误。

**教训**：头文件自足性。凡是头里出现 `std::uintN_t` / `std::size_t`，就必须自己 include
对应头，不能赌"调用方会先包别的"。

## "引擎启动为什么不是从启动器开始" —— 接线缺失，不是 bug

**诊断**：三条独立证据
1. `Makefile` 里**没有** `LAUNCHER` 变量 / `RUN_LAUNCHER` / `run-launcher` —— `make run`
   注释写着"项目主入口"，实际硬编码 `Editor.exe`。
2. `editor/ engine/ runtime/` 里**零处**引用 `Launcher.exe`（grep 无命中）→ 没有任何
   "编辑器→回启动器"的反向路径，也没有"先起启动器"的前置检查。
3. `make info` 只打印 Editor.exe / Game.exe，启动器连汇总都没进。

**根因**：`core::Application` 是库，三个 exe（launcher/editor/runtime）各有自己的
`main()`，**平级**。设计上（launcher_roadmap D1）启动器就是独立进程、不是编辑器的
外壳 —— 所以"引擎"没有单一入口，"启动整个引擎"这个动作没人接线到 Launcher.exe。
启动器不是被绕过，是**没被任何人启动**。

**修**：`Makefile`
- 加 `LAUNCHER` / `RUN_LAUNCHER`（同样 `cmake -E chdir build/bin`，否则 imgui.ini 甩到仓库根）
- `run` → `Launcher.exe`（"启动引擎"= 先选工程）；`run-editor` 不再被 `run` 引用，改为
  直接跑 Editor.exe（跳过启动器，资产根按候选链退化成 exe/assets）；`run-launcher` 作别名
- `.PHONY` / `info` / `help` 同步

**验证**：`make run FRAMES=180` → 窗口标题 `Venn Launcher`，"Recent projects / + New game /
Open project..." 正常；四个目标的 `-n` 展开分别指向 Launcher/Editor/Launcher/Game。
截图 `_venn_verify/launcher_boot.png`。

**没做（有意）**：不给 `Editor.exe` 加"没工程就弹启动器"的硬门禁 —— `tools/` 下所有
验收脚本都是裸起 Editor.exe，加了等于一次打挂全部自动化。要不要这个门禁属于产品决策。

## 启动器两项改造：常驻任务栏 + 类型卡片插图

**需求**：① 编辑器退出后启动器不退出，默认收在任务栏；② 启动器窗口放大，
第一/第三人称选项做成"图 + 文字"卡片，注释文字只在悬浮时提示。

**① 常驻**
- 原 `runPendingSpawn()` 结尾是 `window().invalidate()`（拉起即退出，§5.4 老契约）
  → 改成 `window().minimize()` + `LAUNCHER-MINIMIZED` 日志；恢复时打 `LAUNCHER-RESTORED`。
- `engine/core/Window` 新增 `minimize()`（`glfwIconifyWindow`）。**不能用 `glfwHideWindow`**：
  hide 会把任务栏按钮一起拿走，用户找不回来。
- 主循环早就对 `iconified()` 有分支（只 `glfwWaitEvents` + continue，不渲染）→ 常驻几乎不吃资源。
- **契约反转要同步改验收脚本**：`verify_launcher_open.py` 的 O2 原来断言"启动器自己退出"，
  改成 O2/O2b/O2c/O2d（MINIMIZED + IsIconic + 编辑器退出后仍在 + 恢复日志）；
  `verify_launcher_code.py` 里等退出那段也一样（否则白等 40s 假红）。

**② 卡片 + 插图**
- 窗口 1100×680 → **1280×800**（`kWindowW/H`）。
- 两张动漫插图用 ImageGen 生成后裁成 16:9（1536×864），落在 `assets/launcher/`，
  CMake 加进 `VENN_ALWAYS_ASSET_DIRS`（否则改图不生效）。**原图右下角有 AI 水印，
  裁掉底部 100px 才干净**。
- 卡片：父窗口里一个 `InvisibleButton` 当命中区 + `DrawList` 自绘
  （`AddImageRounded` + `AddText` + `AddRect` 描边）；选中=蓝边+标题条高亮，
  未选中压 55 alpha 暗罩（试过 90 太黑，插图特征会糊）。注释文字改 `SetTooltip`，
  卡面只留标题 —— 正是用户要的"悬浮才提示"。
- 纹理：`assets().loadTexture(abs, "launcher:typeFP/TP", true)` →
  `ImGui_ImplVulkan_AddTexture(view, SHADER_READ_ONLY_OPTIMAL)`；**句柄在
  `onShutdown()` 里 `RemoveTexture`**（后端还活着时的最后一个安全点）。
  加载失败只 WARN 一次并退回纯色块，不让一张图打不开启动器。

**验证**：`verify_launcher_open` 12 项 PASS（含 O2c/O2d）；`verify_launcher_create` /
`verify_launcher_code` / `verify_launcher_ui` / `verify_launcher_display` 全 PASS。
截图 `_venn_verify/l2_type_cards.png` / `l2_type_hover.png` / `l2_type_selected.png`。
