- **脚本内建表零演出 API**。`kBuiltins[]` 60 项逐条看：数学 17 / 集合查询 8 /

## #310 剧本编辑器（面板上写台词）

`editor/DialogueEditorWindow.{h,cpp}`（约 700 行）+ `DialogueAsset` 的**写回**。

### 三个"省了就错"的决定

1. **校验不在面板里实现**。每次改动都是"`toJson` → 丢回 `parseDialogue`"，
   用的是运行时那个校验器。自己再写一套"顺手查一下"= 两套规则，而作者只
   在运行时看到另一套（"编辑器说没问题，进 Play 就 DLG-LOAD-FAIL"）。
   面板里那句话直接叫 **Load check**，与"建议"分栏摆 —— 效力不同的东西
   不能混在一起，否则"游离节点"会被当成"文件坏了"。
2. **读盘失败 → 只读**。`parseDialogue` 是边解析边填，半路出错时 `nodes`
   是前几行的残片。允许存盘 = 把 300 行的剧本截成 119 行。这条和
   "换场景失败后世界是空的"是同一类：**半成品状态必须锁住写操作**。
3. **改 id 连引用一起补**。不补的话 `next`/`goto` 全悬空，而校验器只说
   `next "old" is not a line id`，不告诉你在哪几行。`patched=` 那个数就是
   补了几处的记账（断言 D1 就钉它）。

### 写回的四条"不写"

`index`（缓存 = 身份，落盘等于写死下标）/ `error`+`warnings`（诊断不是内容）/
空 `next`+`choices`（写 `""` 会被当成"跳到空 id"）/ `\uXXXX`（转义后 diff 全废）。
`saveDialogue` 是**临时文件 + rename**：写一半断电 = 文件打不开，而存档点
就在一个快捷键之外。

### 存盘后刷新场景组件（否则症状极怪）

窗口里是新台词、Save 成功、进 Play 还是旧的 —— 因为 `DialoguePlayer::load`
**按路径缓存，同路径不重读**。刷新必须 `player = DialoguePlayer{}` 再 `load`。
正在播的不打断（记 `DLGED-SCENE-SKIP`），等下一次起播。

### 自动化：注入而不是点按钮

`MYVK_EDITOR_DLGED_SCRIPT="sel:2;del;save"` → 调的就是按钮调的那批 `act*`，
同一条路，验的是真行为；控件坐标会随内容高度漂移，点按钮的测试很脆。
矩形锚点仍验一遍（证明面板真画在屏幕上）。

**坑：注入文本必须 ASCII**。Windows 窄环境块按 ANSI 代码页转换，
中文进 `std::getenv` 会变成 GBK 字节 —— 那验的是"编码没配好"。
中文用更硬的判据：原文件里的中文往返一遍逐字节比（B5）。

**坑（老坑重犯一次）**：`"...%s" % m.groups()` —— `m.groups()` 是元组，
`%` 会当成多参数。必须 `% (m.groups(),)`。这次一口气 11 处。

### i18n

新面板 40 条 TR。`verify_i18n_coverage.py` **本来就红**（改前 73 项缺中文），
我这一版把它按回 73（加词条之前是 103）。顺手修了 D 组那一条：
窗口标题不再用带 `###panel_xxx` 的 `snprintf` —— 那串是 ImGui 稳定 ID，
不是给人看的字，放进格式串必然被"格式串没包 TR"抓出来。改成 `std::string`
拼接。

### 验收

- `--selftest dialogue` → **105 条**（97 + G 组 8 条 `rt_*` 往返）
- `tools/verify_dialogue_script.py` → **28/28 PASS**（7 组：打开 / 改+加+存 /
  删被引用的一句 / 改 id / 坏文件只读 / 从零新建 / 存到场景在用的那份）
- `verify_dialogue_editor` 6/6、`verify_dialogue` 11/11、`check_regression_map` PASS

## #311 时间轴轨道编辑器（把运镜排出来）

`editor/TimelineEditorWindow.{h,cpp}`（约 1000 行）+ `SequenceAsset` 的**写回**
（`toJson` / `saveSequence`）。

### 三个关键决定

1. **拖动中不重排，松手才排**。`cameraKeys` 必须按 t 升序（采样前提），但拖动
   改的就是 t。拖动中就 sort 的话，鼠标下面那一帧会在数组里跳到别处，`m_sel`
   失准 —— 症状是"拖到一半，选中项换成了别人"。松手时做一次"取出-插入"
   （`reorderKey`），天然知道身份（sort 之后只能靠 t 猜，而同 t 允许多项）。
2. **UI 用度、资产用弧度**。转换只在这一层。写错的话症状极隐蔽：
   `yaw=0.2` 显示成 11.5° 看着"挺合理"，等镜头发疯才发现。验收里
   `setyaw:90 → 1.5708` 钉的就是这条。
3. **播放头预览走纯函数 `sampleCamera`，不走 `SequencerSystem::tick`**。
   后者的播放头在**组件里**，而窗口手里的与它无关（从菜单裸开一份资产时，
   场景里根本没有组件）。

### 写回的五条"不写" + 两条"必写"

不写：`valid`/`error`/`warnings`（诊断）、`sourcePath`（来源）、空 `payload`、
`\uXXXX`（转义后 diff 全废）。
必写：`duration`（不写就退回"按内容推算"，"拖最后一帧到 9s"会看起来没反应）、
`ease`（"这两帧怎么走"的唯一表述，省略得翻代码查默认值）。

### 逮到一个真实缺陷：`"//"` 注释会丢

`opening.seq.json` 里有一大段 `"//"` 说明（解释 yaw 是弧度、step 的切点在哪），
而 `parseSequence` 以前**不读它**。编辑器一存盘，这段就无声消失了 —— 而作者
不会想到"点 Save 会删注释"。修法：`SequenceAsset::comment` 读写往返，
`rt_comment_roundtrip` 钉住。

### 验收脚本自己错了三次（值得记）

1. `head:6.0;addkey` —— 原资产 6.0s **本来就有帧**，`actAddKey` 正确地拒绝了它，
   于是帧数不变、B1/B7 两条断言**双双变成假阳性**（看着过，其实什么都没测）。
   改成 3.5s 真空档。
2. `B6 改 t 不丢 ease` 选了 4.0s 那一帧 —— 它的 ease 本来就是 smooth，
   "没被改"和"被改成默认值"看起来一样。改用 2.5s 那帧（ease=step）。
3. `C5` 期望 `to=4` —— 而取出第 0 项后数组是 `[2.5,4,6,8]`，7.0 落在 6 和 8 之间
   是下标 **3**。断言写错会让人以为重排错了。

**教训**：断言里的"期望值"必须**算出来**，不能想当然。三条里有两条是
"想当然"（6.0 应该有帧 / 拖到最右边是最后一个）。

### 一个真问题：新增日志锚点

`actSetTime`（输入框改 t）和拖拽走同一个 `reorderKey`，但只有拖拽会打
`TLED-DRAG-END`（松手时）。验收走的是 `settime`，于是 C5 抓不到任何重排证据。
修法：把 `TLED-REORDER` 打进 `reorderKey` / `reorderEvent` 本体 ——
重排是**唯一**会改变"下标 ↔ 身份"对应关系的动作，它必须留痕。

### 布局：工具栏被裁

第一版把「路径/Reload/Save/New」和「时长/循环/播放头/抓取/+Key/+Event/Delete」
挤在两行，1060 宽的面板装不下 —— 截图里"新建过场"被窗口右边缘切掉一半。
拆成三行（文件 / 时间 / 动作）。**按钮被裁一半是最难看的一种布局问题**，
而它在锚点断言里完全不报（矩形照样有）。

### 验收

- `--selftest sequence` → **67 条**（原 58 + F 组 9 条 `rt_*` 往返）
- `tools/verify_timeline_editor.py` → **34/34 PASS**（6 组：打开 / 改+加+存 /
  拖动重排 / 坏文件只读 / 从零新建 / 存到场景在用的那份）
- `verify_sequencer` 8 组、`verify_inspector`、`verify_inspector_tabs`、
  `verify_dialogue_editor` 6/6、`verify_dialogue_script` 28/28、`check_regression_map` 全 PASS
- `verify_i18n_coverage`：补 60 条词条后回到 **73 = 基线**（改前就是 73）

## #312 UI 编辑器最小版（界面变成一份资产）

`engine/ui2/UiDocument.{h,cpp}`（约 1100 行，文档格式 + 放置 + 绘制 + 绑定）
+ `editor/UiEditorWindow.{h,cpp}`（约 1500 行，三栏面板）+ `assets/ui/docs/hud_demo.ui.json`
+ `tools/verify_ui_editor.py`（46 条，A~H 八组）。

**格式**：`{"version":1,"name":…,"canvas":[1920,1080],"//":…,"widgets":[…]}`，
六种控件（panel/nine/image/text/button/progress），锚点 `top-left`…`bottom-right`
（`top-left` 是默认值，`toJson` 省略它）。字段 `rect:[x,y,w,h]` 里的 x/y 是
**距锚点那一侧**的距离，不是屏幕坐标。

### 五个"省了就错"的决定

1. **锚点符号约定只有一份实现**：新增 `UiLayout::placeRectIn(parent, …)`，
   子控件相对**父矩形**、顶层相对屏幕（画布 = 输出尺寸），两处都走它。
   自己再写一遍"锚点和屏幕差一个宽度"是最难查的偏移。
2. **换锚点必须保屏幕位置**：`actSetAnchorKeepRect` 用 `placeRectIn` 的逆运算
   反解 x/y（左锚 `r.x-parent.x`、右锚 `parent.right-r.right`、中锚 `r.cx-parent.cx`）。
3. **校验只有一份**：存盘前 `toJson` → `parseUiDocument`，能解析回来才算通过；
   读盘失败则 `ok=0 && readOnly=1`，坏文件 1 字节不动。
4. **`visible=false` 整棵子树跳过且不推进 cursor**；`placeDocument` 对每个可见
   控件都出记录（含退化矩形），`drawDocument` 用递增 cursor 消费 —— 少跳过一个
   invisible 节点会让整棵树错位一格。
5. **默认关靠结构**：`m_cfg.uiDoc` 为空时运行时**根本不调用** `drawDocument`，
   画面与 #311 之后逐位相同（不是靠 if 记着写）。

### 踩到的坑（都写进注释了）

- **"保持屏幕位置"≠"rect 不变"**：`bottom-right`→`top-right` 后文档 rect 的 y
  必须从 24 变 992，屏幕矩形才是 `1656,992,240,64`。验收第一版拿文档 rect 对
  屏幕 rect，把**正确实现**判成 FAIL（C2/C3 分开写）。
- **`drawn=1` 是写死的**：`UIDOC-STATS` 那个数原来是源码字面量 → 改成
  `drawDocument` 真返回的 `UiDocDrawStats`，另加 `skipped` / `texts`。
- **锚点日志节流要含第 1 帧**：夹具 `frame==60` 扣血，而"每 60 帧一行"的样本
  全在扣血之后 → fill 一条直线，绑对了也证明不了。改成 `==1 || %60==0` 后是
  `213.3 → 149.3`（= 70%）。
- **绑定缺失按 0 算**：`w.value` 默认 1.0 会画出满槽，"看起来血是满的"最骗验收。
- **`reason=(\S+)` 被 NOTIF-PUSH 回显行截走**（`read-only"`）→ 改 `[\w-]+`。
- **`UI2-TEST` 的 actual/expected 可以有空格**（`HP 70/100`）→ `\S+` 改 `(.+?)`。
- **capture_window 必须带 `--no-resize`**：不然它把窗口改三次，每张图尺寸都不同，
  diff 直接返回 1.0，看着像"编辑器不稳定"。`MYVK_FRAMES` 要 `pop` 而不是设空串。
- **H5 判据从"包围盒面积"改成"包围盒内密度"**：改一个控件会同时动画布、右栏
  数字、校验条，包围盒必然覆盖大半窗口（1140x565）。整块重排时密度近 1，
  局部微调只有 5.5% —— 密度才有判别力。

### 连带的既有欠账：图集装满了

图集（2048×3072 / 1138 字形）在 **HEAD 上就已缺 56 个汉字**，这轮 33 条新词条
又加 8 个。重生成：`python tools/gen_sdf_atlas.py --atlas-h 4096`
→ **1200 字形 / 2048×4096 / 0.61 MB**，字号 48 / spread 6 / ascent 48 一个没动，
所以字形位图逐位相同（`verify_hud`、`verify_dialogue` 复跑 PASS 证明文本没漂）。
⚠ `--atlas-h 3072` 已经装不下（需 6.7M 像素，差 6%）。

### 验收

## #316 多选编辑（#313 的第二个子任务，已收口）

需求：「在当前单选之上加选择集，保持 `selection()` 仍是**主选中项**（零破坏）」。

### 一条不变式撑住整个设计

**集合为空 ⇔ `m_selection` 无效；集合非空 ⇒ `m_selection` 一定在集合里。**
主选中项**单独存**，不是"集合里的第一个" —— Ctrl 点掉中间项之后"第一个"会换人，
用户什么都没碰手柄坐标系却突然转了。`validateSelection()` 收口时就靠这一条：
集合空而主选中项还活着 → 以它为准建单元素集合；主选中项无效 → 取 `front()`。
（集合里还多存一份 `m_selectionNames`，同下标，undo / 存盘后**按名字**逐个接回。）

零破坏怎么落地：`selection()` 一个字不改，只在 `select()` 末尾加一句"把集合替换成
一项"，于是既有全部调用点（层级点选 / 导入 / undo 重接 / prefab 实例化）逐位一致。

### 三处刻意的不对称

1. **多选拖拽过滤祖先**：子节点的祖先也在集合里时**不进**目标表 —— 否则父动一次、
   自己再写一次，现象是"带层级批量拖时子物体飞得比父物体远"。
2. **旋转绕支点，缩放不绕**：旋转只有一个矩阵 D，绕支点无歧义；缩放按每目标自己的
   局部轴分配权重，一批朝向不同的物体**没有共同缩放基**，硬凑只会各自变形 + 漂开。
3. **批量编辑语义**：位置/旋转 = 增量 `base + (edit - prior)`，缩放 = 比例
   `base * (edit / prior)`。prior 一致时退化成绝对值（共同值），混合时 = 0 / 1。
   同一个式子覆盖两端 —— "拖到一半值从一致变成不一致"不会换语义、数字不跳。
   纯函数抽在 `editor/MultiEditMath.h`（`batchAdd` / `batchMul` / `orbitPosition`），
   Gizmo 与 Inspector 两处共用。

### 踩到的坑

- **`World::destroy` 不递归**：批量删除必须自己摊平整棵子树，否则留下"parent 指向
  死 id"的孤儿 —— 不在树里（不是根）、却还在渲染，等于凭空多出一堆点不中的幽灵。
- **`HIER-ROW` 会洪水**：`logRect` 自带"矩形没动就不打"，但行**名字**变了矩形位置
  不变 → 还得按名字再节流一次，并限制最多 16 行。
- **行号 ≠ 场景数组下标**：加载器自己补一个 `DirectionalLight`（没有 Transform，
  但**是树里第 0 行**），整张表偏移一位。脚本改成"点一遍读名字"建 {名字→(行, 中点)}。
  另外它一开始有个真 bug：点完没产生新的 `HIER-SELECT` 时 `last_match` 会把**上一行**
  的名字当本行 → row_map 出现连续重名，后面全在点错的东西上。
- **自动化按键两类坑**：修饰键必须用真 `keybd_event`（GLFW 读 `GetKeyState`，
  PostMessage 造的假消息不改状态）；**扩展键**（Delete / 方向键）的 `lParam` 必须带
  bit24（`0x01000000`），否则 GLFW `translateKey` 对 `VK_DELETE` 直接返回
  `GLFW_KEY_UNKNOWN`，现象是"Del 完全没反应"。
- **⚠ 真鼠标用例怕被抢前台**：`mouse_event` 打给"光标底下最上层"的窗口，不是手里的
  hwnd。整套五组要跑两分多钟，期间任何东西抢走前台 → 后续层级点击**一条
  `HIER-SELECT` 都不出现**，与"多选坏了"逐字相同。整套第一次跑就这么红了 7 条，
  同样几个组单独跑全绿。修法：`click` / `drag` / `press_key` 每次发事件前都
  `ensure_foreground`（被抢就抢回来 + 打 WARN），并用 `click_expect`（等日志真的
  涨一行，允许重试一次 —— 窗口刚激活时系统会吞掉第一次点击）。
